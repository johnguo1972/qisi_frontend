# 微信登录实现逻辑整理

> 整理日期：2026年9月4日  
> 适用范围：uni-app 前端、`apps` 后端  
> 说明：本文根据当前项目代码整理，仅描述现有实现，不代表新增或修改方案。

## 一、结论

当前项目中，微信登录按运行端分为以下几种实现：

1. **微信小程序端**：使用 `wx.login` 获取临时登录 `code`，服务端向微信换取 `openid/unionid`；已绑定账号直接签发 JWT，未绑定账号需要通过手机号和短信验证码完成绑定。
2. **H5 端**：当前登录页实际使用的是“H5 展示二维码、微信小程序扫码确认”的设备登录流程。小程序完成身份确认或手机号授权后，H5 轮询状态并使用一次性 `ticket` 换取 JWT。
3. **APP 端**：当前没有微信登录入口或微信 SDK 配置，实际使用手机号 + 短信验证码登录。APP 的扫码能力只是业务二维码扫描，不是微信登录。
4. **后端另有一套标准微信网页 OAuth 流程**：代码位于 `apps/accounts/wechat_web.py`，但当前 uni-app 登录页没有调用这套流程；当前 H5 实际链路以 `wechat-device/*` 接口为准。

## 二、三端登录方式对比

| 端 | 当前微信登录方式 | 首次登录绑定方式 | JWT 获取方式 | 当前状态 |
|---|---|---|---|---|
| 微信小程序 | `wx.login` 直接登录 | 手机号 + 短信验证码 | 小程序调用登录接口后直接获得 | 已接入 |
| H5 | H5 二维码 + 小程序扫码确认 | 微信小程序授权手机号 | H5 使用一次性 `ticket` 换取 | 已接入，实际使用 device 流程 |
| APP | 无微信登录按钮 | 不适用 | 手机号验证码登录 | 当前未实现微信登录 |
| 标准网页 OAuth | 微信开放平台 `qrconnect` | 小程序确认或手机号授权 | H5 使用网页绑定 `ticket` 换取 | 后端存在，前端未完整接入 |

## 三、涉及的核心代码和路由

### 3.1 uni-app 前端

- 登录页：`uniapp/src/pages/login/index.vue`
- 小程序微信登录工具：`uniapp/src/utils/wechat-auth.ts`
- 小程序直接登录接口：`uniapp/src/api/wechat.ts`
- H5 设备登录接口：`uniapp/src/api/wechat-device.ts`
- 标准网页 OAuth 接口封装：`uniapp/src/api/wechat-web.ts`
- 小程序扫码确认页：`uniapp/src/pages/auth/web-binding.vue`
- 登录态保存和角色路由：`uniapp/src/utils/roles.ts`
- 统一请求封装：`uniapp/src/utils/request.ts`

### 3.2 apps 后端

- 认证路由：`apps/accounts/urls.py`
- 普通登录和微信设备登录视图：`apps/accounts/views.py`
- 小程序直接微信登录：`apps/qrcode/views.py`
- 微信设备登录状态机：`apps/accounts/wechat_device.py`
- 微信网页 OAuth 服务：`apps/accounts/wechat_web.py`
- 微信身份模型：`apps/accounts/models.py`
- 账号、角色和 JWT 服务：`apps/accounts/services.py`

项目总路由在 `config/urls.py` 中配置：

```text
/api/v1/auth/      -> apps.accounts.urls
/api/v1/           -> apps.qrcode.urls
```

因此，`/api/v1/auth/wechat-login` 实际由 `apps.qrcode.views.wechat_login` 提供；`wechat-web/*` 和 `wechat-device/*` 由 `apps.accounts.views` 提供。

## 四、微信小程序端直接登录

### 4.1 前端入口

登录页中的微信按钮只在 `MP-WEIXIN` 条件编译下显示。点击后执行：

```text
wx.login()
    ↓
取得临时 code
    ↓
POST /api/v1/auth/wechat-login
```

请求参数：

```json
{
  "code": "微信临时登录凭证",
  "role_type": "student"
}
```

角色来自登录页当前选择项，可选 `student`、`teacher`、`parent`、`admin`。

### 4.2 后端向微信换取身份

后端读取服务端配置：

```text
WECHAT_MP_APPID
WECHAT_MP_APPSECRET
```

然后调用微信接口：

```text
https://api.weixin.qq.com/sns/jscode2session
```

参数包括：

```text
appid
secret
js_code
grant_type=authorization_code
```

微信返回后端身份信息：

```text
openid
unionid
```

AppSecret 只在后端使用，不下发到前端。

### 4.3 已绑定身份的登录流程

后端通过 `appid + openid` 查询 `WechatIdentity`：

```text
WechatIdentity(appid, openid)
    ↓
找到绑定用户
    ↓
检查用户状态
    ↓
检查当前角色授权
    ↓
生成 access_token / refresh_token
```

返回数据包括：

```text
access_token
refresh_token
user
user.roles
user.active_role
```

角色校验规则：

- 用户必须处于 `active` 状态。
- 当前选择的角色必须有有效的 `UserRole` 授权。
- parent 角色按照 `ensure_parent_role_for_login` 规则处理。
- 已具有 teacher 角色的用户选择 student 时，按照 `ensure_student_role_for_login` 规则处理。
- 新用户不能通过微信登录直接创建 teacher 或 admin 账号。

### 4.4 未绑定身份的绑定流程

如果微信身份不存在，后端返回：

```json
{
  "code": 1001,
  "data": {
    "bind_token": "一次性绑定令牌"
  }
}
```

`bind_token` 暂存在缓存中，有效期约 600 秒。

前端收到 `1001` 后跳转：

```text
/pages/student/parent-bind?bindToken=...
```

用户在绑定页：

1. 输入手机号。
2. 调用 `/api/v1/auth/send-code` 获取短信验证码。
3. 选择 student 或 parent 角色。
4. 调用 `/api/v1/auth/wechat-bind`。

请求参数：

```json
{
  "bind_token": "...",
  "mobile": "13800000000",
  "verify_code": "123456",
  "role_type": "student"
}
```

后端校验绑定令牌和短信验证码后：

```text
手机号查找或创建 UserAccount
    ↓
校验角色授权规则
    ↓
创建或更新 WechatIdentity
    ↓
删除 bind_token 缓存
    ↓
生成 JWT
```

### 4.5 小程序登录成功后的前端处理

前端保存：

```text
accessToken
refreshToken
userInfo
```

然后根据 `active_role` 跳转：

- student：小程序专用首页 `/pages/student/mp-home`
- teacher：`/pages/teacher/layout`
- parent：`/pages/parent/layout`
- admin：`/pages/admin/home`

## 五、H5 端当前实际使用的设备扫码登录

### 5.1 登录会话创建

H5 登录页切换到“微信扫码登录”后，调用：

```text
POST /api/v1/auth/wechat-device/session
```

请求：

```json
{
  "requested_role": "student"
}
```

后端创建一个约 300 秒有效的登录会话，并绑定当前浏览器 Session，返回：

```json
{
  "web_session_id": "...",
  "qrcode_url": "/api/v1/auth/wechat-device/qrcode?web_session_id=...",
  "expires_in": 300
}
```

该阶段不签发 JWT。

### 5.2 生成并展示小程序码

H5 使用 `qrcode_url` 展示二维码，后端接口为：

```text
GET /api/v1/auth/wechat-device/qrcode
```

后端执行：

1. 校验登录会话是否存在、是否过期。
2. 校验请求浏览器是否为创建会话的原始浏览器。
3. 创建短期一次性 `bridge_code`。
4. 调用微信小程序码接口生成二维码。
5. 将二维码页面设置为：

```text
pages/auth/web-binding
```

二维码的 `scene` 参数为 `bridge_code`，二维码本身不包含手机号、openid 或 JWT。

### 5.3 小程序扫码确认身份

用户用微信扫描 H5 二维码后，打开小程序页面：

```text
pages/auth/web-binding
```

小程序页面：

1. 从 `scene` 参数读取 `bridge_code`。
2. 调用 `uni.login({ provider: 'weixin' })` 获取 `login_code`。
3. 调用：

```text
POST /api/v1/auth/wechat-device/scan
```

参数：

```json
{
  "bridge_code": "...",
  "login_code": "..."
}
```

后端再次调用 `jscode2session`，得到小程序的 `appid/openid/unionid`。

`bridge_code` 使用后会被消费，不能重复使用。

### 5.4 已绑定微信身份

如果 `WechatIdentity` 已存在：

```text
校验身份和 unionid
    ↓
校验请求角色授权
    ↓
将 device session 标记为 login_confirmed
    ↓
创建一次性 ticket
```

此时小程序只负责确认身份，不直接获得 JWT。

### 5.5 未绑定微信身份及手机号授权

如果微信身份不存在，后端返回：

```json
{
  "status": "phone_authorization_required",
  "phone_binding_token": "..."
}
```

小程序展示 `open-type="getPhoneNumber"` 按钮。用户授权后，小程序从事件中取得一次性 `phone_code`，调用：

```text
POST /api/v1/auth/wechat-device/phone
```

参数：

```json
{
  "phone_binding_token": "...",
  "phone_code": "..."
}
```

后端使用小程序 AppID/AppSecret 获取微信接口调用凭证，再调用：

```text
https://api.weixin.qq.com/wxa/business/getuserphonenumber
```

换取微信平台确认过的手机号。

此处前端不能直接提交手机号，提交的是微信生成的一次性 `phone_code`。

后端取得手机号后：

```text
手机号查找或创建用户
    ↓
执行 requested_role 角色规则
    ↓
绑定 WechatIdentity
    ↓
将 device session 标记为 login_confirmed
    ↓
创建一次性 ticket
```

该 H5 扫码登录流程不需要短信验证码。

### 5.6 H5 轮询和完成登录

H5 每 3 秒调用：

```text
GET /api/v1/auth/wechat-device/status?web_session_id=...
```

可能的状态：

```text
pending
phone_authorization_required
login_confirmed
```

当状态接口返回 `ticket` 后，H5 调用：

```text
POST /api/v1/auth/wechat-device/complete
```

参数：

```json
{
  "ticket": "...",
  "requested_role": "student"
}
```

后端校验：

- ticket 是否存在、是否过期、是否已使用。
- ticket 是否属于原始浏览器 Session。
- ticket 中的角色是否与当前请求一致。
- 用户是否仍处于 active 状态。
- 用户是否仍拥有该角色。

校验成功后消费 ticket，生成正常 JWT 并返回给 H5。H5 保存登录态后跳转到对应角色页面。

### 5.7 H5 设备登录的安全控制

设备登录服务使用缓存保存临时状态，主要包括：

```text
wechat_device:session
wechat_device:bridge
wechat_device:phone_token
wechat_device:ticket
```

登录会话整体有效期约 300 秒，bridge、手机号授权令牌和完成 ticket 均为一次性数据，并通过浏览器 Session 绑定原始 H5 页面。

## 六、后端标准微信网页 OAuth 流程

后端还实现了标准网页 OAuth 相关接口：

```text
POST /api/v1/auth/wechat-web/session
GET  /api/v1/auth/wechat-web/callback
POST /api/v1/auth/wechat-web/binding-session
GET  /api/v1/auth/wechat-web/binding-status
GET  /api/v1/auth/wechat-web/binding-qrcode
POST /api/v1/auth/wechat-web/binding-phone
POST /api/v1/auth/wechat-web/binding-complete
```

设计流程为：

```text
H5 创建 OAuth session
    ↓
跳转微信开放平台 qrconnect
    ↓
微信回调后端 callback
    ↓
后端用 code 换取网页 openid/unionid
    ↓
已绑定网页身份：创建 ticket
未绑定网页身份：通过小程序确认或授权手机号
    ↓
H5 使用 ticket 换取 JWT
```

该流程使用独立配置：

```text
WECHAT_WEB_APP_ID
WECHAT_WEB_APP_SECRET
WECHAT_WEB_REDIRECT_URI
```

网页 OAuth 状态、网页身份绑定会话和完成 ticket 均保存在服务端缓存中，并绑定原始浏览器 Session。

### 当前前后端接入状态

根据当前调用关系：

- `uniapp/src/api/wechat-web.ts` 只导出了接口封装，没有被当前登录页调用。
- 当前 H5 登录页调用的是 `wechatDeviceApi`。
- 当前小程序确认页调用的是 `/auth/wechat-device/scan` 和 `/auth/wechat-device/phone`。
- `wechat-web/binding-qrcode` 生成的小程序码虽然也指向 `pages/auth/web-binding`，但该页面当前使用的是 device 接口。
- 因此，`wechat-web/*` 在后端中是独立存在的实现，当前不是 H5 登录页的实际主链路。

## 七、APP 端登录现状

APP 端登录页没有微信按钮，原因是登录页中的微信按钮仅在以下平台生效：

```text
#ifdef MP-WEIXIN
```

H5 显示的是二维码扫码入口，APP 不满足 H5 或小程序条件，因此也不会显示该入口。

`wechat-auth.ts` 在非小程序端不会调用微信 SDK，只返回：

```ts
{ needBindPhone: true }
```

APP 的 `manifest.json` 中也没有微信登录 SDK 或微信 OAuth 配置。

APP 端虽然通过 `uni.scanCode` 支持普通二维码扫描，但该能力用于业务二维码，不会触发微信登录。

所以 APP 当前实际登录链路为：

```text
输入手机号
    ↓
获取短信验证码
    ↓
POST /api/v1/auth/login
    ↓
后端校验手机号和验证码
    ↓
生成 JWT
```

## 八、统一账号、角色和 Token 处理

### 8.1 微信身份模型

`WechatIdentity`：

- 对应微信小程序身份。
- 通过 `appid + openid` 唯一识别微信身份。
- 一个 `UserAccount` 对应一个小程序微信身份。

`WechatWebIdentity`：

- 对应微信网页 OAuth 身份。
- 通过 `appid + openid` 唯一识别网页身份。
- 一个用户可以关联多个网页微信身份。

### 8.2 JWT 内容和角色

JWT 由后端统一生成，包含当前会话角色：

```text
active_role
```

用户返回数据同时包含：

```text
roles
active_role
role_type
```

其中 `active_role` 表示本次登录实际使用的角色。

### 8.3 前端登录态保存

前端统一保存：

```text
accessToken
refreshToken
userInfo
```

后续请求自动携带：

```http
Authorization: Bearer <accessToken>
```

当接口返回 401 时，前端会清除 token 并重新跳转登录页。

其中：

- `WECHAT_WEB_*` 用于标准网页 OAuth。
- `WECHAT_MP_ENV_VERSION` 控制生成小程序码时使用 release、trial 或 develop 环境策略。
- `PUBLIC_WEB_URL` 用于网页 OAuth 回调后重定向到 H5 页面。

## 十、最终链路总结

```text
微信小程序直接登录：
wx.login
  -> /auth/wechat-login
  -> jscode2session
  -> 查询 WechatIdentity
  -> 已绑定则签发 JWT；未绑定则短信绑定

H5 当前实际登录：
H5 创建 device session
  -> 生成小程序码
  -> 小程序扫码并 wx.login
  -> /auth/wechat-device/scan
  -> 已绑定直接确认；未绑定授权微信手机号
  -> H5 轮询 status
  -> /auth/wechat-device/complete
  -> 签发 JWT

APP 当前登录：
手机号 + 短信验证码
  -> /auth/login
  -> 签发 JWT
```
