## 一、结论

本次开发已经完成方案中约定的代码工作：

1. 微信小程序端新增“微信手机号登录”入口。
2. 小程序端使用 wx.login 和 getPhoneNumber 获取两个一次性凭证。
3. 后端新增 /api/v1/auth/wechat-phone-login 接口。
4. 新学生、新家长可以通过微信手机号授权自动创建平台账号，并直接进入对应页面。
5. 已绑定微信身份的用户可以直接登录。
6. H5 现有“二维码 + 小程序确认 + 手机号授权 + ticket 换 JWT”链路已经具备新用户登录能力，本次检查确认无需修改 H5 业务代码。
7. APP 端按原方案继续使用手机号验证码登录，本次未增加 APP 微信登录。

当前不能宣称已经完成生产验收。服务器小程序体验版正在等待腾讯审核，因此真实微信用户、正式版二维码、生产域名和生产 Session Cookie 尚未完成最终联调。当前适合暂停微信登录开发，转做其他功能；后续恢复时应从第五章开始执行，不需要重新设计或重复开发前述代码。

## 二、本次已完成的功能

### 2.1 小程序新用户直登

小程序登录页在 MP-WEIXIN 条件下显示微信手机号登录按钮。用户主动点击按钮后：

~~~text
用户点击“微信手机号登录”
    ↓
微信 getPhoneNumber 返回 phone_code
    ↓
uni.login 返回 login_code
    ↓
调用 /api/v1/auth/wechat-phone-login
    ↓
后端换取 openid/unionid 和可信手机号
    ↓
自动创建或查找平台账号
    ↓
按角色规则赋予 active_role
    ↓
返回 access_token、refresh_token、user
    ↓
保存登录态并进入对应角色页面
~~~

拒绝手机号授权、凭证获取失败或接口失败时，页面停留在登录页并提示错误，不会自动跳转到短信验证码绑定页面。

### 2.2 新账号与角色规则

- 手机号不存在时，可以自动创建 student 或 parent 账号。
- 新账号会创建对应的 UserRole，小程序直登创建的角色来源为 wechat_mp。
- 手机号已经存在时，复用现有账号和角色授权规则。
- 已有家长账号选择家长角色时，按既有规则处理。
- 教师或管理员不会因为微信登录被自动创建。
- 未获得对应角色授权时，返回 ROLE_NOT_GRANTED。
- 已绑定的微信身份不能重新绑定到另一个手机号。
- 微信身份、unionid、手机号出现冲突时，拒绝登录，不覆盖原绑定关系。

### 2.3 H5 扫码登录

H5 当前主流程使用 wechat-device/*，不是标准网页 OAuth 主流程：

~~~text
H5 创建 device session
    ↓
H5 展示小程序二维码
    ↓
小程序 pages/auth/web-binding 使用 wx.login 扫码确认
    ↓
未知微信身份时，使用 getPhoneNumber 授权手机号
    ↓
后端创建账号并生成一次性 ticket
    ↓
H5 轮询 status
    ↓
H5 调用 complete 换取 JWT
    ↓
保存登录态并按角色跳转
~~~

该链路已通过代码和自动化测试检查。真实微信扫码和生产环境测试仍待体验版审核及正式版发布后进行。

## 五、暂停期间和后续需要做的工作

### 5.1 后端部署

体验版审核通过前，可以先完成后端部署准备：

1. 部署新增后端文件和接口。
2. 重启后端服务。
3. 执行 python manage.py check。
4. 确认接口路由可访问：

~~~text
/api/v1/auth/wechat-phone-login
~~~

5. 确认 Redis 可用，因为 H5 device session、ticket 和部分微信登录状态依赖缓存。
6. 确认生产数据库已有 WechatIdentity、UserRole 等现有表。本次代码没有新增迁移。

### 5.2 小程序上传、审核和发布

1. 使用当前小程序代码构建 mp-weixin。
2. 在微信开发者工具中导入构建产物。
3. 配置并确认小程序服务器域名。
4. 上传体验版。
5. 等待腾讯审核。
6. 审核通过后发布正式版。

小程序手机号授权必须由用户主动点击 getPhoneNumber 按钮触发，不能在页面加载时自动弹出。

### 5.3 正式环境切换

当前开发环境 .env 中仍为：

~~~env
WECHAT_MP_ENV_VERSION=trial
~~~

正式版发布成功后，才将生产环境配置改为：

~~~env
WECHAT_MP_ENV_VERSION=release
~~~

然后重启后端。切换 release 只决定二维码指向正式版小程序，不会替代后端部署、域名配置或真实测试。

### 5.4 小程序合法域名

需要在微信公众平台配置实际生产 API 域名。代码仓库中的配置不能代替微信平台配置。

至少需要确认：

- 小程序 request 合法域名；
- 如果使用上传或下载功能，对应 uploadFile/downloadFile 合法域名；
- 域名使用 HTTPS；
- 证书有效且证书链完整；
- 生产域名能访问后端 /api/v1。

当前 H5 前端使用相对路径 /api/v1，说明项目设计倾向于 H5 与后端通过同源域名或反向代理访问。生产环境仍需确认 Nginx 或网关已经正确转发：

~~~text
https://生产H5域名/api/v1/*
    → 后端服务 /api/v1/*
~~~

### 5.5 H5 HTTPS、Session Cookie 和缓存

项目代码已经具备：

- Django SessionMiddleware；
- Redis 缓存；
- H5 device session 与浏览器 Session 绑定；
- CORS_ALLOW_CREDENTIALS = True；
- H5 请求使用相对 API 地址。

但代码具备能力不等于生产部署已完成。还需要在服务器上确认：

1. H5 使用 HTTPS。
2. H5 与 /api/v1 尽量使用同源域名。
3. 后端响应的 Set-Cookie 能被浏览器保存。
4. 后续请求会携带 Session Cookie。
5. 反向代理不会丢失 Cookie 和 Set-Cookie。
6. 多实例部署时所有实例使用同一个 Redis。
7. 如果 H5 与后端跨域，补充生产 CORS_ALLOWED_ORIGINS，并检查 Cookie 的 SameSite、Secure 和域名策略。

当前项目默认开启 SessionMiddleware 和 Redis，但没有凭此证明生产反向代理和 Cookie 策略已经验收。因此 Session Cookie 仍必须进行生产验证；是否需要新增 Cookie 域名配置，取决于 H5 和后端是否同源。

## 七、注意事项和风险

1. 不要删除或替换原有 /api/v1/auth/wechat-login。它仍是旧的小程序 wx.login + 短信绑定兼容流程。
2. H5 当前主流程是 wechat-device/*，不要把它和 wechat-web/* 标准网页 OAuth 混用。
3. 不要把 phone_code 当作手机号传给后端；后端必须向微信换取可信手机号。
4. login_code 和 phone_code 都是一次性凭证，失败重试时应重新获取，不能长期缓存。
5. 不要在日志中输出 AppSecret、login_code、phone_code、access_token、refresh_token 或完整 Session Cookie。
6. WECHAT_MP_ENV_VERSION=release 只能在正式版已经发布后切换。
7. 体验版测试成员通过，不代表普通微信用户已经可以使用；正式验收必须使用非体验成员账号。
8. 教师和管理员角色不能由微信新用户登录自动创建，必须提前存在角色授权。
9. H5 如果跨域部署，必须同时检查 CORS、Cookie、HTTPS 和反向代理，不能只检查二维码图片能否显示。
10. 如果生产使用多台后端服务器，缓存必须共享，否则 H5 轮询可能查不到创建 session 的状态。
11. 本次没有修改 APP 微信登录，后续若要支持 APP 微信登录，需要另行评估 AppID、微信开放平台应用、uni-app App 原生 SDK 和回调方案。
12. 当前仓库存在与本次功能无关的其他未提交文件和历史文档改动，后续提交时只应选择本次微信登录相关文件。
