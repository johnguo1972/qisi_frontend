# 微信登录新用户直登实施分析

> 整理日期：2026年9月4日  
> 适用范围：微信小程序端、H5 网页端及 `apps` 后端  
> 本文基于当前项目代码和配置整理，重点分析“平台尚无账号时，用户能否使用微信登录并自动创建账号、赋予角色并进入平台”。

## 一、结论

当前项目还没有完全满足“新用户直接使用微信登录并成功进入平台”的目标。

- **微信小程序端**：当前首次微信登录只能获得微信身份，发现没有平台账号后，会跳转手机号 + 短信验证码绑定页，因此不是微信手机号一键注册登录。
- **H5 端**：当前已有“H5 展示二维码 → 微信小程序扫码 → 小程序授权微信手机号 → H5 自动完成登录”的实现。对于新学生、新家长，后端已经具备自动创建账号和赋予角色的能力，但当前小程序环境是 `trial`，不能直接面向普通公众使用。
- **APP 端**：当前没有微信登录入口，也没有微信登录 SDK 配置；APP 仍使用手机号 + 短信验证码登录。
- **teacher/admin 新用户**：当前后端禁止新用户自行创建教师或管理员角色，必须通过后台预授权、机构导入、邀请码或审批流程获得角色。

如果目标是新学生或新家长，建议以现有 H5 设备扫码流程为基础：

```text
H5 点击微信登录
    ↓
H5 展示小程序二维码
    ↓
用户使用微信扫码
    ↓
小程序调用 wx.login 确认微信身份
    ↓
首次使用时授权微信手机号
    ↓
后端自动创建学生/家长账号并赋予角色
    ↓
H5 取得 JWT
    ↓
进入平台
```

如果目标是微信小程序内部也做到“点击微信登录后直接注册并进入平台”，还需要补充小程序端的手机号授权登录流程。

## 二、是否需要发布微信小程序正式版本

### 2.1 开发和测试阶段

不一定需要正式发布。

开发人员、项目成员和体验成员可以使用开发版或体验版进行联调。项目中的小程序码环境可通过以下配置区分：

```text
develop  开发版
trial    体验版
release  正式版
```

但是开发版和体验版只适合有访问权限的测试人员，不能作为普通公众的正式登录入口。

### 2.2 普通用户正式使用

如果 H5 登录要面向没有加入项目成员或体验成员的普通微信用户，必须发布正式版小程序。

正式发布流程通常为：

```text
uni-app 编译微信小程序
    ↓
微信开发者工具上传代码
    ↓
提交微信审核
    ↓
审核通过并发布
    ↓
使用正式版小程序码
```

当前项目 `.env` 中的配置为：

```text
WECHAT_MP_ENV_VERSION=trial
```

因此当前 H5 设备登录二维码会指向体验环境。正式上线时需要在正式部署环境配置：

```text
WECHAT_MP_ENV_VERSION=release
```

并确认正式版本中包含：

```text
pages/auth/web-binding
pages/login/index
pages/student/mp-home
```

项目当前 `.env` 中已配置小程序 AppID 和 AppSecret，且 AppID 与 `uniapp/src/manifest.json` 中的微信小程序 AppID 一致；AppSecret 只能保留在服务端环境变量中，不能下发到前端。

微信小程序登录采用 `wx.login` 获取临时 code，再由服务端调用 `code2Session` 换取微信身份；手机号授权则需要由用户点击小程序授权按钮后取得一次性 code，再由服务端换取手机号。[微信小程序登录文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[微信小程序获取手机号文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)

## 三、当前微信小程序端的实现和不足

### 3.1 当前实现流程

小程序登录入口位于：

```text
uniapp/src/pages/login/index.vue
uniapp/src/utils/wechat-auth.ts
```

当前流程为：

```text
点击“微信一键登录”
    ↓
wx.login()
    ↓
获得临时 code
    ↓
POST /api/v1/auth/wechat-login
    ↓
后端调用 jscode2session
    ↓
取得 openid/unionid
```

后端接口实际位于：

```text
apps/qrcode/views.py -> wechat_login
```

### 3.2 已有平台账号

后端通过：

```text
appid + openid
```

查询 `WechatIdentity`。

如果找到绑定的用户，后端会：

1. 检查用户是否处于 active 状态。
2. 检查当前选择的角色是否已授权。
3. 生成 `access_token` 和 `refresh_token`。
4. 返回用户信息和当前角色。

前端保存登录态后，根据 `active_role` 进入对应页面。

### 3.3 没有平台账号

如果微信身份尚未绑定平台账号，后端返回：

```json
{
  "code": 1001,
  "data": {
    "bind_token": "..."
  }
}
```

前端跳转到：

```text
/pages/student/parent-bind?bindToken=...
```

绑定页要求用户：

1. 输入手机号。
2. 获取短信验证码。
3. 选择 student 或 parent 角色。
4. 调用 `/api/v1/auth/wechat-bind`。

所以当前小程序首次登录实际是：

```text
微信身份登录
    ↓
发现没有平台账号
    ↓
手机号 + 短信验证码绑定
    ↓
生成 JWT
    ↓
进入平台
```

### 3.4 当前是否满足“微信直接登录”

不完全满足。

当前小程序只通过 `wx.login` 获取微信身份，并没有在登录页直接使用 `getPhoneNumber` 获取微信手机号。新用户必须额外输入手机号和短信验证码。

### 3.5 小程序端需要补充的工作

如果要实现新用户微信手机号一键登录，需要增加以下流程：

```text
wx.login 获取 login_code
    ↓
用户点击 getPhoneNumber 按钮
    ↓
获得 phone_code
    ↓
后端验证 login_code 和 phone_code
    ↓
取得 openid 和微信手机号
    ↓
自动创建或查找 UserAccount
    ↓
赋予 student/parent 角色
    ↓
生成 JWT
```

前端需要增加类似以下能力：

```text
button open-type="getPhoneNumber"
@getphonenumber="..."
```

后端需要新增或扩展一个直接登录接口，接收：

```json
{
  "login_code": "小程序 wx.login 返回的 code",
  "phone_code": "getPhoneNumber 返回的 code",
  "role_type": "student"
}
```

后端不能相信前端直接提交的手机号，应使用微信服务端接口验证 `phone_code` 后取得手机号。

## 四、当前 H5 端的实现和不足

### 4.1 当前实际使用的流程

当前 H5 登录页使用的是：

```text
wechat-device/*
```

相关代码：

```text
uniapp/src/pages/login/index.vue
uniapp/src/api/wechat-device.ts
apps/accounts/views.py
apps/accounts/wechat_device.py
```

### 4.2 H5 创建登录会话

H5 调用：

```text
POST /api/v1/auth/wechat-device/session
```

请求参数：

```json
{
  "requested_role": "student"
}
```

后端创建约 300 秒有效的设备登录会话，并绑定当前浏览器 Session，返回：

```json
{
  "web_session_id": "...",
  "qrcode_url": "/api/v1/auth/wechat-device/qrcode?web_session_id=...",
  "expires_in": 300
}
```

### 4.3 H5 展示小程序二维码

H5 使用 `qrcode_url` 展示二维码。

后端生成的小程序码页面为：

```text
pages/auth/web-binding
```

二维码中的 `scene` 参数是一次性 `bridge_code`，只用于关联 H5 浏览器会话，不包含手机号、openid 或 JWT。

### 4.4 小程序扫码确认

用户使用微信扫码后进入：

```text
pages/auth/web-binding
```

小程序页面执行：

```text
读取 scene/bridge_code
    ↓
uni.login({ provider: 'weixin' })
    ↓
取得 login_code
    ↓
POST /api/v1/auth/wechat-device/scan
```

请求参数：

```json
{
  "bridge_code": "...",
  "login_code": "..."
}
```

后端通过 `login_code` 调用微信 `jscode2session`，取得小程序的 `appid/openid/unionid`。

### 4.5 新用户授权微信手机号

如果后端查不到对应的 `WechatIdentity`，会返回：

```json
{
  "status": "phone_authorization_required",
  "phone_binding_token": "..."
}
```

小程序随后显示 `getPhoneNumber` 授权按钮。

用户授权后，小程序获得 `phone_code`，调用：

```text
POST /api/v1/auth/wechat-device/phone
```

参数：

```json
{
  "phone_binding_token": "...",
  "phone_code": "..."
}
```

后端调用微信接口：

```text
https://api.weixin.qq.com/cgi-bin/token
https://api.weixin.qq.com/wxa/business/getuserphonenumber
```

换取微信平台确认过的手机号，然后：

1. 按手机号查找或创建用户。
2. 根据 `requested_role` 处理角色。
3. 将微信身份绑定到用户。
4. 将设备登录会话标记为 `login_confirmed`。
5. 生成一次性 `ticket`。

### 4.6 H5 完成登录

H5 每 3 秒调用：

```text
GET /api/v1/auth/wechat-device/status?web_session_id=...
```

当接口返回 `ticket` 后，H5 调用：

```text
POST /api/v1/auth/wechat-device/complete
```

参数：

```json
{
  "ticket": "...",
  "requested_role": "student"
}
```

后端校验浏览器、角色、用户状态和 ticket 后，签发标准 JWT。

H5 前端保存：

```text
accessToken
refreshToken
userInfo
```

然后根据角色进入平台页面。

### 4.7 H5 是否满足新用户直接登录

对于新学生和新家长，后端逻辑基本满足：

```text
新用户扫码
    ↓
授权微信手机号
    ↓
自动创建平台账号
    ↓
赋予 student/parent 角色
    ↓
H5 自动登录
```

但它不是严格意义上的“一键登录”，用户仍然需要：

1. 使用微信扫描二维码。
2. 在小程序中点击授权手机号。
3. 等待 H5 轮询完成。

另外，当前配置为 `trial`，因此还不能面向普通公众稳定使用。

## 五、角色自动赋予规则

### 5.1 新用户可自动创建的角色

当前后端允许新手机号自动创建：

```text
student
parent
```

对应逻辑位于：

```text
apps/accounts/services.py
```

### 5.2 新用户不能自动创建的角色

当前后端不允许新用户通过登录接口直接创建：

```text
teacher
admin
```

如果用户在登录页选择 teacher/admin，但手机号尚无对应角色授权，后端返回：

```text
ROLE_NOT_GRANTED
```

这是合理的权限控制。前端选择角色只能表达登录意图，不能直接授予高权限角色。

### 5.3 teacher/admin 的后续方案

如果业务要求教师或管理员也能首次微信登录，需要在登录之前完成一种授权：

- 管理员后台预创建账号并授予角色。
- 机构批量导入教师账号。
- 通过教师邀请码或机构邀请码创建角色授权。
- 通过后台审批后授予 teacher/admin 角色。
- 使用企业组织关系自动匹配角色。

## 六、标准微信网页 OAuth 流程的现状

后端还存在另一套标准网页 OAuth 实现：

```text
/api/v1/auth/wechat-web/*
```

其设计流程为：

```text
H5 创建网页 OAuth session
    ↓
跳转微信开放平台 qrconnect
    ↓
微信回调后端 callback
    ↓
后端用 code 换取网页 openid/unionid
    ↓
已绑定身份直接生成 ticket
未绑定身份继续绑定流程
    ↓
H5 使用 ticket 换 JWT
```

该流程需要单独配置：

```text
WECHAT_WEB_APP_ID
WECHAT_WEB_APP_SECRET
WECHAT_WEB_REDIRECT_URI
```

但当前情况是：

- 当前 H5 登录页实际调用的是 `wechat-device/*`。
- `wechatWebApi` 虽然存在，但当前登录页没有调用。
- 当前小程序确认页调用的是 `wechat-device/scan` 和 `wechat-device/phone`。
- `wechat-web/*` 不是当前 H5 登录页的实际主链路。

如果继续使用现有 H5 扫码方案，不需要优先切换到标准网页 OAuth。若要使用纯网页微信扫码登录，还需要另行完成网站应用审核、OAuth 前端接入、回调接入和首次用户注册规则。

网站应用微信登录属于微信开放平台的另一套能力，需要申请网站应用并配置授权回调域名。[微信开放平台网站应用微信登录文档](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)

## 七、现有条件下需要完成的工作

### 7.1 H5 面向普通用户上线前必须完成

1. 将微信小程序提交审核并发布正式版本。
2. 正式部署环境设置：

   ```text
   WECHAT_MP_ENV_VERSION=release
   ```

3. 确认正式版本包含 `pages/auth/web-binding`。
4. 确认小程序主体已完成认证，并具备微信手机号授权能力。
5. 配置并校验小程序服务器域名。
6. 确认 H5 和后端均使用 HTTPS。
7. 确认 H5 请求能够保留当前浏览器的 Django Session Cookie。
8. 确认 Redis/缓存正常工作。
9. 确认后端服务器能够访问微信接口。
10. 验证新学生、新家长、已有身份用户、角色不匹配用户和过期二维码场景。

### 7.2 小程序实现真正直登必须完成

1. 在小程序登录页增加微信手机号授权按钮。
2. 新增或扩展直接微信手机号登录接口。
3. 后端验证 `login_code` 和 `phone_code`。
4. 后端根据微信身份和手机号自动创建或查找用户。
5. 对新用户自动授予 student 或 parent 角色。
6. 返回标准 JWT 和用户信息。
7. 保留短信绑定作为备用方案，处理手机号授权失败或用户拒绝授权的情况。

### 7.3 teacher/admin 登录必须完成

1. 明确教师和管理员的创建来源。
2. 在登录前建立角色授权。
3. 后端继续禁止无授权用户通过前端参数直接创建高权限角色。
4. 增加角色冲突、机构归属和账号停用校验。

## 九、最终判断

### 对新学生、新家长

- H5：后端主要逻辑已经具备，但当前体验版配置不能作为正式公众入口；发布正式小程序并切换 `release` 后，再完成正式环境联调。
- 小程序：当前还需要从“微信身份登录 + 短信绑定”改为“微信身份 + 微信手机号授权”的直接登录流程。

### 对新教师、新管理员

### 对“是否需要发布正式小程序”的最终回答


## 十、分端实施方案：微信小程序端

### 10.1 小程序端目标

小程序端的目标是：平台没有账号时，用户点击微信登录并授权手机号后，系统自动创建平台账号、赋予允许的角色、保存 JWT，最后进入小程序首页，不再进入手机号验证码绑定页。

目标链路：

```text
用户点击微信登录
    ↓
wx.login 获取 login_code
    ↓
用户点击授权手机号
    ↓
getPhoneNumber 获取 phone_code
    ↓
后端向微信换取 openid/unionid 和手机号
    ↓
查找或创建 UserAccount
    ↓
绑定 WechatIdentity
    ↓
赋予 student/parent 角色
    ↓
生成 access_token/refresh_token
    ↓
前端保存登录态并进入小程序首页
```

### 10.2 小程序端前端功能步骤

#### 第一步：显示微信手机号登录按钮

登录页需要在 `MP-WEIXIN` 条件编译下显示微信登录按钮。按钮应由用户主动点击触发手机号授权：

```text
open-type="getPhoneNumber"
@getphonenumber="handleWechatPhoneLogin"
```

不能由页面加载或普通 JavaScript 调用直接触发手机号授权弹窗。

#### 第二步：获取小程序登录 code

在登录流程中调用：

```text
wx.login()
```

取得一次性 `login_code`。该 code 只传给自有后端，不应在前端直接调用微信服务端接口。

#### 第三步：获取微信手机号 code

用户点击授权按钮后，从事件中取得：

```text
event.detail.code
```

该值作为 `phone_code` 传给后端。前端不直接提交用户输入的手机号作为可信身份依据。

#### 第四步：调用直接登录接口

建议新增或扩展接口：

```text
POST /api/v1/auth/wechat-phone-login
```

请求参数：

```json
{
  "login_code": "wx.login 返回的 code",
  "phone_code": "getPhoneNumber 返回的 code",
  "role_type": "student"
}
```

`role_type` 可以来自登录页的角色选择，但它只能表达登录意图，不能绕过后端角色授权规则。

#### 第五步：处理登录结果

成功响应应包含：

```json
{
  "code": 0,
  "data": {
    "access_token": "...",
    "refresh_token": "...",
    "user": {
      "active_role": "student"
    }
  }
}
```

前端收到成功结果后：

1. 保存 `accessToken`。
2. 保存 `refreshToken`。
3. 保存 `userInfo`。
4. 更新用户 Store。
5. 根据 `active_role` 跳转到对应页面。

小程序学生端应进入：

```text
/pages/student/mp-home
```

用户拒绝手机号授权、微信接口失败或角色不允许时，应停留在微信登录页并显示明确错误，不应直接跳转到普通手机号登录页，除非用户主动选择备用登录方式。

### 10.3 小程序端后端功能步骤

#### 第一步：校验小程序登录 code

后端接收 `login_code`，使用服务端配置：

```text
WECHAT_MP_APPID
WECHAT_MP_APPSECRET
```

调用：

```text
https://api.weixin.qq.com/sns/jscode2session
```

取得：

```text
openid
unionid
```

#### 第二步：校验手机号 code

后端使用小程序 AppID/AppSecret 获取微信接口调用凭证，再调用：

```text
https://api.weixin.qq.com/wxa/business/getuserphonenumber
```

传递 `phone_code`，取得微信平台确认的手机号。

后端不得以浏览器或小程序提交的普通 `mobile` 字段作为唯一可信手机号。

#### 第三步：查找或创建用户

建议按以下顺序处理：

```text
先按 appid + openid 查询 WechatIdentity
    ↓
找到身份：取得绑定用户
    ↓
未找到身份：按可信手机号查询 UserAccount
    ↓
手机号也不存在：创建新 UserAccount
```

如果是新用户：

- `student`：创建用户并授予 student 角色。
- `parent`：创建用户并授予 parent 角色。
- `teacher`：没有预授权时拒绝创建。
- `admin`：没有预授权时拒绝创建。

#### 第四步：绑定微信身份

创建或更新：

```text
WechatIdentity
```

绑定字段包括：

```text
user
appid
openid
unionid
```

需要检查：

- 一个微信身份不能绑定多个平台用户。
- 一个用户不能重复绑定冲突的微信身份。
- unionid 存在时不能与已有记录冲突。
- 用户账号必须处于 active 状态。

#### 第五步：签发平台 JWT

角色校验通过后调用统一 Token 服务生成：

```text
access_token
refresh_token
```

JWT 中写入：

```text
active_role
```

前端依靠该字段决定进入学生、家长、教师或管理员页面。

### 10.4 小程序端需要保留的备用功能

微信手机号授权不是每次都能成功，因此建议保留：

```text
微信手机号授权登录失败
    ↓
提示用户重试
    ↓
用户仍拒绝授权
    ↓
可主动选择手机号 + 短信验证码登录
```

备用短信登录不能作为微信新用户的默认跳转结果，否则用户会误以为微信登录失败后必须再次注册。

## 十一、分端实施方案：H5 端

### 11.1 H5 端目标

H5 端的目标是：用户在 H5 页面选择角色后，使用微信扫描二维码，在小程序中确认身份并授权手机号，H5 自动完成登录并进入平台，不再回到手机号验证码登录页。

H5 端必须依赖微信小程序完成扫码确认，因为普通 H5 页面本身不能直接调用小程序的 `wx.login`。

目标链路：

```text
H5 选择角色
    ↓
创建 device session
    ↓
生成正式版小程序二维码
    ↓
微信扫码进入 pages/auth/web-binding
    ↓
小程序 wx.login 确认身份
    ↓
已绑定身份直接确认
新身份授权微信手机号
    ↓
后端创建或查找平台账号
    ↓
生成一次性 ticket
    ↓
H5 轮询状态取得 ticket
    ↓
H5 使用 ticket 换取 JWT
    ↓
保存登录态并进入页面
```

### 11.2 H5 端前端功能步骤

#### 第一步：选择登录角色

H5 登录页当前支持：

```text
student
teacher
parent
admin
```

角色通过 `requested_role` 传给后端。

对于没有平台账号的新用户，建议只允许或默认使用：

```text
student
parent
```

teacher/admin 应显示为需要预授权的角色。

#### 第二步：创建 H5 登录会话

调用：

```text
POST /api/v1/auth/wechat-device/session
```

请求：

```json
{
  "requested_role": "student"
}
```

前端保存返回的：

```text
web_session_id
qrcode_url
expires_in
```

#### 第三步：展示二维码并等待扫码

使用 `qrcode_url` 显示小程序码。

二维码打开页面必须是：

```text
pages/auth/web-binding
```

登录会话有效期约 300 秒，过期后前端应停止轮询并允许用户重新生成二维码。

#### 第四步：轮询登录状态

H5 每约 3 秒调用：

```text
GET /api/v1/auth/wechat-device/status?web_session_id=...
```

状态处理：

| 状态 | H5 页面处理 |
|---|---|
| `pending` | 提示用户使用微信扫码并在小程序中确认 |
| `phone_authorization_required` | 提示用户在小程序中授权手机号 |
| `login_confirmed` 且有 `ticket` | 停止轮询，调用完成登录接口 |
| 会话过期或错误 | 停止轮询，提示重新生成二维码 |

#### 第五步：使用 ticket 完成登录

收到 `ticket` 后调用：

```text
POST /api/v1/auth/wechat-device/complete
```

请求：

```json
{
  "ticket": "...",
  "requested_role": "student"
}
```

成功后必须执行：

```text
保存 access_token
保存 refresh_token
保存 userInfo
更新 Store
停止轮询
按 active_role 跳转页面
```

不能只更新页面状态而不保存 Token，否则页面跳转后会被鉴权逻辑重新送回登录页。

### 11.3 H5 端后端功能步骤

#### 第一步：创建浏览器绑定的 session

后端通过 Django Session 识别原始浏览器，并将以下信息写入缓存：

```text
requested_role
browser_session_id
status=pending
expires_at
```

后端不能只依赖前端提交的 `web_session_id` 判断浏览器身份。

#### 第二步：生成小程序二维码

后端生成一次性 `bridge_code`，再调用微信小程序码接口：

```text
page = pages/auth/web-binding
scene = bridge_code
env_version = release
```

正式环境下应使用：

```text
WECHAT_MP_ENV_VERSION=release
```

`pages/auth/web-binding` 必须已经存在于正式发布的小程序包中。

#### 第三步：接收小程序身份确认

小程序调用：

```text
POST /api/v1/auth/wechat-device/scan
```

后端完成：

```text
login_code
    ↓
jscode2session
    ↓
appid/openid/unionid
    ↓
查询 WechatIdentity
```

如果已绑定身份，则创建登录 ticket；如果未绑定，则返回 `phone_binding_token`。

#### 第四步：接收小程序手机号授权

小程序调用：

```text
POST /api/v1/auth/wechat-device/phone
```

后端使用微信手机号接口取得手机号，再调用可信手机号登录逻辑：

```text
login_with_trusted_mobile
```

该逻辑会：

- 新 student 用户自动创建并授予 student 角色。
- 新 parent 用户自动创建并授予 parent 角色。
- teacher/admin 无预授权时拒绝登录。
- 已存在用户时检查请求角色是否有有效授权。

#### 第五步：创建一次性 ticket

身份确认或手机号绑定成功后，后端创建 ticket，ticket 绑定：

```text
user_id
requested_role
browser_session_id
web_session_id
expires_at
```

ticket 只能由原始 H5 浏览器消费一次。

#### 第六步：完成 JWT 签发

H5 调用 `/auth/wechat-device/complete` 后，后端校验：

- ticket 是否有效。
- ticket 是否过期或已消费。
- 当前浏览器是否匹配。
- 请求角色是否匹配。
- 用户是否 active。
- 用户是否仍有该角色授权。

校验通过后签发标准 JWT。

### 11.4 H5 成功后仍回到手机号登录页的排查步骤

如果用户扫码并授权手机号后仍然回到手机号登录页，应按照以下顺序排查：

```text
1. /auth/wechat-device/scan 是否返回 code=0
2. /auth/wechat-device/phone 是否返回 login_confirmed
3. /auth/wechat-device/status 是否返回 ticket
4. /auth/wechat-device/complete 是否返回 code=0
5. complete 响应是否包含 access_token、refresh_token、user
6. 前端是否执行 persistSession
7. user.active_role 是否存在且合法
8. 浏览器 Django Session Cookie 是否保持
9. 后续请求是否因 401 清除了 accessToken
10. App.vue 是否因没有 token 或 userInfo 重新跳转登录页
```

重点代码：

```text
uniapp/src/pages/login/index.vue
uniapp/src/utils/request.ts
uniapp/src/App.vue
apps/accounts/views.py
apps/accounts/wechat_device.py
```

### 11.5 H5 端正式上线步骤

```text
1. 编译包含 pages/auth/web-binding 的 uni-app 小程序
2. 上传微信开发者工具
3. 提交微信审核
4. 审核通过后发布正式版
5. 设置 WECHAT_MP_ENV_VERSION=release
6. 部署/重启后端服务
7. 清理或等待旧 trial 二维码过期
8. 使用普通微信新用户扫码测试
9. 验证 student/parent 自动创建和进入平台
```

## 十二、分端验收清单

### 12.1 微信小程序端

- 新微信用户选择 student，授权手机号后自动创建学生账号并进入 `/pages/student/mp-home`。
- 新微信用户选择 parent，授权手机号后自动创建家长账号并进入家长页面。
- 已绑定微信用户可以直接登录，不再要求手机号绑定。
- 用户拒绝手机号授权时不会误跳转到手机号验证码登录页。
- 手机号授权接口失败时可以重新授权或选择备用登录。
- 选择 teacher/admin 且无预授权时正确返回 `ROLE_NOT_GRANTED`。
- 小程序刷新或重新打开后仍能根据本地 Token 进入平台。

### 12.2 H5 端

- 普通微信用户可以扫描正式版小程序二维码。
- 小程序可以打开 `pages/auth/web-binding`。
- 新学生扫码后可以授权手机号并自动进入 H5 学生页面。
- 新家长扫码后可以授权手机号并自动进入 H5 家长页面。
- 已绑定用户扫码后无需重复授权手机号。
- H5 成功换取 JWT 后刷新页面不会回到登录页。
- 二维码过期后可以重新生成。
- ticket 只能使用一次，不能被其他浏览器消费。
- 浏览器 Session 丢失时能显示明确错误并重新开始登录。

## 十三、最终实施判断

```text
只修改 trial 为 release：
    只能解决二维码打开体验版/正式版的问题，不能解决小程序首次登录仍要求短信绑定的问题。

小程序端真正直登：
    需要补充 wx.login + getPhoneNumber + 后端直接登录接口。

H5 端新用户登录：
    现有 device 流程已经具备主要后端能力，需发布正式小程序、切换 release、验证 Session/Token，并完成正式联调。

teacher/admin 新用户：
    仍需预授权、邀请码、机构导入或审批，不能仅由登录页角色选择自动授予。
```
