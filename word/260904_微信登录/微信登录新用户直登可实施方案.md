# 微信登录新用户直登可实施方案

> 整理日期：2026年9月4日  
> 适用范围：微信小程序端、H5 网页端、`apps` 后端  
> 目标：在平台尚无账号时，学生或家长通过微信身份和微信手机号授权自动创建平台账号，赋予允许的业务角色，签发 JWT 并进入平台。  
> 说明：本文是开发任务拆分和实施方案，不直接修改业务代码。

## 一、实施目标和范围

### 1.1 目标链路

微信小程序端：

```text
微信登录
    ↓
wx.login 获取 login_code
    ↓
用户授权手机号
    ↓
getPhoneNumber 获取 phone_code
    ↓
后端换取 openid/unionid 和手机号
    ↓
自动创建或查找平台账号
    ↓
赋予 student/parent 角色
    ↓
签发 JWT
    ↓
进入小程序首页
```

H5 端：

```text
H5 选择角色
    ↓
创建 device session
    ↓
展示正式版小程序二维码
    ↓
微信扫码进入 pages/auth/web-binding
    ↓
小程序 wx.login 确认身份
    ↓
新身份授权微信手机号
    ↓
后端创建或查找平台账号
    ↓
创建一次性 ticket
    ↓
H5 轮询并使用 ticket 换取 JWT
    ↓
进入 H5 平台
```

### 1.2 本方案包含的内容

- 微信小程序端首次用户直登。
- H5 端扫码和微信手机号授权登录。
- student/parent 新用户自动创建。
- 已绑定微信身份的快速登录。
- JWT 保存、角色路由和登录态恢复。
- teacher/admin 角色的预授权限制。
- 正式版小程序发布和生产验收。

### 1.3 本方案不包含的内容

- APP 端微信登录。APP 当前继续使用手机号验证码登录。
- 纯微信网页 OAuth 的完整重构。后端虽然存在 `wechat-web/*`，但当前 H5 主流程使用 `wechat-device/*`。
- 自动给无预授权用户创建 teacher/admin 角色。

## 二、任务总览

| 任务类别 | 主要目标 | 主要代码/配置位置 | 结果 |
|---|---|---|---|
| 前端开发任务 | 小程序直登、H5 扫码、Token 保存和页面跳转 | `uniapp/src` | 两端能正确发起并完成登录 |
| 后端接口任务 | 换取微信身份和手机号、创建账号、签发 JWT | `apps/accounts`、`apps/qrcode` | 返回统一登录结果 |
| 数据和角色规则任务 | 微信身份绑定、账号创建、角色授权和冲突处理 | `UserAccount`、`UserRole`、`WechatIdentity` | 账号与权限关系正确 |
| 微信平台配置任务 | AppID、AppSecret、域名、手机号授权和正式版 | 微信公众平台、微信开发者工具、服务器环境 | 普通微信用户可访问 |
| 测试验收任务 | 测试新用户、老用户、异常和正式发布 | `apps/*/tests`、真机和 H5 | 满足上线条件 |

## 三、前端开发任务

## 3.1 微信小程序端

### 3.1.1 登录按钮和授权交互

修改范围：

```text
uniapp/src/pages/login/index.vue
```

需要实现：

1. 在 `MP-WEIXIN` 条件编译下显示微信手机号登录按钮。
2. 使用用户主动点击触发：

   ```text
   open-type="getPhoneNumber"
   @getphonenumber="handleWechatPhoneLogin"
   ```

3. 点击流程中调用 `wx.login()` 获取 `login_code`。
4. 从 `event.detail.code` 获取 `phone_code`。
5. 将两个一次性 code 和当前角色传给后端。
6. 登录按钮增加 loading 状态，避免重复提交。
7. 用户拒绝手机号授权时停留在微信登录页并给出提示。

手机号授权必须由用户点击按钮触发，不能在页面加载时自动弹出授权窗口。

### 3.1.2 小程序 API 封装

修改范围：

```text
uniapp/src/api/wechat.ts
uniapp/src/api/index.ts
```

新增 API 封装，建议使用独立路径：

```text
POST /api/v1/auth/wechat-phone-login
```

建议保留现有 `/auth/wechat-login`，用于兼容原有 `wx.login + 短信绑定` 备用流程，避免直接改变既有接口行为。

### 3.1.3 登录成功后的处理

小程序收到成功响应后必须：

```text
保存 accessToken
保存 refreshToken
保存 userInfo
更新 userStore
按 active_role 跳转
```

学生端跳转：

```text
/pages/student/mp-home
```

家长端跳转：

```text
/pages/parent/layout
```

如果返回 `ROLE_NOT_GRANTED`、`PHONE_AUTHORIZATION_FAILED` 或账号停用，应显示错误信息，不要自动跳转普通手机号验证码登录页。

### 3.1.4 小程序端备用登录

保留现有以下入口：

```text
手机号 + 短信验证码登录
```

备用登录只应在以下情况下使用：

- 用户主动选择手机号登录。
- 用户拒绝微信手机号授权后选择备用方式。
- 微信授权服务暂时不可用。

微信直登失败不能默认把用户送入短信验证码页面，否则会造成“微信登录后又要求手机号登录”的体验。

## 3.2 H5 端

### 3.2.1 H5 登录入口

当前登录页已经包含 H5 微信扫码入口，主要代码为：

```text
uniapp/src/pages/login/index.vue
uniapp/src/api/wechat-device.ts
```

需要确认并完善：

1. 切换到微信扫码模式时创建 device session。
2. 正确显示 `qrcode_url`。
3. 保存当前 `web_session_id`。
4. 每约 3 秒轮询登录状态。
5. 取得 ticket 后停止轮询。
6. 调用完成登录接口。
7. 保存 JWT 和用户信息。
8. 按 `active_role` 跳转，不回到普通手机号登录页。

### 3.2.2 H5 创建会话

调用：

```text
POST /api/v1/auth/wechat-device/session
```

请求：

```json
{
  "requested_role": "student"
}
```

前端必须保存：

```text
web_session_id
qrcode_url
expires_in
```

### 3.2.3 H5 轮询状态

调用：

```text
GET /api/v1/auth/wechat-device/status?web_session_id=...
```

前端状态处理：

| 返回状态 | 前端行为 |
|---|---|
| `pending` | 提示使用微信扫码并在小程序中确认 |
| `phone_authorization_required` | 提示在小程序中授权手机号 |
| `login_confirmed` 且有 ticket | 停止轮询并完成登录 |
| 会话过期 | 停止轮询，允许重新生成二维码 |
| 请求失败 | 保留页面，显示重试提示，不清理已有正常登录态 |

### 3.2.4 H5 完成登录

调用：

```text
POST /api/v1/auth/wechat-device/complete
```

请求：

```json
{
  "ticket": "...",
  "requested_role": "student"
}
```

成功处理必须使用现有的 `persistSession` 或等价逻辑：

```text
accessToken = response.data.access_token
refreshToken = response.data.refresh_token
userInfo = response.data.user
```

然后跳转角色页面。

### 3.2.5 H5 防止再次进入手机号登录页

重点检查以下三个位置：

```text
uniapp/src/pages/login/index.vue
uniapp/src/utils/request.ts
uniapp/src/App.vue
```

必须保证：

1. `/complete` 成功后确实保存 `accessToken` 和 `userInfo`。
2. `userInfo.active_role` 存在且为合法角色。
3. 轮询完成后不再重复执行登录初始化。
4. H5 页面刷新时可以从本地存储恢复登录态。
5. 浏览器 Session Cookie 在创建、轮询和完成登录期间保持一致。
6. 只有真正收到 401 时才清理 token 并跳转登录页。
7. 普通网络错误不能直接清除正常 token。

## 四、后端接口开发任务

## 4.1 小程序直接微信手机号登录接口

### 4.1.1 接口定义

建议新增：

```text
POST /api/v1/auth/wechat-phone-login
```

建议代码位置：

```text
apps/accounts/serializers.py
apps/accounts/views.py
apps/accounts/urls.py
apps/accounts/wechat_device.py 或独立微信登录 service
```

请求参数：

```json
{
  "login_code": "wx.login 返回的一次性 code",
  "phone_code": "getPhoneNumber 返回的一次性 code",
  "role_type": "student"
}
```

字段要求：

- `login_code` 必填。
- `phone_code` 必填。
- `role_type` 必须是 `admin`、`teacher`、`parent`、`student` 之一。
- 后端不能接受前端直接提交的手机号作为可信身份依据。

### 4.1.2 后端处理步骤

```text
校验 login_code 和 phone_code
    ↓
调用 jscode2session
    ↓
取得 appid/openid/unionid
    ↓
调用 client_credential 获取微信 access_token
    ↓
调用 getuserphonenumber
    ↓
取得微信确认的手机号
    ↓
查询 WechatIdentity
    ↓
查询或创建 UserAccount
    ↓
校验并授予角色
    ↓
绑定 WechatIdentity
    ↓
生成 JWT
    ↓
返回统一登录响应
```

### 4.1.3 已绑定微信身份

如果 `appid + openid` 已经存在：

1. 取得已绑定用户。
2. 校验用户状态为 active。
3. 校验 `role_type` 是否有有效授权。
4. 校验 unionid 是否冲突。
5. 不重复创建用户或身份记录。
6. 生成 JWT。

### 4.1.4 未绑定微信身份

如果微信身份不存在：

1. 使用微信服务端换取的手机号查询 `UserAccount`。
2. 如果手机号不存在，按角色规则创建用户。
3. 如果手机号已存在，校验该用户是否允许使用所选角色。
4. 创建 `WechatIdentity`。
5. 生成 JWT。

### 4.1.5 统一成功响应

建议保持现有登录响应格式：

```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "access_token": "...",
    "refresh_token": "...",
    "user": {
      "id": "...",
      "roles": ["student"],
      "active_role": "student",
      "role_type": "student"
    }
  },
  "trace_id": "..."
}
```

### 4.1.6 错误响应

至少需要区分：

```text
INVALID_ROLE
WECHAT_LOGIN_AUTHORIZATION_FAILED
WECHAT_PHONE_AUTHORIZATION_FAILED
WECHAT_IDENTITY_CONFLICT
ROLE_NOT_GRANTED
ACCOUNT_INACTIVE
```

微信接口的具体错误信息应记录服务端日志，但不要把 AppSecret、微信 access_token 或完整敏感凭证返回给前端。

## 4.2 H5 设备登录接口核对和完善

H5 现有接口为：

```text
POST /api/v1/auth/wechat-device/session
GET  /api/v1/auth/wechat-device/qrcode
POST /api/v1/auth/wechat-device/scan
POST /api/v1/auth/wechat-device/phone
GET  /api/v1/auth/wechat-device/status
POST /api/v1/auth/wechat-device/complete
```

### 4.2.1 session

后端保存：

```text
requested_role
browser_session_id
status=pending
expires_at
```

登录会话建议保持现有约 300 秒有效期。

### 4.2.2 scan

`scan` 接口只负责：

```text
验证小程序 login_code
确认微信身份
返回 login_confirmed 或 phone_authorization_required
```

该接口不应直接签发 JWT，避免二维码被其他设备盗用后直接获得平台登录凭证。

### 4.2.3 phone

`phone` 接口负责：

```text
验证 phone_code
取得微信手机号
创建/查找平台用户
绑定 WechatIdentity
创建 ticket
```

该接口不能接受浏览器传入的普通手机号作为可信手机号。

### 4.2.4 status 和 complete

`status` 只向原始浏览器返回：

```text
status
bound
ticket
```

`complete` 负责：

1. 校验浏览器 Session。
2. 校验请求角色。
3. 校验 ticket 有效期和一次性使用状态。
4. 校验用户当前角色授权。
5. 生成标准 JWT。

## 五、数据和角色规则任务

## 5.1 数据模型确认

现有模型：

```text
UserAccount
UserRole
WechatIdentity
WechatWebIdentity
```

小程序身份使用：

```text
WechatIdentity(appid, openid, unionid, user)
```

当前设计中：

- `appid + openid` 唯一。
- 一个 `UserAccount` 对应一个 `WechatIdentity`。
- 微信身份绑定关系不应因为重复登录而重复创建。
- 微信临时 code、bridge、phone token、ticket 保存在缓存，不写入业务数据库。

本次直登如果继续使用现有字段，原则上不需要新增数据库表；开发前仍需确认生产数据库已执行相关迁移。

### 5.2 新用户角色规则

建议固定为：

| 用户情况 | 角色处理 |
|---|---|
| 新用户选择 student | 自动创建用户并授予 student |
| 新用户选择 parent | 自动创建用户并授予 parent |
| 新用户选择 teacher | 无预授权则拒绝 |
| 新用户选择 admin | 无预授权则拒绝 |
| 已有用户选择已授权角色 | 允许登录 |
| 已有用户选择未授权角色 | 返回 `ROLE_NOT_GRANTED` |
| 已停用用户 | 返回 `ACCOUNT_INACTIVE` |

### 5.3 角色来源

teacher/admin 需要确定以下一种或多种授权来源：

- 管理员后台预创建。
- 机构批量导入。
- 教师邀请码。
- 机构身份匹配。
- 管理员审批。

前端的 `role_type` 或 `requested_role` 只能表示用户想以哪个角色登录，不能直接改变 `UserRole`。

### 5.4 账号和微信身份冲突

需要处理：

1. 微信身份已经绑定其他用户。
2. 手机号已经绑定其他用户。
3. 一个用户已经绑定其他小程序微信身份。
4. unionid 与历史记录不一致。
5. 用户角色已被撤销。
6. 多次并发登录导致重复创建。

账号查找、角色授予和微信身份绑定应放在事务中，并使用现有唯一约束和必要的行锁避免重复绑定。

## 六、微信平台配置任务

## 6.1 小程序基础配置

确认以下配置：

```text
uniapp/src/manifest.json
    mp-weixin.appid

后端环境变量：
    WECHAT_MP_APPID
    WECHAT_MP_APPSECRET
```

两处 AppID 必须一致，AppSecret 只能配置在后端环境中。

## 6.2 手机号授权能力

确认小程序主体和认证状态满足微信手机号授权能力要求，并在真机中验证 `getPhoneNumber` 能够返回一次性 code。

需要注意：手机号授权不是普通网页表单，也不是短信验证码。用户需要点击微信授权按钮，后端再用一次性 `phone_code` 向微信换取手机号。

## 6.3 服务器域名和 HTTPS

确认：

- 小程序 request 合法域名已配置。
- H5 访问地址使用 HTTPS。
- 后端 API 使用 HTTPS。
- 生产域名与微信平台配置一致。
- H5 请求期间 Django Session Cookie 不丢失。
- 后端可以访问微信接口。

## 6.4 小程序版本环境

开发测试阶段可以使用：

```text
WECHAT_MP_ENV_VERSION=develop 或 trial
```

正式环境必须：

```text
WECHAT_MP_ENV_VERSION=release
```

配置切换为 `release` 只改变二维码指向的版本，不会自动补充小程序直登接口，也不会改变角色创建规则。

## 6.5 正式发布流程

```text
uni-app 编译微信小程序
    ↓
微信开发者工具上传
    ↓
确认 pages/auth/web-binding 存在
    ↓
提交审核
    ↓
审核通过并发布正式版
    ↓
生产后端设置 WECHAT_MP_ENV_VERSION=release
    ↓
重新部署/重启后端
    ↓
普通微信用户扫码验证
```

## 6.6 标准网页 OAuth 配置说明

如果继续使用当前 H5 设备扫码方案，主要依赖小程序 AppID/AppSecret，不需要优先接入标准网页 OAuth。

如果以后切换 `wechat-web/*`，还需要单独完成：

- 微信开放平台网站应用审核。
- 网站应用 AppID/AppSecret。
- 授权回调域名。
- 前端 OAuth 跳转和回调处理。
- 网页身份与平台账号绑定。

## 七、测试和验收任务

## 7.1 后端单元测试

需要覆盖：

- `login_code` 为空或失效。
- `phone_code` 为空或失效。
- 微信 `jscode2session` 返回错误。
- 微信手机号接口返回错误。
- 已绑定微信身份登录。
- 新手机号创建 student。
- 新手机号创建 parent。
- 新用户申请 teacher/admin 被拒绝。
- 已有用户角色未授权。
- 用户已停用。
- 微信身份冲突。
- 手机号冲突。
- unionid 冲突。
- 并发登录不重复创建身份。
- ticket 重复消费失败。
- 非原始浏览器消费 ticket 失败。

## 7.2 小程序端真机测试

### 新用户

- 新用户选择 student，授权手机号后直接进入学生首页。
- 新用户选择 parent，授权手机号后直接进入家长页面。
- 数据库生成一条 `UserAccount` 和一条 `WechatIdentity`。
- 用户获得正确的 `UserRole`。

### 已有用户

- 已绑定身份再次登录不重复注册。
- 已有多个角色时可以按授权角色进入对应页面。
- 角色已撤销时不能继续进入该角色页面。

### 异常

- 用户拒绝手机号授权。
- 用户取消登录。
- 网络异常。
- 微信接口异常。
- AppSecret 错误。
- 用户选择未授权角色。

## 7.3 H5 端联调测试

- 创建 session 成功。
- 二维码能打开正式版 `pages/auth/web-binding`。
- 小程序扫码后状态变为 `pending` 或 `phone_authorization_required`。
- 新用户授权手机号后状态变为 `login_confirmed`。
- H5 能取得 ticket。
- H5 能调用 complete 获取 JWT。
- H5 成功后进入正确角色页面。
- 刷新 H5 页面不会立即回到登录页。
- 二维码过期后可以重新生成。
- ticket 只能消费一次。
- 其他浏览器不能消费原始浏览器的 ticket。

## 7.4 生产验收

必须使用非项目成员、非体验成员的普通微信账号测试：

```text
普通微信用户
    ↓
访问正式 H5
    ↓
扫描二维码
    ↓
打开正式版小程序
    ↓
授权手机号
    ↓
创建 student/parent 账号
    ↓
H5 自动进入平台
```

## 十、最终建议

建议优先完成 H5 现有 device 流程的正式环境验证，再开发小程序端直接手机号授权登录。

原因是：

1. H5 设备登录后端逻辑已经比较完整。
2. H5 可以先验证新用户自动创建和角色赋予规则。
3. 小程序端直登需要新增前后端接口，变更范围更大。
4. 两端最终都可以复用微信身份、可信手机号、账号创建和 JWT 服务。

最终推荐架构：

```text
微信小程序：
wx.login + getPhoneNumber
    → 直接登录并创建 student/parent

H5：
小程序二维码 + 扫码确认 + getPhoneNumber
    → H5 轮询 ticket 并完成登录

APP：
手机号 + 短信验证码
```
## 十一、方案审查结果与阶段完成验证

## 11.1 审查结论

经过对照当前 uni-app 前端、`apps` 后端、路由、环境配置和现有测试，方案的总体方向正确，可以作为开发依据，但需要明确以下事实：

1. `WECHAT_MP_ENV_VERSION=trial` 改为 `release` 只改变 H5 二维码打开的小程序版本，不会自动实现小程序端新用户直登。
2. `/api/v1/auth/wechat-phone-login` 是本方案建议新增的接口，当前代码中尚不存在，必须完成前后端开发后才能使用。
3. 当前 H5 登录页实际使用 `wechat-device/*`，不是 `wechat-web/*`。实施时不要同时改动两套流程，避免登录状态和回调链路混用。
4. 当前 H5 设备登录后端已具备新 student/parent 用户的主要创建能力，但正式使用前仍需要正式版小程序、`release` 配置、Session Cookie、缓存和微信接口联调。
5. 当前 `WechatIdentity`、`UserRole`、JWT 和普通请求鉴权是多端共用能力。新增微信直登时应复用这些服务，避免另建一套用户或 Token 体系。

## 11.2 对其他功能的影响和控制要求

### 不应影响的功能

以下现有功能不应因为新增微信直登而改变：

- 手机号 + 短信验证码登录 `/api/v1/auth/login`。
- 已有小程序微信登录 `/api/v1/auth/wechat-login` 的兼容流程。
- 已绑定微信身份用户的登录。
- `UserRole` 的撤销和角色校验。
- JWT 自动携带、刷新和 401 重新登录逻辑。
- 学生、家长、教师和管理员已有业务页面及权限。

### 必须控制的影响

1. 新增接口优先使用独立路径，不直接破坏现有 `/auth/wechat-login` 请求格式。
2. 新用户只允许按规则自动创建 student/parent，不能通过前端角色参数直接获得 teacher/admin。
3. 微信身份绑定、手机号查找、角色授予和 Token 签发应在事务中完成。
4. 微信临时 code、手机号 code、bridge、phone token 和 ticket 不能写入前端本地存储或业务日志。
5. H5 登录失败时不能无条件清理已有正常 Token；只有确认 401 或登录态失效时才跳转普通登录页。
6. H5 device session 和标准网页 OAuth session 不得交叉使用。
7. 当前 H5 的手机号授权确认复选框只是前端交互提示，真正的手机号可信来源必须是微信 `getPhoneNumber` 返回的 `phone_code`。
