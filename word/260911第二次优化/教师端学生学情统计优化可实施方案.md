# 教师端学生学情统计优化可实施方案

## 1. 方案说明

### 1.1 需求来源

教师端学情统计需要从“班级/作业整体统计”进一步下钻到“单个学生”，支持：

1. 查看某个学生的作业学习情况；
2. 查看该学生的历史作答记录，而不是只看当前一次结果；
3. 根据学生历次作答和题目关联知识点，形成该学生的知识掌握图谱。

本方案基于当前项目的 Django + Django REST Framework 后端、uni-app/Vue 前端和现有统计页面整理，只做满足上述需求所必需的功能，不引入新的统计平台、AI 生成能力或复杂图谱组件。

### 1.2 实施边界

本次只面向教师端：

- 教师从已有“学情统计”页面进入学生详情；
- 教师只能查看自己管理的班级及班级内学生；
- 学生端、家长端已有的知识掌握接口和页面保持不变；
- 不增加教师修改学生成绩、修改掌握度、删除作答记录等操作；
- 不做班级排名、预测成绩、AI 学情报告、复杂关系网络图和导出报表。

### 1.3 本次执行前已固化的业务口径

为避免开发过程中出现不同理解，本次按以下口径执行：

- 作业历史按 `mission_id + question_id` 区分，同一道题出现在不同作业中视为不同作业记录；
- 同一作业同一道题的当前状态取最后一次非草稿有效作答；
- 知识图谱的当前掌握度按学生维度，对同一 `question_id` 的全部作业作答取最后一次有效客观判定；
- 知识图谱的练习次数保留所有非草稿有效作答次数；
- 主观题待批改计入作答和待批改数量，不计入正确率分母；
- 首期知识图谱只展示学生实际作答过且能识别到的知识点，未练习知识点不展开为 0 值节点；
- 普通作业已有历史数据不强制补建题目快照，普通作业历史题目内容无发布快照时回退当前题目内容；
- 新增功能只查看当前仍属于该班级的 active 学生，暂不开放已退出学生的历史查看。

## 2. 当前代码与需求对应关系

| 当前能力 | 代码位置 | 对本次优化的作用 |
|---|---|---|
| 班级学情总览 | `uniapp/src/pages/teacher/learning-stats.vue` | 作为学生详情入口，当前已有学生汇总表 |
| 作业级学生×题目矩阵 | `uniapp/src/pages/teacher/mission-learning-stats.vue` | 可继续查看某份作业的答题矩阵和学生答案 |
| 班级统计接口 | `apps/institutions/class_views.py`、`apps/institutions/learning_stats_service.py` | 复用班级、作业、学生范围和统计口径 |
| 作业统计接口 | `apps/missions/learning_stats_views.py` | 复用题目顺序、题目快照、最新作答判定逻辑 |
| 作答记录 | `apps/study/models.py` 的 `AnswerAttempt` | 已保存多次作答、作答时间、答案、得分和判定结果，可支撑历史记录 |
| 题目知识点 | `apps/parser/models.py` 的 `ExamQuestion.knowledge_points` | 作为学生知识图谱的统计来源 |
| 知识点层级 | `apps/knowledge/models.py` 的 `KnowledgePoint` | 形成“学科—学段—年级—知识点”的树形展示 |
| 学生知识掌握接口 | `apps/study/knowledge_views.py` | 仅供学生/家长上下文使用，不直接开放给教师，避免权限边界混乱 |

当前存在的主要缺口：

1. 班级统计页在每个作业卡片下的学生完成情况行只有聚合数字，没有进入学生详情的操作；
2. 作业矩阵接口按“学生+作业+题目”只保留最新一次非草稿作答，无法查看历次提交；
3. 学生知识掌握接口的权限是学生/家长上下文，教师不能直接传入学生 ID 查看；
4. 现有知识掌握数据主要是列表，虽已返回 `tree`，教师端尚无针对某一学生的树形掌握展示。

## 3. 目标使用流程

```text
教师端学情统计
  → 选择班级
  → 学生完成情况表点击学生姓名/“查看详情”
  → 学生学情详情
      ├─ 学习概览：当前作业数、作答题数、当前正确率、待批改数
      ├─ 历史记录：按作业查看历次作答及每题结果
      └─ 知识图谱：按知识树查看练习次数、正确率和掌握状态
```

从作业级页面进入时，可在 `mission-learning-stats.vue` 的学生姓名处增加同一详情页入口，并带上 `classId`、`studentId` 和 `missionId`，详情页默认定位到该作业。该入口属于便捷入口，不改变当前矩阵点击单元格的行为。

## 4. 页面设计

### 4.1 新增教师端学生详情页

新增文件：

`uniapp/src/pages/teacher/student-learning-stats.vue`

在 `uniapp/src/pages.json` 增加页面路由：

```text
pages/teacher/student-learning-stats
```

页面分为三个简单区域，不依赖 ECharts 或第三方图谱库。

#### A. 页面头部

显示：

- 返回“学情统计”；
- 班级名称；
- 学生姓名；
- 可选的返回作业提示（从作业页进入时显示）。

#### B. 学习概览

显示以下已有数据可直接计算的指标：

| 指标 | 口径 |
|---|---|
| 历史作业数 | 学生在该班级实际被布置且属于教师权限范围的作业数 |
| 已作答题数 | 所有非草稿作答中，按 `mission_id + question_id` 去重后的作业题目数 |
| 作答次数 | 所有非草稿 `AnswerAttempt` 数量 |
| 当前正确率 | 每个 `mission_id + question_id` 最后一次有效作答的正确数 / 最后一次有效客观作答数 |
| 待批改数 | 最后一次有效作答中 `is_subjective_pending=true` 的数量 |
| 最近学习时间 | 最近一次非草稿作答的 `submitted_at` |

主观题待批改不计入正确率分母，但计入作答次数和待批改数，沿用现有学情统计口径。

#### C. 两个 Tab

##### Tab 1：历史记录

默认按作业倒序展示，每条记录显示：

- 作业名称、作业编号、作业时间；
- 题目数、已作答数；
- 最后一次作答的正确数、错误数、待批改数；
- 当前正确率、完成状态；
- 最近一次作答时间。

点击作业记录后展开题目明细，按该作业题目序号显示：

- 第几题、题目简要内容；
- 学生最后一次答案；
- 最后一次判定：正确、错误、待批改、未作答；
- 得分和最近提交时间；
- 如存在多次作答，显示“查看历次作答”，展开该题所有非草稿记录，按时间倒序显示 `attempt_no`、答案、判定、得分和提交时间。

移动端使用卡片和折叠展示，桌面端可以使用横向滚动表格，保持当前 uni-app 的响应式写法。

##### Tab 2：知识图谱

采用现有知识树的层级展示，不做力导向关系图：

```text
学科
  └─ 学段
      └─ 年级
          └─ 知识点
```

知识点节点显示：

- 知识点名称；
- 练习次数：该学生对关联题目的有效作答次数；
- 正确率：该知识点下客观题有效作答的正确率；
- 掌握状态：已掌握、巩固中、薄弱；
- 最近练习时间。

使用颜色区分状态：绿色表示已掌握，橙色表示巩固中，红色表示薄弱，灰色表示无有效客观题判定。节点点击后只展示该知识点对应的历史题目记录，不增加新的练习或推荐操作。

掌握状态沿用现有阈值：正确率 `>=85%` 为已掌握，`60%~84.99%` 为巩固中，低于 `60%` 为薄弱。没有有效客观题作答时不直接判定为薄弱。

### 4.2 现有页面改动

#### `learning-stats.vue`

在每个作业卡片下的“学生完成情况”表中：

- 学生姓名改为可点击文本，或增加“查看详情”按钮；
- 跳转携带 `classId` 和 `studentId`；
- 保留当前作业展开、完成率、正确率等内容不变；
- 班级切换后，学生详情入口自动使用当前班级 ID。
- 入口不新增班级级别的第二张学生表，避免重复展示和重复请求。

#### `mission-learning-stats.vue`

仅增加学生姓名点击入口：

- 只有页面已携带 `classId` 时才显示学生详情入口，并携带当前班级；
- 页面没有 `classId` 时不显示该入口，避免无法确定教师要查看的班级；教师可返回班级学情统计页选择班级后进入；
- 可携带 `missionId` 作为详情页默认展开的作业；
- 当前矩阵的“点击单元格查看答案”逻辑不改。

## 5. 后端实施方案

### 5.1 新增教师学生详情接口

建议使用班级作为权限边界，新增：

```text
GET /api/v1/classes/{class_id}/students/{student_id}/learning-stats
```

可选查询参数：

```text
mission_id   默认空；传入后详情页默认展开该作业
page         历史作业分页，默认 1
page_size    默认 20，最大 50
```

首期不增加复杂日期筛选和多维筛选，避免把页面做成通用报表平台。后续如果数据量明显增长，再增加时间范围参数。

接口统一返回当前项目格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "class": {"id": "", "name": ""},
    "student": {"id": "", "name": "", "mobile": ""},
    "summary": {
      "mission_count": 0,
      "answered_question_count": 0,
      "attempt_count": 0,
      "correct_count": 0,
      "wrong_count": 0,
      "pending_count": 0,
      "accuracy": 0,
      "last_submitted_at": ""
    },
    "missions": [
      {
        "mission_id": "",
        "mission_name": "",
        "created_at": "",
        "status": "",
        "question_count": 0,
        "answered_count": 0,
        "correct_count": 0,
        "wrong_count": 0,
        "pending_count": 0,
        "accuracy": 0,
        "last_submitted_at": "",
        "questions": [
          {
            "question_id": "",
            "display_no": 1,
            "question_no": "",
            "stem": "",
            "question_type": "",
            "question_missing": false,
            "status": "unanswered",
            "answer_text": "未作答",
            "score": null,
            "last_submitted_at": "",
            "latest_attempt": {},
            "attempt_history": []
          }
        ]
      }
    ],
    "knowledge_graph": {
      "metric_version": "latest_question_attempt_v1",
      "items": [],
      "tree": []
    }
  },
  "meta": {"page": 1, "page_size": 20, "total": 0},
  "trace_id": ""
}
```

返回结构执行要求：

- `missions` 只返回当前分页的历史作业；
- `knowledge_graph` 必须基于该班级范围内学生的全部有效作答聚合，不受 `page/page_size` 影响；
- `mission_id` 如果不在当前分页内，后端必须将该作业插入本次返回或返回明确的 `selected_mission` 数据，不能让前端出现“传入作业但无法展开”的情况；
- `latest_attempt` 返回当前题目状态所依据的最后一次有效作答；
- `attempt_history` 返回该作业该题的全部非草稿有效作答，按 `submitted_at` 倒序；
- 无作答时 `latest_attempt` 为空对象，`attempt_history` 为空数组，题目状态为 `unanswered`。

### 5.2 权限校验顺序

后端必须按以下顺序处理，不能仅凭前端传入的两个 ID 查询：

1. 使用现有 `IsAuthenticated` 和教师角色权限；
2. 使用 `class_views.py` 中的 `_check_teacher_of_class`，确认教师管理该班级；
3. 查询 `ClassStudent(class_obj=class_id, student=student_id, status='active')`，确认学生当前属于该班级；
4. 只取该班级实际发布给该学生的作业；
5. 查询该教师可见作业关联的题目和作答记录；
6. 任何一步不满足时返回 403 或 404，不返回其他班级和学生的数据。

教师不能通过调用学生端 `/student/knowledge-mastery` 并传入学生 ID 绕过权限；教师详情接口应单独使用教师权限和班级成员关系。

### 5.3 统计服务改造位置

在现有 `apps/institutions/learning_stats_service.py` 中新增一个面向单学生的构建函数，例如：

```text
build_student_learning_stats(class_obj, student, mission_id='', page=1, page_size=20)
```

该函数复用现有：

- `_load_question_rows`：取得作业题目 ID、稳定题号和学生目标范围；详情组装时仍需保留对应 `MissionQuestionRel` 与 `ExamQuestion` 对象，不能只使用该函数已经裁剪后的统计字段；
- `_mission_student_ids`：处理作业目标学生范围；
- `ordered_mission_question_rels`：保证题目顺序统一；
- `snapshot_payload`：复用题目展示字段和题号顺序；
- `apply_snapshot_to_question`：读取快照中的知识点和题目字段；`snapshot_payload` 当前只用于展示字段，不能直接用它读取知识点。

不在页面中拼接 SQL，也不复制一套新的作业统计算法。

作业筛选必须单独处理两类数据：

- 兼容 `LearningMission.class_obj` 的旧作业；
- 通过 `MissionClassAssignment` 发布的新作业。

两类数据合并后按 `mission_id` 去重，只保留状态为 `published`、`running` 或 `closed` 的作业，排除草稿。学生必须同时满足班级成员和作业目标学生范围。

### 5.4 历史作答处理规则

查询 `AnswerAttempt` 时：

- 过滤目标学生和目标作业；
- 排除 `submit_source='draft'`；
- 按 `mission_id、question_id、submitted_at、attempt_no、id` 排序，其中 `id` 作为相同时间和次数时的稳定兜底排序字段；
- 同一作业同一题保留全部有效记录用于历史查看；
- 另取同一作业同一题最后一次有效记录用于当前状态、当前正确率和知识点掌握状态；
- `is_subjective_pending=true` 的记录展示为待批改，不计入正确率；
- 未有记录的题目展示为未作答；
- 作业题目以 `MissionQuestionRel` 的发布范围为准，不把学生未被布置的个性化题目误算为未作答。

历史和当前统计的键必须明确区分：

```text
作业历史记录：mission_id + question_id + attempt_id
当前作答状态：mission_id + question_id 的最后一次有效作答
知识图谱掌握度：student_id + question_id 的最后一次有效客观判定
latest_attempt：当前作业题目状态使用的最后一次有效作答
attempt_history：当前作业题目的全部有效作答，按时间倒序
```

这样既满足“当前学情”展示，也保留学生从错误到正确的变化过程。

`latest_attempt` 和 `attempt_history` 中每条作答记录固定包含：

```text
attempt_id、attempt_no、answer_text、answer_content、is_correct、
is_subjective_pending、score、submitted_at
```

其中 `answer_text` 用于直接展示，`answer_content` 保留图片答案或结构化答案所需的原始内容；不返回不属于该教师权限范围的作答数据。

历史题目内容读取规则必须明确：

1. `MissionQuestionRel.question_snapshot` 存在对应字段时，优先使用快照；
2. 快照不存在或字段缺失时，使用当前 `ExamQuestion` 字段；
3. 若题目已经不存在，仍返回作答记录，题目显示 `question_missing=true` 和“题目已删除”，不能因题目缺失导致整份历史接口失败；
4. 本次不对旧普通作业批量补建快照。

### 5.5 知识图谱聚合规则

知识图谱不新增数据库表，直接使用题目已有知识点关联和作答数据：

1. 取学生实际作答过且属于当前班级作业范围的题目；
2. 从 `MissionQuestionRel.question_snapshot['knowledge_points']` 读取知识点；若不存在，再回退到当前题目的 `ExamQuestion.knowledge_points`；`snapshot_payload()` 当前不会自动返回该字段，不能直接依赖其结果获取知识点；
3. 题目关联多个知识点时，对每个知识点各计一次练习次数；
4. 知识点标识优先使用 `id`；没有 ID 时使用“规范化学科+学段+年级+章节+module”组合键，避免只用 `module` 导致重名知识点串数据；
5. 练习次数统计所有非草稿有效作答；
6. 正确率只统计非主观待批改记录；
7. 当前掌握状态基于每个知识点下各题最后一次有效客观作答；
8. `last_practiced_at` 取该知识点最近一次有效作答时间；
9. 使用 `KnowledgePoint` 的既有 `subject、stage、grade_index、chapter、module` 组织数据，但首期展示树固定为“学科—学段—年级—知识点”，`chapter` 只作为知识点唯一键和节点辅助信息，不增加单独章节层；
10. `ExamQuestion.subject` 使用 `M/P` 等旧编码时，先通过现有 `normalize_subject_code` 统一为 `math/physics` 再匹配 `KnowledgePoint`；
11. 查不到知识点基础信息时，保留“未归类知识点”节点，节点指标可以正常返回，不能让整份学生统计失败；
12. 没有知识点的题目不生成普通知识点节点，只在作业历史中保留题目作答记录；若业务需要显示覆盖情况，再统一归入“未归类知识点”，本期按“不生成”执行。

知识图谱返回建议：

```json
{
  "metric_version": "latest_attempt_v1",
  "tree": [
    {
      "id": "subject:math",
      "name": "数学",
      "type": "subject",
      "children": [
        {
          "id": "stage:junior",
          "name": "初中",
          "type": "stage",
          "children": [
            {
              "id": "grade:junior:8",
              "name": "八年级",
              "type": "grade",
              "children": [
                {
                  "id": "kp:123",
                  "name": "一次函数",
                  "type": "knowledge",
                  "attempt": 8,
                  "correct": 6,
                  "accuracy": 75,
                  "mastery": "reviewing",
                  "last_practiced_at": ""
                }
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

同时返回扁平 `items`，便于移动端列表展示；树形和列表使用同一份聚合结果，避免前后端出现两套口径。树形只包含实际作答过的知识点，不补全未练习节点。

### 5.6 数据库与迁移

本需求不需要新增业务表：

- `AnswerAttempt` 已保存历史作答；
- `LearningMission`、`MissionClassAssignment`、`MissionQuestionRel` 已保存作业和发布范围；
- `KnowledgePoint` 已映射现有 `knowledge_points` 表，并且是 `managed=False`，不应在本次新增迁移中重建；
- 部分讲义作业和错题练习已有题目快照，可优先支持历史题目展示；普通作业无快照时按本方案回退当前题目内容。

如果线上历史记录量较大，建议在 `AnswerAttempt` 上增加两条轻量迁移索引：

```text
(student_user_id, submitted_at)
(mission_id, student_user_id, question_id, submitted_at)
```

索引只用于提升查询，不改变现有数据结构和统计结果。开发初期数据量不大时可以先不加，先通过接口测试确认查询耗时；若增加索引，必须先执行迁移检查，不直接修改生产表结构。

## 6. 前端接口封装

在 `uniapp/src/api/institutions.ts` 的 `classApi` 中增加：

```text
studentLearningStats(classId, studentId, params?)
```

对应调用：

```text
GET /classes/{classId}/students/{studentId}/learning-stats
```

新增页面只调用该封装，不在页面中直接使用 `fetch`。类型可以先使用与当前页面一致的局部接口类型，待接口稳定后再抽取公共类型，避免一次性重构现有 API 类型。

页面加载策略：

1. 首次加载请求学生概览、历史作业和知识树；
2. 点击历史作业时只在前端展开已返回的题目数据；
3. 如果后续单个学生作答量过大，再把题目历次作答改为按作业懒加载，不改变首期接口路径；
4. 加载失败、学生已退出班级、无历史作答时分别显示明确空状态。

## 8. 测试与验收标准

### 8.1 后端接口

- 教师访问自己管理班级内学生，返回 200；
- 教师访问非自己管理班级，返回 403；
- 教师访问不属于该班级的学生，返回 403 或 404，且无数据泄露；
- 同一题有两次作答时，历史记录返回两条，当前状态使用最新一条；
- 草稿记录不进入历史和统计；
- 主观待批改作答计入待批改数，不计入正确率分母；
- 未作答题目能展示为未作答，不被误判为错误；
- 多班级作业只统计该学生在当前班级被布置的范围；
- 知识点树返回稳定层级，知识点指标与扁平列表一致；
- 题目没有知识点时接口仍正常返回，作业历史保留该题，但不生成知识点节点。

### 8.2 前端页面

- 班级学情统计页能进入指定学生详情；
- 从作业矩阵进入时能定位到对应学生和作业；
- 历史记录可展开作业和题目；
- 历次答案、判定、得分、提交时间展示准确；
- 知识图谱能按学科、学段、年级、知识点展开；
- 掌握状态颜色和文字对应正确率阈值；
- 无数据、加载中、接口失败、无权限均有明确提示；
- 手机宽度下不出现关键内容被截断，长题目可换行或在自身区域滚动；
- 原有班级学情、作业学情矩阵、学生端知识掌握页面无回归问题。

## 9. 本次明确不开发的内容

- AI 自动生成学生画像或学习建议；

- 班级排名、学生横向对比和成绩预测；
- 新增复杂图数据库或知识点关系网络；

- PDF/Excel 学情报告导出；
- 统计快照、Celery 异步计算和独立 analytics 应用。

首期采用实时聚合，待实际数据量导致接口响应变慢后，再单独评估缓存或快照，不在本需求中提前引入。
