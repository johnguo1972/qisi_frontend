# 家长只读权限隔离与任务详情优化实施方案

## 一、文档说明

### 1.1 文档目的

本方案针对当前家长端存在的两个发布前高风险问题制定可实施的整改方案：

1. 家长角色使用学生上下文后，仍可能调用学生答题写接口；
2. 家长首页点击任务后跳转学生任务页，并可以继续进入学生答题页面。

本方案的目标是使平台形成清晰的角色边界：

```text
学生角色：可以查看任务、开始答题、提交答案、重做错题、使用 AI 辅导
家长角色：只能查看已绑定学生的学习数据，不能产生或修改学生学习行为
```

本文是后续开发、测试、部署和验收的执行依据。本次整理文档不修改业务代码、不修改数据库、不修改 `.env`、不提交 Git，也不部署服务器。

### 1.2 适用范围

适用于：

- Django 后端 API；
- uni-app H5；
- uni-app APP；
- 微信小程序；
- 学生账号和家长账号的双账号绑定模式；
- 已存在的 `StudentParentBind`、`UserRole` 和家长上下文机制。

不改变：

- 教师端的任务发布、批阅和班级管理；
- 管理员端的机构、用户和权限管理；
- 学生端正常答题、提交、错题和成长数据写入流程；
- 已有短信登录和微信登录的正常流程。

## 二、当前问题和代码依据

### 2.1 家长写权限没有隔离

当前学生答题相关接口普遍使用：

```python
IsAuthenticated, IsStudentOrParentContext
```

该权限类只判断当前请求是否能够得到一个有效学生对象，并没有区分 HTTP 方法，也没有禁止家长执行写操作。因此，家长在选择孩子后，可能调用以下接口：

```text
POST /api/v1/student/attempts/start
POST /api/v1/student/attempts
POST /api/v1/student/attempts/{attempt_id}/submit
POST /api/v1/student/attempts/{attempt_id}/retry
POST /api/v1/student/guidance/sessions
POST /api/v1/student/guidance/sessions/{session_id}/reply
POST /api/v1/student/attempts/{attempt_id}/upload-image
POST /api/v1/student/wrong-book/{item_id}/variant-submit/
POST /api/v1/student/export/pdf
```

这些接口可能创建或修改：

- `AnswerAttempt`；
- `StudentLevelProgress`；
- `StudentMissionProgress`；
- `WrongBookItem`；
- 答题图片；
- AI 引导会话；
- 错题变式提交记录。

这与平台规定的“家长只能查看、不能代替学生答题”不一致。

### 2.2 家长任务入口复用了学生答题页面

当前家长首页任务卡片的跳转逻辑为：

```text
家长首页
  -> /pages/student/mission
  -> /pages/student/answer
```

学生任务详情页允许进入关卡，学生答题页包含答案输入、提交、拍照上传、AI 引导和下一题操作。即使后端后续增加权限校验，家长仍会看到不符合其角色的学生界面，造成业务混淆。

### 2.3 学生查询接口存在副作用

当前部分学生查询接口会自动创建或更新进度记录。例如学生首页、任务详情页可能执行：

- 自动创建缺失的任务进度；
- 更新任务整体进度；
- 更新关卡进度。

因此，家长不能简单复用所有学生查询接口来实现严格只读。家长查看数据应使用纯查询逻辑，不能因为查看行为改变学生数据。

### 2.4 当前验证基线

最近一次检查结果：

- Django `check`：通过；
- `makemigrations --check --dry-run`：无新增迁移；
- 家长绑定专项测试：30 项通过；
- H5 构建：通过；
- APP 构建：通过；
- 微信小程序构建：通过；
- 本次定向回归：`57 passed`（家长只读、角色认证、二维码、学生答题流程及多角色权限）；
- 全量测试：`1390 passed, 14 failed, 3 skipped`。

全量失败项属于本次改造前已存在的兼容问题，主要包括 AI 提示变量、前端 Node 运行参数、旧式 `force_authenticate` 未设置 `active_role`、历史教师页面契约等；本次改造涉及的“家长可以创建答题记录”历史预期已调整为禁止写入。发布前仍应单独处理这些既有失败项，不能把全量测试未通过视为本方案已完全通过。

## 三、目标业务规则

### 3.1 角色和账号规则

平台正式采用两个账号绑定模式：

```text
学生手机号 -> 学生账号 -> 学生角色
家长手机号 -> 家长账号 -> 家长角色
```

同一个账号如果同时拥有学生和家长角色，则以 JWT 中的 `active_role` 决定本次会话的权限；不能因为账号同时拥有多个角色而混合使用权限。

### 3.2 家长查看数据的前置条件

家长访问任何孩子数据前，必须同时满足：

1. JWT 的 `active_role` 为 `parent`；
2. 家长账号状态为 `active`；
3. 家长账号拥有有效的 `parent` 角色授权；
4. 当前存在 `StudentParentBind.bind_status = active` 的绑定关系；
5. 当前孩子 ID 来源于服务端家长上下文；
6. 当前孩子账号状态为 `active`；
7. 绑定关系中的孩子 ID 与当前上下文一致。

不能仅根据前端传入的 `student_id` 判断权限。

### 3.3 操作矩阵

| 功能 | 学生角色 | 家长角色 |
|---|---:|---:|
| 查看任务和进度 | 允许 | 允许 |
| 查看任务详情 | 允许 | 允许 |
| 查看错题、成长、知识掌握 | 允许 | 允许 |
| 开始答题 | 允许 | 禁止 |
| 提交答案 | 允许 | 禁止 |
| 重做错题 | 允许 | 禁止 |
| AI 引导答题 | 允许 | 禁止 |
| 上传答题图片 | 允许 | 禁止 |
| 生成或提交错题变式答案 | 允许 | 禁止 |
| 导出学生答题内容 | 按学生权限 | 默认禁止，后续单独设计只读报告导出 |
| 加入或退出班级 | 允许 | 禁止 |
| 绑定家长 | 允许 | 不适用 |
| 绑定学生 | 不适用 | 允许 |

## 四、总体技术方案

采用“后端强制权限隔离 + 家长专用只读接口 + 家长专用任务页面”的方案。

```text
请求进入
  -> JWT 校验 active_role
  -> 角色和账号状态校验
  -> 家长绑定关系和当前孩子上下文校验
  -> 根据接口类型区分只读或写操作
  -> 返回数据或 PARENT_READ_ONLY
```

核心原则：

1. 前端隐藏按钮不能作为安全措施；
2. 后端所有答题写接口必须拒绝家长；
3. 家长数据查询不能复用带数据库写入副作用的学生查询逻辑；
4. 家长任务详情必须使用 `/pages/parent/*` 页面；
5. 学生端继续使用原有 `/pages/student/*` 页面和答题接口；
6. 同一个账号切换角色时，权限以当前 JWT 的 `active_role` 为准。

## 五、后端权限隔离实施方案

### 5.1 新增权限类

建议在 `apps/study/permissions.py` 中增加以下权限。

#### 5.1.1 `IsStudentOnly`

用途：保护所有会产生或修改学习行为的接口。

校验条件：

```text
active_role == student
UserAccount.status == active
UserRole(student).status == active
```

如果请求角色为家长，统一返回：

```json
{
  "code": "PARENT_READ_ONLY",
  "message": "家长端仅支持查看，不能代替学生答题",
  "data": null,
  "trace_id": "..."
}
```

HTTP 状态码使用 `403`。

#### 5.1.2 `IsStudentOrParentContext`（现有学生/家长只读上下文权限）

用途：保护学生和家长的只读接口。

学生请求：

```text
active_role == student
student 角色有效
学生账号 active
```

家长请求：

```text
active_role == parent
parent 角色有效
家长账号 active
当前上下文存在
绑定关系 active
孩子账号 active
```

该权限只负责确定可查询的有效学生对象，不允许被用于 POST、PUT、PATCH、DELETE 写接口。

### 5.2 写接口改造清单

以下接口必须改为 `IsStudentOnly`：

#### 答题接口

```text
POST /api/v1/student/attempts/start
POST /api/v1/student/attempts
POST /api/v1/student/attempts/{attempt_id}/submit
POST /api/v1/student/attempts/{attempt_id}/retry
```

#### 作业码进入和任务状态写入接口

作业码进入接口虽然不是传统答题接口，但当前实现会创建缺失的 `StudentMissionProgress`、增加扫码次数，并返回学生任务页地址，因此家长也必须禁止调用：

```text
POST /api/v1/hw/{short_code}/enter
```

如果保留家长扫码入口，应另行提供纯查询或家长专用进入接口，不能复用学生进入接口。

#### AI 引导接口

```text
POST /api/v1/student/guidance/sessions
POST /api/v1/student/guidance/sessions/{session_id}/reply
```

#### 图片和附件接口

```text
POST /api/v1/student/attempts/{attempt_id}/upload-image
POST /api/v1/student/attempts/{attempt_id}/upload-images
POST /api/v1/attempts/{attempt_id}/images
```

以上三类接口均可能保存图片、更新答题记录的图片数量和提交来源，必须至少统一拒绝家长会话。由于其中二维码模块还兼容教师、管理员或关联人员的既有授权，实际实现可使用“拒绝家长会话 + 保留原有资源权限”的组合，而不能简单删除原有教师/管理员权限。

`POST /api/v1/student/attempts/image-check` 当前只进行图片格式和模糊度校验，不保存学生数据；本次实现仍通过 `IsNotParentSession` 拒绝家长会话，同时保留非家长角色的既有调用权限。

#### 错题变式接口

```text
POST /api/v1/student/wrong-book/{item_id}/variant-submit/
```

#### 错题练习册接口

当前二维码模块还存在错题练习册接口，家长不能创建或提交练习册：

```text
POST /api/v1/practice-sheets
POST /api/v1/practice-sheets/{sheet_code}/submit
POST /api/v1/practice-sheet/{sheet_code}/submit
```

其中两个提交路径是兼容路由，必须使用相同的家长只读拒绝规则。

#### 其他可能产生副作用的接口

```text
POST /api/v1/student/export/pdf
```

导出接口是否允许家长使用，需要单独设计家长报告导出接口。当前阶段默认禁止家长调用学生导出接口。

### 5.3 只读接口改造清单

学生和家长均可以读取的数据，建议使用只读权限：

```text
GET /api/v1/student/growth
GET /api/v1/student/knowledge-mastery
GET /api/v1/student/wrong-book/
GET /api/v1/student/wrong-book/{item_id}/
GET /api/v1/student/wrong-book/{item_id}/variants/
```

但这些接口必须确认内部没有写数据库的副作用。若存在副作用，应抽取纯查询 service 后供学生和家长分别调用。

### 5.4 家长专用只读任务接口

建议新增：

```text
GET /api/v1/parent/overview
GET /api/v1/parent/missions
GET /api/v1/parent/missions/{mission_id}
```

#### `GET /parent/overview`

返回当前孩子的概览数据：

```json
{
  "code": 0,
  "data": {
    "student": {
      "id": "学生ID",
      "display_name": "学生姓名",
      "grade_level": "年级"
    },
    "class_name": "班级名称",
    "today_mission_count": 3,
    "completed_mission_count": 1,
    "total_attempt_count": 20,
    "accuracy": 85.5,
    "wrong_book_count": 4
  }
}
```

该接口只能查询，不能创建进度或更新任务状态。

#### `GET /parent/missions`

支持参数：

```text
student_id：可选，仅用于校验当前上下文，不作为授权依据
scope：today/week/all
class_id：可选
```

返回：

- 任务 ID；
- 任务名称；
- 班级名称；
- 截止时间；
- 关卡数量；
- 题目数量；
- 完成状态；
- 完成百分比；
- 正确率；
- 最近学习时间。

#### `GET /parent/missions/{mission_id}`

返回家长只读任务详情：

```json
{
  "code": 0,
  "data": {
    "mission": {
      "id": "任务ID",
      "name": "任务名称",
      "class_name": "班级名称",
      "deadline": "2026-08-20T23:59:59+08:00"
    },
    "levels": [
      {
        "id": "关卡ID",
        "level_no": 1,
        "level_name": "第一关",
        "question_count": 10,
        "completed_count": 7,
        "progress_percent": 70,
        "status": "in_progress",
        "accuracy": 85.7,
        "last_attempt_at": "2026-08-17T18:00:00+08:00"
      }
    ]
  }
}
```

该接口禁止：

- 创建 `StudentMissionProgress`；
- 修改进度百分比；
- 创建 `AnswerAttempt`；
- 修改任务状态；
- 返回可用于提交答案的会话信息。

### 5.5 家长接口统一错误码

建议统一以下错误码：

| 错误码 | 含义 | HTTP |
|---|---|---:|
| `PARENT_READ_ONLY` | 家长不能执行写操作 | 403 |
| `PARENT_ROLE_REQUIRED` | 需要家长角色 | 403 |
| `PARENT_CONTEXT_REQUIRED` | 尚未选择孩子 | 403 |
| `BINDING_NOT_ACTIVE` | 绑定关系无效 | 403 |
| `STUDENT_NOT_ACTIVE` | 学生账号已停用 | 403 |
| `MISSION_NOT_VISIBLE` | 当前孩子无权查看任务 | 404 或 403 |

前端统一优先展示后端 `message` 或 `detail`，不能只显示“接口异常”。

## 六、家长任务详情前端实施方案

### 6.1 新增页面

新增：

```text
uniapp/src/pages/parent/mission.vue
```

并在 `pages.json` 注册：

```json
{
  "path": "pages/parent/mission",
  "style": {
    "navigationBarTitleText": "任务详情"
  }
}
```

### 6.2 家长首页跳转调整

当前：

```text
/pages/student/mission?id={id}
```

调整为：

```text
/pages/parent/mission?id={id}
```

家长任务卡片只允许进入家长任务详情页，不能进入：

```text
/pages/student/answer
/pages/student/level
/pages/student/variant-practice
```

### 6.3 家长任务详情页面内容

页面包含：

1. 当前孩子信息；
2. 任务名称和班级；
3. 截止时间；
4. 任务整体完成度；
5. 关卡列表；
6. 每个关卡题目数量；
7. 每个关卡完成数量；
8. 正确率；
9. 最近作答时间；
10. 无任务、未绑定、无班级、加载失败等空状态。

页面不包含：

- 答案输入框；
- 选项点击提交；
- 提交答案按钮；
- AI 引导按钮；
- 图片上传按钮；
- 重做按钮；
- 学生答题页面的“下一题”流程。

### 6.4 家长页面角色守卫

家长页面进入时进行前端角色检查：

```text
当前 active_role != parent
  -> 跳转 routeForRole(active_role)
```

前端角色检查只用于改善体验，不能替代后端权限校验。

### 6.5 上下文刷新规则

家长首页和所有家长数据页面需要在 `onShow` 时重新检查：

1. 当前家长角色是否仍有效；
2. 当前孩子是否仍在 `/parent/children` 返回列表中；
3. 家长上下文是否仍有效；
4. 当前孩子是否已解除绑定；
5. 当前孩子账号是否已停用。

如果上下文失效：

```text
清除 activeChildId
清空当前页面数据
显示“孩子绑定已失效”
提供“重新选择孩子”或“添加孩子”入口
```

家长完成绑定后返回首页，必须重新加载孩子列表和学习数据，不能依赖页面首次加载状态。

## 七、H5、APP、微信小程序适配

### 7.1 H5

- 使用 `/pages/parent/mission` 作为任务详情路由；
- 家长菜单继续使用家长专用导航；
- 浏览器刷新后根据 `active_role` 恢复家长路由；
- 任务详情页面不复用学生答题组件；
- 403 错误展示后端真实业务信息。

### 7.2 APP

- 使用相同的家长任务详情页面；
- 禁止依赖 H5 专用条件编译；
- 页面返回后触发 `onShow` 刷新孩子上下文；
- 退出登录清除 `accessToken`、`refreshToken`、`userInfo` 和 `activeChildId`；
- 网络失败使用 APP 兼容的 Toast/Modal；
- 不允许从家长页面跳转学生答题页面。

### 7.3 微信小程序

- 家长首页保持独立路由，不复用学生全局 tabBar；
- 家长任务详情使用 `/pages/parent/mission`；
- 家长页面提供返回和孩子切换入口；
- 小程序抽屉菜单不能出现学生答题菜单；
- 在微信开发者工具中验证家长任务详情和后端 403 错误提示；
- 不允许通过 `reLaunch` 或 `navigateTo` 将家长任务跳转到学生答题页。

## 八、数据安全和并发要求

### 8.1 当前孩子上下文

`parent_context:{parent_id}` 只保存服务端上下文标识。每次访问数据时必须重新查询：

```text
parent_user_id = 当前家长
student_user_id = 当前上下文孩子
bind_status = active
```

不能只信任前端 `activeChildId`。

### 8.2 解除绑定

解除绑定后：

1. 当前关系变为 `removed`；
2. 当前孩子不再出现在 `/parent/children`；
3. 如果被解除的是当前上下文，清除服务端上下文；
4. 如果解除的是其他孩子，不能清除当前正在查看的孩子上下文；
5. 家长访问被解除孩子的数据立即返回 `BINDING_NOT_ACTIVE`；
6. 前端清除被解除孩子的本地 ID。

### 8.3 绑定码消费

当前绑定码为缓存型一次性令牌，建议优化为原子消费：

- Redis `GETDEL`；
- 或使用带锁的 Lua 脚本；
- 或在数据库中持久化绑定码状态并使用行锁。

目标是避免并发请求重复消费同一个绑定码。

### 8.4 绑定关系唯一性

需要检查历史数据是否存在同一家长和学生的多条关系。如果存在，应先清理重复数据，再考虑增加：

```text
(parent_user_id, student_user_id) 唯一约束
```

如果增加数据库约束，必须配套 migration、数据清理脚本和回滚方案。

## 九、测试和验收方案

### 9.1 后端权限测试

#### 家长允许读取

- 有效绑定家长读取 `/parent/overview`；
- 有效绑定家长读取 `/parent/missions`；
- 有效绑定家长读取 `/parent/missions/{id}`；
- 家长读取错题、成长和知识掌握；
- 多孩子切换后读取的是当前孩子数据。

#### 家长禁止写入

以下请求必须返回 `403/PARENT_READ_ONLY`：

- 开始答题；
- 提交答案；
- 提交草稿；
- 重做答案；
- 启动 AI 引导；
- 回复 AI 引导；
- 上传答题图片；
- 调用答题图片校验接口（若采用严格的家长 POST 禁止策略）；
- 提交错题变式；
- 通过作业码进入学生任务并创建学生任务进度；
- 创建或提交错题练习册；
- 学生答题导出接口。

#### 学生回归

- 学生仍可开始答题；
- 学生仍可提交答案；
- 学生仍可重做错题；
- 学生仍可使用 AI 引导；
- 学生数据正常写入；
- 学生端菜单和路由不改变。

### 9.2 越权测试

1. 家长传入未绑定学生 ID；
2. 家长修改 URL 中的任务 ID；
3. 家长修改请求体中的 `student_id`；
4. 家长使用已解除绑定的孩子上下文；
5. 家长使用已停用孩子的上下文；

## 十、实施顺序

6. 确认学生端测试全部通过。

## 十一、数据库、发布和回滚

### 11.1 数据库

如果只修改权限类、查询接口和前端页面，原则上不新增 migration。

如果增加绑定关系唯一约束、访问审计或绑定码持久化，则必须：

1. 备份数据库；
2. 清理重复绑定数据；
3. 创建 migration；
4. 在测试库执行迁移；
5. 验证回滚脚本；
6. 再部署生产环境。

### 11.2 发布顺序

必须先部署后端，再部署前端：

```text
后端权限隔离
  -> 后端只读任务接口
  -> 后端测试
  -> 前端家长任务页
  -> H5/APP/小程序构建
  -> 灰度验证
  -> 正式发布
```

不能只发布前端页面，否则旧页面仍可能调用学生答题接口。

### 11.3 回滚方案

如果发布后发现异常：

1. 优先回滚前端家长任务路由；
2. 保留后端 `PARENT_READ_ONLY` 权限保护；
3. 如果只读接口异常，可临时回退家长只读查询接口；
4. 不回滚学生端答题权限；
5. 不删除已有 active 绑定关系；
6. 检查家长上下文和缓存，不直接清空全局缓存。

## 十二、最终验收标准

本方案完成后必须满足：

```text
家长登录
  -> 选择已绑定孩子
  -> 查看学习概览
  -> 点击任务
  -> 进入家长只读任务详情
  -> 查看关卡和进度
  -> 不能进入学生答题页
  -> 不能提交、修改或生成学生答题记录
```

学生流程必须保持：

```text
学生登录
  -> 查看任务
  -> 进入学生任务详情
  -> 进入学生答题页
  -> 提交答案
  -> 生成学习进度和错题数据
  -> 家长端读取最新结果
```

最终必须通过以下安全结论：

```text
家长端只能读绑定学生数据
后端拒绝所有家长答题写操作
家长任务不再跳转学生答题页面
学生端原有业务不受影响
H5、APP、微信小程序角色和页面一致
```
