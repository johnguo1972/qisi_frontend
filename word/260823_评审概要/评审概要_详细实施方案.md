# 评审概要：新需求与现有功能优化项详细实施方案

版本：v1.1
编制日期：2026-08-25
适用项目：`qisi_frontend`
依据文档：`word/260823_评审概要/评审概要_新需求与优化项.md`

## 1. 文档定位与执行边界

本文件把评审概要转换为可以交给开发、测试和部署人员执行的方案，重点补充：

- 当前代码中已经存在的能力、重复入口和实现缺口；
- 按 P0、P1、P2 分阶段的开发顺序、依赖关系和交付物；
- 后端模型、接口、前端页面、权限、迁移、测试和上线要求；
- 评审中尚未确认的业务规则及建议默认值。

本轮工作只整理文档，不修改业务代码、不执行数据库迁移、不改变生产配置。后续实施必须以本文件和最终确认的业务规则为准。

### 1.1 总体原则

1. 先修复影响正常使用的 P0 问题，再做教师日常核心能力，最后建设讲义、个性化作业、AI 匹配和学情报告。
2. 每个阶段都必须形成“后端接口 + 前端入口 + 自动化测试 + 人工验收 + 回滚点”，不能只完成页面。
3. 现有教师作业链路使用 `LearningMission`、`MissionLevel`、`MissionQuestionRel`；学生个人精练链路使用 `apps/practice`。两者不混写，避免污染现有任务进度和统计。
4. 权限必须由后端强制校验，前端隐藏按钮不算权限控制。
5. 题目、知识点、标签、图片和公式是后续所有能力的基础数据。P0 阶段必须先统一展示和筛选口径，P2 阶段再接入自动匹配和 AI 推荐。
6. H5 是当前主要端，APP 和微信小程序共享 uni-app 页面、API 和部分组件；修改共享逻辑时必须保留三端兼容分支。

### 2.2 已确认的现有基础能力

以下能力已经存在，后续应优先复用而非重新设计：

- `UserAccount.subjects`、`UserAccount.stages` 已支持教师多学科/多学段配置；机构管理员页面已经有学段选择和编辑入口。
- `question_list` 已支持学科、难度、题型、标签、题号/系统编号、知识点、学段和分页参数，但参数与前端展示尚未完全统一。
- `QuestionTag`、`QuestionTagRelation` 已存在，且通过同步逻辑把关系写回 `ExamQuestion.tags`。
- 课程资料已有上传、下载、预览、Word 转 PDF、资料页面和区域 AI 识别接口。
- 教师作业已有 `assignment_mode='flat'`，可以直接保存一份按顺序排列的题目列表；历史关卡模式仍需兼容。
- `mission_progress` 已能返回班级作业的学生、进度状态、完成百分比和最后操作时间。
- 学生答题已经有草稿 attempt 和提交接口，当前 `answer.vue` 主要仍是单题提交体验。
- `apps/practice` 已有个人精练池、精练作业、在线提交、照片上传、PDF 导出和严格关联题候选接口，并且已有 feature flag、健康检查和测试基础。

| 题目显示 | 已有 `display_stem`、表格和图片规范化工具，但列表、在线题目和 PDF 仍有不同组装路径 | 统一题干、表格、公式、选项图片和图片宽高比 |

| 学情报告 | 有班级基础统计、知识掌握和作业进度接口，但没有统一的题目/知识点/讲义/前后对比口径 | 先固定统计快照和口径，再建设多维报告 |

### 2.4 本次复核新增的代码事实和修正项

再次逐项检查代码后，补充以下事实。它们属于实施时必须处理的细节，不能只按评审概要中的页面名称理解：

1. **课程资料 Word 实际有两套转换服务。** `apps/courses/convert_service.py::convert_word_to_pdf` 被 `material_preview` 使用；`apps/courses/views.py::material_pages` 则调用 `apps/parser/services/convert_service.py::word_to_pdf`，随后再调用 `pdf_to_images`。两套服务的可执行文件发现、异常类型、超时和输出目录规则不同，P0 修复必须统一或明确适配层，否则只修一套仍会出现“预览能用、框选导入失败”或相反的情况。
2. **课程资料导入页面是实际 P0 路由问题的一个落点。** `uniapp/src/pages/teacher/course-material-import.vue` 直接使用 `TeacherSidebar`，并传入 `activeItem="course-practice"`；当前 `TeacherSidebar` 没有这个菜单项，也没有对应导航处理。该页面应归入课程管理深层页面，不能继续使用一个不存在的侧栏状态。
3. **课程统计字段存在语义错误。** `apps/courses/serializers.py::CourseSerializer.get_class_count` 当前返回 `obj.tree_nodes.count()`，统计的是课程目录节点数，不是班级数；在新增课程-班级关系前必须修正字段含义，不能把现有 `class_count` 当作真实班级统计。
4. **学生关联题已有通用接口，但不能直接复用。** `/api/v1/questions/<question_id>/similar/` 当前只要求登录，按题目知识点和难度返回候选，没有学生有效身份、作业来源、题目可见性和教师/机构范围校验。它可作为算法参考，不能直接作为学生提交后“关联题入口”的生产接口。
5. **多班级改造会影响现有单班级统计入口。** `apps/institutions/class_views.py::class_learning_stats` 直接按 `LearningMission.class_obj_id` 聚合作业；完成多班级关系后必须同时改为按作业-班级关系统计，否则课程/班级页面会漏算新作业。
6. **题库读写权限需要单独审计。** `question_list` 已有教师范围过滤，但 `question_detail`、标签管理和相似题接口不能仅以 `IsAuthenticated` 作为完整的题库对象权限。P0 至少要确认教师只能查看/编辑其机构和教学范围内的题目，学生端不能通过通用题库接口读取教师专用数据。
7. **分页预览存在路径契约风险。** `apps/parser/services/convert_service.py::word_to_pdf` 返回相对 `MEDIA_ROOT` 的路径，但 `material_pages` 随后直接把该返回值传给 `pdf_to_images`；如果当前工作目录不是 `MEDIA_ROOT`，会出现“PDF 已转换但找不到 PDF”的失败。转换服务必须统一返回绝对内部路径或统一由调用方补齐 `MEDIA_ROOT`，并为该链路增加回归测试。
8. **课程题目来源枚举不一致。** `CourseQuestionLink.SOURCE_CHOICES` 当前没有 `imported_from_material`，但 `import_question` 会写入该值。实施 Word/资料导入修复时应统一来源编码并补充迁移/历史数据兼容，否则课程题目来源筛选和序列化可能出现不一致。

## 5. 阶段 1：P0 现有功能修复

阶段目标：先消除影响正常使用的问题。该阶段不增加新的讲义、AI 或复杂报表业务。

### 5.1 P0-01 路由重复加载和左侧菜单失效

#### 当前落点

- `uniapp/src/pages.json` 注册了 `pages/teacher/layout` 以及多个独立教师页面；
- `uniapp/src/pages/teacher/layout.vue` 又直接 import 并条件渲染 `workbench.vue`、`question-bank.vue`、`favorites.vue`、`my-classes.vue`、`mission-list.vue`、`course-list.vue`、`learning-stats.vue`；
- `uniapp/src/components/TeacherSidebar.vue` 通过事件切换 `currentPage`，而其他页面内部大量使用 `uni.navigateTo`。

#### 实施方案

采用“路由页面负责深层页面，布局页只负责一级工作台切换”的统一策略：

1. 先画出教师页面导航图，明确一级页面和深层页面：工作台、题库、精选、班级管理、课程管理为一级入口；题目编辑、课程资料、作业详情、进度、班级详情为深层页面。
2. 一级入口继续由 `layout.vue + TeacherSidebar` 承载；深层页面不再重复渲染完整侧栏，统一使用返回或回到布局页的导航函数。
3. 禁止同一业务页面同时作为布局动态组件和独立页面被连续压入页面栈。若某页面必须独立访问，则只保留一个真实渲染入口，并用 query 保存当前 tab。
4. 统一 `navigateTo`、`redirectTo`、`reLaunch` 的使用规则：登录后使用 `reLaunch`；一级教师入口使用布局页内部切换；深层详情使用 `navigateTo`；退出详情返回使用 `navigateBack`，无页面栈时回到布局页。
5. 处理页面 `onShow/onMounted` 重复请求：加页面激活标识和请求取消/幂等保护，避免返回页面时多次加载题库和菜单。
6. 检查 H5 浏览器刷新和深层 URL 直接访问；检查 APP 和小程序不能调用 H5 专用 DOM 路由逻辑。
7. 把 `course-material-import.vue` 纳入深层页面清单：它当前直接渲染 `TeacherSidebar`，且传入的 `activeItem="course-practice"` 不在侧栏支持的入口集合中；应改为课程管理下的统一深层页面返回策略。

#### 验收

- 登录后进入教师工作台，连续点击题库、精选、学生管理、作业列表、学情统计、课程管理 20 次，菜单始终可点；
- 从题库进入题目编辑并返回，筛选条件和页面状态符合预期，不重复请求；
- 浏览器刷新一级入口和深层详情不出现空白页；
- 浏览器后退、页面内返回、退出登录均回到正确页面；
- 从课程资料进入“从资料导入习题”后，侧栏不会出现不存在的激活状态，返回课程资料/课程列表路径稳定；
- H5 构建、APP 编译和小程序编译不出现页面注册冲突。

### 5.2 P0-02 题库题型筛选、知识树清除和模糊查询

#### 当前落点

- 后端：`apps/study/question_views.py::question_list` 已有 `question_type`、`knowledge_point_id`、`tag`、`question_no` 等过滤；
- 前端：`uniapp/src/pages/teacher/question-bank.vue` 和 `bank.vue` 存在两套题库页面/筛选实现；
- `tag` 当前按 JSON 数组精确包含；后端没有统一的“关键字搜索题干/选项/题号”参数。

#### 实施方案

统一题库查询契约，建议保留现有参数并新增：

```text
GET /api/v1/questions/
  page=1&page_size=20
  subject=physics
  stages=初中,九年级
  question_type=single_choice,multiple_choice
  difficulty=1,2,3
  knowledge_point_id=12,13
  tag=易错题
  keyword=速度
  review_status=confirmed
  sort=sort_order|created_at|question_no
  ordering=asc|desc
```

1. 后端把查询参数解析集中到一个 service/serializer，空值、非法页码、超大页大小、重复参数统一处理。
2. `keyword` 查询题干、题干 HTML、题号、试卷题号、系统编号；是否查询选项由 ORM 查询 `QuestionOption` 关联实现，不能只在前端过滤。
3. 标签查询优先从 `QuestionTagRelation` 过滤，再兼容历史 `ExamQuestion.tags` JSON 数据；标签名称支持精确和可选模糊两种明确模式，默认精确选中标签。
4. 知识树选择支持再次点击取消；增加“清除当前知识点”和“清空全部筛选”两个动作，清除后把页码重置为 1 并重新请求。
5. 题型、难度、知识点、标签、学段和关键字全部由同一请求提交，不能出现 UI 已选但请求未带参数的情况。
6. 前端只保留一个教师题库主入口；`bank.vue` 如继续兼容旧入口，必须复用同一个 `questionApi.list` 参数构造器。
7. 返回结构固定为 `{items,total,page_no,page_size,scope_configured}`，前端不再同时兼容多套 `res.data` 形态。

#### 验收

- 题型单选、多选、组合筛选结果与数据库抽样一致；
- 点击已选知识点可取消，清空后不会保留旧条件；
- 输入题干、选项、系统编号的部分关键字均可检索；
- 翻页、排序、重置后数量、页码和列表内容一致；
- 教师请求越过授权学科/学段时返回 403，未配置范围时明确显示“尚未配置教学范围”，不显示无原因空白。

### 5.3 P0-03 题库个别题目和图片/公式展示异常

#### 实施方案

1. 以后端 `QuestionListSerializer` 为列表展示唯一数据组装入口，统一调用 `preview_text`、`normalize_tables` 和图片 URL 处理。
2. 题干为空时按“子问题 → 表格文本 → 未提供题干”的顺序降级，禁止把 JSON、`undefined` 或空白显示到列表。
3. 图片响应统一返回 `id、url、file_path、image_type、sort_order、display_width、placement`；相对路径由 `media_url` 转成可访问 URL。
4. 前端图片组件统一使用原始宽高比，设置最大宽度和最大高度，不使用固定宽高拉伸；多图按 `sort_order` 排序。
5. 公式图片与题目插图区分：公式已经在文本中渲染时不重复展示公式裁图；题干图、选项图按位置分别渲染。
6. 对历史 `unknown` 题型只做展示推断，不在读取时回写数据库；需要修复数据时另做离线脚本和审计记录。

#### 验收

覆盖纯文本题、空题干表格题、单图题、多图题、选项图片题、公式题、跨页题；列表、题目详情、在线作答、PDF 四处的顺序和比例一致，不能出现图片拉伸、裁剪或重复。

### 5.4 P0-04 课程资料 Word 导入/预览失败

#### 当前落点

- `apps/courses/convert_service.py` 通过固定路径查找 `soffice`，同步执行 LibreOffice，转换失败只返回 `None`；
- `apps/courses/views.py::material_pages` 实际还调用 `apps/parser/services/convert_service.py::word_to_pdf` 并继续执行 `pdf_to_images`；该服务的查找路径、超时和异常类型与上一套转换服务不同；
- `apps/courses/views.py::material_upload` 只校验大小，允许的扩展名、MIME 和实际文件内容没有形成统一规则；
- `material_preview` 对 Word 直接转换，失败只返回“请下载后用 Office/WPS 打开”；`course-material-import.vue` 的页面预览则走 `material_pages`，两条链路必须同时修复。
- `word_to_pdf` 返回相对 `MEDIA_ROOT` 的路径，而 `material_pages` 直接把它交给 `pdf_to_images`；这条路径契约在非项目根目录、非开发服务器或不同工作目录下可能失败。
- `import_question` 写入的 `source='imported_from_material'` 不在 `CourseQuestionLink.SOURCE_CHOICES` 中，资料导入成功后来源字段存在不一致。

#### 实施方案

1. 统一支持范围：第一期只承诺 `.docx`、`.doc`、`.pdf` 和图片；对不支持的格式在上传前拒绝。是否支持旧 `.doc` 由部署环境实测决定，不能只依据扩展名承诺。
2. 上传时校验扩展名、MIME、文件大小、文件名字符和文件头；禁止路径穿越、双扩展名和空文件。
3. 统一两个转换 service，建议由一个适配层负责 `Word → PDF → 图片`；明确内部绝对路径、媒体相对路径和公开 URL 三种类型，禁止把相对 `MEDIA_ROOT` 路径直接传给需要文件系统路径的函数。增加可配置 LibreOffice 路径、临时用户目录、超时、最大输出大小、标准错误日志、错误类型和清理逻辑。每次转换使用隔离临时目录，避免并发转换锁定用户 profile。不能只修 `apps/courses/convert_service.py` 而遗漏 `apps/parser/services/convert_service.py`。
4. 转换结果不覆盖原 Word，缓存文件放入 `media/courses/<course_id>/previews/`，按原文件哈希或修改时间命名。
5. 统一错误码：`UNSUPPORTED_FORMAT`、`FILE_TOO_LARGE`、`FILE_CORRUPTED`、`CONVERTER_UNAVAILABLE`、`CONVERT_TIMEOUT`、`CONVERT_FAILED`、`PREVIEW_NOT_READY`。
6. 预览接口返回结构化错误和下载 URL；前端显示具体原因、重试和下载按钮，不把服务端异常堆栈显示给用户。
7. 上传后先展示资料记录和预览；只有用户进入“从资料导入题目”时才启动内容识别。识别失败不得删除原始资料。
8. `course-material-import.vue` 当前通过页面图片和框选调用 `material_pages`、`material_ai_recognize`、`import_question`；应为这三个步骤分别返回可定位错误，不能把页面转换失败误报为 AI 识别失败。
9. 统一 `CourseQuestionLink.source` 的合法值，决定保留 `imported_from_material` 还是映射为已有的 `import`；历史数据和序列化输出保持兼容。
10. 将 Word 转 PDF 的单元测试与真实 LibreOffice 集成测试分开；CI 没有 LibreOffice 时只跑 mock，部署环境必须有真实转换冒烟。

#### 接口建议

```json
{
  "success": false,
  "code": "CONVERTER_UNAVAILABLE",
  "message": "当前服务器未配置 Word 预览转换器",
  "data": {
    "download_url": "/api/v1/courses/{course_id}/materials/{material_id}/download/",
    "can_retry": false,
    "can_download": true
  },
  "trace_id": "..."
}
```

#### 验收

- 正常 `.docx` 可上传、预览、下载；损坏 Word、超大文件、不支持格式均有明确提示；
- 并发预览两个 Word 不相互覆盖；
- 课程资料普通预览和“从资料导入习题”的分页预览使用同一转换规则，均能返回页图；
- LibreOffice 不存在或超时，接口在规定时间内返回可理解错误；
- 原始文件始终可下载，预览失败不影响资料记录和后续重试。

### 5.5 P0-05 新教师题库数据可见性

#### 当前落点

`UserAccount` 已有 `subject/subjects/stages`，`apps/knowledge/teacher_scope.py` 已有教师范围解析，`question_list` 已调用范围过滤；但课程列表、知识树、题库不同页面仍有直接读取 `user.subject` 或本地 `stages` 的情况。

#### 实施方案

1. 统一使用一个“当前教师教学范围”服务返回：`subjects、stages、configured、source、is_admin`。
2. 学科兼容中文名、英文 code 和历史单字母 code；范围判断不得只比较显示名。

4. 题库、知识树、课程列表、课程资料导入、讲义和创建作业的题目选择都调用同一范围服务。

7. 对 `question_detail` 的 GET/PUT、题目标签增删、相似题查询和题目篮子等接口做同一轮对象权限审计；不能因为列表接口有范围过滤，就默认详情和写接口已经安全。

#### 验收

- 新增教师配置“初中+物理”后登录可看到对应知识树和题库；
- 没有范围时页面有配置提示且列表为空，接口明确返回未配置状态；
- 请求其他学科/学段返回 403；
- 管理员可修改范围，原教师重新进入后看到新范围；
- 旧教师只有 `subject` 没有 `subjects` 时仍能正常工作；
- 学生或无关教师不能通过题目详情、标签或相似题接口绕过题库范围读取或修改数据。

### 5.6 P0-06 PDF 作业名称和图片排版

#### 当前落点

- `apps/study/student_views.py::_build_pdf` 的标题按 `export_type` 固定生成；
- `apps/missions/pdf_service.py` 使用 `exports/mission_<id>.pdf`；
- `apps/practice/pdf_service.py` 已有 `PracticeSet.title`，但输出路径和标题仍需要统一；
- PDF 图片读取相对路径并按最大宽高缩放，题目图片展示规则与列表未完全共用。

#### 实施方案

1. 扩展 PDF 构建函数的元数据入参：`title、subtitle、export_type、include_answers、watermark_text`，保持旧调用有默认值。
2. 任务 PDF：首页标题使用 `LearningMission.mission_name`；精练 PDF 使用 `PracticeSet.title`；讲义使用讲义名称；错题本使用默认“错题本”。
3. 文件名采用安全化后的业务名称 + 稳定 ID/版本，例如：

```text
作业名称_任务题目_<mission_id>.pdf
精练作业名称_v1_<practice_set_id>.pdf
讲义名称_<handout_id>.pdf
```

名称为空、包含非法文件名字符或过长时使用默认名并保留 ID，不能把用户输入直接放入路径。
4. HTTP 下载响应的 `Content-Disposition` 使用 RFC 5987 编码，同时保留英文安全文件名，避免中文文件名在 H5、APP 和小程序乱码。
5. 抽取统一的 `PdfQuestionRenderer` 或共享组装函数，使用同一套题干、选项、知识点和图片数据。
6. 图片保持宽高比，按原始 `sort_order`，题干图放在题干后、选项图放在对应选项后；超过最大宽高只缩放不裁剪。

8. PDF 生成失败返回业务错误和 trace_id；生成路径写入模型前先确认文件存在，避免数据库存在死链接。

#### 验收

- 普通作业、精练作业、错题作业名称均出现在文件名和首页标题；
- 中文、英文、特殊符号名称均能下载；
- 单图、多图、选项图、公式题不拉伸、不重复、不越界；
- 重新生成同一作业不会产生旧内容覆盖错版本，版本号或时间戳可追踪；
- 无权限用户不能通过猜测 PDF URL 访问其他机构/学生文件。

## 6. 阶段 2：P1 教师日常核心能力

阶段目标：在 P0 稳定后，完成教师日常布置、管理和学生导入能力。此阶段仍不做全自动变式题生成。

### 6.1 P1-01 教师年级范围正式化

P0 只修复可见性，P1 再完成业务层正式化：

1. 确定配置对象是“学段”还是“具体年级”。建议保存具体年级 code，同时由学段字典派生；这样可以支持九年级教师而不是只能支持初中。
2. 如当前阶段只允许学段选择，新增 `teacher_scope` 配置 service，避免把具体年级规则散落在各页面。

### 6.2 P1-02 创建作业支持多个班级

#### 数据方案

当前 `LearningMission.class_obj` 只支持一个班级。建议新增关系表，而不是把多个班级 ID 塞入 JSON：

```text
MissionClassAssignment
- id UUID
- mission FK LearningMission
- class_obj FK institutions.Class
- start_at / end_at，可空，默认继承作业时间
- status active/removed
- target_student_ids JSON，可空；仅用于该班级内的专属学生
- created_at / updated_at
唯一约束：mission + class_obj
```

旧数据迁移：把不为空的 `LearningMission.class_obj` 转为一条关系；旧字段暂时保留读兼容，稳定一个版本后再评估弃用。

#### 接口

```http
POST /api/v1/missions/
{
  "mission_name": "八年级物理作业1",
  "course_id": "...",
  "class_ids": ["class-a", "class-b"],
  "start_at": "...",
  "end_at": "...",
  "question_ids": ["q1", "q2"]
}
```

响应返回每个班级的发布状态、学生数和错误信息。创建和发布前必须逐个校验班级属于当前教师可管理的班级、与课程/机构范围一致；不能只校验 `class_id` 是否存在。发布必须在事务中创建/更新每个班级的进度记录，任何一个班级失败时不能产生半发布状态。

#### 业务规则建议

- 默认多个班级共用题目顺序和作业名称；
- 每班可以有自己的截止时间，但必须在发布前设置；
- 每班完成情况独立统计，不能用总人数相加后覆盖单班状态；
- 取消某班只影响该班，不删除作业题目和其他班级数据；
- 学生专属作业必须有明确的 `class_id + student_id` 关系，不能只依赖全局 `target_student_ids`；
- 同步改造 `apps/institutions/class_views.py::class_learning_stats`、教师作业列表、`mission_progress`、二维码/短码生成和学生端任务查询，所有按 `LearningMission.class_obj_id` 的旧查询都要列入迁移清单。

### 6.3 P1-03 题目选择增加标签和组合筛选

### 6.4 P1-04 教师端选择和布置精练题

#### 推荐边界

教师布置的精练题是“教师作业的一种类型”，不是学生个人 `PracticeSet`。第一期建议沿用 `LearningMission`，增加：

```text
mission_kind: regular | drill | wrongbook_personal
source_type: question_bank | handout | wrongbook | ai_recommendation
```

如果现有生产数据不适合直接加字段，也可以新增 `TeacherDrillAssignment`，但必须复用已有题目关系、班级关系、PDF 和统计 service。

#### 流程

```text
题库/课程/关联题 → 教师选择题目 → 设置精练名称和数量
→ 选择一个或多个班级 → 设置截止时间和提交规则
→ 预览 → 发布 → 学生在线或 PDF 练习 → 教师查看完成/正确率
```

#### 接口建议

```text
POST /api/v1/missions/{id}/kind/drill
POST /api/v1/missions/{id}/questions/replace
POST /api/v1/missions/{id}/publish
GET  /api/v1/missions/{id}/progress
GET  /api/v1/missions/{id}/statistics
```

接口实现可复用现有 `/missions/{id}/questions/` 扁平保存接口，但必须在后端校验题目来源、题目权限和作业类型。教师精练作业学生提交写入现有 `AnswerAttempt`，个人精练仍写入 `PracticeAttempt`，两者不可混用。

### 6.5 P1-05 作业列表展示学生完成情况

#### 状态模型

作业列表和学生明细统一使用以下状态：

```text
not_started  未开始
in_progress  进行中
submitted    已提交
graded       已批改
overdue      已逾期（未完成的派生状态）
```

`overdue` 不必写入数据库，可由 `end_at + 当前时间 + progress_status` 计算；如需要查询性能，再做快照字段。

#### 后端响应

扩展 `GET /api/v1/missions/{id}/progress`：

```json
{
  "summary": {"total": 40, "not_started": 8, "in_progress": 12, "submitted": 15, "graded": 5, "completion_rate": 50},
  "students": [
    {
      "student_id": "...",
      "student_name": "学生A",
      "status": "submitted",
      "progress_percent": 100,
      "answered_count": 10,
      "question_count": 10,
      "correct_count": 8,
      "accuracy": 80,
      "submitted_at": "...",
      "graded_at": null,
      "overdue": false
    }
  ],
  "filters": {"status": null, "keyword": null}
}
```

实现要点：

1. 先按被布置学生集合过滤，再查进度和作答，避免越权读取同机构其他班级学生。
2. 一名学生重复作答时，完成状态按最新有效提交，正确率按第 11 节确认的统计口径。
3. 未开始的学生不能通过缺失 progress 记录简单丢弃，应补出状态行。
4. 前端作业列表显示班级完成数、未完成数和完成率；点击后进入 `mission-progress.vue`，支持学生姓名、状态、正确率筛选。

### 6.6 P1-06 学生单题提交和全部提交

当前学生端已有单题提交基础，P1 需要把交互和接口语义固定下来：

1. 单题提交：保存当前题目 attempt，返回判分/待批阅状态；提交后允许查看结果，但是否允许修改必须由作业规则控制。
2. 全部提交：提交整份作业状态，后端检查是否所有必答题已有有效提交；未完成时返回缺题列表，不改变任务完成状态。
3. 客观题可自动判分；主观题为 `pending_review`，不能在未批阅时统计为正确。
4. 重复点击必须幂等：前端按钮锁定，后端使用 attempt/幂等键或状态校验避免重复创建。
5. 学生提交原题或查看答案后，关联题入口只返回该题有权限访问的候选题；不得把教师端 AI 推荐的内部数据直接暴露给学生。
6. 现有 `/api/v1/questions/<question_id>/similar/` 不能直接作为该入口，因为它只校验登录且是通用题库响应；应新增学生上下文接口，或在现有候选 service 外包一层学生作业/错题权限校验，明确返回题干、选项、图片、知识点和是否可练习字段。
7. 学生端需要补充实际入口状态：答题结果页、任务详情或错题详情中，在原题提交/查看答案后显示“关联题/同类题”按钮；仅存在后端接口而没有页面入口不算完成。
8. 家长只读权限继续沿用现有 `IsStudentOnly` 与 `IsStudentOrParentContext` 边界，家长不能代替学生提交。

### 6.7 P1-07 学生批量导入班级

#### 推荐文件格式

模板列：


#### 数据和接口

建议增加导入任务/结果表，而不是在一次请求中同步处理大文件：

```text
StudentImportTask
- id UUID
- institution / class_obj
- uploaded_by
- file_path
- status uploaded/validating/partially_succeeded/succeeded/failed
- total_count / success_count / failed_count
- error_file_path
- created_at / completed_at
```

接口：

```text
GET  /api/v1/classes/{class_id}/students/import-template
POST /api/v1/classes/{class_id}/students/import
GET  /api/v1/student-imports/{task_id}
GET  /api/v1/student-imports/{task_id}/errors
```

处理规则：

1. 文件类型、大小、列名和最大行数先校验；
2. 手机号格式、姓名长度、学号长度和班级归属逐行校验；
3. 手机号作为默认唯一匹配字段，学号只作为辅助匹配；最终唯一规则必须由业务确认；
4. 已存在学生不重复创建账号，按“加入班级/恢复班级关系/更新允许字段”处理；不覆盖学生登录凭据；
5. 重复行、无效行、班级不匹配行分别返回错误码和原始行号；
6. 成功行和失败行分开统计，支持下载错误结果；
7. 使用事务分批提交，失败不回滚已经成功的合法行，但任务状态必须清楚标记为部分成功；
8. 机构、班级和操作者权限在接口和异步任务执行前后都校验。

## 7. 阶段 3：P2-A 内容关系和讲义能力

### 7.1 P2-A-01 题目与知识点自动匹配

#### 数据建议

现有 `ExamQuestion.knowledge_points` 是 JSON，短期先兼容，不在第一期强制替换。新增匹配记录表：

```text
QuestionKnowledgeMatch
- id UUID
- question FK ExamQuestion
- knowledge_point FK KnowledgePoint，可空
- source manual/import/rule/ai
- confidence Decimal(5,4)，可空
- status suggested/confirmed/rejected
- evidence JSON，可空（命中的关键词、模型版本、规则版本）
- confirmed_by / confirmed_at，可空
- created_at / updated_at
唯一建议：question + knowledge_point + source_version
```

稳定后再考虑把已确认结果同步回 `ExamQuestion.knowledge_points`，以兼容旧查询。旧数据没有知识点时，不应自动静默改写，先生成 `suggested` 待确认记录。

#### 匹配流水线

```text
导入/编辑题目
  → 规范化学科、学段、年级、题型、题干、选项、已有标签
  → 规则初筛知识树范围
  → 关键词/向量/AI 匹配
  → 生成候选和置信度
  → 教师批量确认/修改/撤销
  → 写入确认关系并刷新题目搜索索引
```

第一期只实现规则+人工确认：学科/学段/年级过滤、知识点名称和章节关键词命中、已有手工标签辅助。AI 只在候选不足或需要语义匹配时接入，必须有超时、费用和失败降级。

#### 接口

```text
POST /api/v1/questions/knowledge-matches/preview
POST /api/v1/questions/knowledge-matches/batch-confirm
POST /api/v1/questions/{id}/knowledge-matches/rebuild
GET  /api/v1/questions/knowledge-matches/pending
```

结果必须包含 `confidence、status、source、evidence`；无法匹配进入待处理列表，不能丢失。

### 7.2 P2-A-02 题库勾选生成讲义

### 7.3 P2-A-03 课程、讲义和多个班级关联

当前课程只有 `Course.teacher`，没有班级关系；建议新增：

```text
CourseClass
- course
- class_obj
- status active/removed
- created_at
唯一：course + class_obj

CourseHandout
- course
- handout
- sort_no
- status active/removed
唯一：course + handout
```

班级讲义不直接复制题目；通过课程/讲义关系复用内容，班级作业发布时再生成带快照的任务题目。一个班级可以使用同一课程的不同讲义和不同作业截止时间。

实施前先修正现有 `CourseSerializer.get_class_count` 的语义：当前实现返回 `obj.tree_nodes.count()`，这实际上是课程目录节点数量。新增 `CourseClass` 后，`class_count` 必须改为按有效课程-班级关系统计，并补充回归测试，避免课程列表继续显示错误的班级数。

## 9. 阶段 5：P2-C 学生作答关联题和学情报告

### 9.1 统计口径先行

在开发报告前必须确认并固化以下定义：

| 指标 | 建议默认口径 |
|---|---|
| 正确率 | 只统计已提交且非主观待批阅的有效 attempt；默认取每题最后一次有效作答 |
| 首次正确率 | 每题第一次有效提交，用于前后对比 |
| 最终正确率 | 每题最后一次有效提交，用于当前掌握情况 |
| 作业完成率 | 已提交必答题人数 / 被布置学生数 |
| 学生完成状态 | 未开始、进行中、已提交、已批改；逾期为派生标签 |
| 知识点练习次数 | 题目有效作答按题目关联知识点展开计数；多知识点题按每个知识点计一次 |
| 主观题 | 未批阅不纳入正确率，纳入提交和待批阅数 |
| 班级对比 | 同一讲义/作业、同一统计口径下的班级聚合与个人结果 |

如果总监选择“全部作答平均”或“首次作答”，必须通过 `metric_version` 记录版本，历史报告不能无提示地改变。

### 9.2 报告数据服务

不要在多个页面各自拼 SQL。建议新增 `apps/analytics` 或在 `apps/study` 下建立独立统计 service：

```text
QuestionAttemptMetric
KnowledgeMetric
MissionMetric
HandoutMetric
StudentLearningSnapshot
```

第一期可以实时聚合，数据量增长后用 Celery 生成日/作业快照。所有聚合函数接收统一范围参数：`institution_id、teacher_id、class_id、student_id、mission_id、handout_id、date_range、metric_version`。

### 9.3 报告接口

```text
GET /api/v1/analytics/classes/{class_id}/overview
GET /api/v1/analytics/missions/{mission_id}
GET /api/v1/analytics/handouts/{handout_id}
GET /api/v1/analytics/students/{student_id}
GET /api/v1/analytics/knowledge-points
GET /api/v1/analytics/wrongbook-retry-comparison
```

返回至少包含：

- 班级整体正确率、错误率、完成率；
- 学生个人正确率、错误率、作业状态；
- 每题作答人数、正确人数、正确率、待批阅数；
- 每知识点练习次数、正确率、薄弱等级；
- 讲义整体表现和班级/个人对比；
- 错题重做前后首次/最终正确率；
- 精练作业完成率和正确率；
- 统计时间、统计口径版本和数据是否完整。

### 9.4 多端展示权限

| 角色 | 可查看 |
|---|---|
| 教师 | 自己有权限的班级、作业、讲义和学生统计；不能查看无关机构数据 |
| 机构管理员 | 机构范围内按授权查看汇总和教师/班级统计；是否可查看个人答题内容需单独确认 |
| 学生 | 自己的作业、错题、知识点掌握和成长趋势 |
| 家长 | 当前绑定孩子的只读报告；不能代替学生答题、提交或修改掌握度 |

前端页面建议复用现有 `learning-stats.vue` 扩展为分层页面，家长使用 `/pages/parent/*` 只读页面，不能把教师统计页面直接开放给家长。

## 10. 关键接口和权限约定

### 10.1 接口通用约定

所有新增接口统一：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "meta": {},
  "trace_id": "16位或UUID追踪标识"
}
```

错误至少区分：参数错误 400、未登录 401、无权限 403、资源不存在 404、冲突 409、限流 429、服务依赖失败 503。

POST/PUT/PATCH 的路径必须明确是否带末尾斜杠，前端 API 封装和 Nginx 规则保持一致；当前项目已存在无斜杠和带斜杠兼容路由，新增接口不再继续扩大不一致。

### 10.2 权限分层

1. 身份权限：JWT、`active_role`、账号状态、角色授权。
2. 机构权限：用户是否是目标机构成员，教师是否管理目标班级/课程。
3. 内容范围：学科、学段、年级、题目审核状态和课程归属。
4. 数据对象：班级学生集合、作业目标学生集合、家长当前有效孩子。
5. 操作权限：查看、编辑、发布、批阅、导出、导入分别控制。

后端每个查询必须显式先构造授权 queryset，再叠加筛选条件；不能先按前端传入 ID 查询后再补权限判断。

### 10.3 学生和家长边界

- 学生可提交自己的任务和个人精练作业；
- 家长可查看绑定孩子的数据，可为孩子生成个人精练草稿（如果业务确认），但默认不能代答、提交、上传答题照片或修改掌握度；
- 家长请求不能通过传入 `student_id` 绕过当前上下文；
- 教师不能调用学生个人精练接口伪造学生作答；教师布置的精练走任务域。

| B08 | 错题来源和数量调整 | 阶段 4 使用作业学情矩阵标记错题；默认最多生成 3 道关联题，教师可调整数量作为后续扩展，本阶段不开发 |
| B09 | 正确率口径 | 默认最后一次有效提交；同时保留首次正确率用于前后对比 |
| B10 | 讲义是否可直接对外发布 | 默认不能，先关联课程/班级并发布 |
| B11 | 报告可见范围 | 教师看授权班级，管理员看机构汇总，家长只看绑定孩子 |
| B12 | AI 费用和调用上限 | 机构级每日/每月配额，超限自动降级规则推荐 |

## 12. 数据迁移、兼容和回滚

### 12.1 迁移原则

1. 所有模型变化先生成迁移，再编写数据迁移和反向策略；
2. 大表数据迁移分批执行，避免长事务锁表；
3. 新字段先可空/有默认值，代码双读/双写稳定后再考虑收紧约束；
4. 旧接口保持至少一个发布周期，前端迁移完成并有访问日志后再下线；
5. JSON 历史字段不能一次性转换后删除，先建立可回溯关系表。

### 12.2 重点迁移

- 多班级：由 `LearningMission.class_obj` 生成 `MissionClassAssignment`；
- 教师范围：兼容 `subject` 单值和 `subjects` 多值，兼容历史缺失 `stages`；
- 标签：把历史 `ExamQuestion.tags` 与 `QuestionTagRelation` 对账，缺关系的历史标签先补关系，冲突保留审计；
- 讲义：已存在课程题目关系不直接当作讲义，创建讲义快照时记录来源；
- PDF：旧路径继续可访问，新生成使用新命名；不要批量重生成所有历史 PDF；
- 错题矩阵：教师标记“×”时创建或更新原 `WrongBookItem`，矩阵单元格保存来源关系；取消标记不删除错题历史。

### 12.3 回滚

- P0 前端路由：恢复旧页面入口和前端构建产物即可，数据库无变更；
- Word 转换：保留原始文件和旧预览路径，切换 feature flag 到旧服务；
- PDF：旧 PDF 路径保留，新路径只影响新生成文件；
- 多班级关系：代码回滚前保留旧 `class_obj`，迁移不得删除；
- 新作业/讲义/报告功能：通过 feature flag 关闭入口，数据保留，不物理删除；
- 每次生产发布前保留数据库备份、媒体文件清单、迁移版本和前端构建版本。
