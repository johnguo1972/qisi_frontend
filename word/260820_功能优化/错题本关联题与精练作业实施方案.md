# 错题本关联题与精练作业实施方案

## 1. 文档目的

本文档用于实施以下新增功能：

1. 学生在错题本中选择“加入关联题”，系统推荐最多 3 道与原错题同学段、同学科、同主知识点且难度相同或上下相差一星以内的题目。
2. 原题和关联题均展示题型、难度、知识点、标签等描述，帮助学生选择。
3. 选择后的题目进入学生自己的“精练列表”。
4. 学生可以从精练列表选择题目组成精练作业，在线练习或导出 PDF 后线下练习。
5. 学生完成纸质精练作业后，可以拍照上传。
6. 家长在已选择孩子，或当前账号同时拥有学生角色并选择“我的学生身份”时，也可以查看孩子的错题/关联题，并为该有效学生生成精练作业和 PDF。
7. 学生端新增“精练题”菜单，位置紧跟在“错题本”之后。
8. 功能覆盖 H5、APP 和微信小程序，不改变教师作业、教师 PDF、现有错题本和现有任务答题业务。

本方案只规划和设计，不直接修改现有业务代码。实施时应按照本文档分阶段开发、测试和发布。

## 2. 当前代码核查结论

### 2.1 已有的旧关联题能力与本次边界

当前项目已经存在关联题推荐基础能力：

- 服务：`apps/wrongbook/services.py` 的 `find_variant_questions(question_id, limit=3)`。
- 接口：`apps/wrongbook/views.py` 的 `wrongbook_variants`。
- 路由：`/api/v1/student/wrong-book/<wrong_item_id>/variants/`。
- 前端页面：`uniapp/src/pages/student/wrongbook-variants.vue`。
- 在线练习提交：`apps/wrongbook/variant_views.py` 的 `variant_submit`。

以上能力属于现有“同类题练习”业务，本次不改造其筛选逻辑、接口契约或提交链路。当前逻辑不能直接满足本次“错题本选择并加入精练列表”的新需求：

1. 原题存在 `knowledge_points` 时，当前查询按 `module` 做“命中任一知识点”的匹配，并未同时要求同学段、同学科和允许的难度范围。
2. 匹配不足时会降级为其他条件，可能返回不满足本次“同学段/同学科/知识点/难度”规则的题目。
3. 原题或关联题的返回结构没有统一返回学段、知识点名称、难度标签和 tags。
4. 当前返回的是临时推荐结果，没有“加入精练列表”的持久化记录。
5. 当前 `variant_submit` 会写入 `AnswerAttempt`，并更新错题的复习状态和掌握度；它适合现有“同类题练习”链路，不应直接作为新精练作业的提交入口，否则可能影响现有任务进度、错题状态和掌握度统计。

本次新增独立的错题本候选题接口，不调用上述旧接口和 `find_variant_questions`：

```text
GET /api/v1/practice/wrong-book/<wrong_item_id>/candidates/
```

该接口只负责“错题本中选择关联题”的候选查询，使用新的严格筛选服务；候选题被用户明确选择后，再通过精练池接口持久化。现有 `/api/v1/student/wrong-book/<wrong_item_id>/variants/` 和旧页面继续按原逻辑运行，确保历史同类题练习不受影响。

### 2.2 关联数据现状

当前题目数据已经具备新功能所需的主要字段：

- `apps/parser/models.py` 的 `ExamQuestion.knowledge_points`：JSONField。
- `ExamQuestion.difficulty`：DecimalField。
- `ExamQuestion.tags`：JSONField。
- `ExamQuestion.question_type`：题型编码，并有 `QUESTION_TYPE_LABELS` 中文映射。
- `ExamQuestion.paper.stage`：题目所属试卷的学段字段，作为初中/高中匹配来源；如果题目没有关联试卷或学段为空，不能直接推断学段。
- `QuestionOption`、`QuestionImage`：用于在线题目和 PDF 展示。
- `apps/study/models.py` 中已有 `QuestionTag`、`QuestionTagRelation`，并会同步题目的 JSON tags。

因此，第一期不需要新增题目关联表，也不需要改造题库表。推荐算法直接从现有 `ExamQuestion` 数据读取。未来如果需要接入独立的推荐/关联题服务，应通过 `RecommendationProvider` 适配层替换数据来源，不修改精练列表和精练作业的数据结构。

### 2.3 已有精练/纸张/PDF能力及边界

当前项目存在以下可复用能力：

- `apps/qrcode/models.py` 的 `WrongbookPracticeSheet`：围绕一个错题保存原题和最多 3 道关联题。
- `apps/qrcode/views.py` 的 `create_practice_sheet`、`practice_sheet_info`、`submit_practice_sheet`：支持现有错题练习单。
- `apps/qrcode/views.py` 的 `PaperScanBatch`、`PaperScanPage`：面向教师批量扫描作业，绑定 `LearningMission` 和教师操作人。
- `apps/study/student_views.py` 的 `export_pdf`、`_build_pdf`：已有错题本/教师作业 PDF 生成，当前简答题已经预留 50mm 空白区域。
- `uniapp/src/pages/student/export.vue`：已有学生端 PDF 导出页面。
- `uniapp/src/pages/student/paper-scan.vue`、`practice-sheet.vue`：已有纸张上传和错题练习单入口。

这些代码不能直接承载完整的新需求：

1. `WrongbookPracticeSheet` 通过 `wrong_item` 固定一个错题，无法保存多个错题及多个关联题的有序题组。
2. `PaperScanBatch` 的 `mission` 是必填字段，且由教师创建，不能让学生为个人精练作业创建安全的上传批次。
3. 当前学生 PDF 接口支持 `wrongbook` 和 `mission`，不支持有持久化题组的精练作业，也不能只凭前端传题目 ID 生成个人题组。

结论：复用现有 PDF 底层排版和图片处理能力，但新增独立的精练作业数据域；不复用教师任务表，也不把新数据强行写入现有 `WrongbookPracticeSheet`。

## 3. 业务规则

### 3.1 关联题筛选规则

关联题推荐必须由后端执行，前端不能自行筛选或信任题目 ID。

对每个错题执行以下规则：

1. 排除原题本身。
2. 候选题学段必须与原题一致。学段从 `ExamQuestion.paper.stage` 读取，并统一归一化为“初中”或“高中”；原题或候选题学段为空、无法归一化时，不作为符合条件的候选题，并在不足原因中说明。
3. 候选题学科必须与原题一致；如果原题有学科，候选题学科不一致时不返回。
4. 难度允许适度放宽，但不能无限放宽：
   - 候选题难度与原题相同，或与原题上下相差 1 个难度星级以内，均可返回；
   - 使用后端统一的难度星级归一化值比较，核心条件为 `abs(candidate_star - original_star) <= 1`；
   - 同难度优先，其次优先略难一星，再考虑略简单一星；
   - 原题或候选题难度为空、无法转换为星级时，不纳入候选，不自动放宽规则。
5. 解析知识点标识：优先使用 `id`，没有 id 时使用 `module`，再没有时使用 `name` 或字符串值。
6. 主知识点规则：
   - 原题只有一个有效知识点时，候选题至少命中该知识点 1 个；
   - 原题有两个及以上有效知识点时，候选题至少与原题命中 2 个知识点；
   - 不允许仅因为“同学段+同学科+难度接近”就绕过知识点规则进入推荐结果。
7. 过滤已在当前学生精练列表中的题目，避免重复推荐；如果业务希望允许重复，应由后端显式返回 `already_added`，默认不重复加入。
8. 只从当前题库中允许学生查看的题目中筛选，至少过滤无题干、已删除/不可见或未达到题库发布/复核要求的记录；具体可见状态沿用现有题库访问规则。
9. 按匹配知识点数量降序、难度匹配等级（同难度优先、略难一星次之、略简单一星再次）、题目稳定 ID/题库排序稳定排序，最多返回 3 道。
10. 如果符合条件的题目不足 3 道，返回实际数量，并返回 `insufficient_reason`；不能用不符合规则的题目补足 3 道。

推荐结果应包含：

```json
{
  "id": "题目ID",
  "question_no": "题号",
  "question_type": "single_choice",
  "question_type_label": "单选题",
  "difficulty": 3.0,
  "difficulty_label": "中等",
  "stage": "初中",
  "subject": "物理",
  "knowledge_points": [
    {"id": "...", "module": "力学", "name": "速度"}
  ],
  "knowledge_point_labels": ["力学", "速度"],
  "tags": ["易错题", "期末复习"],
  "stem": "题干",
  "stem_html": "题干HTML",
  "images": [],
  "options": [],
  "match": {
    "matched_knowledge_point_count": 2,
    "required_knowledge_point_count": 2,
    "same_stage": true,
    "difficulty_delta": 0,
    "difficulty_match": "same",
    "already_in_practice_pool": false
  }
}
```

答案、解析不返回给题目选择卡片；在线练习提交后按权限返回判分结果。PDF 默认不包含答案，是否生成答案卷应作为独立的受权限控制参数。

### 3.2 精练列表规则

精练列表是学生级别的题目池，不等同于教师布置的作业：

- 所有权归有效学生账号。
- 学生通过错题关联题选择加入。
- 本期默认只把用户勾选的关联题加入列表；原错题如需加入，应提供单独的“加入原错题”按钮，不能在点击关联题选择时静默加入原题。
- 同一个学生同一道题只能存在一条池记录，使用唯一约束防止重复。
- 删除精练列表题目不会删除错题本、题库题目和历史精练作业。
- 已经加入某个精练作业的题目从列表删除时，不删除作业中的题目快照/关系。

### 3.3 精练作业规则

学生或家长从精练列表选择题目组成精练作业：

- 创建时保存题目顺序，PDF 和在线练习均按该顺序。
- 创建后的作业保存完整题目展示快照，至少包含题干/HTML、选项、题图相对路径、题型、难度、知识点和标签；题库题目后续更新不能导致历史 PDF 内容不可追溯。题目 ID 仍用于关联原题，快照用于历史作业展示和 PDF 重建。
- 精练作业状态建议为：`draft` 草稿、`active` 可练习、`completed` 已完成、`archived` 已归档。
- 创建后可以直接在线练习，也可以导出 PDF。
- 简答题只在 PDF 中增加 50mm 作答空白区域；单选、多选、判断、填空、计算等题型不额外增加该空白区域。
- 学生线下完成后上传照片，上传记录挂在该精练作业及题目下，不写入教师作业扫描批次。

### 3.4 学生与家长权限

统一通过“有效学生”解析业务数据：

- 学生角色登录：有效学生为当前账号。
- 家长角色登录：有效学生为家长上下文中已选择的孩子。
- 同一账号同时拥有学生/家长角色：进入家长端并选择“我的学生身份”时，有效学生为当前账号，不要求绑定自己，也不显示“请先绑定孩子”。

权限建议：

| 操作 | 学生角色 | 家长角色/有效孩子 | 教师/管理员 |
|---|---|---|---|
| 查看错题及关联题 | 允许 | 允许 | 不在本期范围 |
| 加入精练列表 | 允许 | 允许，写入有效孩子名下 | 不允许通过本接口 |
| 创建精练作业 | 允许 | 允许，创建到有效孩子名下 | 不在本期范围 |
| 导出精练 PDF | 允许 | 允许 | 不在本期范围 |
| 在线提交精练作业 | 允许 | 默认不允许代替学生答题 | 不允许 |
| 上传学生作答照片 | 允许 | 默认不允许代替学生上传 | 不允许 |

家长端“可以生成精练作业”的含义是可以为已选孩子组卷和导出；不应因为家长可以查看/生成，就自动获得学生提交答案或修改学生掌握度的权限。

## 4. 推荐的数据模型

建议新增 Django app：`apps/practice`，作为个人精练域。这样可以与 `apps/wrongbook`、`apps/missions` 解耦，避免教师作业和现有错题提交逻辑受到影响。

### 4.1 `PracticePoolItem` 精练列表题目

表名建议：`practice_pool_item`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | UUIDField | 主键，沿用项目 UUID7 |
| `student_user` | FK UserAccount | 有效学生，级联删除 |
| `question_id` | UUIDField | 指向 `ExamQuestion`，建议建索引；项目现有题目关系多处使用 UUID 非 FK，保持一致 |
| `source_wrong_item` | FK WrongBookItem | 可空，记录从哪一道错题进入 |
| `source_type` | varchar(30) | `original_wrong` / `recommended_variant` / `manual` |
| `recommendation_snapshot` | JSONField | 可空，保存匹配知识点数、规则版本等审计信息 |
| `display_snapshot` | JSONField | 保存题型、难度、知识点、标签、题干、选项、题图路径等完整展示快照 |
| `status` | varchar(20) | `active` / `removed` |
| `created_at` | DateTimeField | 创建时间 |
| `updated_at` | DateTimeField | 更新时间 |

约束和索引：

- 唯一约束：`student_user + question_id`。
- 索引：`student_user + status + created_at`。
- 删除精练列表项使用软删除或物理删除均可，建议软删除，便于历史审计；再次加入时恢复 `active`。

### 4.2 `PracticeSet` 精练作业

表名建议：`practice_set`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | UUIDField | 主键 |
| `student_user` | FK UserAccount | 作业所属有效学生 |
| `created_by_user` | FK UserAccount | 实际操作账号，学生或家长 |
| `created_via_role` | varchar(20) | `student` / `parent` |
| `title` | varchar(200) | 由前端输入或默认“错题精练-日期” |
| `status` | varchar(20) | `draft` / `active` / `completed` / `archived` |
| `question_count` | PositiveIntegerField | 冗余统计，创建/变更时维护 |
| `answered_count` | PositiveIntegerField | 冗余统计，按唯一有效答题更新 |
| `progress_percent` | DecimalField(5,2) | `answered_count / question_count * 100` |
| `pdf_file_path` | varchar(500) | 最新 PDF 路径，可空 |
| `pdf_version` | PositiveIntegerField | 题目顺序或内容变更时递增 |
| `created_at` | DateTimeField | 创建时间 |
| `updated_at` | DateTimeField | 更新时间 |
| `completed_at` | DateTimeField | 可空 |

索引：`student_user + status + updated_at`。

### 4.3 `PracticeSetItem` 精练作业题目

表名建议：`practice_set_item`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | UUIDField | 主键 |
| `practice_set` | FK PracticeSet | 级联删除 |
| `pool_item` | FK PracticePoolItem | 可空，`on_delete=SET_NULL`；作业创建后仍保留题目关系 |
| `question_id` | UUIDField | 冗余保存题目 ID，便于历史作业不受列表删除影响 |
| `sort_no` | PositiveIntegerField | 从 1 开始，唯一约束为 `practice_set + sort_no` |
| `source_type` | varchar(30) | 从列表来的原题/关联题/手工题 |
| `display_snapshot` | JSONField | 题型、难度、知识点、标签、题干、选项、题图路径等完整展示快照 |
| `created_at` | DateTimeField | 创建时间 |

约束：

- `practice_set + sort_no` 唯一。
- `practice_set + question_id` 唯一，防止一个精练作业重复同题。

### 4.4 `PracticeAttempt` 精练在线/线下提交记录

表名建议：`practice_attempt`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | UUIDField | 主键 |
| `practice_set` | FK PracticeSet | 所属精练作业 |
| `set_item` | FK PracticeSetItem | 所属题目 |
| `student_user` | FK UserAccount | 实际答题学生，只能是作业所属学生 |
| `answer_content` | JSONField | 选择项/文本/判断等统一结构 |
| `submit_source` | varchar(20) | `online` / `photo` / `paper` |
| `attempt_no` | PositiveIntegerField | 同一作业题目的第几次尝试 |
| `is_correct` | BooleanField | 客观题判分结果 |
| `is_subjective_pending` | BooleanField | 简答/论述等待人工处理 |
| `score` | DecimalField(5,2) | 可空或默认 0 |
| `status` | varchar(20) | `draft` / `submitted` / `pending_review` / `graded` |
| `submitted_at` | DateTimeField | 可空 |
| `created_at` | DateTimeField | 创建时间 |

建议唯一规则：同一 `set_item` 可保留多次尝试，但列表进度按“至少有一次已提交”统计，避免重复点击导致进度异常。

### 4.5 `PracticeAttemptImage` 线下作答照片

表名建议：`practice_attempt_image`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | UUIDField | 主键 |
| `attempt` | FK PracticeAttempt | 级联删除 |
| `student_user` | FK UserAccount | 冗余权限字段 |
| `image_path` | varchar(1000) | 相对 MEDIA_ROOT 路径 |
| `page_no` | PositiveIntegerField | 页码 |
| `blur_score` | DecimalField(5,2) | 可空 |
| `is_blurry` | BooleanField | 默认 false |
| `upload_status` | varchar(20) | `uploaded` / `completed` / `rejected` |
| `created_at` | DateTimeField | 创建时间 |

唯一约束：`attempt + page_no`。

本表独立于 `apps/qrcode.AttemptImage`，不改变现有教师作业扫描和学生任务答题图片逻辑。若后续确实需要“整份精练卷带二维码后一次上传多页”，再增设 `PracticePaperCode`/`PracticePaperPage`，不要复用必填教师 `mission` 的 `PaperScanBatch`。

### 4.6 是否修改现有表

第一期建议不修改以下现有表：

- `ExamQuestion`：现有知识点、难度、标签字段足够。
- `WrongBookItem`：只作为来源，不新增精练状态字段。
- `LearningMission`、`MissionLevel`、`MissionQuestionRel`：继续只服务教师布置作业。
- `AnswerAttempt`、`StudentMissionProgress`：新精练答题写入 `PracticeAttempt`，不污染教师作业进度。
- `WrongbookPracticeSheet`、`PaperScanBatch`：保留兼容现有功能。

如后续统计需要统一查看所有个人精练作业，再单独做报表视图，不把新业务字段塞入教师任务表。

模块职责：

### 5.2 有效学生上下文必须统一

当前 `IsStudentOrParentContext` 已把有效学生放到 `request._effective_student`，但 `apps/wrongbook/views.py` 中仍有代码直接按 `request.user` 查询。实施时必须：

1. 新精练接口统一调用 `effective_student_user(request)` 或读取 `request._effective_student`。
2. 新的错题本候选题接口、精练列表和精练作业接口必须按有效学生查询；现有旧错题/旧 `/variants/` 业务不在本次新接口改造范围内，避免改变既有同类题练习行为。若后续修复旧接口的家长上下文，应单独评审并补回归测试。
3. 写操作使用“有效学生”作为数据归属，使用 `request.user` 作为审计操作者。
4. 家长没有有效孩子上下文时返回明确错误，例如 `PARENT_CONTEXT_REQUIRED`，不能返回空列表掩盖权限问题。
5. 同账号学生/家长切换到“我的学生身份”时，校验当前账号拥有 `student` 角色，再把本人作为有效学生；不能走自绑定流程。

### 5.3 推荐接口

#### 5.3.1 旧关联题接口：保持原样

以下接口属于现有同类题练习业务，本次不改 URL、筛选逻辑、响应字段和提交关系：

```text
GET /api/v1/student/wrong-book/<wrong_item_id>/variants/
```

旧页面 `wrongbook-variants.vue` 继续读取原有 `data` 数组，旧的 `variant-submit` 继续使用原有 `AnswerAttempt` 链路。这样可以保证已有同类题练习功能和业务逻辑不受影响。

#### 5.3.2 新增错题本候选题接口

本次新增专门用于“错题本选择关联题”的接口，不复用旧 `/variants/` 接口：

```text
GET /api/v1/practice/wrong-book/<wrong_item_id>/candidates/
```

该接口由 `apps.practice` 提供，调用新的 `WrongbookCandidateProvider`，严格执行同学段、同学科、知识点命中和难度上下相差一星以内的规则。它只返回候选数据，不自动写入精练列表；用户选择后再调用 `POST /api/v1/practice/pool/items`。

新接口响应契约固定为“`data` 始终是数组，附加信息放在同级 `meta`”：

```json
{
  "data": [{"...": "关联题元数据"}],
  "meta": {
    "original": {"id": "错题ID", "question": {"...": "..."}},
    "stage": "初中",
    "difficulty_rule": "same_or_within_one_star",
    "limit": 3,
    "returned_count": 3,
    "insufficient_reason": null,
    "algorithm_version": "wrongbook-candidate-v1"
  }
}
```

第一期不新增 `items` 替代 `data`，也不依赖响应头传递业务数据；新页面读取新接口的 `data`，需要原题、学段、难度规则和不足原因时读取 `meta`。旧页面和新页面完全分离。

推荐服务接口：

```python
class WrongbookCandidateProvider:
    def recommend_for_wrong_item(self, *, student, wrong_item, limit=3):
        ...
```

第一期实现为 `QuestionBankWrongbookCandidateProvider`，读取 `ExamQuestion` 及其关联 `ExamPaper.stage`；未来外部关联题服务只替换该 provider，不改旧 `/variants/` 接口、旧页面和精练表。

### 5.4 精练列表接口

建议统一挂载到 `/api/v1/practice/`：

```text
GET    /api/v1/practice/pool
POST   /api/v1/practice/pool/items
DELETE /api/v1/practice/pool/items/<uuid:item_id>
POST   /api/v1/practice/pool/items/batch-remove
```

加入请求示例：

```json
{
  "items": [
    {
      "question_id": "题目UUID",
      "source_wrong_item_id": "错题UUID",
      "source_type": "recommended_variant",
      "recommendation_token": "后端返回的短期校验凭证"
    }
  ]
}
```

后端处理：

1. 校验当前有效学生。
2. 校验来源错题属于该学生。
3. 重新执行推荐规则，确认 `question_id` 是该错题允许的推荐题；不能只相信前端传入的题目 ID。
4. 使用 `transaction.atomic()` 和唯一约束批量新增/恢复池记录。
5. 保存推荐匹配快照和题目展示快照。
6. 返回新增、已存在、无权限、推荐失效等逐项结果。

### 5.5 精练作业接口

```text
GET  /api/v1/practice/sets
POST /api/v1/practice/sets
GET  /api/v1/practice/sets/<uuid:set_id>
POST /api/v1/practice/sets/<uuid:set_id>/activate
POST /api/v1/practice/sets/<uuid:set_id>/submit
```

创建请求：

```json
{
  "title": "物理错题精练",
  "pool_item_ids": ["池题目1", "池题目2", "池题目3"],
  "status": "active"
}
```

处理要求：

- 服务端按请求数组顺序创建 `PracticeSetItem.sort_no`。
- 校验所有池题目属于同一个有效学生。
- 去重并限制最大题数，例如 50 道；超过上限返回 400。
- 创建、题目关系、统计字段在一个事务中完成。
- 家长创建时 `student_user` 使用有效孩子，`created_by_user` 使用家长账号。
- 列表返回题目数、已答数、进度百分比、PDF 是否存在、最近操作时间。

### 5.6 在线练习接口

```text
GET  /api/v1/practice/sets/<uuid:set_id>/questions
POST /api/v1/practice/sets/<uuid:set_id>/items/<uuid:set_item_id>/attempts
GET  /api/v1/practice/sets/<uuid:set_id>/progress
```

提交时必须校验：

- 当前为学生会话；
- 精练作业属于当前学生；
- `set_item_id` 确实属于该作业；
- 题目 ID 与 `PracticeSetItem.question_id` 一致；
- 题型对应的答案格式合法。

判分可以复用 `apps/study/answer_views.py` 的客观题判分规则，但应抽取为无副作用的纯函数或适配调用：

- 单选、多选、判断、填空：自动判分；
- 简答、论述、计算、证明等：`is_subjective_pending=true`，不能自动判错并写入错题本；
- 新精练答题只写 `PracticeAttempt`，不更新 `LearningMission`、`StudentMissionProgress`、`WrongBookItem` 和现有 `AnswerAttempt`；
- 进度按该精练作业中“至少提交过一次”的题目数计算。

### 5.7 PDF 接口

```text
POST /api/v1/practice/sets/<uuid:set_id>/export-pdf
GET  /api/v1/practice/sets/<uuid:set_id>/pdf
```

建议采用服务端按 `PracticeSetItem.sort_no` 读取题目，不能接收任意题目 ID 列表直接导出。PDF 参数：

```json
{
  "include_answers": false,
  "watermark_text": ""
}
```

生成逻辑：

1. 查询当前用户有权限访问的精练作业。
2. 按 `sort_no` 获取题目，不使用无序的 `id__in` 查询结果顺序。
3. 复用现有 `_build_pdf` 的中文字体、题图、选项、页码和 50mm 简答题留白能力；建议将公共排版抽取到 `apps/common` 或 `apps/practice/pdf_service.py`，而不是复制两套排版代码。
4. 精练作业标题、题目序号、题型中文、知识点和难度可以展示；默认不展示答案/解析。
5. 文件保存到 `MEDIA_ROOT/exports/practice_<set_id>_v<version>.pdf`，数据库保存相对路径。
6. 作业题目或顺序发生变化时递增 `pdf_version` 并删除/废弃旧 PDF；仅访问时直接返回已有文件。
7. 按用户限流，且校验文件存在；本地返回 localhost 配置域名，生产返回生产域名，统一走现有媒体 URL 配置，不硬编码生产域名。

### 5.8 线下照片上传

第一期建议采用“精练作业题目级照片上传”，入口为：

```text
POST /api/v1/practice/sets/<uuid:set_id>/items/<uuid:set_item_id>/attempts/draft
POST /api/v1/practice/attempts/<uuid:attempt_id>/images
POST /api/v1/practice/attempts/<uuid:attempt_id>/submit
```

流程：

1. 学生在精练作业详情中选择题目，创建草稿答题记录。
2. 选择一张或多张照片上传，校验 JPEG/PNG/WebP、大小、页码和归属。
3. 调用现有图片清晰度分析能力，保存模糊度结果。
4. 学生确认提交后，将 `submit_source` 设为 `photo`，主观题进入待处理状态。
5. 照片只能被该精练作业所属学生访问；家长端默认只能查看，不代学生提交。

后续若产品要求“整份 PDF 带二维码，拍照后自动识别题目”，再新增个人精练二维码表和专用批次表，二维码 payload 至少包含 `practice_set_id`、`student_id`、随机签名和过期时间。禁止复用教师 `PaperScanBatch.mission` 的强绑定模型。

实际路径以后端路由为准；不要在前端拼接生产域名，继续通过 `getPublicMediaUrl`/媒体配置转换下载地址。

### 6.7 API、媒体地址和上传下载的环境兼容

当前 `uniapp/src/utils/request.ts` 在 APP-PLUS 和 MP-WEIXIN 条件下硬编码生产 API 域名，`uniapp/src/utils/media-url.ts` 也硬编码生产媒体域名；因此当前本地运行 APP/微信小程序时，新接口即使后端运行在本地，也会请求生产服务。这是现有代码的环境问题，必须在实施本功能时一并处理，否则不能宣称三端本地测试已联通。

建议建立统一的构建环境配置：

| 平台 | 开发环境 | 生产环境 | 说明 |
|---|---|---|---|
| H5 | 使用 Vite 代理到本地后端 | 使用站点相对路径或生产域名 | 保持现有相对路径能力 |
| APP | `VITE_API_TARGET`/等价 Uni 构建变量指向本地可访问地址 | 指向生产 API | 手机不能访问电脑 `localhost`，本地测试需使用局域网 IP 或测试域名 |
| 微信小程序 | 指向已配置的测试 HTTPS 域名 | 指向生产 HTTPS 域名 | 需在微信开发者工具配置 request/upload/download 合法域名；真机不能使用 localhost |

要求：

1. `request.ts`、`media-url.ts`、`image-upload.ts` 和精练照片上传代码统一读取同一套 API/媒体配置，不再分别写死生产地址。
2. H5、APP、小程序的 JSON 请求均使用 `request.ts`；文件上传使用 `uni.uploadFile` 或公共 `uploadImage`，但 APP/小程序必须传完整可访问 URL，H5 使用 `fetch + FormData`。
3. PDF 下载地址必须由后端媒体配置返回，并经 `getPublicMediaUrl` 转换；APP/小程序使用 `uni.downloadFile` 后 `uni.openDocument`，H5 使用浏览器打开或下载。
4. 小程序必须验证媒体域名和 PDF 下载域名的 HTTPS、证书、CORS/服务器响应头及文件类型；只在 H5 验证通过不能代表小程序可用。
5. API 路由的尾斜杠策略必须固定。建议新精练路由按文档中的“无尾斜杠”形式同时配置后端和前端，避免 APP/小程序对 POST 301/308 跳转处理不一致。

## 7. 关联题数据操作与快照策略

### 7.1 题目元数据规范化

当前历史数据中的 `knowledge_points` 可能是字符串数组，也可能是包含 `id`、`module`、`name` 的对象数组，tags 也可能为空。后端应集中实现：

```python
normalize_knowledge_points(raw) -> [
    {"id": ..., "module": ..., "name": ..., "key": ...}
]
normalize_tags(raw) -> ["标签1", "标签2"]
```

前端只展示后端规范化后的 `knowledge_point_labels` 和 `tags`，不要各页面各自解析 JSON。

### 7.2 数据来源适配

第一期新接口数据来源为现有题库 `ExamQuestion` 及其所属 `ExamPaper.stage`，通过 `QuestionBankWrongbookCandidateProvider` 读取。旧的 `QuestionBankRecommendationProvider`/`find_variant_questions` 继续只服务旧 `/variants/` 业务，不在本次替换。若未来新接口的“关联题”由另一个团队提供：

- 新增配置项 `WRONGBOOK_CANDIDATE_PROVIDER=question_bank|remote`；
- `remote` provider 将外部结果转换成同一响应结构；
- 后端仍重新校验题目是否可访问、题型/难度/知识点是否符合规则；
- 外部接口失败时返回可识别的 `RECOMMENDATION_SERVICE_UNAVAILABLE`，不静默返回随机题；
- 精练列表和精练作业数据表无需变更，旧 `/variants/` 接口也无需变更。

### 7.3 快照原则

加入精练列表时保存推荐匹配快照；组卷时保存题目展示快照。快照不替代题库原始内容，只用于：

- 显示用户当时选择依据；
- 保证历史精练作业 PDF 可复现；
- 排查推荐规则和题库更新造成的问题。

## 8. 不影响现有功能的隔离措施

1. 新增 `apps.practice` 和独立迁移，不改教师任务模型。
2. 新精练答题不写 `AnswerAttempt`，不更新教师任务进度和错题掌握度。
3. 现有 `wrongbook_variants` 接口继续保留，内部逻辑和响应不改；新需求使用独立的错题本候选题接口。
4. 现有 `variant-submit` 继续支持旧的同类题练习，不删除、不改变其返回字段。
5. 现有 `WrongbookPracticeSheet`、教师 `PaperScanBatch` 和任务 PDF 路径不改；新精练照片使用独立表和接口。
6. PDF 公共排版代码抽取时必须先补回归测试，确保教师、学生错题本 PDF 的题目顺序和简答题 50mm 留白不变化。
7. 所有新增查询均按有效学生过滤，不能只按题目 ID 查询。
8. 家长创建的数据必须记录 `created_by_user` 和 `created_via_role`，便于审计。
9. PDF、照片文件路径不得由前端直接决定；后端生成随机或版本化路径。
10. 新功能建议配置 feature flag，例如 `PRACTICE_ENABLED`；关闭时不影响原错题本和教师端。

## 9. 测试方案

### 9.1 后端单元测试

新增 `apps/practice/tests/`，至少覆盖：

#### 推荐规则

- 同学段、同学科、同难度、同一个主知识点可以推荐。
- 难度相同或上下相差一星以内可以推荐；同难度应优先于略难/略简单一星。
- 原题有两个及以上知识点时，候选必须至少命中两个。
- 只同学段+同学科+难度接近但知识点不匹配的题不能返回。
- 相差超过一星、学段不同或学科不同的题不能返回。
- 原题不出现在结果中。
- 推荐结果最多 3 道且无重复。
- 只有 1 道或 2 道符合条件时，不用不符合规则的题补足。
- 原题或候选题缺少有效学段/难度时，返回不足原因，不自动放宽条件。
- 历史字符串、对象、空值知识点均能稳定处理。
- tags 为空、字符串数组、重复 tags 均能稳定返回。

#### 旧功能隔离

- 旧 `/api/v1/student/wrong-book/<wrong_item_id>/variants/` 的结果和旧 `variant-submit` 链路保持回归通过。
- 新 `/api/v1/practice/wrong-book/<wrong_item_id>/candidates/` 单独测试同学段、难度容差和知识点命中规则。

#### 权限和上下文

- 学生只能查看和修改自己的精练池。
- 家长选择孩子后只能访问该孩子。
- 同账号同时有学生/家长角色，家长“我的学生身份”能访问本人数据。
- 家长没有有效孩子上下文时不能访问其他学生，也不能创建数据。
- 学生/家长不能凭题目 ID添加不属于推荐结果的题目。
- 教师和管理员不能通过学生精练接口越权访问学生个人数据。

#### 精练列表和组卷

- 批量加入是事务操作。
- 重复加入幂等，不产生重复记录。
- 删除列表项不删除历史精练作业题目。
- 组卷按请求顺序保存。
- 空题组、重复题、跨学生题目、超过上限均返回明确错误。
- 家长创建的作业归有效孩子，审计人是家长。

#### 在线练习

- 只能提交属于当前精练作业的题目。
- 客观题判分结果正确。
- 主观题进入待处理，不自动进入错题本。
- 进度按已提交题目数计算，重复提交不重复增加进度。
- 精练提交不改变教师任务进度、错题状态、MasteryRecord 和现有 AnswerAttempt。

#### PDF

- PDF 按 `sort_no` 导出，不受数据库 `id__in` 无序结果影响。
- 题型、知识点、难度、标签按快照展示。
- 只有简答题增加 50mm 空白区域，其他题型不增加。
- 学生只能下载自己的精练 PDF，家长只能下载有效孩子的 PDF。
- 题目顺序或内容改变后 PDF 版本重新生成。
- 本地/生产媒体 URL 来自配置，不能固定生产域名。

#### 照片上传

- 图片类型和大小校验有效。
- 图片只能挂到当前学生自己的精练答题记录。
- 页码重复按约定覆盖或拒绝，行为需固定并测试。
- 教师作业扫描批次回归测试通过。

## 11. 风险和处理

| 风险 | 处理 |
|---|---|
| 历史知识点 JSON 格式不统一 | 后端统一规范化，空数据不放宽规则 |
| 题库中符合条件的题不足 3 道 | 返回实际数量和原因，不返回不符合条件的题 |
| 前端伪造题目 ID | 服务端重新执行推荐校验并限制学生范围 |
| 家长上下文被错误使用 | 所有查询/写入统一使用有效学生 helper |
| 新精练答题污染旧统计 | 使用 `PracticeAttempt` 独立记录 |
| PDF 题目顺序错误 | 只从 `PracticeSetItem.sort_no` 构造题目数组并测试 |
| 旧扫描功能受影响 | 不改 `PaperScanBatch.mission` 逻辑，使用独立上传模型 |
| PDF 或照片链接泄露 | 权限接口返回 URL，文件名不使用用户可控路径，必要时增加签名下载 |
| 推荐接口未来替换 | 使用 `RecommendationProvider`，固定响应契约 |

## 12. 方案验收标准

本方案实施完成后，以下场景必须成立：

1. 学生打开错题本，看到原错题的知识点、难度、标签。
2. 点击“加入关联题”后，请求新的错题本候选题接口，最多显示 3 道严格满足同学段、同学科、知识点命中和难度上下相差一星以内规则的题；不足时不使用不匹配题补足，并显示不足原因。
3. 学生选择关联题后，题目进入自己的精练列表，重复加入不会重复。
4. 学生从精练列表选择题目，题目顺序可控，生成精练作业。
5. 学生可以在线练习，完成进度正确显示，主观题进入待处理。
6. 学生可以导出精练 PDF，题目顺序正确，只有简答题后有 50mm 作答空白。
7. 学生可以上传线下作答照片，照片与精练作业题目关联。
8. 家长选择孩子后可以查看该孩子的错题和精练数据，并生成/下载该孩子的精练 PDF。
9. 同一账号同时拥有学生和家长角色时，家长端选择“我的学生身份”即可查看自己的学生数据，不要求绑定自己。
10. 教师布置作业、教师作业 PDF、学生原有任务答题、原有错题本和旧同类题练习全部通过回归测试。

## 13. 最终结论

当前项目已有“关联题推荐字段、推荐服务、同类题页面、题库元数据、PDF 排版和图片处理”的基础，但没有完整的、可持久化的“精练列表—精练作业—在线答题—PDF—照片上传”闭环。

最稳妥的实施方式是：

- 保留现有 `/variants/` 关联题接口和旧同类题练习逻辑；
- 新增专用于错题本选择的候选题接口，按同学段、同学科、知识点和难度容差规则筛选；
- 新增独立 `apps.practice` 精练业务域和迁移；
- 用精练池和精练作业关系表保存题目及顺序；
- 用独立答题/图片表承载在线和线下练习；
- 复用 PDF 基础能力但按精练作业顺序生成；
- 统一使用有效学生上下文处理学生、家长和同账号多角色；
- 不复用教师任务和教师扫描批次，不改变现有业务统计。

按本文档实施，可以满足本次新增需求，同时将新功能对现有教师作业、错题本、任务进度和多端登录逻辑的影响控制在可测试、可回滚范围内。

8. **新增 Django app 必须加入 `INSTALLED_APPS`。** 方案改动清单已补充 `config/settings.py`，并要求先执行迁移检查。
