# 课堂反馈功能开发可实施方案

## 1. 文档信息

- 需求日期：2026-09-16
- 适用端：教师端 H5/uni-app、家长端 H5/uni-app
- 需求入口：教师端工作台课堂练习列表中的“课堂反馈”按钮
- 关联页面：课堂错题统计、家长端作业概括/作业详情
- 交付形式：页面在线预览 + 教师端导出课堂反馈 PDF
- 文档性质：开发实施方案
- 文档版本：V2.0（按复核意见修订）
- 当前结论：已完成需求、现有代码、权限、模型配置和独立模块边界复核；本文档可作为开发拆分和联调依据，未修改业务代码

本文档以当前工作区的 Django + Django REST Framework 后端、uni-app/Vue 前端和已有课堂错题统计能力为基础，给出可以直接拆分开发、联调和验收的实施方案。

## 2. 需求理解与功能边界

### 2.1 目标

课堂练习完成后，系统根据课堂内每个学生的错题题号和原练习题内容，形成一份课堂反馈报告，报告包含：

1. 全班整体情况概览；
2. 每个知识点的错误人数、错误率和掌握情况；
3. 每道课堂练习题的错误人数和错误率，并突出高错误率题目；
4. 一段可以直接复制发送给家长的班级整体反馈话术；
5. 每个学生的错题题号、涉及板块、核心错误知识点、重练安排和个性化家长反馈话术；
6. 教师端查看全班报告并导出一份连续展示所有学生反馈的 PDF；
7. 家长端从课堂讲义作业进入，只查看当前绑定学生的课堂整体情况和该学生话术。

### 2.2 首期不做的内容

- 不由 AI 计算人数、错误率或平均值；所有统计数字由后端根据错题矩阵确定性计算。
- 不把“课堂反馈”和“错题精练”绑定成同一个生成任务。反馈直接使用课堂练习原题及错题统计；错题精练仍沿用现有的导入错题练习题、映射和学生精练作业流程。
- 不向家长展示其他学生姓名、错题题号、个人错误率或个人话术。
- 不自动向家长发送消息，教师仍可以复制话术后通过现有沟通渠道发送。
- 不允许家长导出全班 PDF；首期 PDF 导出仅开放教师端。
- 不在页面端自行拼接统计逻辑，避免前端展示数字与 PDF、家长端数字不一致。
- 反馈业务的核心代码、模型、接口、任务、PDF 服务和前端页面全部放入独立文件/模块；只在现有课堂入口、家长作业卡片、全局路由、应用注册和配置中做最小接入。

### 2.3 固化的业务口径

#### 统计范围

- 仅支持已发布的课堂讲义练习：`LearningMission.status = published`、`source_context = course_practice`、`source_type = handout`、且存在课程和有效班级分配。
- 课堂人数取当前课堂矩阵中的 active 学生，和现有课堂错题统计页保持一致。
- 教师可查看其有权管理的课堂及其班级；若一份课堂练习分配多个班级，教师先选择班级，再生成或查看该班级报告。
- 报告覆盖当前班级的所有 active 学生，包括没有错题的学生，保证 PDF 和目录中的学生人数一致。

#### 错题来源

- 线上答题：复用 `AnswerAttempt` 中当前课堂练习的非草稿、非待批改、`is_correct = false` 记录，经现有同步逻辑写入 `TeacherWrongBookCell`。
- 线下答题：复用课堂错题统计页已经保存的手动标记或 Excel 导入结果。
- `TeacherWrongBookCell` 的有效状态为 `marked/generated/locked`；反馈统计不读取草稿，也不重复解释线上和线下来源。
- 当前矩阵版本 `TeacherWrongBookMatrix.version` 是反馈报告的输入版本。新答题或手动统计导致版本变化后，旧报告保留但标记为“数据已更新，需重新生成”。

#### 错误率公式

设班级有效学生数为 `N`，某道题错误学生数为 `Wq`，某知识点下课堂题目数为 `Qk`。

| 指标 | 计算口径 |
|---|---|
| 题目错误率 | `Wq / N × 100%`；未作答学生不计为错误，仍在班级人数分母中 |
| 知识点错误次数 | 该知识点下所有“学生-错题”组合数 |
| 知识点错误率 | `知识点错误次数 / (N × Qk) × 100%` |
| 累计错题 | 所有有效“学生-题目”错题组合数 |
| 人均错题 | `累计错题 / N`，保留 1~2 位小数 |
| 学生错误率 | `学生错题数 / 课堂练习总题数 × 100%` |

同一道题关联多个知识点时，该错题会分别计入每个知识点，知识点错误次数之和可能大于累计错题；PDF 和页面需标注这一统计特性，避免将两个指标相加比较。

#### 知识点归纳规则

按以下优先级获取知识点标签：

1. 优先读取课堂题目快照中的 `knowledge_points`；发布课堂已使用 `TeacherWrongBookMatrixQuestion.question_snapshot`，保证历史报告不因题库后续编辑而改变。
2. 若快照没有知识点，读取 `ExamQuestion.knowledge_points`。
3. 若仍没有可展示的标准模块，读取已确认的 `QuestionKnowledgeMatch` 对应 `KnowledgePoint.module`。
4. 以上均没有结果时，将题目放入“待归类题目”，并允许 AI 根据题干、解析和现有题目内容给出临时归类；临时归类必须保存到报告快照，不回写题库，不参与下一次报告，除非教师后续确认。

页面和 PDF 中展示的知识点名称以标准 `KnowledgePoint.module` 或题目快照中的模块名称为准。例如：分子动理论、内能的概念与改变方式、比热容概念与应用、比热容实验、热量计算与热平衡等。

当前明确缺口：

1. `workbench.vue` 的 `showClassroomFeedback` 目前只提示“将在下次开发”，没有页面路由；
2. 没有课堂反馈报告、知识点统计、学生话术的持久化表；
3. 没有课堂反馈统计/生成/状态/PDF API；
4. 没有反馈专用 AI prompt 和异步任务；
5. 家长作业卡片目前只有“下载PDF作业”，没有相邻的“查看错题反馈”按钮和 50/50 操作区；也没有只返回绑定孩子的反馈接口；
6. 现有错题精练 PDF 是练习卷，不是本需求中的课堂反馈 PDF，不能直接改名复用。

模型配置核对：当前 `config/ai_config.cfg` 和 `apps/common/ai/config.py` 已存在并支持 `qwen3.7-flash`，但课堂反馈的两个 task 尚未登记。因此开发时必须同时新增 task 配置、prompt 注册和任务白名单，否则服务端会拒绝未知 task 或回退到错误模型。

## 4. 目标用户流程

### 4.1 教师端

```text
教师工作台
  → 课堂练习列表“课堂反馈”
  → 选择班级/读取课堂错题矩阵
  → 点击“生成课堂反馈”
  → 后端固化统计快照
  → AI 生成班级话术和学生话术
  → 页面轮询生成状态
  → 预览全班报告
  → 导出一份连续 PDF
```

如果页面发现矩阵版本发生变化，显示“统计数据已更新，当前报告为旧版本”，允许教师重新生成。重新生成不覆盖旧报告，方便追溯历史。

### 4.2 家长端

```text
家长作业概括/作业详情
  → 课堂讲义作业显示“查看错题反馈”
  → 进入课堂反馈预览页
  → 后端按当前 parent context 找到绑定孩子
  → 返回班级整体统计 + 当前孩子错题与家长话术
```

家长端不传入可切换的学生 ID，不返回 `students` 全量数组；即使修改 URL 中的参数，也只能返回当前绑定孩子，未绑定或无权访问时返回 404/403。

## 5. 推荐数据设计

建议新建独立 Django App `apps/classroom_feedback/`，在其中增加以下四张表。不要把反馈模型、迁移和业务服务继续堆入 `apps/missions/`；反馈模块只读现有课堂错题矩阵和题目数据。报告数据采用“统计结果规范化 + 输入快照 JSON”方式，既便于页面查询，又能保证 AI 话术、PDF 与当时统计结果一致。

建议目录：

```text
apps/classroom_feedback/
  __init__.py
  apps.py
  models.py
  services.py
  views.py
  parent_views.py
  urls.py
  parent_urls.py
  tasks.py
  ai.py
  pdf_service.py
  migrations/0001_initial.py
  tests/
```

`apps/classroom_feedback` 是本功能的唯一业务归属。`apps/missions/`、`apps/study/` 仅保留必要的入口字段、路由挂载或只读适配，不新增反馈领域模型。

### 5.1 `ClassroomFeedbackReport`

一条记录代表某课堂、某班级、某个错题矩阵版本的一次反馈生成结果。

| 字段 | 类型/建议 | 说明 |
|---|---|---|
| `id` | UUID 主键 | 报告 ID |
| `mission` | FK `LearningMission` | 来源课堂练习 |
| `class_obj` | FK `Class` | 来源班级 |
| `source_matrix` | FK `TeacherWrongBookMatrix` | 统计来源矩阵 |
| `source_matrix_version` | PositiveInteger | 生成时矩阵版本 |
| `status` | queued/running/ready/partial/failed/stale | 报告状态 |
| `generation_no` | PositiveInteger | 同一课堂班级的生成序号 |
| `participant_count` | PositiveInteger | 统计时班级人数 |
| `question_count` | PositiveInteger | 课堂练习题数 |
| `total_wrong_count` | PositiveInteger | 累计错题 |
| `average_wrong_count` | Decimal | 人均错题 |
| `class_summary_json` | JSON | 班级统计摘要，数字由后端写入 |
| `class_feedback_text` | Text | AI 班级整体话术 |
| `input_snapshot` | JSON | 节点、题目、知识点、学生错题、统计数字完整快照 |
| `prompt_version` | CharField | 反馈 prompt 版本 |
| `model_name` | CharField | 实际使用模型 |
| `pdf_file_path` | CharField | 生成后的全班 PDF 相对路径 |
| `error_message` | CharField | 非敏感失败原因 |
| `created_by` | FK UserAccount | 发起教师 |
| `created_at/updated_at/completed_at` | DateTime | 审计时间 |

建议索引：`(mission, class_obj, -created_at)`、`(source_matrix, source_matrix_version)`。报告不是按 `mission + class` 做单条唯一约束，因为需要保留历史版本。

### 5.2 `ClassroomFeedbackQuestionStat`

保存报告中的每道题统计，避免每次打开页面重新扫描矩阵。

| 字段 | 说明 |
|---|---|
| `report` | 所属报告 |
| `source_question_id` | 课堂练习原题 UUID |
| `node_id/node_name_snapshot/node_sort_no` | 讲义节点快照 |
| `question_no` | 节点内显示题号 |
| `wrong_count/wrong_rate` | 错误人数/错误率 |
| `knowledge_labels` | 该题对应的知识点名称和稳定 key |
| `question_snapshot` | 题干、解析、题型、知识点等只读快照 |
| `sort_no` | 课堂题目顺序 |

唯一约束建议为 `report + source_question_id`。

### 5.3 `ClassroomFeedbackKnowledgeStat`

保存按知识点聚合的班级统计。

| 字段 | 说明 |
|---|---|
| `report` | 所属报告 |
| `knowledge_key/knowledge_name` | 标准知识点 key/展示名 |
| `question_count` | 该知识点覆盖的课堂题数 |
| `wrong_count` | 学生-题目-知识点错误次数 |
| `denominator` | `participant_count × question_count` |
| `error_rate` | 后端计算后的百分比 |
| `mastery_level` | `good/attention/weak` 等稳定枚举 |
| `question_ids` | 关联题目 UUID 数组，便于下钻 |
| `sort_no` | 展示顺序 |

掌握情况建议首期使用固定阈值，并在接口返回 `threshold_version`：

- `< 30%`：掌握较好；
- `30% ~ 49.99%`：基本掌握，需巩固；
- `>= 50%`：薄弱，需重点训练。

阈值只决定标签，不能改变错误率原始数字；后续如果产品调整阈值，可通过版本字段识别历史报告。

### 5.4 `ClassroomFeedbackStudent`

保存一名学生在一份报告中的个性化内容。

| 字段 | 说明 |
|---|---|
| `report/student` | 报告和学生，报告内唯一 |
| `student_name_snapshot/class_name_snapshot/student_no_snapshot` | 页面/PDF 展示快照 |
| `wrong_question_ids` | 错题 UUID 数组 |
| `wrong_question_nos` | 按课堂顺序保存的题号数组 |
| `wrong_count/wrong_rate` | 学生错题数和错误率 |
| `knowledge_summary` | 知识点名称、关联题号和个人错误次数 |
| `review_arrangement` | 建议重练题号或节点，来源于规则，不由 AI 编造 |
| `feedback_text` | 可直接发给家长的话术 |
| `ai_status` | pending/succeeded/fallback/failed |
| `ai_model/prompt_version` | AI 审计信息 |
| `ai_error_message` | 非敏感错误信息 |

没有错题的学生也创建记录，`wrong_question_nos=[]`，生成鼓励性反馈或使用安全兜底话术，不能在页面缺席。

### 5.5 迁移与历史数据

新 App 使用自己的迁移序列，正式开发时生成：

```text
apps/classroom_feedback/migrations/0001_initial.py
```

同时在 `INSTALLED_APPS` 注册 `apps.classroom_feedback`，在全局 URL 配置挂载教师和家长路由。不要直接修改旧迁移，不要按 `word/sql` 中的历史 BIGINT 快照设计主键；当前业务模型和迁移使用 UUID，应以 Django Models 和实际数据库为准。

## 6. 后端实施设计

### 6.1 新增服务文件

新增 `apps/classroom_feedback/services.py`，只负责业务计算和快照组装，不把统计逻辑散落到 View 或前端。

建议提供以下函数：

```text
prepare_feedback_scope(mission_id, teacher, class_id)
build_feedback_snapshot(mission, matrix)
aggregate_question_stats(snapshot)
aggregate_knowledge_stats(snapshot)
create_feedback_report(mission, matrix, teacher, idempotency_key)
get_feedback_report_payload(report, viewer)
mark_stale_reports(mission, matrix)
```

服务内部应复用现有 `prepare_classroom_matrix` 和 `classroom_statistics_payload` 的范围校验，但不要重新创建或修改 `TeacherWrongBookCell`。建议先取得现有统计 payload，再从其中的 `questions/students` 和题目快照构建不可变输入。

### 6.2 新增教师接口

在 `apps/classroom_feedback/views.py` 新增接口，并在 `apps/classroom_feedback/urls.py` 定义，最后由 `config/urls.py` 独立挂载。不要把反馈 View 和 URL 注册到 `apps/missions/urls.py`，避免与现有错题统计耦合。接口路径保持当前课堂统计的无尾斜杠写入风格，同时可按项目现有兼容策略补充尾斜杠别名。

#### 读取报告

```http
GET /api/v1/missions/{mission_id}/classroom-feedback?class_id={class_id}
```

权限：`IsAuthenticated + IsTeacherSession`，并通过 `can_manage_matrix` 校验教师是否有权管理该课堂。

返回当前班级最新报告；没有报告时返回 `report: null` 和当前统计输入版本，前端显示“尚未生成”。

#### 发起生成

```http
POST /api/v1/missions/{mission_id}/classroom-feedback/generate
Content-Type: application/json

{
  "class_id": "班级UUID",
  "matrix_version": 3,
  "idempotency_key": "前端生成请求唯一键",
  "force": false
}
```

处理规则：

1. 校验 `matrix_version`，不一致返回 409 `VERSION_CONFLICT`，并带回 `current_version`；
2. 校验课堂范围、班级范围、学生范围和题目快照；
3. 在事务中生成统计快照、题目统计、知识点统计和学生记录；
4. 相同 `mission + class + matrix_version + idempotency_key` 重复请求返回原报告，不重复调用 AI；
5. 报告进入 `queued` 后异步投递任务，接口立即返回 `202` 或当前项目统一的成功 envelope。

### 6.4 AI 生成链路

课堂反馈不是学生一提交题目就立即调用 AI。正确的先后顺序是：

```text
学生线上作答/教师线下统计
  → 现有课堂错题矩阵同步或保存
  → 教师点击“生成课堂反馈”
  → 后端固定统计快照和知识点归纳
  → AI 生成班级话术、学生家长话术
  → 报告完成并可预览/导出
```

#### 推荐新增的 AI 文件和模型

- `apps/classroom_feedback/ai.py`：反馈组件，负责 prompt 变量、响应字段校验、内容安全检查和规则兜底。
- `apps/classroom_feedback/tasks.py`：反馈批次、班级话术、学生话术异步任务。
- `config/ai_config.cfg`：新增 `classroom_feedback_class_summary` 和 `classroom_feedback_student_script` task/prompt，两个 task 均指定 `qwen3.7-flash`。
- `apps/common/ai/config.py`：将两个新 task 加入任务白名单/配置校验；模型名统一登记为 `qwen3.7-flash`。
- `config/settings.py`：将反馈任务路由到 `ai.feedback`。

不建议复用 `apps/study/feedback_engine.py`，该文件生成的是答题即时鼓励语，不包含班级统计、知识点归纳、家长话术和报告快照。

#### AI 输入

班级话术输入：班级人数、题目数、累计错题、人均错题、知识点统计、每道题统计、最高错误率题目、课堂名称和节点名称。后端统计数字、题号和错误率作为只读事实传入，AI 不负责计算。

学生话术输入必须逐学生单独组装，至少包含：学生姓名快照、学生错题题号、每道错题的题目内容/题干摘要、解析或答案要点、标准知识点、学生个人错误率、班级同题错误率、班级薄弱知识点、固定重练安排和班级总体反馈摘要。题目内容不能只在“需要消歧”时提供，因为本需求明确要求结合练习题内容归纳知识点；超长题干应在后端安全截断并保留题号，不能丢失题号与知识点映射。

每个学生必须单独调用 `classroom_feedback_student_script`，请求中带入 `student_id`、个人错题集合和唯一输入指纹；禁止先生成一段通用话术再复制给全班。不同错题集合必须生成不同的重点和正文；若不同输入得到完全相同的正文，任务应自动重试一次，仍相同则使用包含该学生错题题号/知识点的规则兜底文本，保证家长看到的内容与学生本人对应。

#### 模型、参数和话术模板

本期反馈话术统一使用通义千问 `qwen3.7-flash`：

| 任务 | 模型 | 温度 | 最大输出 | 调用粒度 |
|---|---|---:|---:|---|
| `classroom_feedback_class_summary` | `qwen3.7-flash` | 0.3 | 4096 tokens | 每份报告 1 次 |
| `classroom_feedback_student_script` | `qwen3.7-flash` | 0.3 | 2048 tokens | 每个学生 1 次，可单独重试 |

模型名称必须从服务端配置读取，不能由前端传入；报告保存实际 `model_name`、`prompt_version`、输入指纹和 AI 状态。请求超时 300 秒、最多重试 2 次，具体值可按现有 AI 客户端配置调整。题目若为纯图片且题干/解析无法提供，才考虑先用现有视觉模型提取文本；本功能本身不默认调用视觉模型，也不使用 `qwen3.7-plus` 生成反馈话术。

话术可借鉴用户提供的模板，但必须由数据驱动并避免机械套用。班级话术应包含“本节课学习内容、班级掌握较好的部分、错误集中知识点/题目、下一步建议”；学生话术应包含“家长称呼、课堂名称、本人错题数和题号、对应知识点、具体重练建议、鼓励和教师跟进”。示例结构：

```text
班级：各位家长好！本周我们完成了《{课堂名称}》练习检测。整体来看，同学们在{掌握较好知识点}方面掌握较好，但在{薄弱知识点}以及{高错误率题目/能力}上错误较集中。请结合错题完成针对性订正和重练，老师会在后续课堂继续检查。

学生：{学生姓名}家长您好！本次《{课堂名称}》练习中，{学生姓名}共错{wrong_count}道，题号为{题号列表}，主要涉及{个人知识点}。建议先订正{重点题号}，重点复习{知识点}，再完成{重练安排}。及时订正并理解错因后，相信孩子能逐步巩固，本周老师也会继续关注。
```

若课堂错题精练包已经生成，`重练安排`可引用真实包/题号；若尚未生成，只能表述为“建议订正上述题目并完成对应知识点练习”，AI 不得虚构“已生成重练卷”。

#### AI 输出契约

要求只返回 JSON，不返回 Markdown 和思维过程：

```json
{
  "strengths": ["..."],
  "focus_points": ["..."],
  "action_suggestions": ["..."],
  "feedback_text": "可以直接发给家长的完整话术",
  "confidence": 0.86
}
```

后端必须校验：

- `feedback_text` 非空且长度在配置范围内；
- `focus_points` 只能使用输入中存在的知识点；
- 学生话术必须包含该学生至少一个真实错题题号或知识点（无错题学生使用专门鼓励模板）；
- 不同错题输入不得复用完全相同的学生正文；
- 不允许出现其他学生姓名、排名、手机号或未提供的分数；
- 不允许 AI 修改 `wrong_question_nos`、人数、错误率等统计字段；
- JSON 不合格、超时或模型不可用时，保存 `ai_status=fallback`，使用规则模板完成报告，不能让页面一直停留在加载中。

班级整体话术和学生话术应分别调用，便于单个学生失败后重试，不影响整班其他学生结果。学生数量较多时使用 Celery group/chord 或等价批次调度，报告只有在全部学生成功或明确进入 fallback 后才变为 `ready/partial`。

## 8. PDF 实施设计

### 8.1 文件与生成策略

新增：

```text
apps/classroom_feedback/pdf_service.py
```

PDF 由后端使用 ReportLab 生成，中文字体沿用现有 `STSong-Light` 注册方式，必要时再统一封装到公共 PDF 工具。生成完成后保存到：

```text
MEDIA_ROOT/exports/classroom_feedback/{report_id}/课堂反馈-{课堂名}-{班级名}.pdf
```

数据库只保存相对路径，接口通过当前项目媒体 URL 规则返回 `pdf_download_url`。

### 8.2 页面结构

以用户提供的示例作为视觉和内容参考，PDF 按 A4 连续排版：

1. 封面：教学质量分析、课堂名称、错题反馈话术表、课程/班级/日期/版本；
2. 目录：一、班级整体掌握情况；二、学生个人反馈话术（人数）；
3. 整体概览：四个统计指标及班级整体文字总结；
4. 班级知识点统计表；
5. 高错误率题目表，超过阈值的错误率使用红色；
6. 班级整体反馈话术框；
7. 每个学生一段连续内容：学生姓名、错题题号、涉及板块、核心错误知识点、重练安排、反馈话术；
8. 学生内容超出一页时自然分页，学生块可以跨页但标题不能孤立在页尾；下一名学生接续往下展示，不为每名学生强制新建一份 PDF。

### 8.3 导出可靠性

- 统计数字从 `ClassroomFeedbackReport` 和子表读取，不在 PDF 生成过程中再次扫描在线答题；
- PDF 使用报告快照中的题号和知识点，题库后续修改不影响历史文件；
- 文件写入临时路径后原子替换，避免生成半个 PDF；
- 生成失败时不覆盖旧文件，并返回可识别的 `PDF_GENERATE_FAILED`；
- 报告版本变为 stale 后，旧 PDF 仍可由教师查看，但页面需明确它对应旧统计版本；
- 文件名对 Windows/Linux 均安全处理，课堂名、班级名、学生名中的 `/\\:*?"<>|` 替换为下划线。

## 9. 关键业务伪代码

### 9.1 统计快照

```text
mission, matrix = prepare_classroom_matrix(mission_id, teacher, class_id)
raw = classroom_statistics_payload(mission, matrix)

students = active students in raw
questions = active questions in raw
for question in questions:
    labels = normalize_knowledge(question.snapshot)
    wrong_count = count(student where student.cell(question).wrong)
    save question_stat(question, labels, wrong_count, wrong_count / student_count)

for label in all question labels:
    related_questions = questions containing label
    wrong_count = sum(wrong(student, question) for related questions)
    denominator = student_count * len(related_questions)
    save knowledge_stat(label, wrong_count, denominator, wrong_count / denominator)

for student in students:
    wrong_questions = questions where student.cell(question).wrong
    labels = distinct labels of wrong_questions
    save student_feedback_row(student, wrong_questions, labels)
```

### 9.2 防止旧报告覆盖新报告

```text
POST generate locks matrix/report input
  → report.source_matrix_version = request.matrix_version
  → task starts
  → task writes only when report.status in queued/running
  → GET compares latest matrix.version with report.source_matrix_version
  → mismatch: report.status = stale, keep old content
```

### 9.3 AI 失败兜底

```text
class_summary AI failed → use deterministic class template, report remains partial/fallback
student AI failed → only this student uses deterministic template
all rows have usable text → report can be viewed and exported
retry → only retry failed/fallback rows, not duplicate successful rows
```

## 12. 风险、回滚与注意事项

| 风险 | 处理方式 |
|---|---|
| 题目知识点数据不完整 | 规则优先、AI 仅做临时归类并保存快照；反馈生成不可因单题无标签而失败 |
| AI 响应慢或限流 | 异步队列、学生级任务、重试和兜底；不在 HTTP 请求中同步调用 AI |
| 统计版本变化 | 通过 `source_matrix_version` 和 stale 状态隔离历史报告 |
| 家长越权 | 接口只使用 `request._effective_student`，不接受任意 student_id；增加权限测试 |
| PDF 中文/分页问题 | 使用现有中文 CID 字体；长文本用 Paragraph，表格设置重复表头和分页策略 |
| 现有工作区有未提交改动 | 新增文件尽量独立；不回退或覆盖课堂错题统计、错题精练等已有改动 |
| 队列未部署 | 上线前检查 worker 是否监听 `ai.feedback`，并增加任务积压监控 |
| 模型配置未登记或返回相同话术 | 发布前执行配置校验；按学生单独调用并校验题号/知识点和正文唯一性，失败时重试或使用个性化规则模板 |
| 家长入口放错页面或按钮换行 | 以 `MpMissionCard.vue` 为主入口做视觉回归，两个按钮用同一 `flex` 操作区并固定 50/50 |

回滚时可以先隐藏工作台和家长端入口、停止新反馈任务投递；不删除已生成报告表和 PDF 文件，待确认无调用后再单独清理。已有课堂错题统计接口不依赖反馈表，因此反馈功能下线不会影响原有错题统计和错题精练。

## 13. 最终推荐方案

本功能采用“现有课堂错题矩阵作为唯一统计源 + 独立 `apps/classroom_feedback` 模块 + 后端生成不可变反馈快照 + `qwen3.7-flash` 按学生独立生成话术 + 报告版本化 + 教师全量/家长单学生隔离”的设计。

核心先后关系为：

```text
课堂练习作答或线下统计
  → 错题矩阵版本确定
  → 后端计算题目/知识点/学生统计
  → 固化报告快照
  → AI 生成班级和学生家长话术
  → 页面预览
  → 教师导出 PDF
```

错题精练可以在课堂反馈之前、之后或不生成，均不影响课堂反馈；如果教师后续生成错题精练，仍使用现有 `ClassroomWrongDrill*` 流程。这样可以保证统计数字、AI 话术、家长查看内容和 PDF 导出内容始终围绕同一份课堂反馈快照，功能边界清晰，便于开发、测试、回滚和后续扩展。

### 13.1 修订后可执行性结论

经本次复核，需求中的教师入口、班级/题目/知识点统计、逐学生个性化话术、模板化 PDF、教师全量查看、家长绑定学生隔离，以及家长作业卡片相邻 50/50 入口均已写入实施方案。方案可以进入开发执行，但上线前仍必须完成以下前置条件：

1. 确认实际课堂矩阵中每道题能取得题干/解析和知识点快照；缺失时走“待归类/规则兜底”，不能让 AI 结果直接成为统计事实；
2. 在 `apps/common/ai/config.py` 和 `config/ai_config.cfg` 登记两个反馈 task，并验证服务端实际可调用 `qwen3.7-flash`；
3. 完成 `apps/classroom_feedback` 的迁移、全局路由、Celery 队列和媒体目录配置；
4. 完成 `MpMissionCard.vue` 的 50/50 按钮回归和家长越权测试；
5. 通过本方案第 11 节测试后再灰度开放教师生成和家长查看。

在上述前置条件未完成前，文档是可实施设计，不代表功能已经在当前代码库中完成；当前代码仍需按阶段实施，不能仅通过新增页面完成全部需求。
