# 学生端固定式与非固定式引导问题分析及修复方案

## 1. 文档目的

本文整理学生端答题引导中“固定选项引导”和“非固定选项引导”的现状、问题根因、最终判断、优化方向及修复优先级。

本文仅用于问题分析和后续实施依据，本次不修改任何代码。

## 2. 需求目标

学生答错题目后，系统应能够：

1. 通过固定式和非固定式引导帮助学生定位错因。
2. 根据学生当前回答判断其理解是否正确、部分正确或存在概念错误。
3. 根据学生的回答动态生成下一步引导，而不是单纯按照固定脚本推进。
4. 使用千问 `qwen3.7-flash` 快速完成实时评价和引导。
5. AI 服务异常时不阻塞答题流程，并向学生提供可继续操作的反馈。

## 3. 当前功能和调用链

### 3.1 固定选项引导：B 模式

代码入口：

- `apps/study/guidance_views.py`
- `uniapp/src/pages/student/guidance.vue`

处理流程：

```text
学生进入 B 模式
    ↓
读取 ExamQuestion.ai_answer_b
    ↓
读取 questions[step_index]
    ↓
返回引导问题和 A/B/C/D 选项
    ↓
学生选择引导选项
    ↓
后端判断 correct_option
    ↓
学生回答后额外调用一次 qwen3.7-flash
    ↓
分析本轮回答和错因，写入已有会话记录
    ↓
返回正确性、评价、纠正方向和下一步问题
```

B 模式进入页面时主要读取题目已有的固定引导内容；当前代码在学生选择后只进行程序判断，尚未额外调用 AI 分析学生的动态错因。优化后应在学生回答之后调用一次 `qwen3.7-flash`，将本轮回答、对话和错因写入已有会话记录，再返回下一步。

如果 `ai_answer_b` 不存在，后端使用通用的固定兜底问题和选项，内容与具体题目关联较弱。

### 3.2 非固定选项引导：C 模式

处理流程：

```text
学生进入 C 模式
    ↓
存在 ai_answer_c.questions？
    ├─ 是：直接读取预生成问题
    └─ 否：同步调用 guidance_generate 生成 3~5 个问题
             ↓
          保存到当前 session
    ↓
学生输入一句回答
    ↓
只调用一次 guidance_evaluate（qwen3.7-flash）
    ↓
分析回答、判断错因、生成纠正方向和下一问题
    ↓
写入对话和错因记录后进入下一步
```

当前 C 模式存在两类 AI 调用：

1. `guidance_generate`：当 `ai_answer_c` 缺失时，当前代码会实时生成引导问题；优化后应迁移到后台准备，避免阻塞学生进入页面。
2. `guidance_evaluate`：学生每次提交一句回答时调用一次，同时完成回答评价、错因分析、纠正方向和下一问题。

## 4. 当前使用的模型

| 使用场景 | Task | 当前模型 | 当前用途 |
| --- | --- | --- | --- |
| C 模式实时生成问题 | `guidance_generate` | `qwen3.7-flash` | 生成 3~5 个递进式引导问题 |
| C 模式实时评价 | `guidance_evaluate` | `qwen3.7-flash` | 评价学生当前回答 |
| 教师引导评价 | `teacher_guidance_evaluate` | `qwen3.7-flash` | 教师端评价学生回答 |
| B 模式预生成 | `mode_b_answer` | `qwen3.7-plus` | 生成固定选项引导内容 |
| C 模式预生成 | `mode_c_answer` | `qwen3.7-plus` | 生成开放式引导内容 |
| 题目探查、知识分析 | `question_probe`、`knowledge_analysis` | `qwen3.7-flash` | 题目预处理 |
| 图像事实提取 | `vision_fact_extract` | `qwen3-vl-plus` | 提取图表、几何图等视觉事实 |
| AI 答案校验 | `deepseek_*` | `deepseek-v4-pro` | 复杂答案和模式内容校验 |

当前实时引导任务已经配置为 `qwen3.7-flash`，但 B/C 预生成任务仍使用 `qwen3.7-plus`，因此同一题可能走不同的模型路径。

需要区分“题目引导步骤的准备”和“学生回答后的错因分析”：前者可以后台准备，后者必须发生在学生提交回答之后。目标方案中，B/C 学生回答后的实时分析统一只调用一次 `qwen3.7-flash`。

## 5. 已发现的问题

### 5.1 非固定引导数据不可用

当题目的 `ai_answer_c` 为空时，`start_guidance` 会同步调用 `guidance_generate`。

当模型请求失败、超时、限流、并发资源不足或模型返回格式不符合要求时，代码会捕获异常，并将 C 模式降级为 B 模式：

```text
非固定选项引导数据不可用，已降级到固定选项引导模式
```

当前异常被统一处理，前端无法区分以下原因：

- API Key 或 URL 配置问题。
- Qwen 服务超时。
- HTTP 429 限流。
- HTTP 5xx 服务异常。
- AI 并发资源不足。
- AI 返回 JSON 或 Schema 校验失败。

此外，代码使用了较宽泛的异常捕获，导致原始错误原因没有保存到会话，也没有返回可追踪的错误分类。

### 5.2 C 模式响应时间过长

当前 AI 任务配置为：

- 单次请求超时：300 秒。
- `retry_count = 3`，最多执行 4 次请求。
- 重试等待时间：1 秒、2 秒、4 秒。
- Qwen 并发资源等待时间：最多 300 秒。

因此一次学生交互可能经历：

```text
等待并发资源 → 请求模型 → 超时或失败 → 重试 → 再次等待资源
```

此外，AI 请求直接在 Django 同步接口中执行，接口必须等待模型处理完成，导致：

- Web 工作线程被长时间占用。
- 学生页面长时间显示“思考中”。
- 多名学生同时使用时，后续请求更容易等待并发资源。
- 模型服务短暂异常时，用户体验明显变差。

### 5.3 `AIRequestError` 信息不足

当前 C 模式评价失败时，前端看到的是：

```text
AI 评价暂时不可用：AIRequestError
```

该信息只能说明请求失败，无法判断具体原因。

当前 AI 客户端虽然记录了部分模型、状态码和耗时日志，但视图层生成的 `trace_id` 没有完整传入 AI 组件，导致一次学生会话和 AI 请求日志之间难以关联。

### 5.4 C 模式评价缺少当前引导问题

当前评价主要传入：

- 原题题干。
- 原题参考答案。
- 学生回答。

没有传入：

- 当前正在回答的引导问题。
- 当前步骤的参考答案。
- 当前步骤的关键评分点。
- 当前步骤的追问提示。
- 学生之前的回答。

例如当前引导问题是：

```text
在 s-t 图像中，图线的斜率代表哪个物理量？
```

学生回答：

```text
匀速运动
```

但后端传给评价模型的参考答案是原题答案 `BD`。模型无法准确判断“匀速运动”是否回答了当前引导问题。

### 5.5 实时生成没有传入完整题目上下文

实时 `guidance_generate` 当前主要传入题干和原题答案，没有传入：

- 原题选项。
- 原题解析。
- 详细解答。
- 题目类型。
- 知识点。
- 图像 URL。
- `ai_vision_extract` 中的图像事实。

对于“如图”“观察图像”“根据坐标图”等题目，模型无法看到图像，也没有获得结构化读图事实，只能根据题干文字猜测。

本次示例中的 s-t 图像虽然会返回给前端展示，但并没有真正传给实时引导模型。

### 5.6 C 模式不是根据回答动态引导

当前无论学生回答正确、错误、部分正确还是答非所问，系统都会直接将 `step_index` 加一，并返回预先生成的下一道问题。

因此当前 C 模式实际是：

```text
固定问题链 + 独立评价文字
```

而不是：

```text
学生回答 → 独立返回评价文字 → 按预设脚本进入下一步
```

### 5.7 B 模式存在选项值比较错误

后端向前端返回的选项格式是：

```text
A. 分析已知条件，找出关键信息
```

前端提交的也是完整字符串，但后端比较的是：

```text
A. 分析已知条件，找出关键信息 == A
```

两者不相等，因此即使学生选择了正确的引导选项，也可能被判断为错误。

### 5.8 C 降级到 B 后存在步骤状态风险

当 C 模式连续两次被判定为无效输入后，系统会切换为 B 模式，但没有始终将 session 中的 `step_index` 重置为 B 模式的第 0 步。

可能出现以下情况：

```text
C 模式已执行到第 2 步
    ↓
降级到 B 模式并显示 B 第 1 步
    ↓
下一次提交却按 session 中旧的 C 步骤索引读取 B 内容
```

这会造成前端显示步骤和后端实际判断步骤不一致。

## 6. 对示例问题的最终判断

### 6.1 关于“非固定选项引导数据不可用”

该提示并不一定表示题目本身没有数据，也可能表示实时 `guidance_generate` 请求失败。

对于没有 `ai_answer_c` 的题目，当前系统把“内容尚未生成”和“模型服务调用失败”混合处理，最终都显示为“非固定选项引导数据不可用”。

### 6.2 关于 `AIRequestError`

示例中的 C 模式启动已经成功，并返回了 4 步引导内容，说明实时生成请求成功。

随后回复接口返回：

```text
AI 评价暂时不可用：AIRequestError
```

这说明失败发生在后续的 `guidance_evaluate` 请求，而不是 C 模式问题生成阶段。

根据当前代码，最可能的原因包括：

1. Qwen 服务请求超时。
2. Qwen API 临时限流或 5xx 错误。
3. Qwen 并发资源不足。
4. 网络连接异常。

仅凭 `AIRequestError` 无法进一步确定具体原因，需要结合服务端日志中的 HTTP 状态码、耗时、重试次数和 trace_id 判断。

### 6.3 关于回答分析不准确

该问题是确定存在的，不是单纯的模型能力问题，主要是输入给模型的上下文不完整：

- 没有传当前引导问题。
- 没有传当前步骤参考答案和关键点。
- 没有传图像或视觉事实。
- 使用原题答案 `BD` 代替当前引导问题的参考答案。
- 下一步问题不根据评价结果动态调整。

因此即使千问调用成功，也无法保证对学生回答进行准确的错因判断和后续引导。

## 7. 最终优化目标架构

```text
题目导入/教师审核完成
    ↓
后台准备 B/C 引导步骤、题目上下文和图像事实
    ↓
保存题目版本和引导内容
    ↓
学生进入引导时直接读取
    ↓
学生回答一句
    ↓
仅调用一次 qwen3.7-flash
    ↓
判断错因、生成评价和纠正方向
    ↓
将对话、回答、错因和评价写入已有会话记录
    ↓
再返回下一步问题
```

## 8. 修复方案和优先级

### P0：修复正确性和上下文问题

#### 8.1 修复 B 模式选项标签比较

后端接收完整选项文本时，应先提取选项标签，再和 `correct_option` 比较：

```text
A. xxx → A
B. xxx → B
```

同时应兼容前端直接提交 `A` 的情况。

选项对错由程序确定，但错因不是固定选项预先携带的数据。学生提交后，服务端应额外调用一次 `qwen3.7-flash`，输入当前固定问题、选项语义、正确答案、学生选择和必要上下文，由该次调用分析本轮回答、判断动态错因、给出纠正方向；随后将学生回答、完整对话和分析结果写入现有会话记录，再返回下一问题。不得为同一回答再次单独调用模型生成评价或下一问，也不需要新增题目侧错因数据结构。

#### 8.2 评价请求增加当前步骤上下文

C 模式评价至少需要传入：

- 原题题干和选项。
- 当前引导问题。
- 当前步骤参考答案。
- 当前步骤关键知识点。
- 当前步骤追问提示。
- 学生历史回答。
- 学生本轮回答。

不能继续只使用原题答案作为当前引导问题的参考答案。

#### 8.3 传入图像事实

对于图表、几何图、实验图等题目，应优先使用预处理阶段的 `ai_vision_extract` 结果，例如：

```text
0~3s：路程由 0m 增加到 12m
3~6s：路程保持 12m 不变
6~9s：路程由 12m 增加到 18m
```

这样可以减少实时模型重复读图，降低响应时间并提高准确度。

#### 8.4 将 C 模式评价改为结构化返回

学生回答一句后只调用一次模型，该次响应同时返回评价、错因、纠正方向和下一问题：

```json
{
  "result": "correct|partial|incorrect|unclear",
  "error_type": "概念错误|读图错误|计算错误|条件遗漏|表达不完整",
  "evaluation": "简短评价",
  "correction_direction": "针对错误原因的纠正方向",
  "next_question": "完成记录后展示的下一问题",
  "next_hint": "针对性提示",
  "confidence": 0.92
}
```

接口层只返回公开的简短评价和引导，不返回模型思维过程。

#### 8.5 根据单次分析结果决定下一步

- 正确：记录本轮结果后进入下一知识点。
- 部分正确：记录缺失条件或步骤，下一问题围绕缺失点设计。
- 概念错误：记录概念错因，下一问题进行概念辨析。
- 读图错误：记录读图错因，下一问题重新提示图像关键事实。
- 计算错误：记录公式、单位或计算错因，下一问题聚焦对应环节。
- 答非所问或无法判断：记录本轮情况，下一问题限定回答范围或要求补充最小必要信息。

一次模型响应和本轮对话记录完成后才能执行 `step_index + 1`；同一条学生回答不再进行多轮模型追问。

### P1：解决响应慢和服务不可用问题

#### 8.6 将 B/C 内容生成移到后台

题目导入或教师审核后，通过后台任务准备 `ai_answer_b` 和 `ai_answer_c` 中的固定引导步骤、题目上下文和必要的图像事实；这里不生成某个学生尚未回答时的错因。学生进入页面时直接读取已有内容。

学生进入页面时不应等待完整的 C 模式问题链生成。

#### 8.7 为实时交互配置短超时

建议实时评价任务独立配置：

| 配置项 | 建议值 |
| --- | --- |
| timeout | 8～15 秒 |
| retry_count | 0 次（不自动重试） |
| max_tokens | 512～1024 |
| temperature | 0～0.2 |
| 并发资源等待 | 2～5 秒 |

当前所有 AI 任务被限制为 300 秒，后续应允许交互式任务使用独立配置。

#### 8.8 AI 失败时不要继续推进步骤

当实时评价失败时：

1. 保留当前学生回答。
2. 不增加 `step_index`。
3. 返回可重试标识。
4. 不自动发起第二次模型调用；如学生主动重新提交，则视为新的一轮回答。
5. 必要时使用本步骤的静态提示或安全降级，但不能将兜底内容冒充 AI 错因分析。

#### 8.9 优化模型连接和请求资源

可以考虑：

- 复用 HTTP 客户端连接。
- 减少每次请求创建和关闭客户端的开销。
- 限制学生实时任务的并发等待时间。
- 对相同题目、相同步骤使用缓存。
- 对题目内容版本建立缓存键，题目修改后自动失效。

### P2：完善数据质量和可维护性

#### 8.10 不扩展题目侧引导数据结构

B 模式的固定问题、选项、正确答案和下一步骤继续使用现有题目引导数据，不新增“错因”字段，也不把学生的错误原因预先写入题目。

学生回答后的对话、程序判定、AI 错因、评价、纠正方向和下一问题，复用现有学生引导会话记录（例如已有 `content_log_json` 或答题记录）保存。C 模式发送给模型的当前步骤参考答案、关键评分点和历史回答属于运行时上下文组装，不等同于新增题目错因结构。

#### 8.11 统一模型路由策略

实时学生交互统一使用 `qwen3.7-flash`。

学生回答后的 B/C 分析、错因判断、纠正方向和下一问题统一使用 `qwen3.7-flash`。引导步骤后台准备如需调用文本模型，也优先使用 `qwen3.7-flash`，避免学生进入页面时同步等待。

`qwen3-vl-plus` 仅用于离线图像事实提取，不参与学生每次回答后的实时链路；`qwen3.7-plus` 不作为本需求的学生端实时引导模型。模型切换或调整后，需要重新验证：

- 引导问题质量。
- 物理、数学题的计算准确率。
- 图像题的事实一致性。
- 错因分类准确率。

#### 8.12 增强日志和错误分类

每次 AI 请求建议记录：

- `session_id`
- `question_id`
- `mode`
- `step_index`
- `trace_id`
- 实际 provider 和 model
- 请求耗时
- HTTP 状态码
- 重试次数
- 错误分类

前端只显示友好的用户提示，服务端保留详细诊断信息。

#### 8.13 修复 C 降级后的 session 状态

C 降级到 B 时，应同步重置：

- `mode_type = B`
- `step_index = 0`
- B 模式步骤状态
- 当前步骤相关缓存

确保前端展示步骤和后端实际处理步骤一致。

## 9. 推荐实施顺序

```text
第一阶段：修复 B 选项标签比较
        ↓
第二阶段：补齐 C 模式当前问题、参考答案、评分点和视觉事实
        ↓
第三阶段：将评价接口改为结构化错因分析
        ↓
第四阶段：根据评价结果动态选择下一步
        ↓
第五阶段：拆分实时 AI 任务的超时、重试和并发等待配置
        ↓
第六阶段：将 B/C 生成迁移到后台，并增加缓存
        ↓
第七阶段：完善日志、监控和模型质量评估
```

## 10. 验收标准

### 固定选项引导

- 提交 `A. xxx` 和提交 `A` 都能正确识别。
- 正确选项能显示正确反馈。
- 学生提交选项后只调用一次 `qwen3.7-flash`，根据本轮回答动态分析错因并给出纠正方向。
- 学生回答、对话、错因和评价写入现有会话记录，不新增题目侧错因数据结构。
- `ai_answer_b` 缺失时仍能立即进入可用兜底流程。

### 非固定选项引导

- 模型评价时能获取当前引导问题，而不是只获取原题答案。
- 图像题能够使用视觉事实进行评价。
- 对正确、部分正确、错误、答非所问分别返回不同处理结果。
- 学生回答后只调用一次 `qwen3.7-flash`，同一次响应返回评价、错因、纠正方向和下一问题。
- 对话和错因信息在返回下一问题前写入现有会话记录，下一问题根据学生回答调整。
- 不对同一回答进行多轮模型追问；AI 失败时不自动重复调用、不推进步骤，并记录安全降级状态。

### 性能和稳定性

- 正常实时评价尽量控制在 3～8 秒内。
- AI 服务异常时不等待数分钟。
- 前端不再显示 `AIRequestError` 等内部异常类型。
- 可以通过 `trace_id` 定位一次完整的学生引导请求。

## 11. 最终结论

当前系统已经配置并调用 `qwen3.7-flash`，但还没有形成完整可靠的“学生回答分析和自适应引导”能力。

问题的主要根因不是单一模型不稳定，而是系统设计和数据传递存在缺口：

1. AI 调用在同步接口中执行。
2. 交互任务使用了过长的超时和重试策略。
3. C 模式评价缺少当前引导问题和当前步骤参考答案。
4. 图像只展示给前端，没有传递给实时模型。
5. C 模式下一步仍按固定脚本推进。
6. B 模式当前没有在学生回答后额外调用 AI 进行动态错因分析。
7. B 模式存在完整选项文本与选项标签比较不一致的问题。
8. AI 服务异常被统一隐藏，无法快速定位。

建议优先修复正确性问题和上下文问题，再优化实时响应速度，最后完善后台预生成、缓存、日志和模型质量评估。
