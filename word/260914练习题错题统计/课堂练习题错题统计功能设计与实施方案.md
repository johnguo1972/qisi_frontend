# 课堂练习题错题统计功能设计与实施方案

## 1. 文档目的

本文档用于指导教师端“课堂练习题错题统计”功能的开发、联调和验收，覆盖：

1. 课堂管理列表和课程详情的入口按钮。
2. 课堂练习错题统计页面的上下布局、讲义节点切换和学生/题号矩阵。
3. 学生线上答题后的自动错题统计。
4. 学生线下答题后的教师手动标记和 Excel 导入。
5. 总练习题数、学生人数、累计错题、人均错题及学生错题率。
6. “生成精练题”按钮的本期前置校验；精练题真正生成保留到后续开发。

本方案只设计课堂练习场景，不改变学生错题本、学生精练列表、通用教师错题矩阵和已有作业批改的既有业务语义。

本次修订已针对实际代码复核结果补充执行前提：教师端主列表以 `workbench.vue` 为实际入口，课堂练习必须保存不可变的节点来源，矩阵历史数据不能因课堂练习编辑而级联删除，统计模式按学生判断而不是按整堂课强制二选一，Excel 导入规则必须兼容模板实际结构并明确覆盖语义。

Excel 模板保留在本目录：

- [错题统计.xlsx](./错题统计.xlsx)

## 2. 当前代码核查结论

### 2.1 已有代码和可复用能力

| 领域 | 当前实现 | 本需求中的用途 |
|---|---|---|
| 教师课堂/作业列表 | `uniapp/src/pages/teacher/workbench.vue`、`uniapp/src/pages/teacher/mission-list.vue` | `layout.vue` 当前实际显示 `workbench.vue`；`mission-list.vue` 为兼容入口，两处都必须按课堂练习来源分流 |
| 课程卡片 | `uniapp/src/components/CourseCard.vue` | 当前只有“课程资料”“课程练习”，需要补充“错题统计”“课堂反馈” |
| 课程详情 | `uniapp/src/pages/teacher/course-detail.vue` | 顶部操作栏和“课程操作”列表都需要补充两个按钮 |
| 课堂练习数据 | `apps/missions/models.py`、`apps/missions/views.py` | `LearningMission` 保存 `course`、`source_context`、`source_node_ids`；课堂练习节点被保存为 `MissionLevel`，题目关系为 `MissionQuestionRel` |
| 学生范围 | `MissionClassAssignment`、`ClassStudent` | 错题矩阵只允许展示当前已发布课堂练习实际分配到的学生 |

| 学生错题本 | `apps/wrongbook/models.py` 的 `WrongBookItem` | 现有错题矩阵单元格必须关联此记录；手动或导入标记时复用 `get_or_create` |
| 通用教师错题矩阵 | `apps/missions/wrongbook_matrix.py`、`wrongbook_matrix_views.py`、`wrongbook-matrix.vue` | 复用范围同步、版本控制、单元格保存、审计和并发校验的核心思路；不要直接复用其“生成错题练习”按钮语义 |
| XLSX 解析 | `apps/institutions/import_views.py` 的 `_read_xlsx` | 当前只读第一个工作表，不能直接满足本需求的多节点工作表；应抽取为可复用的多工作表解析工具后再使用 |

### 2.2 当前实现与新需求的差距

现有 `wrongbook-matrix.vue` 主要是通用作业错题矩阵，当前行为包括：

- 展示全部题目，不按讲义节点切换。
- 没有顶部四项统计和学生错题率。
- 没有 Excel 导入。
- 单元格默认可编辑，没有“开始手动统计/保存/取消”状态。
- 当前生成函数会先自动保存待保存单元格，再调用已有错题练习生成接口；这与本需求“未保存时点击生成要提示，真正生成放到下次开发”不一致。
- 没有根据 `AnswerAttempt` 自动回填课堂练习矩阵。
- 现有矩阵模型的来源任务唯一约束不适合一个课堂练习同时按多个班级分别统计，必须在新接口中明确班级范围，或完成按班级分片的迁移。

因此，本需求不建议在现有通用页面中继续堆叠条件分支。建议新建课堂练习错题统计适配层和页面，复用底层矩阵的通用单元格、版本和审计能力。

## 3. 业务对象和统一口径

### 3.1 课堂练习的唯一来源

只有同时满足以下条件的 `LearningMission` 才能进入本功能：

```text
status = published
source_context = course_practice
course_id is not null
```

课堂练习节点使用以下不可变映射：

```text
CourseTree.id/name/sort_no
        ↓ 创建或发布课堂练习时固化
MissionLevel.source_node_id + level_name_snapshot + node_sort_no_snapshot
        ↓ 每道题同步固化
MissionQuestionRel.source_node_id + source_node_name_snapshot
        + level_id + question_id + node_question_no + sort_no
```

统计页和 Excel 映射只使用课堂练习快照中的 `source_node_id`、节点名称、节点顺序和节点内题号。不要根据题目当前所属课程节点、`source_node_ids` 数组下标或节点名称临时反推历史课堂练习节点，否则课程目录调整后会导致历史统计串节点。旧课堂练习如果没有节点快照，必须在进入本功能时一次性补建；无法无歧义补建的任务不得进入新页面，应返回明确错误。

### 3.2 错题单元格口径

一个有效单元格由以下三项唯一确定：

```text
matrix_id + student_id + source_question_id
```

单元格 `wrong=true` 表示该学生在该课堂练习题中被计为错题；页面显示 `❌`。空白表示正常、未标记或没有线上答题数据。不要用学生姓名或题目显示序号作为数据库主键。题目显示序号必须使用当前节点内的 `node_question_no`，数据库唯一键仍使用题目 UUID。

建议在 `TeacherWrongBookCell` 增加 `mark_source` 字段：

| 值 | 含义 |
|---|---|
| `online` | 从线上有效答题自动得到 |
| `manual` | 教师在页面中手动标记 |
| `import` | 教师通过 Excel 导入 |

现有 `status` 继续表示单元格生命周期：`marked`、`cancelled`、`generated`、`locked`。`mark_source` 表示来源，不能与 `status` 混用。

### 3.3 线上答题判定

线上错题数据来源为 `AnswerAttempt`，筛选条件为：

```text
attempt.mission_id = 当前课堂练习
attempt.student_user_id 属于当前矩阵学生范围
attempt.question_id 属于当前课堂练习题目范围
attempt.is_subjective_pending = false
attempt.submit_source != draft
attempt.is_correct = false
```

同一学生同一题只需有一条有效错误答题记录即可计为错题。这样可以保留“学生曾经答错过该题”的错题语义，即使学生后来重答正确，也不会在本次课堂错题统计中自动消失。删除、作废或更换课堂练习关系时，才允许撤销对应的线上单元格。若产品后续改为“只看最后一次答题结果”，应另行确认并修改统计口径，不能在前端自行改变。

主观题在教师批阅前不计入错题；批阅接口把 `is_subjective_pending` 改为 `false` 且判为错误后，应触发同一套线上同步服务。

### 3.4 统计公式

统计范围为当前选定班级和当前课堂练习的全部有效节点。

```text
总练习题数 = 有效课堂练习题目数（去重后的 source_question_id）
学生人数   = 当前有效学生数
累计错题   = status in (marked, generated, locked) 的有效学生/题目单元格数
人均错题   = 累计错题 / 学生人数；学生人数为 0 时返回 0
学生错题率 = 该学生错题数 / 总练习题数 × 100%；总题数为 0 时返回 0
```

除四项汇总外，接口还必须返回每道题的 `wrong_count` 和 `wrong_rate`，以满足“统计所有题目的错题情况”。题目错题率的分母为当前有效学生数，分母为 0 时返回 0。

页面展示的百分比由后端返回数值，统一保留两位小数；前端只负责追加 `%`，不要在多个页面重复计算。

   - `source_context=course_practice`：进入新的课堂练习错题统计页。

所有新页面 URL 参数统一使用 `course_id`、`mission_id`、`class_id`；不要在同一条新链路中混用 `courseId`、`missionId`。

## 5. 错题统计页面布局和交互

### 5.1 页面上下结构

页面分为上下两部分，中间不放与本需求无关的复杂操作。

上半部分：

1. 页面标题：课程名/课堂练习名/当前班级。
2. 班级选择器：多班级任务必须明确选班；单班级可直接展示。
3. 四个统计卡片：总练习题数、学生人数、累计错题、人均错题。
4. 每个学生的错题率可显示在右侧学生信息或统计表下方，不新增另一套学生查询接口。
5. 操作按钮：刷新、导入错题统计、手动统计错题、生成精练题。
6. 数据模式提示：线上自动统计、线下手动统计或 Excel 导入。

下半部分：

- 左侧：当前课堂练习的节点列表，按 `node_sort_no` 排序，显示节点名和题目数量。
- 右侧：矩阵表格。
  - 固定第一列为学生姓名，可附带学号。
  - 表头为当前节点下的练习题序号。
  - 学生/题号交叉单元格显示 `❌` 或空白。
  - 横向滚动只作用于右侧题目区域；学生列固定。
  - 题号按当前节点内的 `node_question_no` 显示，不能使用全局 `sort_no`、UUID 或数据库无序结果显示。

节点切换只改变当前展示题目，不重新请求学生名单，也不改变已保存的单元格。前端应使用后端返回的 `node_id` 过滤 `questions` 和每个学生的 `cells`，不要使用题目数组下标作为节点关联。

### 5.2 三种数据模式

模式按学生确定，不按整堂课强制二选一。响应中 `mode` 表示页面是否存在可编辑的线下数据：只要当前班级所有学生都有线上有效答题则为 `online`，只要存在没有线上有效答题的学生则为 `offline`；每个学生另返回 `data_source`，值为 `online` 或 `offline`。线上学生只读，线下学生可手动标记或导入。若产品最终确定一堂课只能使用一种模式，应在服务端增加明确的课堂级约束，而不是由前端猜测。

边界规则：学生人数为 0 时返回 `mode=offline`；当部分学生线上、部分学生线下时仍返回 `mode=offline`，但线上学生行必须锁定，不能因为页面整体为 offline 而开放线上学生编辑。

#### 线上自动统计

- 页面打开时后端同步 `AnswerAttempt`，返回自动错题单元格。
- 表格只读，不能手动修改自动结果。
- 没有线上有效答题记录时，返回所有单元格空白，并显示“暂无线上答题数据”。
- 有线上答题但全部正确时，表格仍全部为空，统计累计错题为 0；页面显示“已有线上答题，当前暂无错题”。

#### 线下手动统计

- 仅对没有线上有效答题记录的学生允许进入编辑；已有线上答题的学生行和对应单元格只读。
- 初始按钮为“手动统计错题”。
- 点击后进入编辑态，按钮改为“保存统计”，同时显示“取消”按钮。
- 编辑态点击单元格切换 `wrong`，只修改前端待保存集合。
- 点击“取消”丢弃未保存变更并恢复最近一次后端数据。
- 点击“保存统计”才提交后端；保存成功后退出编辑态并刷新统计。

#### Excel 导入

- 仅允许导入到没有线上有效答题的学生；Excel 中出现线上学生时返回 `ONLINE_DATA_READ_ONLY` 并整体回滚。导入不会修改线上学生的单元格。
- 有未保存手动变更时，先提示保存或取消，不能静默覆盖。
- 后端整本校验通过后再一次性写入；部分行成功、部分行失败时不写入半成品。
- 默认采用“本次导入全量覆盖线下数据”语义：当前班级中本次 Excel 涉及节点的线下学生/题目单元格，值为 `1` 的设为 `import/marked`，空白设为 `cancelled`；不涉及的节点和线上学生不变。若产品要采用追加语义，必须另设 `append=true` 并在页面明确显示，不能隐式混用。
- 导入成功后退出编辑态，重新加载节点、矩阵和统计。

## 6. 后端模块和数据设计

### 6.1 推荐目录

在现有 `apps/missions` 内增加课堂场景适配层，不新增重复的错题矩阵表：

```text
apps/missions/
├─ classroom_wrongbook_service.py       # 节点解析、线上同步、统计、导入
├─ classroom_wrongbook_views.py         # 课堂场景接口
├─ classroom_wrongbook_import.py        # XLSX 多工作表解析和校验
└─ migrations/                          # 字段、索引、约束迁移
```

`wrongbook_matrix.py` 中稳定的通用能力（范围同步、单元格并发保存、审计）可以抽成内部公共函数，由新服务调用。不要复制一份几乎相同的学生范围、题目快照和版本校验逻辑。

### 6.2 现有模型的最小扩展

#### `TeacherWrongBookMatrixQuestion`

新增以下快照字段，确保课程目录改名后历史统计仍可按原节点查看：

| 字段 | 类型 | 说明 |
|---|---|---|
| `source_node_id` | UUID，可空 | `CourseTree.id`，只作来源标识，不直接依赖当前目录存在 |
| `node_name_snapshot` | varchar(200) | 统计页显示的节点名称 |
| `node_sort_no` | positive integer | 节点顺序 |

现有 `source_relation`、`source_question_id`、`question_no_snapshot`、`sort_no` 和 `question_snapshot` 继续保留。

但当前 `MissionLevel` 和 `MissionQuestionRel` 没有可靠的课程节点 ID，不能只在错题矩阵创建时补救。必须在课堂练习创建/编辑/发布链路中增加并写入以下字段：

| 对象 | 字段 | 说明 |
|---|---|---|
| `MissionLevel` | `source_node_id` | 对应 `CourseTree.id`，可空仅用于兼容历史数据 |
| `MissionLevel` | `node_name_snapshot` | 发布时的节点名称 |
| `MissionLevel` | `node_sort_no_snapshot` | 发布时的节点顺序 |
| `MissionQuestionRel` | `source_node_id` | 题目所属的课堂节点 |
| `MissionQuestionRel` | `source_node_name_snapshot` | 题目所属节点名称快照 |
| `MissionQuestionRel` | `node_question_no` | 节点内显示题号，供页面和 Excel 使用 |

课堂练习发布时必须校验每道题只能归属一个节点；同一题在多个节点重复出现时，要么按不同关系生成独立的课堂题目快照，要么拒绝发布，不能依赖 `source_question_id` 去重后静默丢失节点信息。

现有 `source_relation` 外键不能继续使用 `CASCADE`，否则编辑课堂练习删除关系时会级联删除历史错题矩阵。迁移方案为：将矩阵题目和单元格的 `source_relation` 改为可空 `SET_NULL`，历史展示完全依赖题目/节点快照；同步调整服务层对空关系的处理。不得通过删除历史矩阵来规避外键问题。

#### `TeacherWrongBookCell`

新增：

```text
mark_source varchar(20) default 'manual'
```

为已有数据设置 `manual`，不改变旧数据的显示。新增索引建议为：

```text
(matrix_id, mark_source, status)
(matrix_id, student_id, status)
```

#### 导入批次

必须增加 `TeacherWrongBookImportBatch`，用于审计和前端显示导入结果；只有在确认不新增表的情况下，才允许使用现有审计表保存同等完整信息：

| 字段 | 说明 |
|---|---|
| `id` | UUID7 主键 |
| `matrix` | 当前矩阵 |
| `uploaded_by` | 操作教师 |
| `file_name` | 原始文件名，不作为路径 |
| `status` | `validating` / `succeeded` / `failed` |
| `sheet_count` | 识别到的节点工作表数 |
| `total_cells` | 读取到的非空标记单元格数 |
| `imported_count` | 实际写入数量 |
| `skipped_count` | 已存在且结果不变的数量 |
| `failed_count` | 错误数量 |
| `errors` | JSON 错误数组，含 sheet、row、column、reason |
| `created_at` | 创建时间 |
| `completed_at` | 完成时间 |

如果团队不希望新增批次表，至少必须把文件名、导入数量、错误摘要写入现有 `TeacherWrongBookMatrixAudit.payload`；不能只在日志中记录。

导入采用同步事务接口时，`validating` 不是对外可见的长期状态：批次记录应先在事务外创建，校验失败后更新为 `failed`，校验成功并写入矩阵后更新为 `succeeded`。如果文件较大改为异步任务，才保留 `validating` 并增加查询批次状态接口。

### 6.3 多班级约束

当前 `TeacherWrongBookMatrix` 有“一个来源任务只能有一个矩阵”的唯一约束。如果一个课堂练习可以发布给多个班级，必须改为：

```text
class_obj IS NULL  → source_mission 唯一（兼容旧通用矩阵）
class_obj IS NOT NULL → source_mission + class_obj 唯一（课堂统计矩阵）
```

课堂统计接口必须在服务端解析并校验 `class_id`：

- 只有一个有效班级时可以省略，后端自动选中。
- 多个有效班级时缺少 `class_id` 返回 `CLASS_REQUIRED`，前端显示班级选择器。
- 传入不属于任务分配范围的班级返回 404/403，不允许仅凭题目或课程 ID 查询。

迁移前先检查重复矩阵；旧矩阵不得直接删除。迁移完成后执行唯一约束检查和历史接口回归测试。

具体迁移顺序必须固定为：

1. 先为 `MissionLevel`、`MissionQuestionRel`、`TeacherWrongBookMatrixQuestion`、`TeacherWrongBookCell` 增加可空字段和新索引。
2. 为已发布课堂练习回填节点快照；回填无法确定的任务标记为 `scope_invalid`，禁止进入新统计页并输出修复清单。
3. 将 `source_relation` 改为 `SET_NULL`，检查删除课堂练习关系不会删除矩阵题目、单元格和审计记录。
4. 清理或合并重复的课堂矩阵后，再增加 `(source_mission, class_obj)` 唯一约束；旧通用矩阵保持原有兼容逻辑。
5. 所有迁移完成后执行 `python manage.py check`、`python manage.py makemigrations --check` 和历史矩阵回归测试。

## 8. Excel 模板解析规则

### 8.1 模板结构

当前模板实际包含两个工作表：

1. `Sheet1`：班级、年级、上课时间、学生姓名、手机号等基础信息，作为人工核对信息，不作为节点工作表。
2. `错题地图第1讲`：节点统计表。
   - 第 1 行为标题。
   - 第 2 行：A 列为“姓名”，B 列起为题号 `1、2、3...`。
   - 第 3 行起：每行一个学生。
   - 单元格为 `1` 表示该学生该题错误；空白表示不计错题。

后端必须按工作表名称匹配节点名称。`Sheet1` 是本模板固定的基础信息表，只按固定名称和表头识别后忽略；其他未匹配当前课堂练习节点的工作表一律返回 `NODE_NOT_FOUND`，不能静默忽略，也不能把未知工作表当成新节点写入数据库。模板中的示例姓名必须先替换为当前班级真实姓名，不能直接把示例数据导入生产课堂。

### 8.2 解析实现

项目依赖中没有 `openpyxl`。建议将 `apps/institutions/import_views.py` 中只读首表的 XLSX XML 解析逻辑抽取为 `apps/common/xlsx_reader.py`，扩展支持：

- workbook relationships 到 worksheet 的映射。
- shared strings 和 inline strings。
- 多工作表顺序。
- 单元格坐标转行列号。
- 空单元格补齐。
- 文件大小和工作表/行数上限。

不要在课堂错题导入页再复制一套 ZIP/XML 解析代码。若决定引入 `openpyxl`，必须同步更新 `requirements.txt`、部署镜像和测试环境；不能只在本机可用。

### 8.3 校验规则

校验必须先完成，全部通过后才开启数据库事务。

1. 文件扩展名必须为 `.xlsx`，大小不超过 10 MB。
2. 至少有一个与当前节点匹配的统计工作表。
3. 仅忽略名称为 `Sheet1` 且表头符合基础信息表的工作表；其他工作表必须匹配当前节点，否则报 `NODE_NOT_FOUND`。不允许用“无法解析就忽略”的宽松规则。
4. 每个节点工作表第 2 行必须存在姓名列和数字题号。
5. 同一工作表题号不能重复。
6. 题号必须存在于该节点的课堂练习快照中；未知题号报错。
7. 学生姓名先做首尾空白、连续空白和 Unicode 规范化；只允许精确匹配当前班级学生。模板中类似示例姓名尾部的 `a` 不得自动删除，除非产品明确配置了别名规则；重名时返回 `AMBIGUOUS_STUDENT`，不能随机匹配。
8. 单元格只接受数字 `1` 或空白；其他值返回 `INVALID_MARK_VALUE`。
9. 数据行的学生必须属于当前课堂和班级；模板中不存在的学生返回 `STUDENT_NOT_FOUND`。
10. 一个学生在同一工作表不能出现两次。
11. 允许模板缺少某些题号列，缺失列视为空白；不允许出现未知题号列。
12. 同一批次内重复导入相同结果时记为 `skipped_count`，不产生重复单元格。
13. 导入默认是“所涉及节点的线下学生全量覆盖”：标记为 `1` 的单元格设为 `import/marked`，空白单元格将既有 `manual` 或 `import` 错误设为 `cancelled`；线上学生、未涉及节点和 `generated/locked` 单元格不允许被覆盖。
14. 若存在姓名尾部字符、别名或模板中的旧班级信息，前端必须在导入前提示“请使用当前班级真实姓名”；不得以 `Sheet1` 的手机号或年级信息替代系统学生 ID 进行静默匹配。

### 8.4 导入映射伪代码

```python
def import_classroom_wrongbook(matrix, workbook, version, teacher):
    validate_version(matrix, version)
    scope = load_matrix_scope(matrix)
    parsed = parse_all_sheets(workbook)
    validated_marks = []

    for sheet in parsed.sheets:
        if is_roster_sheet(sheet):
            continue
        node = scope.node_by_normalized_name.get(normalize(sheet.title))
        if node is None:
            raise ImportError('NODE_NOT_FOUND', sheet.title)

        question_by_no = scope.questions_by_node_and_no[node.node_id]
        headers = parse_question_headers(sheet)
        validate_headers(headers, question_by_no)

        for row_no, row in data_rows(sheet):
            student = scope.student_by_normalized_name.get(normalize(row.name))
            if student is None:
                raise ImportError('STUDENT_NOT_FOUND', sheet.title, row_no)
            for question_no, value in row.marks(headers):
                if value != 1:
                    validate_blank(value, sheet.title, row_no, question_no)
                    continue
                question = question_by_no[question_no]
                validated_marks.append((student.id, question.id))

    with transaction.atomic():
        for student_id, question_id in deduplicate(validated_marks):
            upsert_wrong_cell(
                matrix=matrix,
                student_id=student_id,
                question_id=question_id,
                mark_source='import',
                marked_by=teacher,
            )
        write_import_audit(matrix, teacher, validated_marks)
```

真实实现中错误应使用项目异常类型和结构化错误对象；伪代码只用于说明事务边界和映射顺序。

导入实现还必须收集“已涉及节点的全部线下学生/题目”集合，对 Excel 中的空白值执行取消逻辑，而不是只写入值为 `1` 的单元格。建议先生成完整的 `desired_marks`，校验无误后在同一事务中执行 upsert 和取消；线上、`generated`、`locked` 单元格必须在事务内再次校验并拒绝覆盖。批次审计要记录 `replace_scope`、实际变更数、取消数和跳过数。

## 9. 线上自动同步实现

建议提供唯一服务函数：

```text
sync_classroom_online_wrongbook(mission_id, class_id=None)
```

调用位置：

1. 学生提交客观题并生成 `AnswerAttempt` 后。
2. 教师批阅主观题并更新 `AnswerAttempt` 后。
3. 教师首次打开或手动刷新课堂错题统计页时作为补偿同步。

服务函数的职责：

- 读取当前课堂练习的活动学生和题目快照。
- 用一次查询得到有效错误答题的 `(student_id, question_id)` 集合。
- 对集合内项目 `get_or_create WrongBookItem`，再 upsert `TeacherWrongBookCell(mark_source='online', status='marked')`。
- 对原来来源为 `online` 且不存在任何有效错误答题记录的单元格设为 `cancelled`；学生后来重答正确不能撤销“曾经答错”的统计结果。不要覆盖 `manual/import` 来源单元格；对线上学生产生的任何手动/导入写入都返回 `ONLINE_DATA_READ_ONLY`。
- 使用事务和唯一约束，保证重复提交不会产生重复记录。
- 不在循环中逐条查询学生和题目；先建立内存字典，再批量处理，避免 N+1 查询。

线上同步服务不得修改 `MasteryRecord`、学生作业进度或学生端错题本的其他状态。学生答题已有逻辑继续负责这些业务，课堂统计只读取并投影结果。答题写入与同步应处于同一事务，或采用可重试的事务外补偿机制；GET/刷新同步必须幂等，不能因答题接口短暂失败导致页面永久缺数据。

```text
latestImport
```

统计、节点和学生数据均来自 `matrix`；不要单独维护一套 `wrongCount`、`studentCount`、`questionCount` 再在单元格点击时手动累加。单元格变化后统一重新请求或使用后端响应覆盖 `matrix`，这样可以避免节点切换、取消编辑和并发冲突时数据不一致。

Excel 选择和上传必须按发行端实现：H5 使用文件选择器；App 使用 `uni.chooseFile` 或项目当前可用的本地文件选择能力；微信小程序使用其可用的文件选择/上传能力。若某端无法选择 `.xlsx`，该端显示“不支持 Excel 导入，请使用 H5/指定端操作”，不能把本地路径直接传给后端。三个端都必须传 `multipart/form-data` 的 `file`、`class_id`、`version` 和可选 `replace_scope`，并处理成功、校验失败、409 冲突三类响应。

## 11. 权限、安全和并发

1. 所有课堂统计接口使用教师登录和教师会话权限。
2. 权限判断沿用 `can_manage_matrix` 的创建教师、班级教师和课程编辑者规则，但课堂接口还必须校验 `source_context=course_practice`。
3. 服务端重新计算学生和题目范围，不能相信前端上传的学生 ID、题目 ID、节点 ID。
4. Excel 只保存导入元数据和错误摘要；原始文件如需保存，路径必须由后端生成，不能使用用户可控文件名拼接路径。
5. 使用矩阵 `version` 做乐观锁；保存或导入遇到 409 时提示“数据已被更新，请刷新后重试”，并丢弃本地待保存集合。
6. 线上自动数据和教师手动数据不能互相静默覆盖。权限按学生行判断：线上学生禁止手动保存和导入，线下学生允许手动保存和导入；线下学生后续产生线上答题时，后端将该学生切换为线上只读，并按 `mark_source` 记录冲突，不覆盖已有人工数据。页面刷新必须显示“该学生已有线上答题，人工统计已锁定”的提示。
7. `WrongBookItem` 的创建必须以当前有效学生和当前课堂题目为前提，禁止仅凭上传的 UUID 写入。

## 14. 验收标准

1. 教师可从课堂管理列表和课程详情进入正确的课堂错题统计页面。
2. 教师从实际 `workbench.vue`、兼容 `mission-list.vue`、课程卡片和课程详情进入时，参数、任务选择和权限结果一致。
3. 课程存在多个课堂练习时，必须先选择任务，不会默认打开错误任务。
4. 页面上半部分四项统计、题目错题人数/错题率准确，学生错题率与后端数据一致。
5. 页面下半部分能按讲义节点切换；左侧固定学生列，右侧显示节点内题号，错误单元格显示 `❌`。
6. 学生线上答题后，客观题错误自动显示；主观题待批阅不显示，批阅为错后显示。
7. 没有线上答题时，进入页面右侧矩阵全部为空，并可进入手动统计。
8. 手动统计必须经过“开始编辑—保存/取消”，未保存内容不会影响服务端数据。
9. 模板中的 `1` 能正确导入为错题；节点、学生、题号不匹配时有明确错误且不产生半批数据。
10. 导入空白能正确取消线下旧标记，导入、手动保存和线上同步都不会产生重复的学生/题目单元格。
11. 生成精练题按钮按本期三种校验提示工作，不提前创建精练题任务。
12. 旧的学生错题本、学生作业列表错题统计、教师通用错题矩阵和已有错题练习生成流程回归通过。
13. 所有前端字段都能在后端响应中找到对应字段，所有 ID 统一使用字符串，所有错误都有稳定的 `reason_code` 或接口错误码。

## 15. 最终设计结论

本需求的核心不是再创建一套独立的“学生×题目”表，而是在现有教师错题矩阵基础上增加课堂练习的节点来源、线上答题同步、线下导入和页面状态控制。推荐采用“通用矩阵核心 + 课堂练习适配层”的结构：

- `LearningMission/MissionLevel/MissionQuestionRel` 负责课堂练习、节点和题目范围。
- `AnswerAttempt` 负责线上答题事实，课堂统计服务负责投影为 `online` 单元格。
- `TeacherWrongBookCell` 负责统一保存线上、手动和导入的错题状态。
- `WrongBookItem` 继续作为学生错题记录和后续精练题的来源关联。
- Excel 导入只负责解析、校验和写入矩阵，不在前端猜测学生或题目 ID。
- 前端只消费统一响应，不复制后端统计公式。
- 本期“生成精练题”只完成校验和提示，后续生成流程独立开发。

这样可以满足线上自动统计、线下手动统计和 Excel 导入三条业务路径，同时把旧页面、旧接口和后续精练题生成的边界保持清楚。

本方案在完成第 6.2、6.3 节的数据迁移，第 4 节的实际入口接入，第 8 节的模板兼容规则以及第 12 节测试后，可以进入开发执行。当前文档本身已完成设计修订，但不代表源代码已经实现；开发完成后必须以第 14 节验收标准和第 12.3 节命令进行验证。
