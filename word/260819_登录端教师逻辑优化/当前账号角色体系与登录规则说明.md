# 当前账号角色体系与登录规则说明

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档日期 | 2026-08-23 |
| 适用端 | H5、小程序 |
| 适用链路 | 手机号验证码登录、微信登录、角色切换 |
| 当前状态 | 已按当前代码和数据模型整理 |

## 2. 结论摘要

当前平台不是“选择任意角色即可进入对应平台”，而是：

> 登录页面上的角色是本次登录请求的目标角色；只有账号已经拥有该角色的有效授权，登录或切换才会成功。

一个账号可以拥有多个角色，但“多角色”不等于“任意角色自动开通”。当前已支持教师主动选择学生或家长登录时自助开通对应角色；其他未授权角色仍不能通过选择入口直接获得。

## 3. 当前支持的角色

系统当前定义四类平台角色：

| 角色值 | 页面名称 | 主要用途 |
|---|---|---|
| `student` | 学生 | 学生做题、错题本、精练题、成长等 |
| `teacher` | 教师 | 教师备课、组卷、布置作业、查看学生情况等 |
| `parent` | 家长 | 绑定学生后查看学生作业和学习情况 |
| `admin` | 管理员 | 机构和平台管理 |

登录页会展示这些角色入口，但入口展示仅表示平台支持该角色，不表示当前账号已经开通该角色。

## 4. 账号角色数据结构

系统使用两层角色信息：

### 4.1 `UserAccount.role_type`

这是账号的历史默认角色和兼容字段，不能单独代表当前账号全部可用角色。

### 4.2 `UserRole`

这是当前多角色授权表，核心字段包括：

- `user`：账号；
- `role`：角色值；
- `status`：授权状态，只有 `active` 才能使用；
- `grant_source`：角色来源，例如业务开通、登录自助开通等。

同一账号可以有多条不同角色授权，例如：

```text
同一账号
├── teacher / active
├── student / active
└── parent  / active
```

当前会话使用 `active_role` 表示本次进入的平台角色。切换角色时只重新签发对应角色的会话令牌，不会覆盖账号已有的其他角色。

相关代码：

- `apps/accounts/models.py`
- `apps/accounts/roles.py`
- `apps/accounts/serializers.py`

## 5. 手机号验证码登录规则

登录接口：

```text
POST /api/v1/auth/login
```

请求中的 `role_type` 表示希望进入的角色。

### 5.1 新账号

| 选择角色 | 当前行为 |
|---|---|
| 学生 | 验证码校验通过后可创建学生账号并登录 |
| 家长 | 按当前家长登录规则可开通家长角色并登录 |
| 教师 | 不能通过普通登录自助创建，返回 `ROLE_NOT_GRANTED` |
| 管理员 | 不能通过普通登录自助创建，返回 `ROLE_NOT_GRANTED` |

教师和管理员涉及教学、机构及管理权限，必须由业务或平台管理员预先授权，不能由用户仅通过登录页选择获得。

### 5.2 已有账号

已有账号请求某个角色时，系统会检查该账号是否存在对应的有效授权：

- 已有该角色授权：登录成功；
- 教师账号主动选择学生：自动开通学生角色并以学生身份登录；
- 已有账号主动选择家长：按家长自助开通规则处理；
- 没有该角色授权：返回 `ROLE_NOT_GRANTED`；
- 账号已停用：返回 `ACCOUNT_INACTIVE`。

当前已有账号选择家长角色时，遵循已实现的家长角色自助开通规则；但这只代表获得家长端登录资格，不代表已经绑定任何学生。查看学生数据仍需完成家长与学生的有效绑定。

## 6. 角色切换规则

角色切换接口：

```text
POST /api/v1/auth/switch-role
```

切换流程如下：

```text
当前登录账号
    ↓
提交目标角色
    ↓
检查 UserRole 是否存在且 status=active
    ├── 是：签发目标角色会话并进入对应端
    └── 否：返回 403 ROLE_NOT_GRANTED
```

因此，教师账号点击“学生端”后报错，是因为该账号当前只有教师授权，没有有效的学生授权。这是后端权限校验，不是前端页面故障。

相关代码：

- `apps/accounts/views.py` 的 `login`、`switch_role`
- `apps/accounts/roles.py` 的 `has_user_role`
- `uniapp/src/pages/login/index.vue`

## 7. 教师账号如何拥有学生和家长角色

### 7.1 教师获得学生角色

教师在登录页主动选择“学生”，使用已验证的手机号或微信身份登录即可。后端会在账号状态正常、账号具有教师角色且学生角色尚未被撤销的前提下，自动创建一条：

```text
UserRole(role=student, status=active, grant_source=self_login)
```

然后以 `active_role=student` 签发会话，进入学生端。原有教师角色不会被覆盖，之后可以在角色切换入口之间切换。

如果该教师账号的学生角色曾被明确撤销，系统不会通过再次登录恢复该角色，仍会返回 `ROLE_NOT_GRANTED`，以保证撤销操作有效。

### 7.2 教师获得家长角色

教师在登录页主动选择“家长”，使用同一账号手机号或微信身份登录即可。系统会按家长自助开通规则增加 `parent` 角色，并以家长身份进入家长端。

家长角色开通后，还需要在家长端提交学生绑定申请，并由学生确认，才能查看该学生的学习数据。角色开通不等于自动拥有学生数据访问权。

### 7.3 前端操作步骤

1. 退出当前教师会话，返回登录页；
2. 选择“学生”或“家长”；
3. 使用同一个已注册手机号完成验证码登录，或使用已绑定微信身份登录；
4. 登录成功后进入所选角色的页面；
5. 需要切回教师端时，在角色切换入口选择教师。

当前管理员成员管理页面仍主要用于开通教师和管理员角色；教师自助开通学生、家长角色通过登录页完成。

## 8. 为什么不能允许选择任意角色直接登录

如果任意用户都可以通过选择角色直接登录，将产生以下风险：

- 普通用户可以伪装成教师，访问教学和学生数据；
- 普通用户可以伪装成管理员，访问机构管理功能；
- 角色切换接口无法区分“选择角色”和“已获授权角色”；
- 微信扫码、手机号登录和小程序登录的权限边界会失效；
- 账号审计无法追踪角色来源和授权责任。

因此，当前系统把“登录认证”和“角色授权”分开处理：验证码或微信授权证明用户身份，`UserRole` 决定用户可以进入哪些平台角色。

|---|---:|---:|---:|---:|
| 新账号 | 可登录 | 拒绝，需授权 | 按家长自助开通规则处理 | 拒绝，需授权 |

## 10. 当前平台是否支持“一个账号多个角色”

支持。当前多角色模型和会话机制已经支持一个账号同时拥有多个角色。

但当前不支持以下行为：

> 新用户不经过授权，仅通过选择教师或管理员角色，就自动获得教师或管理员角色并登录。

这不是技术上不能实现，而是当前平台的安全策略和业务规则明确禁止。若未来需要调整，应单独设计角色申请、审核、授权来源和审计规则，不能只放开登录接口的角色校验。

## 11. 相关接口和错误码

| 接口 | 用途 |
|---|---|
| `POST /api/v1/auth/login` | 手机号验证码登录 |
| `POST /api/v1/auth/switch-role` | 切换已授权角色 |
| `POST /api/v1/auth/wechat-login` | 小程序微信登录 |
| 微信网页登录相关接口 | H5 微信扫码登录和账号绑定 |

常见错误：

| 错误码 | 含义 |
|---|---|
| `ROLE_NOT_GRANTED` | 账号未开通请求的角色 |
| `INVALID_ROLE` | 提交了系统不支持的角色值 |
| `ACCOUNT_INACTIVE` | 账号已停用 |

## 12. 最终规则

当前平台采用以下规则：

1. 角色入口可以统一展示，但必须经过角色授权才能进入；
2. 一个账号可以拥有多个角色；
3. 角色切换只能切换到已经开通且状态为 `active` 的角色；
4. 学生和家长支持一定范围的自助开通流程；
5. 教师和管理员不能通过普通登录自助获得权限；
6. 教师主动选择学生登录时，可以自助开通学生角色并进入学生端；
7. 教师主动选择家长登录时，可以按家长规则自助开通家长角色；
8. 管理员角色仍不能通过普通登录自助获得。
