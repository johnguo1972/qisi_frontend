关联 题的功能 ，我顺便 做了：

方案对比：
1. 推荐：独立 QuestionRelation 关联表
   - 每一对关联题只保存一条记录，逻辑上双向关联。
   - 可按原题查询“已关联题”，也可排除已关联题后查询“可关联题”。
   - 支持唯一约束，重复点击“关联”不会产生重复关系。
   - 后续可自然扩展“解除关联、关联来源、人工备注”等能力。
2. 在题目 JSON 字段中保存关联 UUID 列表
   - 改动少，但双向同步、去重、删除和查询都会复杂。
   - 不利于后续统计及权限审计。
   - 不推荐。
3. 每次点击仅动态查找类似题、不保存关系
   - 不满足“建立关联关系后转到已关联 Tab”的要求。
   - 不采用。
拟定实现如下：
- 将现有按钮从“类似题”改为“关联题”。
- 点击后弹出带右上角关闭按钮的关联题弹窗，默认打开“可关联题”页签。
- 弹窗包含两个 Tab：
  - “已关联题”：显示此前已建立关联的题目。
  - “可关联题”：显示满足全部条件、且尚未关联的题目。
- 候选条件由后端统一执行：
  - 同一学科；
  - 具体难度系数在本题难度 ±0.5 范围内，包含边界；
  - 至少包含一个相同知识点；
  - 排除本题及已关联题。
- 为兼容目前知识点 JSON 中可能存在的“知识点 ID、module、名称”等结构，后端会先统一标准化再判断交集，避免仅依赖某一种旧格式造成漏匹配。
- 候选列表展示题号、题干摘要、难度系数、共同知识点；每行右侧增加多选框。
- 用户勾选多题后点击弹窗内“关联”按钮：
  - 后端批量建立去重后的双向关联；
  - 成功后自动切换到“已关联题”；
  - 同时刷新两个 Tab，已关联题不再出现在候选列表。
- 候选结果采用分页加载，避免相同学科和难度条件下题量很大时弹窗卡顿。
