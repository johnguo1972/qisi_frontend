## 一、方案概述

### 1.0 v1.2 执行边界与架构决策

本方案仍只覆盖学生端二维码、小程序、手机 H5、纸质作业和家长/助教提交，不改变教师现有题库、组卷和任务管理的核心流程。以下决策覆盖文档中旧版本的同名内容：

1. `MissionShortCode` 是作业入口短码的唯一来源，不在 `LearningMission` 再增加 `short_code` 字段。当前任务模型只有一个 `class_obj`，因此一个任务对应一个班级；需要投放到多个班级时，沿用现有“按班级克隆任务”能力，每个任务/班级生成一条短码。
2. 新增接口使用文档中写明的完整路径，客户端不得依赖 Django `APPEND_SLASH` 重定向，避免 POST 被 301/302 改写。现有无尾斜杠的学生接口保持不变。
3. 学生图片必须先关联到已创建的 `AnswerAttempt`，再上传图片；不再把学生答题图片发送到题库图片接口。
4. 家长只能通过服务端绑定关系代理某个孩子，客户端不能直接提交任意 `student_id`。
5. 纸质扫描不是“只扫二维码”：必须创建扫描批次、上传页面图片、校验学生/任务/页码、处理重复页和缺页后才能归档。
6. AppSecret、openid、session_key 只允许在后端或服务端缓存中存在，不能进入前端、接口响应或版本库。

### 1.0.1 当前项目兼容性结论

开发前必须先修复前端依赖版本漂移，并补充 `build:mp-weixin` 脚本。后端 `manage.py check` 通过不代表二维码功能已存在；当前仓库尚无 `apps/qrcode`、微信登录接口、扫码页面和纸质扫描页面，因此本文件是实施方案，不是已完成能力。

### 1.1 背景

当前系统学生端仅支持 App 平板端（学生/家长）和 H5 平台端（教师/家长/机构），使用 UniApp 架构开发。为了解决以下问题，需要引入 **"微信小程序 + 手机H5网页 + 纸质作业二维码"** 作为学生端主方案：

- 学生不一定拥有平板设备，手机才是最高频的终端
- 纸质作业（线下场景）无法与系统打通
- 微信小程序无需下载安装，扫码即用，使用门槛极低
- 培训机构场景需要纸质作业的高效分发与回收

### 1.2 核心目标

老师布置作业后，系统自动生成：

| 产出物 | 说明 |
|--------|------|
| 微信小程序入口 | 学生扫码直接进入小程序对应作业页面 |
| H5 网页链接 | 浏览器可直接访问的作业页面 |
| 作业二维码 | 每份作业生成专属二维码，扫码直达 |
| 6位作业码 | 方便学生手动输入进入作业 |
| 可打印的纸质作业PDF | 含"一人一码"，支持批量扫描归档 |

### 1.3 学生完成作业的多种路径

| 路径 | 适用场景 |
|------|----------|
| 手机在线做题 | 选择/判断/填空等适合手机操作的题型 |
| 纸上完成后拍照上传 | 计算/作文/几何作图等不适合手机输入的题型 |
| 打印作业完成后扫码上传 | 有打印条件的场景 |
| 培训机构公共设备提交 | 使用机构平板/电脑/扫描仪 |
| 家长/助教代为上传 | 低年级学生场景（详见第七章） |

## 三、二维码功能详细需求

### 3.1 作业二维码（核心功能）

#### 3.1.1 功能描述

老师发布作业（`learning_mission`）后，系统自动为该作业的每个班级生成专属二维码。二维码绑定信息：

```json
{
  "type": "mission",
  "mission_id": "uuid-v7",
  "class_id": "uuid-v7",
  "student_id": "uuid-v7 | null",
  "subject": "数学",
  "end_at": "2026-08-10T23:59:59"
}
```

> **注意**：使用 `end_at`（与模型字段名一致），不使用 `deadline`。

#### 3.1.2 二维码内容格式

推荐使用 URL 格式（兼容小程序和H5）：

```
https://qisi.chengxuelu.com/hw/{mission_short_code}
```

其中 `mission_short_code` 为作业的短码（6位大写字母数字组合，如 `A3F8K2`），方便手动输入。

#### 3.1.3 扫码后行为（H5 中转页）

二维码统一指向 H5 中转页，由前端判断环境后跳转：

```
https://qisi.chengxuelu.com/hw/A3F8K2
```

| 终端环境 | 判断方式 | 行为 |
|----------|----------|------|
| 微信扫码 | `navigator.userAgent` 含 `MicroMessenger` | 展示"打开小程序"按钮，调用 URL Scheme / URL Link |
| 其他手机浏览器 | 移动端 UA 检测 | 直接跳转H5作业页面 |
| PC浏览器 | 桌面端 UA | 展示H5页面+二维码供手机扫码 |
| App内WebView | `window.QisiApp` 全局变量 | 通过 JS Bridge 跳转App原生页面 |

H5 中转页路径：`uniapp/src/pages/student/scan-entry.vue`（通过 Nginx 配置 `/hw/{code}` 指向该页面）。

#### 3.1.4 作业短码生成规则

- 格式：6位大写字母 + 数字（排除易混淆字符 I/O/L/0/1）
- 字符集：`ABCDEFGHJKMNPQRSTUVWXYZ23456789`
  - 字母（去I/L/O）：**23个**
  - 数字（去0/1）：**8个**
  - 合计：**31个字符**
- 组合空间：**31⁶ ≈ 8.87亿**，配合限流可防遍历
- 唯一性：全局唯一，数据库唯一索引保证
- 有效期：跟随作业截止时间（`end_at`），过期后短码标记为 `expired`

### 3.2 学生专属二维码（一人一码）

#### 3.2.1 功能描述

在打印纸质作业时，每份作业顶部自动打印该学生的专属二维码，用于：

- 标识作业归属（哪个学生的）
- 标识作业信息（哪次作业的哪一页）
- 支持批量扫描归档（高速扫描仪一次性扫描40份作业，自动拆分）

#### 3.2.2 二维码内容格式

```json
{
  "type": "paper_homework",
  "student_id": "uuid-v7",
  "mission_id": "uuid-v7",
  "page_no": 1,
  "total_pages": 3,
  "question_range": "1-8"
}
```

编码为 URL：
```
https://qisi.chengxuelu.com/paper/{student_short_code}/{mission_short_code}/p1
```

#### 3.2.3 学生短码生成规则

- 格式：8位大写字母 + 数字（字符集同上，31个字符）
- 与学生的班级关联绑定
- 每个学生在每个班级有唯一的短码

### 3.3 同类错题练习二维码

#### 3.3.1 功能描述

老师批改后分配同类错题时，系统自动生成"错题强化练习"二维码，支持三种模式：

| 模式 | 说明 |
|------|------|
| 手机直接完成 | 选择/判断/填空等适合手机的题型 |
| 生成错题练习单PDF | 含原错题+错因提示+同类题+学生专属二维码 |
| 答案纸上传 | 题目在手机上查看，学生在纸上计算，上传答题纸 |

### 3.4 拍照上传增强功能

#### 3.4.1 基础拍照流程（已实现）

当前 `answer.vue` 已支持拍照上传，调用 `uni.chooseImage` 或 H5 的 `input[type=file]`。

现有图片上传接口：`POST /api/v1/student/attempts/<attempt_id>/upload-image`

#### 3.4.2 需要新增的增强功能

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 图片模糊检测 | P1 | 拍摄后自动检测是否模糊，提示重拍 |
| 多页连续拍摄 | P1 | 支持连续拍摄多页，自动编号 |
| 漏页提醒 | P2 | 检测是否有缺失页码 |
| 上传断点续传 | P2 | 网络中断后可继续上传 |
| 提交前预览确认 | P1 | 展示所有已拍照片的预览，支持排序/删除 |
| 图片自动压缩 | P1 | 上传前自动压缩到合理大小（<1MB） |

> 注：纸张边缘识别、自动裁剪、纠偏等高级图像处理功能建议使用第三方 SDK（如百度OCR SDK / 腾讯云图像处理），不在本次自研范围内。

## 四、数据库设计（Django ORM）

> **重要**：所有新表使用 Django ORM 定义，通过 `makemigrations` + `migrate` 执行迁移，与项目现有59张表的管理方式保持一致。所有 UUID 主键使用 `uuid_utils.compat.uuid7`（UUID v7，时间有序）。

### 4.1 新建 Django 模型

在 `apps/qrcode/models.py` 中定义：

```python
import uuid_utils.compat as uuid_compat
from django.db import models
from apps.accounts.models import UserAccount
from apps.missions.models import LearningMission
from apps.institutions.models import Class
from apps.wrongbook.models import WrongBookItem


class MissionShortCode(models.Model):
    """作业短码 —— 每个已发布任务/班级对应一条6位短码。"""
    id = models.UUIDField(primary_key=True, default=uuid_compat.uuid7, editable=False)
    mission = models.ForeignKey(
        LearningMission, on_delete=models.CASCADE,
        related_name='short_codes', db_column='mission_id',
    )
    class_obj = models.ForeignKey(
        Class, on_delete=models.SET_NULL, null=True, blank=True,
        db_column='class_id', related_name='mission_short_codes',
    )
    short_code = models.CharField(max_length=6, unique=True, db_index=True)
    payload_json = models.JSONField(default=dict, blank=True)
    status = models.CharField(max_length=20, default='active')  # active/expired/revoked
    scan_count = models.IntegerField(default=0)
    expires_at = models.DateTimeField(null=True, blank=True)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        db_table = 'mission_short_code'
        constraints = [
            models.UniqueConstraint(
                fields=['mission', 'class_obj'],
                name='uq_mission_short_code_mission_class',
            ),
        ]

    def __str__(self):
        return f"ShortCode({self.short_code}) -> {self.mission}"

### 4.2 现有模型扩展

在 `apps/accounts/models.py` 新增微信身份表，不能使用 `login_name=wx_{openid}` 作为唯一绑定方式：

```python
class WechatIdentity(models.Model):
    id = models.UUIDField(primary_key=True, default=uuid_compat.uuid7, editable=False)
    user = models.OneToOneField(UserAccount, on_delete=models.CASCADE, related_name='wechat_identity')
    appid = models.CharField(max_length=64)
    openid = models.CharField(max_length=128)
    unionid = models.CharField(max_length=128, blank=True, default='')
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        db_table = 'wechat_identity'
        constraints = [
            models.UniqueConstraint(fields=['appid', 'openid'], name='uq_wechat_appid_openid'),

```

### 5.2 接口详细设计

#### 5.2.1 获取作业二维码

```
GET /api/v1/missions/{mission_id}/qrcode
```

**响应**：`image/png` 二维码图片

**参数**：
- `size`: 二维码尺寸，默认 300
- `format`: 图片格式，`png`（默认）/ `svg`

#### 5.2.2 通过短码获取作业信息（公开接口）

```
GET /api/v1/hw/{short_code}
```

**响应**（JSON）：
```json
{
  "code": 0,
  "data": {
    "mission_id": "uuid",
    "mission_name": "第三章练习",
    "class_name": "三班",
    "subject": "数学",
    "end_at": "2026-08-10T23:59:59",
    "level_count": 3,
    "question_count": 15,
    "status": "published",
    "need_login": true
  }
}
```

> `subject` 从现有 `creator_teacher.subject` 映射；`LearningMission` 没有独立 subject 字段时返回 `null`。此接口为**公开接口**（无需登录），仅返回作业基本信息，不返回学生、手机号、题目正文或答案。

#### 5.2.3 进入作业（需登录）

```
POST /api/v1/hw/{short_code}/enter
```

**请求体**：
```json
{
  "device_type": "miniprogram"
}
```

**响应**：
```json
{
  "code": 0,
  "data": {
    "mission_id": "uuid",
    "redirect_url": "/pages/student/mission?id=xxx",
    "progress": {
      "progress_status": "in_progress",
      "progress_percent": 35
    }
  }
}
```

服务端必须校验：短码 active、当前时间未超过 `expires_at`/任务 `end_at`、任务已发布、学生属于该任务班级或目标学生列表。进入接口负责创建缺失的 `StudentMissionProgress`，不能仅返回前端 redirect_url。

#### 5.2.3.1 家长代理提交规则

家长先调用 `/parent/children`，再调用 `/parent/context` 选择孩子。后续学生任务、答题和图片接口从服务端代理上下文读取真实学生 ID：

```json
{
  "acting_role": "parent_proxy",
  "child_id": "uuid",
  "context_token": "short-lived-token"
}
```

服务端必须查询 `StudentParentBind(bind_status='active')`，并将 `AnswerAttempt.student_user_id` 设置为绑定孩子；不能允许家长越权切换到未绑定学生。

#### 5.2.3.2 答题图片的正确顺序

学生端先提交答案文本/选择项，创建 `AnswerAttempt` 并取得 `attempt_id`，然后再调用图片接口，最后由服务端更新图片清单和 `image_count`：

```text
POST /api/v1/student/attempts
  → 返回 attempt_id
POST /api/v1/student/attempts/{attempt_id}/upload-images
  → 创建 AttemptImage，返回每页检测结果
```

图片上传必须校验 attempt 所属真实学生、题目和任务；上传失败时 attempt 保留 `image_upload_status='partial'/'failed'`，允许重试，不得创建题库 `QuestionImage`。

#### 5.2.3.3 微信登录与绑定

```json
POST /api/v1/auth/wechat-login
{ "code": "wx.login 返回的一次性 code" }
```

已绑定身份直接返回 access/refresh token；未绑定身份只返回：

```json
{ "code": 0, "data": { "need_bind_phone": true, "bind_token": "短期一次性令牌" } }
```

响应中禁止返回 `openid` 和 `session_key`。AppID、AppSecret 必须从 `WECHAT_MP_APPID`、`WECHAT_MP_APPSECRET` 环境变量读取，调用微信接口必须设置超时并处理微信错误码。

```json
POST /api/v1/auth/wechat-bind-phone
{
  "bind_token": "...",
  "mobile": "手机号",
  "verify_code": "短信验证码",
  "role_type": "student | parent"
}
```

绑定接口复用现有 `verify_code` 和 `generate_tokens(user)`，成功后创建 `WechatIdentity`，并使 bind_token 立即失效。

#### 5.2.4 生成纸质作业PDF（一人一码）

```
GET /api/v1/missions/{mission_id}/paper-pdf
```

**参数**：
- `class_id`: 班级ID（可选，默认该教师所有班级）
- `student_ids`: 指定学生ID列表（可选，默认全班）
- `include_answer_sheet`: 是否包含答题纸，默认 false

**响应**：PDF 文件流

**PDF内容结构**：
```
[封面] 作业标题 + 班级 + 截止日期（end_at）
[第1页] 学生A专属二维码 + 题目内容（第1-N题）
[第2页] 学生A专属二维码 + 题目内容（续）
...
[分隔]
[第1页] 学生B专属二维码 + 题目内容
...
```

> 使用 `reportlab` 生成 PDF，对于大班級（40+学生）使用 Celery 异步生成。

#### 5.2.5 多图上传+模糊检测（扩展现有接口）

```
POST /api/v1/student/attempts/{attempt_id}/upload-images
Content-Type: multipart/form-data
```

**参数**：
- `images`: 图片文件列表（支持多文件，最多20张）
- `page_order`: 页面顺序（JSON数组，可选）
- `client_request_id`: 客户端幂等键，重试时保持不变

**响应**：
```json
{
  "code": 0,
  "data": {
    "images": [
      {
        "id": "uuid",
        "url": "https://...",
        "page_no": 1,
        "blur_score": 85.5,
        "is_blurry": false
      }
    ],
    "total_pages": 3
  }
}
```

**实现说明**：
- 文件类型验证：仅允许 JPEG/PNG/WebP
- 单张大小限制：< 5MB
- 上传后使用 Pillow 计算 Laplacian 方差进行模糊检测；检测只针对本次上传文件，不根据客户端传入 URL 下载文件
- 模糊阈值：blur_score < 50 判定为模糊

#### 5.2.6 图片模糊检测

```
POST /api/v1/student/attempts/image-check
```

**请求体**：
```json
使用 `multipart/form-data` 的 `image` 文件，或使用本次上传接口返回的 `image_id`；服务端不接受任意远程 URL。
```

**响应**：
```json
{
  "code": 0,
  "data": {
    "blur_score": 35.2,
    "is_blurry": true,
    "suggestion": "图片较模糊，建议重新拍摄"
  }
}
```

### 5.2.7 纸质作业扫描归档

助教端必须先创建批次，并指定任务；每次识别纸张上的二维码后上传对应页面图片。二维码解析结果必须保留 `student_code`、`mission_code`、`page_no`、`total_pages`，不能只返回任务短码。

```text
POST /api/v1/paper-scan/batches
{ "mission_id": "uuid", "expected_count": 40 }

POST /api/v1/paper-scan/batches/{batch_id}/pages
multipart/form-data:
  image, student_code, mission_code, page_no, total_pages, client_request_id

GET /api/v1/paper-scan/batches/{batch_id}/summary
POST /api/v1/paper-scan/batches/{batch_id}/complete
```

服务端处理规则：

- 操作人必须是任务教师、机构授权助教或管理员；任务、班级和学生码必须匹配。
- `(batch_id, student_id, page_no)` 唯一；重复上传返回原记录，不重复生成答题记录。
- `summary` 返回学生总数、已收页、缺页、重复页、未知码和待人工审核页。
- `complete` 只有在没有未知码、重复页和缺页（或人工确认放行）时才能成功。
- 归档时按学生/任务/页码生成答题材料，并以 `submit_source='scan'` 创建或更新对应答题记录；全流程保留批次审计记录。

## 八、H5 中转页实现

### 8.1 路由映射

当前 H5 使用 UniApp hash 路由，二维码地址 `/hw/{code}` 不是 UniApp 路由本身。生产环境必须由 Nginx 将短码重定向为 hash 页面，不能把请求代理到仅用于本地开发的 5273 端口：

```nginx
# Nginx 配置
location ~ ^/hw/([A-Z2-9]{6})$ {
    return 302 /#/pages/student/scan-entry?code=$1;
}
location ~ ^/paper/([A-Z2-9]{8})/([A-Z2-9]{6})/p([0-9]+)$ {
    return 302 /#/pages/student/scan-entry?student_code=$1&code=$2&page=$3;
}
```

实际配置应合并到现有 H5 静态 `location /`，保留 `/api/`、`/static/`、`/media/` 的既有代理/alias；`/hw/` 和 `/paper/` 必须放在通用 `location /` 之前或使用正则优先级验证。

### 8.2 中转页逻辑（scan-entry.vue）

```typescript
// pages/student/scan-entry.vue
import { onLoad } from '@dcloudio/uni-app'

onLoad((options) => {
  const code = String(options?.code || options?.scene || '').trim().toUpperCase()

  // 仅 H5 读取 UA；小程序环境不能访问 navigator
  // #ifdef H5
  const ua = window.navigator.userAgent || ''
  const isWechat = /MicroMessenger/i.test(ua)
  const isMobile = /iPhone|iPad|Android/i.test(ua)
  // #endif
  // #ifdef MP-WEIXIN
  const isWechat = true
  const isMobile = true
  // #endif

  if (isWechat) {
    // 微信环境：展示"打开小程序"按钮
    loadMissionByCode(code)
    // 微信 H5 通过已配置的 wx-open-launch-weapp 或服务端生成的 URL Link 打开小程序，不能直接拼接 URL Scheme。
  } else if (isMobile) {
    // 手机浏览器：直接展示H5作业页面
    loadMissionByCode(code)
  } else {
    // PC浏览器：展示二维码供手机扫码
    showDesktopQR(`https://qisi.chengxuelu.com/hw/${code}`)
  }
})
```

### 8.3 微信环境打开小程序

微信扫码扫描到 H5 链接时，需要通过微信开放标签或服务端生成的 URL Link 打开小程序：

- **二维码主方案**：使用 `wxacode.getUnlimited` 生成小程序码，scene 只携带 6 位短码，直接进入 `pages/student/scan-entry`。
- **H5 微信内打开**：使用 `wx-open-launch-weapp` 或后台生成的 URL Link；需要配置业务域名、JS 接口安全域名和用户点击动作。
- 不在前端保存 AppSecret，也不在 H5 页面直接拼接或暴露 URL Scheme。

### 12.4 Nginx 配置

```nginx
server {
    listen 443 ssl;
    server_name qisi.chengxuelu.com;

    # 已有的 API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # H5 使用 hash 路由：二维码路径先重定向到真实页面
    location ~ ^/hw/([ABCDEFGHJKMNPQRSTUVWXYZ23456789]{6})$ {
        return 302 /#/pages/student/scan-entry?code=$1;
    }
    location ~ ^/paper/([ABCDEFGHJKMNPQRSTUVWXYZ23456789]{8})/([ABCDEFGHJKMNPQRSTUVWXYZ23456789]{6})/p([0-9]+)$ {
        return 302 /#/pages/student/scan-entry?student_code=$1&code=$2&page=$3;
    }

    # 生产环境使用现有 H5 静态 alias，不代理 5273 开发端口

    # 静态文件
    location /media/ {
        alias /mnt/datadisk0/qisi/backend/media/;
    }
}
```

> 实际 Nginx 配置需根据服务器上的部署方式（H5是独立Nginx静态服务还是由Django serve）调整。

## 十三、安全与性能考量

### 13.1 安全

| 风险 | 对策 |
|------|------|
| 短码被猜测遍历 | 31⁶ ≈ 8.87亿组合空间，配合接口限流（同一IP每分钟≤30次） |
| 二维码被伪造 | 后端校验短码对应真实数据才有效，无数据则返回404 |
| 图片上传安全 | 限制文件大小（单张<5MB）、类型（仅jpg/png/webp）、数量（单次≤20张） |
| 微信登录安全 | code 一次性使用（微信服务端校验）；openid 只进服务端身份表，AppSecret/session_key 不下发 |
| 家长代提交权限 | 必须有 `student_parent_bind` 记录才能代提交 |
| 纸质扫描越权 | 批次绑定任务和操作人；二维码中的学生/任务/页码必须全部匹配 |
| 图片检查 SSRF | 只接收上传文件或服务端生成的 image_id，不请求客户端提供的任意 URL |

### 13.2 性能

| 场景 | 优化策略 |
|------|----------|
| 二维码生成 | 后端缓存（Redis，key=`qr:{mission_id}:{size}`，TTL 1小时） |
| 短码查询 | 数据库唯一索引 + Redis 缓存（TTL 10分钟）；缓存命中仍校验过期时间 |
| 图片上传 | 前端压缩（quality=80）+ 多图并发上传 |
| PDF生成 | 大班级使用 Celery 异步生成，返回任务ID；必须提供任务状态查询和失败重试 |
| 模糊检测 | 后端 Pillow Laplacian 方差检测，<50判定模糊 |

---

### 13.3 幂等、限流和过期处理

- 短码公开查询按 IP+短码限流；进入任务按用户+短码限流。限流必须落到 Redis/DRF throttle，不得只写在设计说明中。
- 短码生成使用数据库唯一约束和最多 5 次重试；超过重试次数返回可识别错误并记录日志。
- 每次查询都以 `expires_at` 和 `LearningMission.end_at` 的较早时间为准；过期短码返回 `410` 或业务码 `4101`，并异步更新为 `expired`。
- 上传、批次页面、微信绑定都要求 `client_request_id`/一次性令牌幂等，网络重试不能重复写入。
- PDF 异步生成必须提供 `GET /api/v1/tasks/{task_id}` 状态接口，状态至少包括 `pending/running/success/failed`。
