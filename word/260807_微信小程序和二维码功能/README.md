### 数据库新增表

| 表名 | 用途 | 主键策略 |
|------|------|----------|
| `mission_short_code` | 作业短码（任务+班级一条，6 位，31^6 ≈ 8.87 亿种组合） | UUID v7 |
| `student_class_short_code` | 学生班级短码（一人一码，8 位） | UUID v7 |
| `attempt_image` | 答题图片管理（多图片 + 模糊评分） | UUID v7 |
| `wrongbook_practice_sheet` | 错题练习单（含 class_id） | UUID v7 |
| `paper_scan_batch` | 纸质作业扫描批次 | UUID v7 |
| `paper_scan_page` | 扫描页与学生/任务/页码的归档记录 | UUID v7 |

### 关键技术修正

| 修正项 | 说明 |
|--------|------|
| UUID 生成 | 使用 `uuid_utils.compat.uuid7`（与项目一致），非 `gen_random_uuid()` |
| JWT 函数 | 使用 `generate_tokens(user)`（非 `generate_jwt_tokens`） |
| 截止时间字段 | 统一为 `end_at`（非 `deadline`） |
| 图片 URL 字段长度 | `VARCHAR(1000)`（非 500） |
| submit_source | 扩展现有 `AnswerAttempt.submit_source` choices（不新增字段） |
| 小程序 tabBar | 使用原生 `pages.json` 的 `tabBar` 配置 |
| 登录页角色 | 小程序端仅显示学生/家长两个角色 |
| 扫码函数 | 封装到 `utils/scan.ts`，组件不直接调用 wx.scanCode |
| H5 中转 | `/hw/{code}` 由 Nginx 重定向到 hash 页面，不直接代理开发服务器 |
| 微信密钥 | 仅后端环境变量保存，前端和文档不保存 AppSecret/session_key |
| 图片流程 | 先创建答题记录，再上传 `AttemptImage`，最后以图片状态完成提交 |
| 家长代理 | 服务端根据绑定关系确定 `student_user_id`，不信任前端传入学生 ID |

### 生产环境部署步骤

详见文档 01 第 4 章和第 10.4 节。主要流程：

1. 备份数据库（pg_dump）
2. Git pull + 激活虚拟环境
3. 清理/校验前端依赖（`npm ci`，确保所有 UniApp 包版本一致）
4. Django migrate（UUID v7 + 6 张新表 + 微信身份表）
5. 收集静态文件
6. 重启 gunicorn
7. 配置 `/hw/`、`/paper/` hash 中转和 `/media/` 路由
8. 重载 Nginx
9. 小程序端：`npm run build:mp-weixin` → 真机验证 → 开发者工具上传 → 提交审核 → 发布
