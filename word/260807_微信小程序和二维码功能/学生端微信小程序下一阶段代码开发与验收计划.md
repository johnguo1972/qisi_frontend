## 0.4 对 H5 和 App 的影响及兼容要求

小程序改动原则上不应破坏 H5 和 App，但本项目共享 `pages.json`、API、工具和业务页面，因此每次修改都必须进行三端兼容检查。

### 不会直接影响 H5/App 的改动

- 仅新增 `#ifdef MP-WEIXIN` 条件编译分支。
- 仅新增小程序专用组件，并且只在 `mp-home.vue` 等小程序页面中引用。
- 仅新增小程序页面和 API 文件。
- `pages.json` 只新增页面注册，不修改 H5/App 的入口、已有页面路径和既有导航行为。

### 可能影响 H5/App 的改动

1. 修改共享 `answer.vue` 时，必须保留 H5 的文件选择和 App 的 `uni.chooseImage` 分支，不能无条件执行 `wx.chooseMedia`。
2. 修改 `image-upload.ts` 时，必须保留 H5/App 分支，不能删除原有上传实现。
3. 修改 `request.ts` 或 `media-url.ts` 时，必须确认 H5 仍使用相对 API 地址，App 和小程序仍使用生产 HTTPS 地址。
4. 修改后端答案接口时，必须保持 H5/App 旧请求兼容，或提供版本化接口。
5. 小程序学生/家长继续进入 `pages/student/mp-home`，H5/App 继续进入 `pages/student/layout`。
6. `switchTab` 只能跳转到 tabBar 页面；普通页面必须使用 `navigateTo`。

### 共享文件的分端处理矩阵

| 文件/模块 | MP-WEIXIN | H5 | APP-PLUS | 兼容要求 |
|---|---|---|---|---|
| `pages/student/answer.vue` | 使用 attempt 图片上传流程和 `wx.chooseMedia` | 保留文件选择、预览和原有 H5 上传流程 | 保留 `uni.chooseImage` 和 App 上传流程 | 通过条件编译或平台适配函数隔离，不复制三套提交业务逻辑 |
| `utils/image-upload.ts` | `wx.chooseMedia`，上传到 `/student/attempts/{id}/upload-images` | `document.createElement('input')`、`FormData`、`fetch` | `uni.chooseImage`、`uni.uploadFile` | 公共函数只负责统一结果格式，平台 API 不能跨端直接执行 |
| 后端答案提交 | 支持 attempt 创建/上传/提交新流程 | 继续支持原有提交请求，或迁移到兼容的新流程 | 继续支持原有提交请求，或迁移到兼容的新流程 | 新接口不能删除旧字段；必要时保留旧接口并增加新接口 |
| 图片上传响应 | 读取 `data.items[*].url` | 保持现有响应解析兼容 | 保持现有响应解析兼容 | 不允许只为小程序改变旧端响应格式 |
| 入口页面 | `pages/student/mp-home` | `pages/student/layout` | `pages/student/layout` | `App.vue`、登录页和退出登录回跳保持同一规则 |

### 0.3 attempt 图片上传接口方案

推荐采用两阶段提交：

#### 第一步：创建草稿 attempt

```http
POST /api/v1/student/attempts/start
Authorization: Bearer <JWT>
Content-Type: application/json
```

请求：

```json
{
  "question_id": "题目UUID",
  "mission_id": "任务UUID，可为空",
  "level_id": "关卡UUID，可为空"
}
```

响应至少包含：

```json
{
  "code": 0,
  "data": { "attempt_id": "attempt UUID" }
}
```

#### 第二步：上传图片

```http
POST /api/v1/student/attempts/{attempt_id}/upload-images
Authorization: Bearer <JWT>
Content-Type: multipart/form-data
```

字段名统一为 `images`。接口必须校验：

- attempt 存在
- attempt 所属用户等于当前 JWT 用户
- 图片数量、大小和格式限制
- 返回可访问的图片 URL

当前后端有两个相关接口：旧的单图接口返回 `data.url`，文档指定的批量接口 `/student/attempts/{attempt_id}/upload-images` 返回 `data.items`。前端不能读取不存在的 `data.images` 字段。前后端应统一使用批量接口和 `data.items`，推荐响应格式为：

```json
{
  "code": 0,
  "data": {
    "items": [
      { "id": "图片UUID", "url": "/media/...", "page_no": 1 }
    ]
  }
}
```

#### 第三步：提交答案

```http
POST /api/v1/student/attempts/{attempt_id}/submit
Authorization: Bearer <JWT>
Content-Type: application/json
```

请求：

```json
{
  "answer_content": {
    "text": "文字答案",
    "images": ["图片URL"]
  }
}
```

如果后端不采用两阶段接口，则必须明确允许前端先调用现有 `POST /student/attempts` 创建 attempt，再使用响应中的 `attempt_id` 上传图片，并补充更新 attempt 答案内容的接口。不能让前端继续调用 `/questions/upload-image/`。

## 三、阶段 1：前端答题图片闭环

涉及文件：

- `uniapp/src/pages/student/answer.vue`
- `uniapp/src/api/student.ts`
- `uniapp/src/utils/image-upload.ts`
- `uniapp/src/components/PhotoUploadEnhanced.vue`

执行要求：

1. 进入主观题页面时创建或准备草稿 attempt。
2. `PhotoUploadEnhanced` 统一处理拍照、相册选择、预览、删除、重试和上传状态。
3. 微信小程序使用 `wx.chooseMedia`。
4. H5/App 保留现有平台分支。
5. 上传地址只能是：

```text
/api/v1/student/attempts/{attempt_id}/upload-images
```

6. 提交时把图片 URL 和文字答案一并写入 attempt。
7. 上传失败不能导致答案静默丢失，应允许重试。
8. 图片上传成功后再提交答案，或使用后端两阶段提交接口。

当前 `image-upload.ts` 中的临时实现不能只读取 `data.images`；必须读取 `data.items`，并兼容每项的 `url` 字段。

验收：

- 选择相册图片成功上传
- 调用摄像头拍照成功上传
- 上传中显示状态
- 上传失败可重试
- 退出页面后重新进入不会错误显示其他题目的图片
- 后端数据库中的图片关联当前 attempt 和当前用户
- 不能访问或上传到其他用户的 attempt
