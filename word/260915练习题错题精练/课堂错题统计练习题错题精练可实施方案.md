# 课堂错题统计“练习题错题精练”可实施方案

> 复核日期：2026-09-16
>
> 适用范围：教师端课堂管理/课堂练习错题统计、学生端个性化错题重练、PDF 预览与下载；学生端作业名称、题目来源和任务类型也纳入本方案。

> 本次修订：补充“错题练习题 DOCX + 一次性映射表导入—按题号建立 UUID 映射—按学生生成精练题”闭环。错题练习题 DOCX 必传，映射表在界面上可选；当 DOCX 没有可解析的“针对练习册题号”时，映射表是确认激活和生成的必要条件。映射表不按学生维护，并明确复用现有 DOCX 解析能力、使用 `import_purpose=wrongbook_drill` 和 `source_type=wrongbook_drill`，不修改其他 DOCX 导入场景。

## 1. 结论摘要

仓库已经具备本需求约 60% 的基础能力：

- 课堂练习错题统计页面已经存在，支持线上自动统计、线下手动标记和 Excel 导入。
- 错题矩阵已经按“学生 + 课堂练习题”保存错题状态，并有版本号、来源和审计能力。
- 题目已有快照、图片、选项、答案、解析等数据，适合生成历史稳定的 PDF。
- 学生端已经能看到已发布 `LearningMission`，并支持作业 PDF 下载。
- 系统已有通用“错题 → 关联题”生成流程，但该流程是 AI/规则候选题逻辑，不是本需求的固定映射逻辑。

本需求的主要缺口不是重新做错题统计，而是补上下面的闭环：

```text
导入“同类错题练习”DOCX
    ↓ 复用现有 DOCX 解析能力，标记 wrongbook_drill
按错题练习题中的针对练习册题号与当前课堂练习册题目自动建立内部映射
    ↓
课堂练习错题
    ↓ 按原练习册错题号查询对应的错题练习题
错题练习题（精练题实际内容来源）
    ↓ 按学生分组、保存题目快照
每个学生一份错题重练作业
    ↓ 生成专属 PDF
学生端查看/下载；教师端按学生预览/下载
```

推荐采用“一个生成批次 + 每个学生一个个性化作业”的实现方式。这样可以直接复用学生端作业权限、进度和 PDF 展示，同时避免当前共享 PDF 路径导致的学生题目串看问题。

## 2. 需求口径与图示映射解释

### 2.1 映射关系的方向

图 1 的两列建议固定解释为：

| 图示列 | 业务含义 | 示例 |
|---|---|---|
| 错题练习题号 | 错题重练中实际要呈现的精练题 ID/题号 | 5、6、7 |
| 针对练习册题号 | 课堂练习中学生答错的练习册原题 ID/题号 | 4 |

因此每一行表达：

> 当学生错了课堂讲义练习题 4 时，将精练题 5、6、7 加入该学生的错题重练作业。

必须用下面的验收样例验证方向，避免生成时把关系反向使用：

```text
课堂错题：4
映射记录：5→4、6→4、7→4
生成结果：精练题 5、6、7
```

数据库字段命名建议直接体现方向：`drill_question_id` 表示导入的精练题，`source_wrong_question_id` 表示学生做错的练习册原题。错题统计提供原题 ID/题号，自动映射提供精练题 ID，接口和数据库不要使用含义模糊的 `question_id`。

图中 `20～32 原题` 这类内容不应作为错题练习题生成结果；导入错题练习题 DOCX 时应将其识别为原题标记并跳过，不应把它当作精练题。

重要边界：图 1 存在一对多、且不一定同号的关系，仅凭“错题练习题号”和“练习册题号”两个显示数字不能推导出 `5、6、7 → 4`。导入时必须从 DOCX 可解析的“针对练习册题号”信息、该导入批次已绑定的业务元数据或一次性映射表中取得目标题号；三者都无法提供时，必须在预览中标记 `missing_target` 并禁止确认激活，不能默认按同号映射、不能全库猜测，也不能让生成服务静默选题。

自动题号映射允许一对多：同一道课堂错题可以对应多个精练题。生成时按错题练习题导入文档顺序去重，避免同一学生同一道精练题重复出现。

### 2.2 “只针对讲义练习题的错题”

本期生成范围必须同时满足：

1. 错题来源是当前已发布的课堂练习任务中的题目。
2. 错题单元格属于当前选择的班级。
3. 当前课堂使用的练习册题目能够定位到题号和题目 ID。
4. 已导入当前课堂/讲义对应的错题练习题，并能按题号与练习册题目自动匹配。
5. 匹配出的错题练习题属于当前导入批次，题目内容和答案可生成快照。

不纳入本期生成的内容：

- 学生错题本中与本课堂练习无关的历史错题。
- 通用错题矩阵自动筛选出的 AI 候选题。
- 仅通过 `QuestionRelation` 建立、但没有出现在当前错题统计对应关系中的关联题。
- 没有导入错题练习题、或按题号没有匹配结果的课堂错题；该错题应记录为“暂无对应精练题”，不能静默替换为其它题。

### 2.3 讲义题目来源和范围

当前平台存在两条题目来源链路，实施时必须区分：

```text
课程目录练习：CourseQuestionLink(course, tree_node, question)
讲义练习：    HandoutQuestion(handout, question, display_snapshot)
课堂任务：    MissionQuestionRel(mission, level, question, question_snapshot)
```

本功能的最终错题范围以当前课堂任务的 `MissionQuestionRel` 为准，因为它代表实际发布给学生的题目和当时的题目快照。不能仅通过当前课程目录或当前讲义重新反查，否则题目移动、讲义替换后会影响历史统计。

错题练习题导入批次必须与当前课堂任务、练习册/讲义和讲义节点绑定。系统优先使用导入题目中可解析的 `target_workbook_question_no`；当前提供的 DOCX 没有该信息时，使用本批次一次性上传的映射表，与当前课堂练习册题号建立内部映射。生成时定位到 `source_wrong_question_id`（练习册原题）和 `drill_question_id`（导入的错题练习题）。映射表不按学生维护；如果 DOCX 和映射表都没有目标题号信息，不能直接生成。

本需求涉及的两个示例文件分别承担不同职责：`2026年秋季物理9年级A+B班-练习册（上册）(1).docx` 提供练习册原题，`第2讲 热机和热量转化-同类错题练习(1).docx` 提供生成精练题的实际题干、选项、图片、答案和解析。错题练习题导入只能使用专用业务类型 `wrongbook_drill`，不能改变普通课程题目或讲义导入的既有语义。

### 3.2 当前实现与需求的差距

1. `classroom-wrongbook-statistics.vue` 的“生成精练题”目前只做前置校验，然后提示“功能将在下次开发”。
2. 当前课堂统计接口没有返回每个学生的精练题生成状态、作业 ID 或 PDF 地址。
3. 现有通用生成流程会根据 AI/知识点/难度推荐题，不能直接满足图 1 的确定性映射。
4. `QuestionRelation` 是逻辑双向关系，不能替代本功能按错题练习题导入后生成的“精练题 → 针对练习册错题”自动映射。
5. `CourseQuestionLink` 只是课程题目关联，`HandoutQuestion` 只是讲义题目关联，二者只能用于题目范围校验，不能作为本功能的映射来源。
6. 当前通用生成代码按一个批次创建一个 `LearningMission`，再通过 `MissionQuestionRel.target_student_ids` 做题目可见性；但是 `LearningMission.pdf_file_path` 只有一个路径，生成的 PDF 会包含批次中所有学生的题目，无法保证学生 PDF 个性化。
7. 当前统计页的学生错题率由前端按当前节点的可见题目重新计算；需求中的学生错题率应按当前课堂练习全部有效题目计算，建议以后端返回值为准。
8. 当前表格已有“错题率”列，但没有“操作”列；生成后需要按学生展示“查看/预览/下载”操作。
9. 生成接口需要同时读取课堂错题原题关系、活动错题练习题导入源和自动题号映射，并兼容 `HandoutQuestion` 和 `CourseQuestionLink` 两种练习册/讲义题目来源；不能要求教师为学生重复导入或填写映射。
10. 现有 `mission_kind` 和 `source_type` 序列化器是白名单，新增个性化错题重练任务时必须同步修改，否则任务可能无法通过现有任务接口或被普通作业列表错误展示。
11. 现有学生首页会展示所有已发布任务；若重复生成不归档旧任务，学生会看到多份相同错题重练作业。
12. 现有矩阵题目唯一键是 `matrix + source_question_id`；同一题若出现在多个节点，节点信息会被合并，必须在发布时禁止或调整矩阵唯一键。

## 4. 推荐总体架构

### 4.1 选择“每个学生一个个性化作业”的原因

推荐为每个有有效映射结果的学生创建一条内部个性化 `LearningMission`：

- 学生首页可以直接复用现有发布作业列表。
- 学生只能看到自己的任务和题目，不依赖前端过滤来保证隔离。
- 每条任务天然拥有独立 `pdf_file_path`。
- 教师端可以通过学生行找到唯一的作业和 PDF。
- 学生可以继续使用现有任务答题、提交、进度和图片题能力。

这些个性化任务应使用独立的 `mission_kind=classroom_wrong_drill`，并在教师普通作业列表中默认隐藏或按“来源课堂练习”归组，避免生成 40 名学生后教师作业列表出现 40 条重复任务。

### 4.2 新增数据对象

需要新增“错题练习题导入批次”和题号映射数据，但映射表只作为本批次一次性导入项，不按学生维护。教师上传“同类错题练习”DOCX，并可同时上传映射表；系统复用现有 DOCX 解析能力，使用 `import_purpose=wrongbook_drill` 解析并保存错题练习题。若 DOCX/业务元数据已包含 `target_workbook_question_no`，系统直接自动建立映射；若没有，则使用本次上传的映射表建立映射。生成服务另外增加批次、学生 package 和题目展开快照。

课堂错题统计和导入批次之间至少要能提供以下字段：

```text
source_wrong_question_id       学生做错的练习册原题 UUID
source_wrong_question_no       练习册原题显示题号
drill_question_id              导入的错题练习题 UUID
drill_question_no              错题练习题显示题号
source_node_id                 练习册原题来源节点
drill_source_set_id             错题练习题导入批次 UUID
relation_status                matched / duplicate / missing_target / missing / invalid / original
relation_order                 错题练习题在导入文档中的顺序
```

其中 `source_wrong_question_id` 是学生做错的练习册原题，`drill_question_id` 是导入的错题练习题，方向固定为“错题练习题 → 针对的练习册错题”。显示题号仅用于导入匹配和展示，导入确认后必须保存两个 UUID；`original`、空关系和无效关系不能生成精练题。一个练习册错题可以对应多个错题练习题，生成时按导入文档顺序去重并保序。

#### A. `ClassroomWrongDrillSourceSet` 和 `ClassroomWrongDrillSourceQuestion`

保存一次错题练习题 DOCX 导入及其解析结果：

```text
ClassroomWrongDrillSourceSet
  id
  course_id
  source_mission_id
  source_node_id
  workbook_handout_id       当前课堂使用的练习册/讲义（如有）
  import_purpose             wrongbook_drill
  source_type                wrongbook_drill
  file_name / file_path
  version
  status                     parsing / validating / pending_mapping / active / failed / archived
  question_count
  matched_count
  unmatched_count
  error_json
  created_by / created_at / completed_at

ClassroomWrongDrillSourceQuestion
  source_set_id
  question_id                解析后复用的 ExamQuestion UUID
  drill_question_no          错题练习题号
  target_workbook_question_no 错题练习题针对的练习册题号
  question_snapshot
  answer_snapshot
  analysis_snapshot
  sort_no
  parse_status              valid / missing_content / missing_answer / failed
```

解析后的题目可以复用现有 `ExamQuestion` 题库实体，但必须通过 `source_set_id` 和 `source_type=wrongbook_drill` 区分来源，不能把错题练习题误加入当前课堂练习的 `MissionQuestionRel`。

答案来源固定为最终匹配到的错题练习题 `drill_question_id` 对应的 `ExamQuestion.answer`；解析说明使用对应的 `ExamQuestion.analysis`。练习册原题的答案不能替代精练题答案，AI 也不能在答案缺失时自动猜测。导入预览/生成前必须逐题校验精练题题库记录和答案字段：缺少答案的题目进入 `missing_answer`，默认阻止确认激活；只有产品明确允许“无答案练习卷”时，才可单独放宽，并且 PDF 答案区必须明确标注缺失，不能伪造答案。生成时将已校验的答案、解析保存为 `answer_snapshot`、`analysis_snapshot`。

#### B. `ClassroomWrongDrillNumberMapping`

保存系统根据题号自动建立的映射，不提供逐条手工录入流程：

```text
id
source_set_id
source_mission_id
source_node_id
workbook_question_id       练习册原题 UUID
  workbook_question_no       练习册原题题号
  drill_question_id          导入错题练习题 UUID
  drill_question_no          错题练习题题号
  target_workbook_question_no 错题练习题针对的练习册题号
  match_status               matched / duplicate / missing_target / missing / invalid
match_reason
sort_no
created_at
```

默认匹配键为“当前课堂任务/节点 + 错题练习题的 `target_workbook_question_no`”；错题练习题自身的显示题号只用于定位精练题，不作为练习册原题号。若导入文件无法解析 `target_workbook_question_no`，则使用本批次映射表；DOCX、业务元数据和映射表都无法提供目标题号时，必须保持 `pending_mapping/missing_target`，不能确认激活，不能由系统猜测。重复题号、跨节点同号和无法匹配的行必须在预览中列明。

#### C. 一次性映射表导入约定

对于当前提供的 DOCX，推荐在同一次导入操作中上传映射表。映射表不是每个学生一份，而是“当前课堂练习/讲义节点/错题练习题导入版本”一份；导入完成后保存到 `ClassroomWrongDrillNumberMapping`，后续生成和批量导出直接复用，不要求教师重复上传。

建议增加 `ClassroomWrongDrillMappingImport` 保存映射文件本身及校验过程：

```text
id
source_set_id
file_name / file_path
file_fingerprint
status                     validating / valid / invalid / superseded
row_count
valid_row_count
invalid_row_count
error_json
created_by / created_at / completed_at
```

映射文件记录与 `source_set_id` 一对一绑定一个当前版本；重新上传时创建新版本，旧版本只读并标记 `superseded`。确认导入时必须同时保存映射文件版本和自动映射版本，生成批次只引用已经确认的版本。

映射表至少包含两列，列含义固定且不能调换：

```text
错题练习题号    针对练习册题号
5               4
6               4
7               4
```

导入规则：

1. `错题练习题号` 必须能唯一匹配本次 DOCX 导入的 `drill_question_no`。
2. `针对练习册题号` 必须能唯一匹配当前课堂任务/讲义节点中的练习册原题号。
3. 允许多个错题练习题号指向同一个练习册题号，形成一对多映射。
4. 同一错题练习题号指向多个不同练习册题号时，标记为 `duplicate`，禁止激活，避免同一道精练题来源不确定。
5. 映射表多余行、缺少题号、重复行、`原题`、非法字符和跨节点题号必须在预览中逐项列出；确认激活时不得静默丢弃错误行。
6. DOCX 已提供 `target_workbook_question_no` 时，映射表只能作为校验或覆盖前先提示冲突；默认不允许两种来源产生不一致映射。
7. DOCX 没有目标题号且未上传映射表时，导入源可以保存为 `pending_mapping`，但不能确认激活，也不能生成精练题。

映射完整性和激活规则固定为：

- `matched` 行必须同时解析到本次 DOCX 的 `drill_question_id` 和当前课堂任务的 `workbook_question_id`。
- `duplicate`、`missing_target`、`missing`、`invalid` 行不能进入有效映射，也不能被静默忽略；前端必须展示错误原因和行号。
- 当前提供的 DOCX 没有目标题号时，允许先保存 DOCX 和映射表解析结果；只有映射表校验完成且至少存在一条有效 `matched` 关系时，才可将源设置为 `active`。
- 源文件仍存在未匹配的精练题时，可以按产品选择“阻止激活”或“允许部分映射激活”；第一版默认允许部分映射激活，但生成时仅使用 `matched` 行，并对受影响学生显示 `partial/no_mapping`。
- 映射表中的“原题”或不属于精练题的行不生成 `drill_question_id`，只能作为预览警告，不得混入学生作业。

映射表建议支持 `.xlsx`，可复用现有安全的 Excel 读取工具，但必须使用独立的映射表校验服务和接口，不能复用课堂错题统计 Excel 的“学生姓名+错题标记”字段语义。

发布课堂练习时必须保证错题统计能够保留练习册原题关系；同一 `source_question_id` 在一个任务中如果属于多个节点，需使用 `source_node_id + source_question_id` 作为题目身份，不能在统计时合并节点。

### 4.3 与现有模型的关系

```text

  └─ TeacherWrongBookMatrix
       └─ TeacherWrongBookCell(student, source_question, wrong)
            └─ ClassroomWrongDrillBatch
                 └─ ClassroomWrongDrillPackage(student)
                      ├─ ClassroomWrongDrillItem(source wrong → drill question)
                      └─ LearningMission(mission_kind=classroom_wrong_drill)
                           └─ MissionQuestionRel(只放该学生的精练题)
```

`TeacherWrongBookCell` 仍然是“这个学生哪一道课堂题错了”的来源，但它记录的是练习册原题 ID。错题练习题 DOCX 导入后，系统按 DOCX 元数据或一次性映射表生成并保存内部映射；生成服务通过“学生错题原题 ID → 自动题号映射 → 导入的错题练习题”读取精练题。新表保存导入源、自动映射、生成批次和展开后的关系结果，不按学生重复维护映射。

## 5. 错题练习题 DOCX 导入和自动题号映射

本需求需要教师手动导入一次“同类错题练习” DOCX，并可在同一次操作中上传一份练习题—错题映射表；不需要按学生重复导入或维护映射。DOCX 是精练题的实际内容来源，映射表是当前 DOCX 缺少目标题号时的关系来源；系统使用现有 DOCX 解析能力解析题干、选项、图片、答案和解析，再按题号绑定练习册原题。

### 5.1 导入入口和业务隔离

推荐在 `classroom-wrongbook-statistics.vue` 当前课堂错题统计页面的“生成精练题”按钮旁增加“导入错题练习题”按钮。当前页面已经确定课堂练习、讲义节点和班级，上传时可自动带入 `mission_id`、`source_node_id` 和练习册范围，教师不需要重复选择学生。

导入服务必须复用现有 DOCX 解析器和异步文档处理能力，仅增加业务参数和独立的映射表校验参数：

```text
import_purpose = wrongbook_drill
source_type = wrongbook_drill
```

不得修改现有 DOCX 解析核心逻辑，不得改变普通课程题目导入、讲义导入、题库导入和其他使用 DOCX 的接口语义。建议在现有文档导入入口增加可选业务上下文，或新增专用包装接口调用同一解析服务；专用接口负责来源标记、范围绑定、导入批次、可选映射文件关联和后续映射，不把映射表传入普通 DOCX 解析器。

导入对象按“课程/课堂练习/讲义节点/导入版本”保存，不按班级学生保存。一个错题练习题导入批次可以被当前课堂的所有学生复用。

### 5.2 导入解析、预览和自动匹配

导入流程：

1. 教师在当前课堂错题统计页上传 `第2讲 热机和热量转化-同类错题练习(1).docx`，并可同时上传映射表。
2. 后端调用现有 DOCX 解析能力，按 `import_purpose=wrongbook_drill`、`source_type=wrongbook_drill` 保存解析任务；映射表由专用业务适配层独立读取。
3. 解析出错题练习题号、题干、选项、图片、答案、解析和原文顺序；如果 DOCX/元数据能提供针对练习册题号，则同时保存 `target_workbook_question_no`。
4. 加载当前课堂使用的练习册题目，例如 `2026年秋季物理9年级A+B班-练习册（上册）(1).docx` 已进入题库/讲义后的题目集合。
5. 优先使用 DOCX/元数据中的目标题号；否则使用本次上传映射表的“错题练习题号 → 针对练习册题号”建立自动匹配；不能把错题练习题显示题号直接当成练习册原题号。
6. 生成导入预览，展示总题数、映射表行数、成功匹配数、重复题号、未匹配题号、缺失目标、解析失败题号和无效题目。
7. 教师确认本次导入；只有 DOCX 解析成功且映射覆盖满足要求时，系统才激活导入批次和映射。映射表缺失时可以保存为 `pending_mapping`，但当前提供的 DOCX 不能进入可生成状态。

这里的“针对练习册题号”由业务适配层从现有解析结果/文档元数据或本次上传的映射表提取，不能修改 DOCX 解析器核心或改变其他导入场景。如果当前 DOCX 没有该信息且没有映射表，适配层必须将本批次置为 `pending_mapping/missing_target`，教师后续补传映射表即可，不必重新上传 DOCX；不能用题目顺序或同号规则冒充映射。

默认内部关系为：

```text
错题练习题号 5 → 练习册题号 4
错题练习题号 6 → 练习册题号 4
错题练习题号 7 → 练习册题号 4
```

表示练习册第 4 题错了时，生成错题练习第 5、6、7 题。导入完成后实际保存两个题目 UUID，不能在生成时只依赖全局数字题号。

### 5.3 错题统计和自动映射的使用关系

生成服务按以下方式读取：

1. 从 `TeacherWrongBookCell` 读取某学生当前有效的练习册错题；该错题的 `source_question_id` 就是练习册原题 ID。
2. 根据当前课堂任务、节点和错题练习题导入批次，查询 `ClassroomWrongDrillNumberMapping.workbook_question_id` 对应的错题练习题 ID。
3. 从 `ClassroomWrongDrillSourceQuestion` 读取错题练习题快照，校验题目未删除、未下架且内容可以创建快照。
4. 将每条有效关系展开为 `source_wrong_question_id → drill_question_id`，按错题练习题文档顺序排序。
5. 同一学生的重复精练题只保留一次，同时保留其对应的多个错题来源。

`CourseQuestionLink`、`HandoutQuestion` 和 `MissionQuestionRel` 只负责练习册/讲义题目归属、课堂发布和题目快照校验；`ClassroomWrongDrillNumberMapping` 是由错题练习题导入后按题号自动生成的业务映射，不是教师手工维护的映射文件；`QuestionRelation` 不能作为本功能的自动候选来源。

### 5.4 对应关系数据要求

系统自动生成的映射至少应提供以下信息；如果 DOCX 解析后只有显示题号，后端需要在当前课堂题目范围内解析并补充 UUID，不增加教师逐条填写步骤：

```text
source_wrong_question_id       练习册原题 UUID
source_wrong_question_no       练习册原题显示题号
drill_question_id              导入错题练习题 UUID
drill_question_no              错题练习题显示题号
source_node_id                 练习册原题来源节点
drill_source_set_id            错题练习题导入批次 UUID
relation_status                matched / invalid / original / missing
relation_order                 错题练习题在导入文档中的顺序
```

关系方向固定为“错题练习题针对练习册错题”。例如导入匹配记录为 `5→4、6→4、7→4`，学生错题包含练习册第 4 题时，生成错题练习题 5、6、7；不能反向生成练习册原题 4。`原题`、空关系、无效关系不生成精练题。

### 5.5 生成前自动校验

点击“生成精练题”前，后端必须按学生执行预检并返回：有效错题数、已匹配自动映射的错题数、可生成精练题数、未匹配错题明细、无效题目明细。校验至少包括：

- 错题属于当前课堂任务、当前班级且状态有效。
- 错题练习题能解析到当前导入批次的题目 UUID。
- 练习册原题和错题练习题均未删除、未下架，且题目内容可以创建快照。
- `target_workbook_question_no → workbook_question_id → drill_question_id` 方向和顺序有效；同一精练题重复时按规则去重。
- 当前课堂任务通过 `HandoutQuestion` 发布时，不能错误地只从 `CourseQuestionLink` 反查练习册原题。

这些校验在服务端完成，前端只展示检查结果；错题练习题 DOCX 和映射表只需按当前课堂导入一次，不依赖教师按学生重新上传或填写文件。

### 5.6 每个学生生成正确性的强约束

对每个学生 `student_id`，生成服务必须把错题统计中的有效练习册原题集合记为 `W(student_id)`，并按当前活动导入源的自动映射计算：

```text
expected_drills(student_id)
  = distinct ordered drill_question_id
    for each wrong_question_id in W(student_id)
    where active_mapping.workbook_question_id = wrong_question_id
      and active_mapping.match_status = matched
      and active_source_question.parse_status = valid
```

生成结果必须满足：

1. `ClassroomWrongDrillItem` 的精练题集合等于 `expected_drills(student_id)`，不能从全班题目池、其他学生结果或 `QuestionRelation` 自动补题。
2. 每个精练题都必须保留其对应的错题来源；同一精练题被多道错题命中时，题目只生成一次，但来源列表必须完整保存。
3. `drill_question_id` 解析失败、题目失效、精练题答案缺失或映射 `match_status` 不是 `matched` 时，该关系不能进入作业，并必须进入该学生的缺失/失败明细。
4. 生成前后都校验数量和 ID 集合；如果结果与预检不一致，批次失败并保留错误日志，不能发布错误或串学生的作业。
5. 只有 `expected_drills(student_id)` 非空时才创建该学生的 `LearningMission`；因此不会创建空作业，也不会因其他学生有题而给没有题的学生错误分配题目。

## 6. 生成流程

### 6.1 触发条件

教师点击“生成精练题”时：

1. 若有未保存的手动错题，提示先保存或取消。
2. 校验当前班级、矩阵版本、错题练习题导入源版本和自动题号映射版本；版本由服务端从现有数据计算，教师不需要填写。
3. 校验当前课堂/讲义节点存在 `status=active` 且映射已确认的 `wrongbook_drill` 导入源；没有导入源时提示“请先导入错题练习题”，导入源为 `pending_mapping` 时提示“请先补充并确认映射表”。
4. 统计当前班级所有有效错题单元格。
5. 没有错题时禁止提交。
6. 有错题但全部没有匹配到导入源题目时，批次完成为“无对应精练题”，不能创建空作业。
7. 已生成且矩阵版本、错题统计快照、导入源版本和自动映射版本都未变化时，直接返回原批次，保证幂等。

### 6.1.1 无映射的发生原因、预防和恢复

“无映射”不是随机结果，而是当前学生的有效练习册错题没有匹配到已导入且有效的错题练习题。常见原因包括：

1. 当前课堂/讲义节点还没有确认有效的 `wrongbook_drill` 错题练习题导入源，或导入源仍为 `pending_mapping`。
2. 导入 DOCX 中没有对应题号、题号无法解析、题号重复，或题目解析失败/被标记为无效。
3. 当前 DOCX 没有目标题号且映射表未上传、映射表格式错误，或映射表中的精练题号/练习册题号无法匹配当前范围。
4. 导入的错题练习题与当前课堂练习、讲义节点或练习册版本绑定错误，不能跨课堂或跨节点匹配。
5. 练习册原题题号在当前任务范围内不存在、重复，或原题已删除/下架，导致自动映射无法落到唯一原题 UUID。
6. 导入的错题练习题已被替换、下架，或无法生成有效题目快照。
7. 精练题在题库中缺少 `ExamQuestion.answer`，无法生成可靠答案附录。
8. 当前学生的错题集合没有命中任何有效的自动题号映射；其他学生能生成不代表每个学生都一定有可生成题目。

为避免生成后才发现问题，点击生成前必须执行预检并展示：学生数、有效错题数、已匹配错题数、未匹配错题数、无效题目数和预计精练题数；同时提供未匹配错题明细。预检必须直接读取导入源、自动映射和课堂错题统计，并校验方向、UUID、课程/讲义/节点范围、题目状态和重复关系。

正常生成处理规则：

- 一个学生部分错题有映射时，生成包含已映射精练题的 `partial` 或 `published` 专属作业，并在教师端保留未映射明细；不能因为一条错题缺映射而丢弃该学生全部可生成题目。
- 一个学生全部错题都没有有效对应练习题时，不创建空 `LearningMission`；教师应补充/更换正确的错题练习题 DOCX 或映射表，重新预览并确认导入源后再次生成即可。
- 不允许自动把练习册原错题或 AI 猜测题当作精练题补位；错题练习题必须来自已导入的 `wrongbook_drill` 源。若产品未来需要兜底题，必须另行定义并单独标记来源。
- 生成前若存在未匹配错题，默认允许教师“取消并修正错题练习题导入”或“继续生成已匹配部分”二选一，并记录本次选择；不要求教师为学生逐条填写映射。

### 6.2 重新生成、替代和归档规则

首次生成后，错题矩阵中的相关单元格会进入 `generated` 状态，现有代码会禁止直接修改这些单元格。因此不能把“再次生成”简单理解为重复调用接口，必须明确采用新批次策略：

1. 教师修改错题统计时，基于当前矩阵递增 `request_version` 并创建新生成批次；若旧单元格已经生成，应提供“重新统计/开启新版本”操作，不能绕过现有锁定逻辑直接改历史数据，也不能改写已发布批次、学生作业或 PDF 的历史快照。
2. 新批次使用新的 `(matrix_version, source_statistics_version, source_set_id, number_mapping_version)`；其中导入源和自动映射版本由服务端生成，旧批次保持只读。
3. 新批次成功后，将旧 `Package` 标记为 `superseded`，旧个性化 `LearningMission` 标记为 `archived` 或 `closed`。
4. 学生首页只展示当前有效 package 对应的任务，不展示被替代批次。
5. 教师统计表默认显示最新批次，历史批次在“生成记录”中查询。
6. 新批次部分失败时，不得把旧批次隐藏；只有对应学生生成成功后，才替换该学生的旧作业。

如果产品决定不允许重新生成，页面必须明确显示“已生成后不可修改/不可再次生成”，不能保留容易产生歧义的重试按钮。

### 6.4 生成逻辑

```text
取当前班级 status in (marked, generated, locked) 的错题单元格
  ↓
读取 `TeacherWrongBookCell.source_question_id`（练习册原题 UUID）
  ↓ 按 `source_set_id + source_node_id + 练习册原题 UUID` 查询自动题号映射
得到导入的错题练习题 `drill_question_id`，并读取错题练习题快照
  ↓
按 student_id 分组
  ↓
每个学生：对应练习题去重、按错题练习题导入文档中的 `sort_no`/题目顺序排序
  ↓
创建 ClassroomWrongDrillPackage
  ↓
创建一个 student-only LearningMission
  ↓
为每个精练题创建 MissionQuestionRel 和题目快照
  ↓
保存 PDF 所需快照；首次预览/下载时生成该学生专属 PDF
  ↓
批次和学生行回写 published/partial/no_mapping
```

精练题的 `MissionQuestionRel` 建议写入：

```text
source_type = wrongbook_drill
mission_kind = classroom_wrong_drill
source_student_id = 当前学生
source_wrong_book_item_id = 对应错题本记录
source_set_id = 错题练习题导入批次
number_mapping_id = 自动题号映射记录
source_role = related_question
source_provider = wrongbook_drill_import
source_matrix_id = 原错题矩阵
source_wrong_question_id = 练习册原题 UUID
question_snapshot = 精练题快照
```

本期不要把原错题也作为学生作业题目写入 `MissionQuestionRel`；原错题仅保存在 `ClassroomWrongDrillItem.source_question_snapshot`，用于 PDF 首页的错题统计和知识点归纳。

### 6.5 异步处理

建议生成采用 Celery 异步任务，原因是一个班级可能一次生成几十份 PDF，且题目图片读取和 ReportLab 生成可能较慢。

可新增：

```text
apps/missions/tasks.py
  generate_classroom_wrong_drill_batch_task(batch_id)

apps/missions/classroom_wrong_drill_service.py
  request_classroom_wrong_drill()
  generate_classroom_wrong_drill_batch()
  classroom_wrong_drill_payload()
```

生成任务必须支持单个学生失败不影响其他学生，并在批次详情中记录：无映射、题目不存在、快照失败、PDF 失败、发布失败等阶段和原因。

## 7. PDF 方案

### 7.1 不直接复用当前普通任务 PDF

当前 `apps/missions/pdf_service.py` 只按任务关系输出题目，适合普通作业；图 2 还要求：

- 个性化标题和学生姓名。
- 首页错题统计。
- 错题知识点归纳。
- 使用建议。
- 末尾附精练题答案。

建议新建：

```text
apps/missions/classroom_wrong_drill_pdf_service.py
```

底层仍可复用 `student_views._build_pdf` 的中文字体、A4、图片和页码处理；首页和答案附录建议增加专用 ReportLab flowable，不要把课堂精练业务判断塞进普通任务 PDF。

### 7.2 PDF 结构

每个学生的 PDF 结构建议如下：

1. 标题：`错题重练（个性化定制）`。
2. 副标题：课程名/讲义节点/课堂练习名称。
3. 学生姓名、班级、生成日期。
4. `本次错题统计`：该学生错题的课堂练习题号、错题数量。
5. `重练说明`：说明精练题是根据本次错题和固定映射生成的。
6. `错题知识点归纳`：按原错题快照中的知识点去重汇总。
7. `使用建议`：先独立完成、重点复盘、完成后订正等固定文案。
8. 分页输出精练题，题号按学生作业顺序重新编号；保留题干、选项、表格、图片和公式。
9. 文件最后增加 `参考答案`，默认只输出本次映射得到的精练题答案；如产品确认需要，才同时输出精练题解析，但不能输出没有生成的原题答案。

### 7.3 图 2 的字段和版式对照

为避免只实现“内容相似”而不符合模板，开发时按以下字段固定生成：

| 模板区域 | 固定内容 | 数据来源 |
|---|---|---|
| 第一行标题 | `错题重练（个性化定制）` | 固定文案 |
| 第二行 | `第 N 讲《节点名称》错题重练` | 课堂任务节点快照，多个节点时按任务名称生成 |
| 学生信息 | `姓名：xxx`、`日期：YYYY 年 M 月 D 日`、班级 | package 学生快照、生成日期、班级快照 |
| 本次错题统计 | `第 1、2、4 题`、错题总数 | 当前学生有效错题单元格的节点内题号 |
| 重练说明 | 说明错题号如何映射为精练题 | 固定文案 + 本次映射数量 |
| 错题知识点归纳 | 按原错题知识点去重后合并显示 | `source_question_snapshot.knowledge_points` |
| 使用建议 | 先独立完成、重点复盘、完成后订正等 | 固定文案，可配置版本 |
| 题目正文 | 按模块/节点分组，显示题干、选项、表格、图片、公式 | `drill_question_snapshot` |
| 参考答案 | 与正文题号一致，只显示精练题答案 | `answer_snapshot` |

版式验收要求：

- 使用 A4 纸、中文字体、统一页边距和页码；沿用现有 ReportLab 的字体注册和图片处理。
- 每个讲义模块/节点开始前显示模块标题，样式与图 2 的蓝色章节标题一致。
- 正文题目分页时不能拆开题号和题干；图片过高时按最大高度缩放。
- 答案部分使用 `PageBreak` 从新页开始，并明确标识 `参考答案`。
- 生成正文时 `include_answers=False`；答案附录由专用模板单独追加，不能把普通 `_build_pdf` 的答案开关直接作用于正文。
- 公式、表格和图片缺失时保留题干并记录警告；不能因为单张图片丢失导致整份 PDF 生成失败。

生成规则：

- 练习卷正文不出现答案和解析。
- 答案必须来自生成时保存的 `answer_snapshot`，不能因为题库后来修改而改变已发布 PDF。
- 答案附录按正文题号顺序排列。
- PDF 路径必须包含学生/批次/版本信息，不能只使用课堂任务的单一共享路径。
- 重新生成只在错题矩阵、错题统计快照、错题练习题导入源或自动映射版本发生变化时创建新版本，不覆盖旧批次 PDF。

### 7.4 PDF 文件命名和批量导出规则

单个学生 PDF 的对外下载文件名固定为：

```text
课堂练习名称-讲义(第几节)-学生名称--错题精练题.pdf
```

示例：

```text
热机课堂练习-讲义(第2节)-张三--错题精练题.pdf
```

命名字段来源必须使用生成批次/任务快照，不能依赖当前页面节点：

- `课堂练习名称`：当前课堂练习任务名称快照。
- `讲义(第几节)`：当前课堂任务绑定的讲义节次/节点名称快照，首期一个生成批次必须对应唯一讲义节次；跨节任务需要产品另行定义命名规则，不能由前端自行拼接。
- `学生名称`：生成时的学生姓名快照。

文件实际存储路径仍使用 package UUID、批次和版本目录，下载响应通过 `Content-Disposition` 返回上述中文文件名，不能把姓名、题号等可猜测信息直接作为物理存储路径。文件名中的 Windows 非法字符 `\\ / : * ? \" < > |` 统一替换为下划线；同一班级学生重名时，ZIP 内按学生 UUID 建目录，但目录内 PDF 文件名仍保持上述规则。

教师端批量导出统一生成 ZIP，ZIP 内每个文件都是一名学生的独立 PDF，PDF 文件名必须保持上述格式。单个学生的“下载 PDF”仍直接下载 PDF，不改变文件名规则。

### 8.3 错题练习题导入和自动映射接口

新增的是“错题练习题源 DOCX 导入 + 一次性映射表导入”接口，不是按学生填写映射接口。接口应复用现有文档导入/解析服务，仅传入 `import_purpose=wrongbook_drill`、`source_type=wrongbook_drill` 和当前课堂范围；映射表作为可选的独立上传字段处理：

```http
POST /api/v1/missions/{mission_id}/classroom-wrongbook-statistics/drill-source/import
GET  /api/v1/missions/{mission_id}/classroom-wrongbook-statistics/drill-source/import/{import_id}
GET  /api/v1/missions/{mission_id}/classroom-wrongbook-statistics/drill-source
POST /api/v1/missions/{mission_id}/classroom-wrongbook-statistics/drill-source/confirm
POST /api/v1/missions/{mission_id}/classroom-wrongbook-statistics/drill-source/mapping
```

上传接口使用 `multipart/form-data`，其中 DOCX 为必传，映射表为可选；状态接口返回解析状态；映射接口接收本批次的 `.xlsx` 映射表并生成预览；查询接口返回当前课堂/讲义节点的活动导入源及自动映射覆盖情况；确认接口只允许确认解析成功、范围匹配且映射完整的批次。映射优先取 DOCX/元数据中的 `target_workbook_question_no`，否则取本批次映射表的“错题练习题号 → 针对练习册题号”；前端只展示预览，不要求教师按学生逐条录入。

现有课堂错题统计查询接口需要增加导入源状态、映射版本和每个学生的匹配统计；生成服务也可以在同一事务范围内查询 `TeacherWrongBookCell.source_question_id`、活动导入源和自动映射，不必把映射关系写回原有错题统计表。建议生成接口增加预检模式或返回预检结果，按学生列出错题总数、已匹配数、未匹配数和预计精练题数。

## 9. 教师端改造

### 9.1 错题练习题导入

uniapp/src/pages/teacher/classroom-wrongbook-statistics.vue

- 弹窗展示本次统计到的学生数、错题数、可映射错题数。
- 确认后调用异步接口。
- 页面轮询批次状态，或使用现有项目可用的任务状态机制。
- 轮询结束刷新统计数据，不清空矩阵错题。
- 生成期间切换班级或重复点击要有明确提示。

### 9.5 错题率口径修正

前端应优先展示接口返回的 `student.wrong_rate`。当前节点切换只改变题目矩阵，不应改变学生整堂课堂练习的错题率；如果产品确实要显示“当前节点错题率”，应另加明确字段 `node_wrong_rate`，不能复用总错题率字段。

## 10. 学生端改造

推荐尽量复用现有学生任务链路：

1. 生成成功后，个性化 `LearningMission` 状态为 `published`。
2. 学生首页现有 `student_home` 自动查询并展示该任务。
3. 学生端作业名称固定显示为“课堂练习名称-讲义(第几节)-错题精练题”，不拼接学生姓名；学生姓名只用于 PDF 文件名和作业详情中的学生信息。
4. 进入任务后只返回该学生的精练题关系。
5. PDF 按钮使用该学生任务自己的 `pdf_file_path`。
6. 学生端任务元数据固定显示：`题目来源：错题本`、`类型：精练题`；内部使用 `mission_kind=classroom_wrong_drill` 和 `source_type=wrongbook_drill`。

学生端任务查询必须增加“当前有效批次”过滤：不能只按 `status=published` 查询。访问任务详情时还要校验该任务对应 package 的 `lifecycle_status=current`；历史归档任务只能用于教师历史查看，学生不可继续访问。

PDF 建议采用“题目先生成、文件按需生成”的方式：教师批量生成时创建学生任务和题目快照；学生或教师首次点击预览/下载时调用鉴权接口生成 PDF 并缓存到 package。这样既满足“可以生成 PDF”，也避免一个班级生成几十份文件时阻塞整批任务。

学生端必须继续隐藏 `answer_snapshot`、`analysis_snapshot` 和题目快照中的答案字段；答案只在 PDF 的最后答案区输出，不能通过任务题目接口直接返回。

### 10.1 任务枚举、列表和访问改造

如果采用 `mission_kind=classroom_wrong_drill`，需要同步修改现有白名单和列表行为：

- `apps/missions/serializers.py` 的 `CreateMissionSerializer` 增加新类型，或明确规定该任务只能由专用服务直接创建。
- `source_type` 使用专用值 `wrongbook_drill`，前端显示为“错题本”；`mission_kind=classroom_wrong_drill` 前端显示为“精练题”，避免继续伪装成普通 `teacher_matrix`。
- `apps/missions/views.py::mission_list` 默认排除 `mission_kind=classroom_wrong_drill`，或改为按来源课堂练习归组。
- `MissionListSerializer` 增加 `is_personal_wrong_drill`、`source_mission_id` 或等价字段，供教师端识别。
- 学生首页、任务详情、教师任务详情和 PDF 标题增加“错题重练”文案。
- 专用生成服务仍需复用现有发布校验、班级分配和 `StudentMissionProgress` 创建逻辑，不能只把任务状态直接改成 `published`。

本期默认规则：

- 保留 `LearningMission` 的在线作答链路；如果产品最终只允许打印，可在前端隐藏答题入口，不改变映射、快照和 PDF 数据结构。
- 答案附录只属于 PDF，未提交前不通过学生端题目接口返回答案；解析是否附在答案区仍以第 14 节的产品确认项为准，默认不附解析。

## 13. 测试与验收标准

### 13.1 后端测试

- 一道课堂错题映射多个精练题时，学生作业包含全部精练题且不重复。
- 多道课堂错题映射同一道精练题时，学生作业只保留一题，并能在来源摘要中显示多个来源。
- 提供的错题练习 DOCX 能通过现有解析器导入为 `wrongbook_drill` 源；普通课程/讲义/题库 DOCX 导入的结果和接口语义不变。
- 对当前提供的 DOCX 同时上传映射表后，映射表列“错题练习题号/针对练习册题号”能正确生成 `5→4、6→4、7→4`；列反、缺列、重复题号、跨节点题号和缺失映射均被拒绝或明确列入预览。
- 只上传 DOCX 时，若 DOCX 没有目标题号，导入源保持 `pending_mapping`，不能确认激活或生成作业；补传映射表后无需重新上传 DOCX 即可激活。
- 映射表中的每一行精练题都能解析到本次 DOCX 导入的题目 UUID，每一行练习册题号都能解析到当前课堂任务的原题 UUID；不能跨导入批次或跨课堂复用题号。
- 每道已匹配精练题都能从其 `ExamQuestion.answer` 读取答案；缺少答案时标记 `missing_answer`，不能生成可发布的答案附录，也不能用练习册原题答案或 AI 猜测答案替代。
- 使用一次性映射表时，以示例数据验证错题练习题 5、6、7 均映射到练习册题 4；不需要教师按学生逐条填写，后续生成直接复用该批次映射。
- 导入源按课堂练习、讲义节点和版本隔离；切换课堂/节点不能读取其他导入源，重复导入同一版本具备幂等或明确版本替换规则。
- 映射方向验收固定为：错题 4 对应映射 5→4、6→4、7→4 时，生成题目必须是 5、6、7，而不能生成题目 4。
- 没有对应练习题的错题不生成替代题，学生行显示 `no_mapping`。
- 不同学生的错题集合不同，生成的 `LearningMission`、题目关系和 PDF 均不同。
- 同一学生重复提交相同矩阵、错题统计、导入源和自动映射版本时不创建重复任务；任一版本变化时创建新批次。
- 新批次成功后旧任务归档；新批次部分失败时，成功学生替换旧任务，失败学生仍保留旧任务。
- 线上、手动、导入三种 `TeacherWrongBookCell` 都能参与生成；已取消单元格不能参与。
- 未保存版本、错误班级、重复幂等请求和并发生成均有保护。
- 教师不能访问其它课程/班级的错题统计对应关系或 PDF；学生不能访问其它学生的 package。
- 题目、错题练习题导入源、自动映射或错题统计后来变更，已发布作业和 PDF 仍使用生成时快照。
- 选择单个学生、多个学生和全选时，批量导出只处理当前班级当前有效批次；切换班级或批次不会串用已选学生。
- 批量导出会为尚未生成 PDF 但已有有效 package 的学生按需生成 PDF，并将成功文件打包为 ZIP；无映射、失败和归档学生进入跳过/失败清单。
- 批量导出重复提交使用幂等键返回原导出任务，不产生重复 ZIP；导出任务完成后每个 PDF 文件名均符合约定。
- 讲义题目通过 `HandoutQuestion` 进入课堂任务时，对应练习题仍能准确校验，不依赖当前 `CourseQuestionLink` 反向猜测关系。
- 同一课堂任务中同题多节点时发布被拒绝，或矩阵身份已升级为 `node + question`，不能出现节点合并。
- 导入源无活动版本、导入题号重复/缺失、练习册原题不存在或范围不一致时，生成前预检阻止全量生成并显示可修复明细；选择继续时只生成已匹配学生题目。

## 14. 风险、默认决策和实施前确认

为使方案可以直接开发，第一版默认决策如下；只有产品明确改变时才需要调整设计：

1. **对应关系方向**：固定为“错题练习题号 → 针对练习册错题号”。练习册错题 4 命中 5→4、6→4、7→4 时，生成 5、6、7。
2. **对应关系主键**：正式使用题目 UUID；题号仅用于导入时匹配和显示。教师只需为本课堂一次性导入错题练习 DOCX；当前 DOCX 无目标题号时，可同时或后续补传一次映射表，不按学生填写，服务端不能跨范围猜测。
3. **错题来源**：`TeacherWrongBookCell.source_question_id` 是练习册原题 ID；导入的 `wrongbook_drill` 源题目是精练题实际内容来源。
4. **精练题范围**：导入源必须绑定当前课堂练习、讲义节点和练习册版本；自动映射必须同时落到当前任务允许的练习册原题和导入错题练习题。
5. **生成范围**：一次生成当前选择班级的全部有效错题学生；后续可增加选择学生，但不改变数据结构。
6. **在线作答**：第一版保留现有 `LearningMission` 在线作答能力；PDF 是练习卷，答案只放在 PDF 最后一部分。
7. **PDF 生成时机**：题目和作业在教师生成时创建；PDF 首次由教师或学生点击时生成并缓存。
8. **重复生成**：采用新批次替代旧批次，旧批次只读归档，学生只看最新有效批次。

仍需产品确认的只有两项，不确认时按默认执行：

- 图 2 的答案区是否同时显示精练题解析；默认只显示答案，不显示解析。
- 精练题是否需要在线作答；默认支持在线作答，若只打印可在实现阶段隐藏答题入口，不影响映射和 PDF 数据结构。

映射表不是按学生填写的业务数据，而是当前导入批次的一次性输入。对于当前提供的 DOCX，默认要求映射表完成校验后才能激活和生成；只有后续 DOCX 模板能够稳定解析 `target_workbook_question_no` 时，才允许在不上传映射表的情况下直接激活。

### 14.1 本次复核后的数据源和版本口径（以本节为准）

本功能需要教师为当前课堂/讲义节点导入一次错题练习 DOCX；当前提供的 DOCX 没有目标题号时，还需要同时或后续补传一次映射表，但不按学生维护。系统使用 `import_purpose=wrongbook_drill`、`source_type=wrongbook_drill` 标记导入源，并优先使用 DOCX/元数据、否则使用映射表，按“错题练习题号/针对练习册题号”生成 `ClassroomWrongDrillNumberMapping`。生成时将“练习册原题 UUID → 自动映射 → 导入错题练习题 UUID”连同导入源版本、映射版本、错题统计版本、题目快照和题目顺序保存到 `ClassroomWrongDrillItem.relation_snapshot`。

`ClassroomWrongDrillBatch` 和 `ClassroomWrongDrillPackage` 保存 `matrix_version`、`source_statistics_version`、`source_set_id`、`number_mapping_version` 及生成结果。重复请求在这些版本未变化时返回原结果；错题统计、导入源、自动映射或矩阵版本变化时创建新批次，旧批次和旧学生任务标记为 `superseded/archived`，不修改历史快照。

当前矩阵实现只有一个版本字段时，“开启新版本”应实现为递增矩阵 `request_version`、保留旧矩阵单元格并创建新生成批次，而不是新增一套无关联的矩阵记录。若产品暂不支持矩阵版本化，则已生成单元格禁止编辑，只能通过新批次重新生成。

本期在线作答默认保留 `LearningMission` 的既有能力；PDF 正文不展示答案，文件末尾仅附精练题答案。精练题解析是否一并附在答案区仍以产品确认项为准，默认不附解析。

## 15. 推荐最终方案

第一版按以下固定方案实施：

1. 教师在当前课堂错题统计页导入一次错题练习 DOCX，并可同时或后续导入一次映射表；复用现有 DOCX 解析能力，仅使用 `import_purpose=wrongbook_drill`、`source_type=wrongbook_drill`，映射表由独立适配层处理。
2. 系统优先读取 DOCX/元数据中的目标题号；当前 DOCX 没有目标题号时，按映射表“错题练习题号 → 针对练习册题号”生成映射，并绑定当前课堂练习、讲义节点和导入版本。映射表未上传时仅保存为 `pending_mapping`，不允许生成。
3. 课堂统计继续使用现有 `TeacherWrongBookMatrix` 和 `TeacherWrongBookCell`，不复制错题统计数据；生成服务从学生错题原题 ID 查询自动映射，再读取导入错题练习题作为精练题内容。
4. 点击生成后，按学生展开并生成 `ClassroomWrongDrillPackage`；只有有有效精练题的学生创建独立 `LearningMission`，旧批次按替代规则归档。
5. 每个学生生成一份独立 PDF：首页严格按图 2 展示错题摘要、模块标题和使用建议，正文展示导入的精练题，文件末尾分页附精练题答案。
6. 教师统计表在错题率后增加操作列；生成成功后支持查看精练题、预览 PDF 和下载 PDF，PDF 首次点击时按需生成。
7. 学生表格最前增加复选框和全选；教师可以选择多个学生或全选当前班级可导出学生，异步生成并下载包含独立 PDF 的 ZIP。
8. 每个 PDF 文件名固定为 `课堂练习名称-讲义(第几节)-学生名称--错题精练题.pdf`，批量 ZIP 中重名学生通过学生 UUID 目录隔离。
9. 学生端复用现有作业首页和答题链路，但只展示最新有效的个人错题重练任务，名称为“课堂-讲义-错题精练题”，元数据为“题目来源：错题本、类型：精练题”。
10. 所有生成结果保存导入源、自动映射、题目、答案、解析和错题统计快照；题库、导入源或错题统计变化不会修改历史作业。
