# 课堂错题练习与错题映射实施方案

## 1. 目标与边界

在“课堂管理”课次卡片及课程详情中，于“错题统计”前新增“错题练习”“错题映射”入口。两个入口不再以“已发布课堂练习”作为前置条件，支持教师在线下布置作业后，先后或同时导入错题练习题 DOCX 和映射关系 XLSX。

本次交付包含资源导入、展示、映射表编辑及保存；不改变已有错题统计矩阵、学生端精练题生成和 PDF 的既有流程。

## 2. 已有能力与复用原则

- 错题练习题导入复用 `POST /missions/{mission_id}/classroom-wrongbook-statistics/wrong-drill/sources`，字段名保持 `wrongbook_file`、`class_id`、`source_node_id`。
- 映射表导入复用 `POST /missions/{mission_id}/classroom-wrongbook-statistics/wrong-drill/sources/{source_set_id}/mapping`，字段名保持 `mapping_file`、`class_id`。
- DOCX 仍由既有异步文档导入链路解析；页面仅根据任务状态轮询刷新，不重复实现解析逻辑。
- 题目展示只使用已入库的 `question_snapshot`，不向页面传递 ORM 对象或依赖当前题库题目，保证导入后内容稳定。

## 3. 业务流程

1. 教师点击“错题练习”或“错题映射”。
2. 前端调用课堂错题资源上下文接口：有已发布课堂练习时复用最近课堂练习；没有时创建一条内部“线下错题资源”载体。该载体不出现在学生作业中，也不会发布给学生。
3. 错题练习页无数据时显示“当前暂未导入错题练习题”；点击导入后提交 DOCX，解析完成后按题号、题干、选项展示导入快照。页面不显示课堂练习左侧节点和右侧操作区。
4. 错题映射页无数据时显示“当前暂未导入错题映射表”；须先有错题练习题源。导入 XLSX 后展示“错题练习题号 → 针对练习册题号”。
5. 教师点击编辑后修改表格，点击保存。服务端校验题号非空、错题练习题号存在且不重复，替换该题源映射并递增映射版本；保存成功后的新映射立即成为生效数据。

## 4. 前后端契约

| 接口 | 用途 | 关键返回字段 |
| --- | --- | --- |
| `POST /courses/{course_id}/wrong-drill-context` | 获取或创建资源上下文 | `mission_id`、`class_ids`、`offline_context` |
| `GET /missions/{mission_id}/.../wrong-drill/sources` | 获取题源列表、导入状态 | `source_set_id`、`question_count`、`mapping_count`、`import_task` |
| `GET /missions/{mission_id}/.../wrong-drill/sources/{source_set_id}` | 题目/映射页面读取 | `questions[].snapshot`、`mappings[]` |
| `PATCH /missions/{mission_id}/.../wrong-drill/sources/{source_set_id}/mapping` | 保存人工编辑映射 | `mappings[].wrong_question_no`、`mappings[].workbook_question_no` |

所有 ID 均以字符串传输。页面只读取后端声明字段；导入文件字段沿用现有接口，避免同一业务出现两套上传协议。

## 5. 数据与权限

- 线下资源载体使用 `source_context=course_offline_wrongbook`，仅在课程没有课堂练习时创建，并关联课程当前有效班级。
- 题源、映射仍归属 `ClassroomWrongDrillSourceSet`，不复制题目实体；题目展示读取该题源的题目快照。
- 映射保存采用整表替换和事务；失败时旧表保持不变。
- 所有接口沿用教师会话与课程管理权限检查，且校验题源必须属于当前上下文任务。
- 在线下上下文中，映射可先保存为有效资源关系；由于没有线上课堂题目 ID，该映射不会被错误地用于自动生成学生精练题，待后续关联实际课堂练习后再进入生成链路。

## 6. 页面实现

- `classroom-wrong-drill.vue`：顶部“刷新 / 导入错题练习题”，空态与题目列表；题目卡片使用中间题目区的简化样式。
- `classroom-wrong-mapping.vue`：顶部“刷新 / 导入映射关系表 / 编辑 / 保存”，表格读写隔离；非编辑状态为文本，编辑状态为输入框。
- `CourseCard.vue`、`course-list.vue`、`course-detail.vue`：新增入口并保持原错题统计与课堂反馈行为不变。
- `pages.json`：注册两个教师端页面路由。

## 7. 验收清单

1. 未发布课堂练习的课程，点击两个新入口均可进入，不再显示“当前课程暂无已发布的课堂练习”。
2. 无题源时错题练习页展示指定空态；提交合法 DOCX 后显示解析出的题号、题干和选项。
3. 无映射时映射页展示指定空态；未导入题源时点击导入映射会提示先导入错题练习题。
4. XLSX 导入后显示所有有效映射；编辑、保存后刷新页面仍为保存后的值。
5. 非法 DOCX、非法 XLSX、空题号、重复错题练习题号会得到后端错误提示，旧有效数据不被覆盖。
6. 已有课堂练习的课程仍使用原任务上下文，原错题统计、生成精练题、PDF 下载回归正常。

## 8. 验证结果

已执行 `python manage.py check`，结果为 `System check identified no issues (0 silenced)`。建议联调时分别使用“已有课堂练习”和“纯线下课次”各跑一遍上述验收清单，并补充接口级测试覆盖资源上下文创建、题源详情读取和映射保存事务。

## 9. 无学生统计时的默认错题与精练题生成方案

### 9.1 适用场景

当课堂没有发布线上练习，或没有导入学生错题统计，但同时满足以下条件时启用默认模式：

- 错题练习 DOCX 已导入完成；
- 映射关系表已导入且状态为 `ready`；
- 映射表中存在有效的“练习题号 → 错题题号”关系；
- 当前课堂仍有有效学生。

该模式仅用于明确的线下布置场景，不能覆盖已有的真实学生作答统计。

### 9.2 题号与映射方向

映射表统一采用以下列顺序：

```text
练习题号    错题题号
```

- “练习题号”是原练习册/练习题中的题号，用于匹配课堂题目；
- “错题题号”是错题练习 DOCX 中的题号，用于生成学生精练题。

服务端内部仍可使用 `workbook_question_no` 和 `wrong_question_no` 字段，但展示、导入模板、编辑页面和保存接口必须保持上述业务含义一致。

### 9.3 统计页面展示

没有线上练习题时，错题统计页面不应显示空题号列。应从当前有效映射中取得全部“练习题号”，构造统计题目列表：

- 表头显示所有有效练习题号；
- 每个学生都展示这些题号对应的统计单元格；
- 未导入学生统计时，每个学生的有效映射题目默认标记为错题（叉号）；
- 无效映射、标记为“原题”或无法匹配练习题的行不进入统计和生成。

默认标记应明确标注来源，例如“线下导入默认”，避免误认为真实线上作答结果。真实统计导入后，应以真实统计覆盖默认标记。

### 9.4 后端数据与生成逻辑

推荐将默认标记持久化为 `TeacherWrongBookCell`，并使用可识别的 `mark_source`（如 `offline_import_default`）：

1. 根据有效映射取得原练习题 ID；
2. 为课堂每个有效学生创建或更新对应错题单元格；
3. 保证操作幂等，重复刷新、导入或生成不会产生重复记录；
4. 生成任务继续使用“学生错题单元格 → 映射 → 错题练习题”的现有链路；
5. 只有在无真实统计且来源状态为 `ready` 时才启用默认模式。

前端生成按钮不能仅以 `wrong_count === 0` 拦截。应改为：真实错题数大于 0，或存在有效默认映射时允许生成；后端仍需再次校验课堂、学生、题源和映射权限，不能只依赖前端判断。

### 9.5 错题映射页面增加“生成精练题”

在 `classroom-wrong-mapping.vue` 页面右侧增加“生成精练题”按钮，功能与错题统计页面保持一致：

- 使用当前课堂上下文、当前有效错题练习题源和映射关系；
- 默认选择当前课堂全部学生，也支持后续扩展为选择学生；
- 点击后调用现有错题精练生成接口，不复制生成业务逻辑；
- 生成前检查题源是否导入完成、映射是否为 `ready`、是否存在有效学生；
- 无学生统计时自动走第 9 节的默认错题模式；
- 展示排队中、生成中、成功、部分失败和失败状态，并支持刷新查看历史；
- 生成成功后显示每名学生的生成数量及 PDF/精练题入口；
- 生成失败时展示具体原因，不清除已有映射和历史记录。

按钮只负责触发和展示，实际生成统一复用 `wrong_drill_generate` 接口及 Celery 任务，确保错题统计页面与错题映射页面生成结果一致。

### 9.6 风险控制与验收

- 首次按默认模式生成前增加确认提示，明确“将为所有学生按映射题目默认标记错题”；
- 默认标记与真实统计分开记录，便于追溯和后续覆盖；
- 映射表存在重复题号、缺失题号或无效原题时，生成前显示校验结果；
- 重新导入映射表后，旧映射按事务整体替换，历史生成任务和 PDF 保持不可变；
- 验收至少覆盖：无线上练习、无学生统计、有效映射、部分无效映射、重复点击生成、重新导入真实统计、映射页面直接生成等场景。

## 10. 无线上作业时原练习题 ID 的来源与绑定（实施必需）

### 10.1 问题说明

现有 `_workbook_number_map()` 主要通过 `MissionQuestionRel` 查找原练习题。当课堂没有发布线上练习时，任务可能不存在对应的 `MissionQuestionRel`。如果仅保存 Excel 中的题号字符串，映射虽然看似导入成功，但 `workbook_question_id` 为空，后续无法构造统计单元格，也无法匹配生成精练题。

因此，默认错题模式不能只依赖题号文本，必须补充“练习题号 → 原练习题 ID”的线下题源绑定。

### 10.2 线下练习题源

无线上作业场景下，原练习题应从以下受控来源之一解析：

1. 当前课堂已导入的练习题文档；
2. 当前课程下已导入、且属于当前课堂上下文的练习题；
3. 单独建立并绑定到课堂的“线下练习题源”。

题源必须能够提供唯一映射：

```text
练习题号 → ExamQuestion.id
```

题源选择必须限定在当前课程/课堂范围内，不能按全库题号直接匹配，避免不同文档或不同教师的同号题发生串题。

### 10.3 映射导入校验

映射表导入或编辑保存时，服务端按以下顺序处理：

1. 读取“练习题号”和“错题题号”；
2. 校验错题题号存在于当前错题练习 DOCX；
3. 根据当前线下练习题源将练习题号解析为 `ExamQuestion.id`；
4. 解析不到原题、原题号重复或题源不属于当前课堂时，将该行标记为无效；
5. 只有所有可生成行都具备有效 `workbook_question_id` 时，映射状态才可为 `ready`；
6. 返回逐行错误信息，例如“练习题号 23 不存在”或“练习题号 8 对应多个原题”。

允许保留部分有效行，但必须明确显示有效数量和无效数量；无效行不得参与统计、默认打叉或精练题生成。

### 10.4 默认错题记录创建

没有学生统计时，服务端不能只在前端显示叉号。应在生成前或进入默认模式时，在事务中为每个有效学生和每个有效原练习题创建或更新 `TeacherWrongBookCell`：

```text
matrix + student_id + source_question_id(ExamQuestion.id)
```

记录使用专用来源标识（如 `offline_import_default`），并满足：

- 重复执行不会产生重复记录；
- 已有真实统计记录不被默认记录覆盖；
- 后续导入真实统计时，可按业务规则覆盖默认标记；
- 默认标记可在页面上区分显示并可审计。

### 10.5 生成前置条件

错题统计页和错题映射页的生成入口统一执行以下服务端校验：

- 当前课堂存在有效学生；
- 错题练习题源状态为 `ready`；
- 映射关系状态为 `ready`；
- 至少存在一条有效映射；
- 每条有效映射均已解析出原练习题 ID 和错题练习题 ID；
- 存在真实错题记录，或可以创建默认线下错题记录。

前端不能仅依据 `wrong_count` 是否大于 0 判断能否生成；后端必须执行同样的校验，防止绕过页面直接调用接口。

### 10.6 两个页面的统一生成流程

错题统计页面和错题映射页面的“生成精练题”按钮均调用同一个生成接口和 Celery 任务，流程统一为：

```text
校验题源和映射
    ↓
解析/补全原练习题 ID
    ↓
无真实统计时创建默认错题记录
    ↓
按学生匹配原练习题
    ↓
按映射找到错题练习题
    ↓
生成个人精练题和 PDF
```

映射页面按钮默认面向当前课堂全部学生；生成前应弹出确认提示，说明将按导入映射为所有学生默认标记错题。生成状态、部分失败原因、历史记录和 PDF 入口与错题统计页面保持一致。

### 10.7 完整可实施验收标准

- 无线上练习时，页面显示线下题源中的全部有效练习题号；
- 映射表每一行都能解析出原练习题 ID 和错题练习题 ID；
- 无学生统计时，每名学生的有效题目单元格显示默认错题标记；
- 点击错题统计页或错题映射页的生成按钮，都能为学生生成对应精练题；
- 无效映射不会生成题目，并能展示具体行级错误；
- 重复点击、刷新页面或重新打开页面不会重复创建错题和精练题；
- 导入真实学生统计后，真实结果与默认标记能够按规则区分和覆盖；
- 已有线上作业场景的原统计和生成流程保持不变。
