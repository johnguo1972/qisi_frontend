## 3. 旧脚本不能直接执行，新脚本已实现

指定文件 `word/sql/导入题目数据_脚本_v2.py` 当前是 MySQL `INSERT INTO ... VALUES` 解析脚本，不是 JSON ZIP 导入器，且存在这些硬编码：

1. 默认读取 `word/sql/qisi_ai_tutor.sql`。
2. 只导入题目 ID 1—13。
3. 使用旧整数 ID；当前 `ExamQuestion.id` 是 UUID。
4. 固定使用测试试卷 `M90001`。
5. 不处理 JSON 的子问题、表格、插图、公式、外部题号、课程和标签。

因此不要直接把 ZIP 作为参数传给旧脚本。现在已经新增独立命令，不修改也不复用旧命令入口：

~~~bash
python manage.py import_g9_autumn_practice
~~~

新增文件：

~~~text
apps/study/management/commands/import_g9_autumn_practice.py
apps/study/management/commands/publish_g9_autumn_practice.py
apps/study/management/commands/verify_g9_autumn_practice.py
apps/papers/migrations/0003_exam_paper_source_fields.py
apps/parser/migrations/0007_examquestion_json_source_fields.py
~~~

三个命令职责分离：

1. `import_g9_autumn_practice`：只导入 JSON、题目、选项、子问题、表格、图片和公式。
2. `publish_g9_autumn_practice`：只创建/更新课程、8 个讲次目录、课程题目关联和固定标签。
3. `verify_g9_autumn_practice`：读取原 ZIP，对数据库内容、媒体文件、课程关联和标签关系进行复核；发现任一错误时退出失败。

项目已有 `import_large_question_zip` 也不能原样使用：它默认读取 JSON 数组，而本包的 `all_questions.json` 是对象；现有 HTTP JSON 导入会丢失 `subquestions/tables`，且未完整映射 `compound/judgement`。

补充：新命令也不调用旧的 `generate_question_system_id("物理")`。本地现有题库的 `QuestionIDCounter` 与历史 `Pxxxxx` 数据不同步时，该旧生成器会反复命中已存在的题号并失败。本命令在数据库现有 `P` 前缀系统题号最大值之后分配下一个未占用题号，并逐次检查唯一性，避免和旧题库导入流程相互影响。

## 4. 新导入命令的实现和硬性要求

### 4.1 输入和幂等

新命令已经实现以下能力：

- 校验 SHA-256。
- 校验存在 `manifest.json`、`all_questions.json`、`questions/`、`assets/`。
- 读取 `all_questions.json["questions"]`，数量必须为 277。
- 校验 `question_id` 唯一且每个资源引用存在。
- 支持 `--dry-run`，dry-run 不写数据库。
- 使用外部 `question_id` 作为幂等键；数据库主键仍由 Django 生成 UUID。
- 同一 ZIP 重跑时更新同一题，不新增重复题目。

### 4.2 试卷和题目

新增字段用于幂等和追溯：`ExamPaper.source_package_id`、`ExamPaper.source_sha256`、`ExamQuestion.source_external_id`、`ExamQuestion.source_question_type`。

建议唯一外部试卷键：

~~~

`ExamPaper` 建议：

grade = 九年级
paper_type = json_import_practice
has_solution = False

~~~

题目映射：

| JSON | 数据库 |
|---|---|
| question_no | question_no、paper_question_no |
| section | section_title |
| stem | stem |
| answer.raw | answer；空时写空字符串 |

必须将原始 `question_type` 和 `question_id` 保存在 `raw_text` 或等价源字段中，便于重跑和追溯。

### 4.3 子问题、表格和资源

已增加 `ExamQuestion.subquestions` 和 `ExamQuestion.tables` JSONField，并在题目详情、题库列表和课程练习序列化器中返回；完整原始题目 JSON 也保存在 `raw_text`。本包有 91 道题、269 个子问题，复核命令会逐题比较。

资源复制到：

~~~text
MEDIA_ROOT/exams/json_imports/<paper_uuid>/
~~~

要求使用 basename 防路径穿越，目标文件名使用“题目 UUID + 原文件名”，用 `update_or_create` 保证重跑不重复。题库列表保留插图预览，题目详情和课程练习返回插图及公式图；详情接口还返回选项、子问题和表格。

复核命令还会按资源文件内容计算 SHA-256，与 ZIP 中对应资源逐个比对，不能只以数据库记录数量判断资源导入成功。

### 7.1 旧版 Django shell 方案（仅排障）

~~~python
import os
from django.db import transaction
from apps.accounts.models import UserAccount
from apps.papers.models import ExamPaper
from apps.parser.models import ExamQuestion
from apps.courses.models import Course, CourseTree, CourseQuestionLink
from apps.study.models import QuestionTag, QuestionTagRelation

teacher = UserAccount.objects.get(id="<TEACHER_UUID>", role_type="teacher")
paper = ExamPaper.objects.get(id="<PAPER_UUID>")
questions = list(ExamQuestion.objects.filter(paper=paper).order_by("sort_order", "id"))
if len(questions) != 277:
    raise RuntimeError(f"题目数不是277：{len(questions)}")

with transaction.atomic():
    course, _ = Course.objects.get_or_create(
        name="九年级物理秋季班课件练习", teacher=teacher, is_deleted=False,
        defaults={"description": "答案和解析待补充", "subject": "物理", "grade_level": "九年级"},
    )

    names = []
    for q in questions:
        name = (q.section_title or "未分讲次").split("/", 1)[0].strip()
        if name not in names:
            names.append(name)

    nodes = {}
    for order, name in enumerate(names, 1):
        node, _ = CourseTree.objects.get_or_create(
            course=course, parent=None, name=name,
            defaults={"sort_order": order},
        )
        node.sort_order = order
        node.save(update_fields=["sort_order"])
        nodes[name] = node

    for q in questions:
        name = (q.section_title or "未分讲次").split("/", 1)[0].strip()
        CourseQuestionLink.objects.update_or_create(
            course=course, question=q,
            defaults={"tree_node": nodes[name], "source": "import",
                      "source_course_name": course.name, "is_deleted": False},
        )

    tag, _ = QuestionTag.objects.get_or_create(
        name="9年级秋季班课件练习",
        defaults={"color": "#e67e22", "created_by": teacher},
    )
    for q in questions:
        QuestionTagRelation.objects.get_or_create(question=q, tag=tag)
        names = list(
            QuestionTagRelation.objects.filter(question=q).select_related("tag")
            .values_list("tag__name", flat=True)
        )
        ExamQuestion.objects.filter(id=q.id).update(tags=names)

    tag.question_count = QuestionTagRelation.objects.filter(tag=tag).count()
    tag.save(update_fields=["question_count"])

print(course.id, tag.id, len(questions))
~~~

期望：题目 277、课程关联 277、标签关系 277、标签计数 277、目录 8。

## 11. 已发现的 bug/遗漏

| 风险 | 影响 | 处理 |
|---|---|---|
| v2 只读旧 SQL、只导入 13 条 | 无法导入本 ZIP，严重漏题 | 已用独立 JSON 管理命令解决，旧脚本保持不动 |
| 旧脚本使用整数 ID | 与 UUID 模型不一致 | 外部 question_id 幂等，数据库生成 UUID |
| 大 ZIP 命令不识别对象格式 | 可能 0 条或全跳过 | 读取 `all_questions.json["questions"]` |
| judgement/compound 映射不全 | 题型/答题异常 | 按第 4 节映射并保存原题型 |
| 子问题/表格无字段 | 内容可能丢失 | 已增加 JSONField、migration、序列化返回和复核 |
| 标签关系和 `ExamQuestion.tags` 不同步 | 标签筛选为空 | 同一事务同步，验收 API |
| 标签计数可能过期 | 列表数量不准 | 导入后按关系表重算 |
| 公式图不在题库列表预览 | 列表页不展示公式裁剪图 | 详情接口和课程练习接口返回完整图片类型；复核命令逐个校验 |
| 试卷/教师模糊匹配 | 可能绑定错误对象 | 固定 UUID |
| 未部署 migration | 导入时报字段不存在 | migrate --plan、migrate、check |
| 原始包无答案解析 | 自动判分不可用 | 标记待审核，不得补写 |
| 合并 JSON 与单题 JSON 不一致 | 可能导入错误版本 | 新导入命令逐题比对，不一致立即失败 |
| 同名课程或标签已有无关数据 | 可能误把旧题混入本课程/标签 | 发布命令检测到无关关联时直接失败 |
| 课程题目未挂讲次目录 | 页面筛选/编排不完整 | 复核命令要求 8 个目录且每条关联有目录 |
| 复核只看数据库数量 | 内容错位仍可能显示数量正确 | 复核命令逐题比较题干、选项、子问题、表格、图片文件 |
| 复合题/实验题父记录的 `stem` 为空 | 原数据将实际题干放在 `subquestions[].stem`，课程列表直接显示 `stem_preview` 时出现空白行 | 保留原始 `stem` 不改写；接口增加可读预览，父题为空时拼接子题内容 |
| ZIP 未提供难度字段 | 277 道题的 `difficulty` 均为 NULL，旧前端直接显示 `L{{ difficulty }}` 会显示孤立的 L | 增加 `difficulty_label`，空值显示“未评定”；1—5 映射为基础巩固、较易、中等、较难、困难 |
| 表格只作为 JSON 返回、前端按文本显示 | 表头和数据列无法对齐，合并单元格重复值也会错位 | 接口返回规范化表格，课程练习按 CSS Grid 网格显示，保留原始 JSON |
| 表格抽取出全空尾列 | 课程练习中间出现无意义的竖向分隔线，像内容被分段 | 展示层只删除“所有行均为空”的尾列；内部空单元格仍保留，避免破坏真实列关系 |
| 表格抽取出全空间隔行 | 选项表上下出现大块空白区域 | 展示层删除全空行；原始 `tables` JSON 不修改，保留数据追溯能力 |
| 题干与表格抽取文本混在预览中 | 表格内容重复、换行不清晰 | 预览层识别并截断可识别的表格尾部；详情仍保留原始 `stem/raw_text` |
| 编辑页调用审核详情接口未返回展示字段 | 课程列表正常但进入编辑页仍把表格文本显示在题干中 | 审核详情序列化器同步返回 `display_stem`、规范化 `tables`、`subquestions` 和 `difficulty_label`；编辑页按题干/表格分开渲染 |
| 编辑页只能预览表格、无法修改 | 表格内容纠正后无法保存 | 左侧增加独立表格编辑器，支持修改单元格、增删行列和删除表格；审核更新接口同步保存 `tables` |
| 课程练习把关联记录 ID 当成题目 ID | 编辑、AI、生成变式调用 review/course 接口 404 | 课程接口同时返回 `id`（关联 ID）和 `question_id`（题目 ID）；前端题目操作统一传 `question_id` |
| 生成变式缺少模式或题目未确认 | 请求无法进入生成任务，接口报参数/状态错误 | 前端先校验 `confirmed`，再选择数值、情境、条件或综合变式模式；未确认行显示“待确认”，批量按钮只对全为已确认的选择启用；后端继续校验题目属于当前课程 |
| 生成变式轮询任务 404 | 创建接口返回 Celery 执行 ID，但状态接口查询数据库 `VariantTask` UUID，两者不一致 | API 先创建 `VariantTask` 数据库记录，再启动 Celery；返回数据库任务 UUID，Celery ID仅保存为内部追踪字段；单个和批量生成统一处理 |
| 变式状态持续请求或同题出现两个任务 ID | 旧轮询未处理 404，或重复点击/重复定时器导致并行轮询 | 404 立即终止轮询；同一题已有任务时禁止重复提交；改为请求完成后再安排下一次，并设置最大等待次数；前端重新构建后清理旧页面定时器 |
| 课程练习序号与原题号混淆 | 题干前缺少当前列表位置，或误把原题号当列表序号 | 增加独立“序号”列，按当前目录列表顺序从 1 开始；原题号 `question_no` 保持不变 |
