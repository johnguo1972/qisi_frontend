## ⚠️ 重要说明：迁移方式

### 为什么用 SQL 而不是 `python manage.py migrate`？

这19张表**没有对应的 Django 模型定义**（它们是旧系统的表、日志表、系统表等）。

Django 的 `makemigrations` 会提示 "No changes detected"，因为：
- 这些表没有 `models.py` 中的模型定义
- Django 迁移系统只管理**有模型定义的表**

### 所以服务器部署方式

**直接执行 SQL 文件**（不是 migrate 命令）：

```bash
# 服务器上直接执行 migrate_19_tables.sql
docker exec -i app-pgsql psql -U appuser -d appdb < migrate_19_tables.sql
```

## ⚠️ 注意事项

### 1. 序列与自增字段
- `nextval('xxx_id_seq')` 类型的字段已创建对应序列
- `GENERATED BY DEFAULT AS IDENTITY` 类型会自动创建序列，无需额外处理
- 服务器执行 migrate_19_tables.sql 时会自动处理

### 2. test_connection 表
- 使用 `uuid_generate_v4()` 作为主键默认值
- 需要先创建 `uuid-ossp` 扩展
- migrate_19_tables.sql 开头已包含 `CREATE EXTENSION IF NOT EXISTS "uuid-ossp";`

### 3. 重复执行安全
- SQL 文件中**没有** `DROP TABLE IF EXISTS`
- 如果表已存在，执行会报错（但不会影响已存在的表）
- 如需重新执行，先手动 `DROP TABLE` 对应表

### 4. 数据不迁移
- 本次迁移**只创建表结构**，不迁移任何数据
- 所有新创建的表都是空表（0条记录）
