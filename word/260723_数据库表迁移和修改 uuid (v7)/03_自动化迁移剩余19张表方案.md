### 步骤 2：为缺失表创建/修改 Django 模型

#### 2.1 检查哪些表已有模型定义

```bash
# 在 Django 项目根目录执行
grep -r "class Meta:" --include="*.py" apps/ | grep "db_table" | sed 's/.*db_table = //' | tr -d "'" | sort
```

#### 2.2 为缺失表创建模型

**如果表已有模型定义**：
- 只需修改 `managed = False` → `managed = True`

**如果表没有模型定义**：
- 创建新模型文件
- 从 `public.sql` 提取表结构定义

**示例**（auth_user 表）：
```python
# apps/accounts/models.py（如果不存在则创建）

from django.db import models
from django.contrib.auth.models import AbstractUser

class AuthUser(AbstractUser):
    """Django 内置用户表"""
    
    class Meta:
        db_table = 'auth_user'
        managed = True  # 关键：由 Django 管理
```

### 脚本 3：collect_new_migrations.py

**用途**：收集所有新生成的迁移文件

```python
import os
import glob

# 扫描所有 apps 的 migrations 目录
app_dirs = [d for d in os.listdir('apps') if os.path.isdir(f'apps/{d}')]

migration_files = []
for app in app_dirs:
    migrations_dir = f'apps/{app}/migrations'
    if os.path.exists(migrations_dir):
        # 找所有 .py 文件（排除 __init__.py）
        files = glob.glob(f'{migrations_dir}/*.py')
        files = [f for f in files if '__init__' not in f]
        migration_files.extend(files)

print(f"找到 {len(migration_files)} 个迁移文件")
for f in migration_files:
    print(f"  - {f}")
```

## ⚠️ 注意事项

### 1. 模型定义优先级

- **优先使用 Django 模型定义**（确保代码一致）
- **避免使用 `public.sql` 的原始结构**（除非表没有 Django 模型）

### 2. managed 属性

- **Django 管理的表**：`managed = True`
- **外部系统维护的表**：`managed = False`（保持现状）

### 3. 迁移冲突

- 如果服务器已有部分迁移记录，需要：
  1. 检查 `django_migrations` 表
  2. 对比本地迁移状态
  3. 使用 `--fake` 标记已应用的迁移

### 4. 外键关系

- 确保所有关联的表都已创建
- 注意外键字段的类型（int vs UUID）

## 📞 常见问题

### Q1: 如果某个表没有 Django 模型定义怎么办？

**A**: 需要创建模型：
1. 从 `public.sql` 提取表结构
2. 创建对应的 Django 模型
3. 设置 `managed = True`

### Q2: 迁移失败怎么办？

**A**: 
1. 查看错误日志
2. 检查表结构是否冲突
3. 回滚迁移：`python manage.py migrate <app> <previous_migration>`

### Q3: 服务器迁移记录冲突怎么办？

**A**: 使用 `--fake` 标记：
```bash
python manage.py migrate --fake <app> <migration_name>
```
