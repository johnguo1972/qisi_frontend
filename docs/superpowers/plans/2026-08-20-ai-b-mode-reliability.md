# B 模式 AI 批处理成功率提升实施计划

> **执行方式：** 在 `feature/ai-mode-b-reliability` 隔离工作区内串行实施；不修改 `.env`，不触发生产任务。

## 目标

降低无标准答案题目进行 B 模式批处理时的不可诊断失败率，并保持既有“探查 → DeepSeek 基线 → Qwen B 模式 → 仅比较最终答案 → 冲突复核”的仲裁语义不变。

## 工作项

1. **保留失败阶段**
   - 为仲裁提供方异常保留可安全记录的 `stage`；任务分类函数优先读取该字段和异常链。
   - 统一产出 `baseline_invalid`、`qwen_generate`、`qwen_structure_repair`、`deepseek_final_review`、`schema_invalid`、可重试网络错误等分类。
   - 测试：阶段异常、异常链和局部 B 失败写入 `AIProcessingJobItem.error_code`。

2. **收紧 B 模式结构恢复**
   - 保留现有一次 `mode_b_structure_repair`，仅在 Qwen B 输出的结构/Schema 失败时触发；修复失败保留独立阶段。
   - 不把答案不一致、基线无效或权限/配置错误误当成结构错误重试。
   - 测试：首次结构错误后修复成功、修复失败、非结构错误不走修复。

3. **有限且分类明确的重试**
   - 仅对 429、连接超时、读取超时和 5xx/服务不可用执行一次带退避的任务内重试。
   - 基线无效、Schema 无法修复、最终答案冲突在既有允许次数耗尽后立即结束当前题；同一批其他题继续运行。
   - 测试：可重试错误只执行两次，不可重试错误只执行一次，最终结果保留准确失败分类。

4. **验证与交付**
   - 运行 AI 仲裁、兼容性和 review 数据库回归；执行 `manage.py check` 与差异检查。
   - 连接本地数据库后，以少量无答案 B 模式题建立人工压测任务，记录成功、失败阶段和耗时；不调用生产数据。
   - 经复核后提交功能分支；由用户决定是否合并/部署/重试生产剩余题。

## 验收标准

- B 模式失败不再被笼统标记为 `unknown_error`，可按阶段统计。
- 已有的单次结构修复仍生效且不会扩大为无限重试。
- 网络类临时故障最多额外重试一次；逻辑/数据错误不会消耗无效调用。
- 单题失败不会阻塞同一 Job 的后续题；成功步骤继续即时持久化。
