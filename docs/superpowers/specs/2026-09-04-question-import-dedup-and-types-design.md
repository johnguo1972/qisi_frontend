# 习题导入精确去重与统一题型设计

**日期：** 2026-09-04
**状态：** 已确认设计，待实施计划评审
**范围：** `apps/study` JSON 习题包导入、`apps/parser` 题目模型、AI 探查题型输出、入库批次审计 API，以及 UniApp 题型展示/筛选和入库历史弹窗。

## 1. 目标

1. 正常从页面上传 JSON/ZIP 习题包时，全库识别题干、选项和内嵌公式/图片内容完全相同的题；已存在的题不再创建、复制图片或重复写入关联数据。
2. 同一上传包内的重复题也只导入一次。
3. 每次导入明确返回：读取总数、新导入数、数据库重复跳过数、包内重复跳过数和失败数。
4. AI 探查、JSON 导入、数据库、题型字典 API 与前端筛选共用同一套题型标准，避免“实验题被导入为简答题”等不一致。
5. 保留来源题型和历史题，不自动删除或合并既有重复题。

## 2. 非目标

- 不做“语义相似题”识别；措辞不同、数字不同、选项不同或图像字节不同的题均不视为重复。
- 不比较答案、解析、知识点、难度、来源试卷、标签和 AI 答案；这些字段不同不产生新题。
- 不在本次变更中自动合并或删除历史重复题。
- 不为阅读理解、材料分析、综合、完形填空等题目载体另建题型；它们按具体作答方式归类。

## 3. 统一题型契约

### 3.1 标准题型

| 编码 | 名称 | 归类规则 |
| --- | --- | --- |
| `single_choice` | 单选题 | 仅一个正确选项 |
| `multiple_choice` | 多选题 | 包含不定项选择题 |
| `fill_blank` | 填空题 | 文字、数值或公式填空 |
| `true_false` | 判断题 | 含多个子判断项时仍为判断题 |
| `short_answer` | 简答题 | 简短文字回答 |
| `question_answer` | 问答题 | 需要较完整解释、分析或分步回答 |
| `proof` | 证明题 | 数学证明或推理论证 |
| `experiment` | 实验题 | 实验设计、探究或操作分析 |
| `computation` | 计算题 | 计算过程及结果 |
| `drawing` | 作图题 | 几何、电路、光路等作图或标图 |
| `essay` | 作文题 | 语文作文、英语写作和论述写作 |

`unknown` 只作为历史兼容和异常待核查状态：它不出现在常规筛选项，也不允许作为 AI 探查成功结果。AI 返回非法题型时，必须按同一提示词重试一次；再次失败则记录待核查原因，不伪装成任一标准题型。

### 3.2 来源映射与推断

导入不额外调用 AI。先保留 `source_question_type`，再按确定性规则映射：

- 单项选择、单选、选择题（答案只有一个选项）映射为 `single_choice`；多项选择、不定项选择映射为 `multiple_choice`。
- 解答题有计算/推导要求时映射为 `computation`，否则映射为 `question_answer`。
- 阅读理解、材料分析、综合题、完形填空按其具体小题的选项、空格和预期答题方式映射，不新增类别。
- 原始题型缺失时，以选项数量、答案结构和题干的判断/填空/作图标记推断；无法确定则保留 `unknown` 并标记待核查。

AI 提示词与结构化输出 schema 使用以上 11 个代码枚举；持久化前再由统一规范化函数校验，任何别名只在输入边界转换一次。

## 4. 精确去重规则

### 4.1 去重内容

计算 `content-v1` SHA-256 指纹的规范化载荷由以下内容按顺序组成：

1. 题干文本；
2. 每个选项的标签和内容，且选项顺序参与计算；
3. 题干/选项中引用的公式，使用解析后的规范化 LaTeX 或等价文本，不使用导入包中不稳定的占位符名称；
4. 题干/选项中引用的图像，使用图片文件的 SHA-256 和其在内容中的顺序。

题型**不参与**指纹。这能确保同一题即使导入时题型不准确、后续被 AI 探查纠正，也不会因此重复入库。题型由统一题型规则独立更新。

文本规范化使用 Unicode NFKC、统一换行和空白、去除首尾空白；不删除标点、数值、公式命令或题目正文。公式及图片无法安全解析时，当前题记为失败，不以残缺内容生成指纹。

### 4.2 指纹登记表

新增 `QuestionContentFingerprint`（归属 `parser`）：

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `fingerprint` | `CharField(64, unique=True)` | SHA-256 十六进制值；数据库唯一性保证并发安全 |
| `algorithm_version` | `CharField` | 当前为 `content-v1`，为将来算法升级留出边界 |
| `canonical_question` | 可空 `OneToOneField(ExamQuestion)` | 该指纹代表的历史最早题或新导入题 |
| `state` | `reserving` / `active` | 防止并发请求同时创建相同题 |
| `created_at` / `updated_at` | 时间字段 | 审计和故障恢复 |

不直接在 `ExamQuestion` 加唯一哈希字段：历史库已存在重复题，直接唯一迁移会失败。登记表可为历史重复项选择一题作为 canonical，而不破坏历史数据。

### 4.3 导入流程

1. 解压并读取 JSON，验证必需的题干、选项和资源文件。
2. 对每题完成公式占位符解析、图片哈希读取、题型规范化和内容指纹计算。
3. 先按当前包内指纹去重；后续同指纹题计为“包内重复跳过”。
4. 对每个包内唯一指纹，在数据库事务内创建 `reserving` 登记记录：
   - 创建成功：导入 `ExamQuestion`、选项和资源，再将登记记录设为 `active` 并关联该题；
   - 唯一约束冲突：读取已有 canonical 题，计为“数据库重复跳过”；
   - 任一步失败：回滚本题事务并移除未激活的预留记录。
5. 只有至少一题真正导入时才保留并更新 `ExamPaper`、`ParseTask`。上传包全部重复时不创建空试卷，也不复制媒体文件。
6. 返回统计和最多 20 条明细。重复明细含来源题号、重复类别、已存在题 UUID、已有题所在试卷及题干摘要；失败明细含题号和安全错误信息。

## 5. 历史数据迁移

新增管理命令：

```text
python manage.py backfill_question_fingerprints --dry-run
python manage.py backfill_question_fingerprints --apply
```

命令按稳定排序扫描现有题目；同一指纹仅建立一条登记记录并选择最早创建的题作为 canonical。默认只报告，不写库；`--apply` 才写入。它不删除、不合并、不修改历史题干、选项或答案。

## 6. 对外接口与前端

- JSON 导入响应新增 `total_read`、`imported`、`skipped_existing`、`skipped_in_package`、`failed`、`details`，保留既有响应字段兼容旧前端。
- `GET /question-types/` 仅返回上述 11 个可选标准题型；删除面向新功能的 `subjective` 伪类别，历史 `unknown` 可展示但不可选择。
- 题库、课程练习、创建作业和编辑页从共用题型字典/常量读取标签，避免各页面自行维护不一致映射。
- AI 探查结果须写入标准题型；若与旧题型不同，更新题目 `question_type` 并保留 `source_question_type`，不影响内容指纹。

## 7. 异常处理与可观测性

- 导入包资源缺失、损坏或公式无法规范化：该题失败并继续处理下一题。
- 同一指纹正在被另一导入请求预留：短暂重试读取；确认已激活后按数据库重复跳过。
- 长时间未激活的预留记录由管理命令检查并安全清理，绝不删除 `active` 记录。
- 记录结构化日志：导入任务 ID、题号、指纹前 12 位、结果类型和耗时；日志不记录完整题干或敏感内容。

## 8. 测试与验收

1. 同题干、同选项、同公式和同图像的跨包题仅导入一次。
2. 同题干但任一选项不同、公式不同或图像哈希不同的题均可导入。
3. 同题在不同题型标注下仍识别为同一题；新题型可被 AI 后续更新。
4. 同包重复、跨包重复、并发重复导入均有正确统计且不产生额外媒体文件。
5. 全重复上传包不会创建试卷或 ParseTask。
6. 11 类题型、常用别名、未知题型和 AI 非法返回分别符合题型契约。
7. 历史回填在 `--dry-run` 不写库，`--apply` 不删除或合并历史题。
8. JSON 导入现有公式占位符和图片资源回归通过，导入后前端可正确渲染。

## 9. 新增/导入习题历史

### 9.1 审计模型

新增 `QuestionIngestionBatch`，记录一次具有明确操作者和来源的入库动作，而不从 `ExamQuestion.created_at` 反推。该模型至少包含：

| 字段 | 用途 |
| --- | --- |
| `actor` | 发起操作的登录用户 |
| `source_type` | `json_import`、`manual_create`、`photo_create`、`course_material_import` |
| `course` / `paper` | 可空的课程与试卷关联，用于界面范围过滤 |
| `source_name` | 上传包、课程资料或人工操作的可读名称 |
| `status` | `running`、`success`、`partial_success`、`failed` |
| `total_read`、`created_count`、`skipped_existing_count`、`skipped_in_package_count`、`failed_count` | 本批次的统计数据 |
| `started_at`、`finished_at`、`created_at` | 时间审计字段 |

JSON 导入每个上传包建立一条批次记录；手工新增和拍照新增各建立一条 `created_count=1` 的记录；课程资料导入按一次资料导入建立一条记录。题目没有真正写入时，批次仍保留，用 `created_count=0` 和对应跳过/失败数说明结果。

现有 `ParseTask` 继续服务于 JSON 导入的处理进度，不能作为唯一历史来源；`QuestionIngestionBatch` 是跨来源、面向教师界面的统一审计记录。

### 9.2 历史查询 API

新增受登录保护的入库历史查询接口，默认仅返回最近 30 天、按完成/创建时间倒序的记录：

```text
GET /questions/ingestion-history/?scope=bank
GET /questions/ingestion-history/?scope=course&course_id=<UUID>
```

- `scope=bank`：返回当前教师发起的全部入库批次。
- `scope=course`：仅返回当前教师在指定课程范围内发起、且明确关联该课程的批次；不混入其他课程或题库全局记录。
- 返回项包含时间、来源、来源名称、状态、新增数、数据库重复跳过数、包内重复跳过数和失败数；默认单页 30 条。
- 仅教师本人可查看自己的历史；无权限课程直接返回 403，不泄露批次是否存在。

### 9.3 界面

- 题库管理的“新增”按钮旁增加文字链接 **“导入习题历史”**。
- 课程练习的“新增习题”按钮旁增加同名链接。
- 点击后打开同一可复用弹窗组件，标题为“新增/导入习题历史”，右上角提供关闭按钮。
- 题库管理调用 `scope=bank`；课程练习调用 `scope=course` 并传入当前课程 ID。
- 弹窗每行显示：操作时间、来源、来源名称、新增题数；导入类记录同时显示重复跳过和失败数量。无记录时显示“近 1 个月暂无新增或导入记录”。

### 9.4 本项验收

1. JSON 上传、手工新增、拍照新增、课程资料导入均产生可查询的入库批次记录。
2. 题库管理只显示当前教师最近 30 天的全部入库记录。
3. 课程练习只显示当前课程的记录，不显示其他课程或无课程关联的题库导入。
4. 全重复导入包在历史中可见，新增数为 0，重复跳过数正确。
5. 弹窗正确展示时间、来源和数量；空历史、失败批次和权限拒绝均有明确状态。
