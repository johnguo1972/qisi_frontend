# 微信网页扫码登录设计

## 目标

在 H5 登录页提供“手机号验证码登录”和“微信扫码登录”两种并列入口。两种入口在取得可信手机号后复用同一账户识别、角色校验、JWT 签发及多角色切换流程。

微信扫码登录必须由用户勾选“手机号绑定授权确认”后才能开始；扫码路径不发送短信、不校验短信验证码。

## 范围与边界

- 仅 H5 页面显示网页扫码登录；小程序保留现有微信一键登录。
- 登录时的 `requested_role` 以用户在登录页选择的角色为准。
- 不因微信扫码自动授予管理员、教师、家长或学生角色。
- AppSecret 仅放在本地和生产服务器环境变量中，不进入前端、源码、Git 或日志。
- 若微信授权未提供有效手机号，扫码登录失败并提示用户完成手机号授权；不得降级为短信验证。

## 用户流程

```text
登录页选择角色
  ├─ 手机号验证码登录
  │    └─ 验证手机号和短信验证码
  └─ 微信扫码登录
       ├─ 勾选“手机号绑定授权确认”
       ├─ 创建单次扫码会话并展示二维码
       ├─ 微信扫码、确认登录及手机号授权
       └─ 服务端验证微信回调并获得可信手机号
                         ↓
                 统一登录完成服务
                         ↓
      按手机号找账户 → 校验 requested_role → 签发 JWT
                         ↓
                    进入所选角色页面
```

多角色用户在二维码登录和手机号登录中均使用登录页选择的角色建立会话；后续使用既有切换角色接口。所选角色未授予时，服务端拒绝登录并返回可用角色，不自动变更角色。

## 架构

### 独立网页微信身份表

新增 `WechatWebIdentity`，不修改现有小程序 `WechatIdentity` 的一对一关系。

字段：

- `user`：关联 `UserAccount`；
- `appid`：微信开放平台网页应用 AppID；
- `openid`：网页应用身份标识；
- `unionid`：可选的跨应用身份标识；
- `created_at`、`last_login_at`。

约束：`appid + openid` 全局唯一。该表不保存微信临时 token、手机号授权凭证或 AppSecret。

### 回调与一次性票据

服务端将随机 `state` 记录到 Redis，TTL 为 5 分钟并且只能消费一次。其内容至少包括请求角色、回跳地址和创建时刻。

微信回调只在服务端处理。回调验证成功后，服务端创建短期、单次消费的登录票据并重定向到 H5；JWT 不得置于回调 URL 查询参数。

### 账户关联规则

1. 以微信授权手机号查找现有 `UserAccount`。
2. 已有网页微信身份但关联用户与手机号不一致时，拒绝并记录安全事件。
3. 已有小程序身份且 UnionID 唯一匹配时，可建立网页身份关联。
4. 不存在账户时，调用与手机号验证码登录相同的账户创建/角色安全规则；不可因请求角色创建高权限账户。
5. 关联成功后更新 `last_login_at`。

## API 契约

### `POST /api/v1/auth/wechat-web/session`

请求：`requested_role`、`phone_authorization_confirmed=true`。

响应：二维码授权地址、短期会话标识和过期时间。

未勾选确认、角色非法或请求频率超限时返回明确错误码。

### `GET /api/v1/auth/wechat-web/callback`

接收微信的 `code` 和 `state`。服务端验证 `state`、用服务端 AppSecret 交换可信微信身份和手机号授权结果，处理账户关联后创建一次性登录票据并跳转 H5。

### `POST /api/v1/auth/wechat-web/complete`

请求：一次性登录票据。

响应与现有 `/auth/login` 保持一致：访问令牌、刷新令牌、用户资料、当前角色和完整角色列表。

## 配置与部署

新增生产环境变量：

- `WECHAT_WEB_APP_ID`
- `WECHAT_WEB_APP_SECRET`
- `WECHAT_WEB_REDIRECT_URI`

生产部署前需在微信开放平台配置 HTTPS 授权回调域名，并确认网页应用具有扫码后手机号授权所需的产品能力。服务端日志只能记录流程状态、错误码和脱敏标识，不记录 code、token、手机号授权凭证或 AppSecret。

## 安全控制

- `state` 随机、短期、单次消费，并绑定请求角色。
- 回调只允许配置的回跳地址和 HTTPS 域名。
- 前端不能上传手机号作为微信扫码身份依据。
- 微信身份、手机号和账户之间的冲突失败关闭。
- 对创建会话、回调失败和票据消费实施限流。
- 一次性登录票据过期或重复消费时必须拒绝。

## 测试与验收

后端测试覆盖：

- 已授权手机号的扫码登录；
- 未勾选授权确认、拒绝授权、无手机号及过期/重放 state；
- 多角色用户分别以四种角色登录；
- 未授予角色、OpenID/手机号冲突与 UnionID 唯一/歧义匹配；
- 扫码流程中不调用短信发送和短信校验；
- JWT、角色列表和手机号验证码登录响应契约一致。

前端验证覆盖：H5 二维码入口、确认勾选、加载/取消/失效提示、回跳票据消费及 H5 构建。

生产验收：使用测试微信号完成真实扫码回调和一个已有多角色账户的角色登录；不以模拟回调替代真实授权链路验收。
