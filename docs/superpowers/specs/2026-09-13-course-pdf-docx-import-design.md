# 课程练习 PDF/DOCX 试卷导入设计

日期：2026-09-13  
状态：已确认，待实现计划评审

## 目标与范围

教师在课程练习的“新增习题”面板中上传一份 PDF 或 DOCX 试卷。系统异步提取文本、表格和插图，以 `qwen3.7-plus` 将逐题片段结构化，自动导入题库并立即关联当前课程。

首期范围：

- 支持 `.pdf` 与 `.docx`；不支持旧版 `.doc`。
- 单文件最大 100 MB；PDF 最多 100 页。DOCX 的转换/解析结果同样不得超过 100 页等价处理上限。
- 自动入库、自动关联当前课程；新题标记为待审核，但不阻断教师在课程内查看和使用。
- 内容指纹去重命中时不重复建题，仍建立当前课程关联。
- 保留现有拍照/上传和 JSON 数据包导入能力；不新增独立 FastAPI、Redis 或对象存储服务。

不在本期范围：旧 `.doc`、人工确认后才入库、变式题生成，以及修改已有 AI 探查流程。

## 采用方案

在现有 Django、Celery、课程题目关联、题目媒体和 JSON 入库链路上扩展。文档解析生成内部标准题目对象，再调用与 JSON 导入共用的标准化、媒体保存、内容指纹去重和课程关联服务。

这避免了独立服务与现有登录、媒体、任务状态、题库去重和课程关联脱节。

## 用户界面

课程练习页面的“新增习题”面板保留两个现有 Tab：`拍照/上传`、`JSON数据包导入`，增加第三个 Tab：`PDF-Word文档导入`。

新 Tab 仅允许选择 `.pdf`、`.docx`，展示“最大 100 MB、最多 100 页、后台异步解析”的提示。提交后显示 `排队中`、`文档解析中`、`AI结构化中`、`导入中`、`完成`、`部分完成`或`失败`。面板关闭和页面离开不取消任务；再次进入当前课程，或打开“导入习题历史”，可恢复任务状态与最终统计。

导入历史为当前课程过滤，新增来源标签 `PDF/Word 文档导入`，展示文件名、提交/完成时间、阶段、读取数、新增数、重复数、失败数、关联数和有限条脱敏错误摘要。

## 数据模型

### QuestionIngestionBatch

扩展 `SourceType`，增加 `document_import`。继续作为统一可审计批次：操作者、课程、试卷、来源文件名、状态、读取/新增/重复/包内重复/失败计数、开始/完成时间。

### QuestionDocumentImportTask

新建与 `QuestionIngestionBatch` 一对一的任务表，持久化：

- 原始文件相对媒体路径、文件名、检测到的 MIME 类型与文件大小；
- 文档类型、页数、当前阶段、阶段进度和 Celery 任务 ID；
- 结构化候选题数、关联数、有限条脱敏错误摘要；
- 原始 AI 响应/解析中间信息的受控审计引用，而非暴露给前端。

状态机：`queued → extracting → structuring → importing → success | partial_success | failed`。终态与批次状态一致。任何任务状态查询均按课程和权限范围约束。

## API 契约

新增课程专用接口：

```text
POST /api/v1/courses/{courseId}/questions/import-document/
GET  /api/v1/courses/{courseId}/questions/import-document/{taskId}/status/
```

`POST` 使用 `multipart/form-data`，字段为 `file` 和可选 `tree_node_id`。服务端验证登录身份、课程管理权限、课程上下文、扩展名、文件签名、实际大小和 PDF 页数；成功时创建运行中导入批次与任务记录，保存原始文件、投递 Celery，并返回 `batch_id`、`task_id`、`course_id`、`tree_node_id` 和初始阶段。

课程上下文缺失或节点不属于课程时直接拒绝，不得退化为题库导入。`GET` 返回当前阶段、进度与计数；终态额外返回有限错误摘要。响应不得包含本地路径、API 密钥或未授权媒体地址。

现有 JSON 导入接口不改其 URL 与行为；公共入库逻辑从视图抽出为可被 JSON 与文档任务调用的服务。

## 异步处理流水线

1. Web 请求持久化源文件和任务记录，并路由到专用 `document.import` Celery 队列。
2. Worker 创建任务专用临时目录。
3. PDF 通过 PyMuPDF 提取文字块、图片、表格候选、页号和坐标，并生成页面图作为扫描件/视觉识别兜底。DOCX 通过 `python-docx` 提取段落、表格、内嵌图片和文档顺序。
4. 本地规则依据题号、选项编号和页序切分候选题，避免将整卷提交给模型。
5. 对每个候选题，将文本、邻近插图/页图、表格和已有公式信息交给 `qwen3.7-plus`，要求输出严格 JSON。
6. 清理 Markdown 围栏、提取 JSON 对象、依据 Schema 校验题干、题型、选项、表格和图片引用。
7. 将合格结构化结果交给共享入库服务：媒体落库、公式资源处理、内容指纹去重、创建或复用 `ExamQuestion`、创建或复用 `CourseQuestionLink`。
8. 以已成功处理的题目为单位提交；完成后更新任务和批次统计，并清理临时文件。

专用队列在生产环境并发限制为 1–2，防止文档解析挤占已有批量 AI 队列。

## 图片、表格和公式

- PDF 图片根据页码、坐标与相邻题目范围绑定；跨页题保留所有相关页图和插图。
- DOCX 图片根据段落/表格 XML 顺序与相邻文本绑定。
- 表格保留结构化行列数据，并生成题目可展示的 HTML。
- 已存在的 LaTeX 与公式占位符原样保留。无法可靠转写的扫描公式保留原图并标记待审核，禁止虚构 LaTeX。
- `qwen3.7-plus` 是最终题目结构化模型。若该模型接口不能接收视觉内容，仅对 OCR、图文对应和公式缺失部分调用已有视觉能力；视觉结果作为输入交由 `qwen3.7-plus` 汇总，不能替代最终结构化结果。

## Qwen 结构化契约

每个请求要求低温度、纯 JSON，至少返回：题号、题型原始值、题干、选项、答案、解析、表格、插图引用、置信度和需要人工审核原因。题型沿用导入时不严格限定的规则，保留源题型；后续 AI 探查可以更新规范题型。

模型输出必须经过 JSON Schema 与业务校验。无题干、非法图片引用、重复选项标签、无法解析 JSON 或高风险截断均为该题失败，不得创建半成品题目。

## 去重与课程关联

复用现有 `QuestionContentFingerprint` 和媒体参与的内容哈希。处理结果分为：

- 新内容：创建题目、媒体和课程关联；
- 题库已有：不创建题目，创建当前课程关联；
- 当前课程已关联：不创建重复关联，计入已存在关联；
- 同一文档重复：仅处理首个标准题目，后续计入包内重复。

默认关联到请求节点；未指定节点时使用课程的“未分类导入习题”节点。所有重复处理均遵循这一规则。

## 容错、安全与可观测性

- 单题 AI 超时、不可解析 JSON 或图片读取失败可重试一次；二次失败记录为单题失败，继续处理其余题。
- 损坏文件、超限文件、无可解析内容或解析器初始化失败为任务级失败，零题入库。
- 多题中部分失败时状态为 `partial_success`；已成功入库题目保留。
- 原始文件、提取图片、AI 审计数据仅在服务端受控存储；前端使用现有受控媒体访问机制。
- 文件名使用 UUID 重命名；验证文件签名、限制路径、隔离临时目录，拒绝路径穿越和伪造扩展名。
- 只有课程教师或课程管理管理员可以创建、查看当前课程的任务；不得跨课程读取任务或错误摘要。

## 测试与上线验证

自动测试至少覆盖：

- PDF/DOCX 扩展名和文件签名校验；100 MB 和 100 页限制；
- 文本、选项、表格、图片和跨页题切分；
- Qwen JSON 清洗、Schema 校验、无效结果与单题重试；
- 新题、题库重复、课程已关联和包内重复的统计及关联；
- 权限隔离、课程节点归属、状态轮询和错误脱敏；
- UniApp 新 Tab、限制说明、上传、轮询、关闭后恢复和导入历史展示。

上线前安装并锁定 `PyMuPDF`、`python-docx`，配置专用队列 Worker。使用一份含选项、公式、表格、插图和跨页题的 PDF，以及一份含表格/图片的 DOCX，验证“上传 → 异步任务 → 自动入库 → 课程可见 → 历史统计”的完整链路。
