# 教师题库授课范围与知识点包含筛选设计

## 背景与目标

教师端题库管理必须只显示其授课学段和科目范围内的知识树与题目。教师可以教授多个科目；当只有一个可授科目时，页面不得提供切换到其他科目的能力。

点击知识树叶子知识点时，右侧题目列表必须显示“包含该知识点”的所有题目。题目可以关联多个知识点，任一关联项命中即视为命中。

本设计只涉及 `front/` 内的 Django 后端和 UniApp 教师端页面。

## 数据模型与兼容策略

在 `UserAccount` 中新增 JSON 列表字段 `subjects`，保存教师可授科目的数据库代码，例如：

```json
{
  "subject": "physics",
  "subjects": ["physics", "math"],
  "stages": ["junior"]
}
```

- `subjects` 是教师可授科目的完整来源。
- 保留现有字符串字段 `subject`，作为默认科目和历史兼容字段。
- 数据迁移为历史用户回填 `subjects=[subject]`；空 `subject` 不伪造授权范围。
- 写入教师资料时，同步将 `subject` 更新为 `subjects` 的第一项；无授课科目时两个字段都为空。
- 管理员的机构成员编辑界面把“科目”改为可多选，学段继续采用多选。
- 管理员以管理员角色访问维持现有权限；以教师角色访问时套用本文的教师授课范围限制。

## 后端接口与访问控制

### 教师知识树

`GET /api/v1/teacher/knowledge-tree/` 从认证会话的教师身份读取 `subjects` 和 `stages`。

- `subject` 请求参数只能选择 `subjects` 中的项目；缺省时使用默认科目。
- 请求的 `stages` 只能是当前教师已授权学段的子集；服务端始终以授权范围为上限。
- 未配置任一科目或学段时返回空树及明确的 `scope_configured=false` 状态，不回退为全库。
- 成功响应扩展为 `grades`、`allowed_subjects`、`allowed_stages`、`selected_subject` 和 `scope_configured`。
- 题量统计仅统计当前知识树范围内的题目，避免跨科目、跨学段计数混入。

### 题库列表

`GET /api/v1/questions/` 对教师角色强制叠加授课范围，不能依赖前端参数完成权限控制。

- 当前科目只能选择教师被授权的科目；未传时使用默认科目。
- 当前学段只能落在教师的 `stages` 内。
- 没有已配置范围时返回空分页结果和可识别的范围未配置状态。
- 管理员角色继续使用既有的全题库行为。

### 知识点包含筛选

`knowledge_point_id` 的筛选规则是“包含任一所选知识点”：

- `ExamQuestion.knowledge_points` 是 JSON 数组时，对每个选中 ID 使用 JSON `contains` 查询；数组内任一对象的 `id` 命中即返回该题。
- 兼容历史数据：缺少稳定 ID 但保存了 `module` 名称的题目，按知识点表中的 `module` 做同等命中。
- 保留 AI 富化数据的兼容兜底，但优先使用题目正式 `knowledge_points`。
- 多选时各 ID 使用 OR 关系；选择“未分类”时只返回空或 NULL 知识点数组的题目。

## 前端交互

题库管理页以知识树响应返回的授权范围为唯一渲染依据。

1. 单科教师：左上角显示科目名称但不可打开选择器。
2. 多科教师：只展示 `allowed_subjects`，切换后清空已选知识点、重置至第一页，并重新加载树和题目。
3. 左侧知识树叶子节点和顶部知识点下拉框共用同一 `activeKnowledgePoint` 状态。选择任一入口都立即重置分页并加载列表。
4. 树仅渲染当前科目和已授权学段的节点。
5. 教师资料没有有效学段或科目时，显示“请由管理员配置授课科目和学段”，不展示全题库。
6. 角色切换和资料刷新后重新读取后端授权范围，避免浏览器本地缓存造成越权显示。

## 错误处理

- 前端收到授权范围无效、科目越权或范围未配置响应时，清空旧树和旧题目，并显示明确提示。
- 通过 URL 或接口手动提交未授权的 `subject`、`stages` 或知识点，不返回越权数据。
- 对历史 JSON 格式异常的知识点记录，查询必须跳过异常项而不导致整个题库接口 500。

## 验证计划

后端定向测试覆盖：

1. 数据迁移把单科教师回填为单元素 `subjects`。
2. 单科教师只能取到对应科目和学段，且伪造其他科目或学段无效。
3. 多科教师仅能在授权科目中切换。
4. 管理员教师双角色在不同活动角色下分别遵守正确权限。
5. 一题关联多个知识点时，按其中每一个知识点都能查到该题。
6. 旧 `module` 格式、数值/字符串 ID 和空知识点题目均按定义处理。

前端验证覆盖：

1. 单科控件不可切换，多科控件只列授权科目。
2. 点击树叶子节点后请求携带统一的 `knowledge_point_id` 且列表刷新。
3. 顶部筛选、树节点、重置筛选之间状态一致。
4. H5 构建通过，并用真实教师会话做一次有数据的接口/页面验证。

## 非目标

- 不改变题目、知识点或 AI 处理数据的业务语义。
- 不改动课程共享、任务、学生端、微信登录或部署流程。
- 不在本次新增按机构、班级或课程维度细分教师授课范围；如后续需要可演进为独立的授课范围表。
