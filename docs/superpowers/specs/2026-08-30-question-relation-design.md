# 题库“关联题”功能设计

## 目标

将题库管理中每题的“类似题”操作改为“关联题”。教师可在弹窗中查看已关联题，并从符合规则的候选题中多选建立人工关联；也可在已关联题中解除不再需要的关联。

## 范围

- 仅修改 `front` 内的 Django 后端、UniApp 题库页面、测试和数据库迁移。
- 本次提供建立和解除人工关联；不提供自动 AI 推荐关联或跨学科关联。
- 解除关联只移除两题之间的关联记录，不删除任一题目、题目答案、知识点或其他题目的关联。

## 数据模型

新增 `QuestionRelation` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID 主键 |
| `question_left` | 关联对中 UUID 较小的题目 |
| `question_right` | 关联对中 UUID 较大的题目 |
| `created_by` | 建立关联的用户 |
| `created_at` | 建立时间 |

`question_left` 与 `question_right` 设联合唯一约束；服务层把任意两个题目规范为同一固定顺序，因此一对题只保存一行，但查询任一端均可得到另一端，形成逻辑双向关系。服务层拒绝题目关联自身。

解除关联直接删除这条规范化后的关联记录；不存在的关系视为幂等成功，不报错。

## 接口契约

接口遵循既有题库 API 的认证、题目可见性和响应封装规则。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/questions/{id}/relations/` | 返回已关联题，支持分页 |
| `GET` | `/api/v1/questions/{id}/relation-candidates/` | 返回可关联候选题，支持分页 |
| `POST` | `/api/v1/questions/{id}/relations/` | 批量建立关联，负载为 `{"question_ids": ["..."]}` |
| `DELETE` | `/api/v1/questions/{id}/relations/{related_id}/` | 解除原题与指定已关联题之间的关系 |

解除接口只接受一条已建立关系：服务端将 `{id}` 与 `{related_id}` 规范化为唯一题对，在当前用户具备题库管理权限且两题均可见时删除。响应包含 `removed: true|false`；`false` 表示该关系已经不存在，前端仍将其从当前列表移除并刷新总数。

候选题必须同时满足：

1. 题目不是原题且尚未关联；
2. `subject` 与原题一致；
3. 两题均有具体难度，且候选题难度位于原题难度的闭区间 `[difficulty - 0.5, difficulty + 0.5]`；
4. 两题至少存在一个相同标准知识点。

知识点字段为历史兼容的 JSON 数据。候选筛选服务先将每个知识点规范为稳定键：优先使用知识点 ID，其次 `module`，最后名称；再比较集合交集。这样旧字符串结构、对象结构和当前标准知识点结构都能参与匹配。查询先按学科和难度范围缩小数据库集合，再在服务层判断知识点交集，避免依赖某一 JSON 结构的 PostgreSQL 专有查询。

候选和已关联题统一返回：题目 UUID、题号、题干摘要、难度、知识点摘要；候选结果额外返回共同知识点名称。分页默认 50 条，并返回总数。

## 前端交互

1. `QuestionDetailCard` 的“类似题”按钮改名为“关联题”。
2. 点击后打开带遮罩的“关联题”弹窗，右上角提供关闭按钮；默认显示“可关联题”标签页。
3. “可关联题”展示候选列表及每行复选框；选中 UUID 可跨页保留。点击“关联”后提交全部已选 UUID，成功后提示、清空选择、刷新两个标签页并切换到“已关联题”。
4. “已关联题”只展示已经建立关系的题目。每一行提供“解除关联”按钮。
5. 点击“解除关联”先弹出轻量确认提示：“解除后仅取消两题的关联，不会删除题目或答案。是否继续？”确认后调用 `DELETE` 接口；成功后立即从已关联列表移除该行、刷新总数，并刷新候选列表，使该题重新成为可关联候选。
6. 解除接口失败时保留当前已关联列表，不做本地删除，并显示可读错误提示；重复点击或其他端已解除时按幂等成功处理。
7. 缺少原题难度或知识点时，候选页显示“当前题目缺少难度或知识点，无法生成可关联题”，而非返回误导性的候选结果；已关联页仍可正常查看和解除历史关联。

## 权限与一致性

- 读取候选和已关联题沿用题库题目读取权限。
- 创建、解除关联沿用当前教师题库管理权限；管理员遵循同一授权规则。
- 批量创建使用事务与数据库唯一约束，重复请求幂等；响应包含新建数量、已存在数量和无效 UUID。
- 解除操作采用精确题对删除，且不影响其他关联对；删除后候选查询自然重新包含该题。

## 错误处理

- 原题或指定关联题不存在：404。
- 关联自身、指定题不可见或无管理权限：不删除关系，并返回可读的 400/403 错误。
- 待解除关系不存在：返回 200 且 `removed: false`，保证重试安全。
- 原题缺少 `subject`、`difficulty` 或可识别知识点：候选接口返回空结果及可读原因。
- 接口失败：前端保留当前弹窗、已选状态和已关联列表，并显示错误提示。

## 验证

- 模型测试：双向查询、顺序规范化、联合唯一、拒绝自身关联、精确解除和重复解除幂等。
- 接口测试：同学科且难度边界 `±0.5`、知识点交集、异学科排除、无交集排除、已关联排除、批量幂等、解除后关系列表与候选列表的变化、权限与不可见题。
- 页面测试/构建：按钮名称、双 Tab、候选勾选并建立关联、已关联行解除确认/成功/失败状态、H5 构建。
