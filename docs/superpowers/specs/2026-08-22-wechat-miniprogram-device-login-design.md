# 微信小程序单二维码设备登录设计

## 1. 目标

将 H5 登录页现有的微信开放平台网页扫码流程，调整为“网页展示一个普通图片形式的小程序码，手机扫码后完成电脑端登录”的设备登录流程。

本次改造实现以下体验：

- 手机号验证码登录页中，“微信扫码登录”使用右对齐文字链接，位于“登录”按钮下一行；
- 点击链接后在当前登录卡片内切换到微信扫码视图，不跳转到微信开放平台中间页面；
- 微信扫码视图立即展示普通 `<img>` 小程序码，不使用 `iframe`；
- 二维码位于操作按钮上方，按钮用于二维码过期、加载失败时重新生成；
- 已绑定小程序微信身份的用户扫码后自动登录电脑网页；
- 首次使用的小程序微信身份必须在小程序中主动点击一次“授权手机号并登录”；
- 首次绑定完成后，后续扫码不再重复索取手机号授权；
- 登录角色以网页端当前选择的学生、教师、家长或管理员角色为准；
- 不发送短信，不接受前端自行填写的手机号作为微信登录依据。

## 2. 微信能力边界

微信开放平台网站应用的 `snsapi_login` 只能取得网页应用身份，不能取得可信手机号；标准 PC 扫码页面还依赖微信页面自身的扫码轮询，不能简单地把授权 URL 转成二维码图片替代 `iframe`。

因此新入口不再使用网站应用 `qrconnect` 作为主登录协议，而使用微信小程序码承载一次性设备登录桥接码。小程序通过 `wx.login` 取得小程序身份；只有首次未绑定身份才调用 `getPhoneNumber`，且必须由用户主动点击微信原生授权按钮。

H5 上原有的“手机号绑定授权确认”复选框不再作为手机号授权凭证。真正的授权发生在小程序原生 `getPhoneNumber` 按钮，H5 不得伪造、代替或自动触发该授权。

## 3. 页面交互

### 3.1 手机号验证码登录视图

- 保留角色标签、手机号、验证码、保持登录状态和“登录”按钮；
- 删除当前按钮形态的“微信扫码登录”；
- 在“登录”按钮下一行右侧显示文字链接“微信扫码登录”；
- 链接具有键盘焦点、点击态和可识别的可访问性语义，但视觉上不呈现边框、背景色或按钮高度。

### 3.2 微信扫码登录视图

- 保留同一组角色标签；切换角色时立即作废旧会话并生成新角色对应的二维码；
- 进入视图后自动创建扫码会话并显示二维码，无需先跳转到微信页面；
- 二维码使用 `<img>` 显示，固定为完整正方形，不裁切、不滚动、不使用 `iframe`；
- 二维码下方显示剩余有效时间和当前状态；
- 二维码下方提供“重新生成微信二维码”按钮；用户要求中的“开始微信扫码”操作由自动生成取代，避免出现二维码已经显示但仍要求再次点击开始的矛盾状态；
- 底部使用文字链接“手机号验证码登录”切回原视图；
- 离开页面、切换登录方式或切换角色时，停止轮询并作废当前前端会话状态。

状态文案至少包括：

- 正在生成二维码；
- 请使用微信扫描二维码；
- 已扫码，正在确认微信身份；
- 请在小程序授权手机号；
- 登录成功，正在进入系统；
- 二维码已过期，请重新生成；
- 所选角色未开通；
- 微信服务或网络暂时不可用。

## 4. 数据复用与缓存状态

### 4.1 小程序身份

复用现有 `WechatIdentity` 模型：

- `appid + openid` 唯一标识一个小程序微信身份；
- `user` 关联已有 `UserAccount`；
- `unionid` 在微信返回时保存，但不得在空值或不唯一时单独作为登录依据。

本次不新增重复的小程序身份表，也不修改用户多角色模型。

### 4.2 设备登录会话

设备登录会话保存于 Redis，不落数据库。会话包括：

- 随机 `web_session_id`；
- 原网页 Django session 标识；
- 网页选择的 `requested_role`；
- 创建时间、绝对过期时间；
- 当前状态：`pending`、`scanned`、`phone_required`、`bound`、`failed`；
- 扫码确认后的小程序 `appid/openid/unionid`；
- 绑定完成后的一次性完成票据；
- 安全错误分类，不保存手机号、微信临时 code 或 access token。

会话默认有效期为 300 秒。所有派生桥接码和票据使用原会话的绝对过期时间，任何操作不得延长总有效期。

## 5. 完整数据流

```text
H5 选择角色并点击“微信扫码登录”
        ↓
创建浏览器绑定的设备登录会话
        ↓
服务端生成短桥接码和体验版/正式版小程序码
        ↓
H5 以普通 <img> 显示二维码并轮询状态
        ↓
手机微信扫描小程序码，进入 pages/auth/web-binding
        ↓
小程序 wx.login → 服务端 code2session
        ↓
按 appid + openid 查询 WechatIdentity
   ├─ 已绑定
   │    ├─ 所选角色有效 → 创建一次性完成票据
   │    └─ 所选角色无效 → 会话记录 ROLE_NOT_GRANTED
   └─ 未绑定
        ↓
      小程序显示“授权手机号并登录”
        ↓
      用户主动触发 getPhoneNumber
        ↓
      服务端向微信换取可信手机号
        ↓
      复用统一账户与角色策略，建立 WechatIdentity
        ↓
      创建一次性完成票据
        ↓
H5 轮询取得票据并消费
        ↓
签发 JWT，按网页选择的角色进入系统
```

## 6. API 契约

新接口统一放在 `/api/v1/auth/wechat-device/`，避免继续扩大语义已经不同的 `wechat-web` 接口。

### 6.1 `POST /api/v1/auth/wechat-device/session`

H5 创建扫码登录会话。

请求：

```json
{"requested_role": "student"}
```

响应数据：

```json
{
  "web_session_id": "opaque-value",
  "qrcode_url": "/api/v1/auth/wechat-device/qrcode?...",
  "expires_in": 300
}
```

服务端建立或确认 Django session，并将设备会话绑定到该浏览器。非法角色直接拒绝。

### 6.2 `GET /api/v1/auth/wechat-device/qrcode`

仅允许原浏览器读取当前设备会话的小程序码。响应是微信返回的真实图片内容，使用微信响应的实际图片类型，不返回桥接码正文。

二维码场景值只包含不超过 32 字符的随机一次性桥接码，不包含用户 ID、手机号、角色或 JWT。

### 6.3 `POST /api/v1/auth/wechat-device/scan`

由小程序绑定页调用。

请求包含：

- `bridge_code`：小程序码中的一次性场景码；
- `login_code`：当次 `wx.login` 返回的一次性 code。

服务端调用 `jscode2session`，验证 AppID、OpenID 和桥接会话。响应分为：

- `login_confirmed`：已有小程序身份且角色校验成功；
- `phone_authorization_required`：首次身份，需要用户点击手机号授权；
- 明确的受控错误：会话过期、桥接码重放、身份冲突、角色未授予或微信服务失败。

首次扫描后返回一个仅供该小程序身份继续手机号授权的短期 `phone_binding_token`；原桥接码立即失效。

### 6.4 `POST /api/v1/auth/wechat-device/phone`

仅首次绑定调用。

请求包含：

- `phone_binding_token`；
- `phone_code`：原生 `getPhoneNumber` 返回的一次性 code。

服务端向微信换取可信手机号，复用现有账户创建、账户状态、多角色和高权限保护规则，创建或校验 `WechatIdentity`，然后将网页设备会话标记为 `bound`。

浏览器提供的手机号、短信验证码、OpenID 或用户 ID 均不作为可信输入。

### 6.5 `GET /api/v1/auth/wechat-device/status`

H5 使用原浏览器 session 和 `web_session_id` 轮询。

未完成时只返回状态和安全错误码；完成后返回一次性 `ticket`。不返回手机号、OpenID 或用户 ID。

### 6.6 `POST /api/v1/auth/wechat-device/complete`

H5 提交一次性 `ticket` 和当前角色。服务端验证浏览器绑定、角色一致性、票据有效期和单次消费规则后，返回与手机号验证码登录一致的 JWT 和用户会话数据。

## 7. 账户与角色规则

- 已有 `WechatIdentity`：只能登录该账号已经拥有的角色；家长角色继续使用现有家长角色兼容规则；
- 首次绑定到已有手机号账号：不得改变账号已有管理员、教师、家长、学生角色；
- 首次手机号不存在：只允许按现有自助登录规则创建学生或家长账号；不得通过扫码自助创建管理员或教师权限；
- 微信身份已绑定到其他账号、手机号指向其他冲突身份或 UnionID 冲突时失败关闭；
- 用户状态不是 `active` 时拒绝登录；
- JWT 中的 `active_role` 必须等于网页创建会话时选择的角色。

## 8. 安全控制

- 网页会话、桥接码、手机号绑定 token 和完成票据均使用密码学安全随机值；
- 桥接码、`wx.login` code、手机号 code 和完成票据都只能消费一次；
- 网页轮询和完成操作必须匹配原 Django session，防止登录 CSRF 和票据转移；
- 小程序扫码确认后锁定 AppID/OpenID，手机号授权步骤不能替换微信身份；
- Redis 故障、微信接口异常或数据库冲突均失败关闭，不降级为接受前端手机号；
- 日志只记录 trace ID、会话阶段、脱敏会话标识和错误分类，不记录手机号、OpenID 全文、临时 code、access token 或 AppSecret；
- 对创建会话、扫码确认、手机号授权、状态轮询和完成登录分别限流；
- 过期会话在前后端均提示重新生成，不自动无限重试。

## 9. 兼容与清理策略

- 现有 `/auth/wechat-web/*` 网站 OAuth 接口暂时保留，避免一次发布同时删除回滚通道；
- H5 新入口只调用 `/auth/wechat-device/*`，不再加载微信扫码 `iframe`、不再跳转 `qrconnect`、不再处理网页 OAuth callback；
- 新流程生产验证稳定后，再单独提出删除旧网页 OAuth 页面、接口、`WechatWebIdentity` 和环境变量的清理任务；
- 小程序原有 `/auth/wechat-login` 和 `/auth/wechat-bind` 暂时保留，其他小程序登录入口不受本次改造影响。

## 10. 测试方案

### 10.1 后端自动测试

- 会话绑定原浏览器、非法角色和 Redis 故障失败关闭；
- 二维码桥接码长度、内容保密、过期和单次消费；
- `wx.login` code 正常、无效、重放及微信接口异常；
- 已绑定身份扫码后直接产生完成票据；
- 未绑定身份只返回手机号授权要求，不提前登录；
- 手机号授权成功、拒绝、无 code、微信换号失败和 token 重放；
- 现有账号四角色校验、多角色选择、未授予角色和账号停用；
- 新账号不能自助获得管理员或教师角色；
- OpenID、UnionID、手机号与账号冲突全部拒绝；
- 跨浏览器轮询、跨浏览器完成、重复票据和过期票据全部拒绝；
- 登录响应与手机号验证码登录的会话契约一致。

### 10.2 前端自动与构建验证

- 手机号页链接的位置和文字样式；
- 微信视图进入即创建会话，不发生 `window.location.assign`；
- DOM 中不存在微信登录 `iframe`；
- 二维码使用 `<img>` 完整显示；
- 轮询状态、角色切换、重新生成、返回手机号页和卸载清理；
- 小程序绑定页自动执行 `wx.login`；
- 已绑定身份显示成功，首次身份显示原生手机号授权按钮；
- H5 生产构建和 `mp-weixin` 生产构建均通过。

### 10.3 真实验收

必须使用正式微信环境验证以下两条链路：

1. 未绑定微信：扫码 → 小程序手机号授权 → 网页自动登录；
2. 已绑定微信：扫码 → 网页自动登录，不再要求手机号授权。

分别验证至少一个普通角色和一个已有多角色账号。模拟微信响应、仅生成二维码或静态构建成功都不能替代真实端到端验收。

## 11. 发布顺序与回滚

1. 发布后端新接口，旧入口保持不变；
2. 构建并上传包含新绑定页逻辑的小程序体验版；
3. 在测试环境完成首次绑定和再次扫码两条真实链路；
4. 发布小程序正式版；
5. 发布 H5，将入口切换到设备登录协议；
6. 生产端到端验证后保留旧接口至少一个发布周期。

若任一阶段失败，H5 回滚到上一个构建，后端新接口可保留但不被调用；手机号验证码登录始终作为独立可用入口，不受扫码登录发布影响。
